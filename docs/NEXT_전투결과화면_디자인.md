# 다음 세션 프롬프트 — 전투 결과 화면 디자인 개선

아래 「프롬프트」 절을 새 세션에 그대로 붙여넣는다. 그 아래 「참고」는 프롬프트가 가리키는
사실을 모아 둔 것이다(2026-10-12 기준. 세션에서는 코드를 직접 다시 확인할 것).

## 프롬프트

```
전투 결과 화면(대전이 끝난 뒤 승리·무승부·패배를 보여 주는 화면)의 디자인을 본격적으로
개선하려고 한다. 지금은 화풍이 입혀지지 않은 초기 모양 그대로다. 이미 화풍이 잡힌 다른
화면들과 같은 결로 다시 잡아 줘.

시작하기 전에 HANDOFF.md와 CLAUDE.md를 읽고, 아래를 코드에서 직접 확인해 줘.

■ 지금 상태
- 대전 결과는 `packages/client/src/screens/ResultScreen.tsx` 하나다(약 180줄).
  `.scr-result` 위에 제목(승리/무승부/패배) · 한 줄 사유 · 보상 줄(군량 · 재료 · 장수 카드 0~2장) ·
  예상 승률 한 줄 · 단추 둘([다시 편성] · [도시로])이 세로로 놓여 있을 뿐이고,
  CSS는 `style.css`의 `.scr-result` 십여 줄이 전부다(제목 색만 승/무/패로 갈린다).
- 그리는 갈래가 셋이다. 다 살아 있어야 한다.
  ① 승리 · 패배 — 보상은 이미 계정에 들어가 있고 보여 주기만 한다.
  ② 무승부 — 보상 셋(장수 카드 1장 · 재료 · 군량) 중 **하나를 골라야** 반영된다.
     고르기 전에 나가면 아무것도 안 남는다.
  ③ 성립하지 않은 판(`voided`: 상대 이탈 · 양쪽 유휴) — **승/무/패 제목 · 보상 칸 · 예상 승률을
     띄우지 않는다.** 띄우면 「무승부를 당했다」로 읽힌다(CLAUDE.md 「성립하지 않은 판」).
     참가비 환불 여부 한 줄만 있다.
- 기획 pptx에는 **결과 화면 목업이 없다**(14쪽에 승리 조건 · 보상 규칙만 있다).
  그래서 이번에는 설계를 먼저 제안해야 한다.
- 화면에 아직 안 쓰는 데이터가 있다 — `BattleOutcome`(`packages/meta/src/types.ts`)의
  `picks`(출전 장수) · `kills`(장수별 격파 수) · `fallen`(퇴각 = 부상한 내 장수) ·
  `mySquad` · `theirSquad`(부대 이름) · `power`(양쪽 전투력).
  무엇을 화면에 올릴 수 있는지 먼저 확인하고, 승리 · 패배 · 무승부 · 온라인 · AI에서
  각각 실제로 값이 오는지 봐 줘(온라인은 서버 정산 `settled`가 보상을 갈아 끼운다).

■ 참고할 화면 (이미 구현돼 있다)
- 도적떼 방어전 결과 — `RaidBattleScreen.tsx`의 `RaidResultScreen`(`.rrs-`, 2026-09-21 화풍).
  **같은 「결과」 화면이 이미 화풍을 입은 사례**라 가장 가까운 출발점이다. 카드는 장터 뽑기와
  같은 액자(`.mkt-card`)를 쓴다 — 「카드를 얻었다」가 한 게임 안에서 한 모양이라는 규칙.
- 장터 뽑기 결과(카드 공개 연출) · 랭킹(`.rk-`, 목판 · 두루마리) · 궁궐 · 대장간(액자 · 9분할).
- 전투 화면의 판때기 그림들(`assets/icons/battle_*` · `panel_*`)과 이번에 손본 매칭 대기 두루마리
  (`QuoteScroll`, 왼쪽부터 쓸어 입히는 연출).

■ 이번 세션에서 할 일
1. 위 화면들의 화풍 규칙(판때기 · 액자 · 제목 · 단추 · 카드 모양 · 연출)을 짧게 정리해서
   결과 화면에 옮길 수 있는 것과 없는 것을 갈라 보여 줘.
2. 결과 화면의 새 디자인을 두세 안으로 제안하고 추천을 말해 줘. 함께 정할 것:
   - 승 · 무 · 패를 어떻게 다르게 보이게 할지(제목 그림 · 색 · 도장 같은 것).
   - 무엇을 더 보여 줄지 — 출전 장수 · 격파 수 · 부상 · 부대 이름 · 전투력 같은 것 중에서.
   - 보상(특히 장수 카드)을 어떻게 공개할지, 등장 연출을 둘지.
   - 무승부 택1과 성립하지 않은 판은 그 디자인 안에서 어떻게 생기는지.
   글로만 말하지 말고 **실제 크기로 그린 시안**을 보여 줘(아래 「눈 확인 방법」).
   내가 고르면 구현한다.
3. 범위를 확인해 줘 — 결과 화면 하나만 할지, 전투가 끝나는 순간(판 위)에서 결과 화면으로
   넘어가는 사이의 연출까지 함께 볼지.

■ 지켜야 할 것 (CLAUDE.md에 있는 것 중 이 작업에서 특히 밟기 쉬운 것)
- **화면이 판정하지 않는다.** 보상 · 승률 숫자는 meta가 낸다(`winChance()` 등). 화면이 공식을
  다시 적으면 표시만 조용히 어긋난다. 무승부 택1도 고른 것을 넘길 뿐이다.
- 스모크가 이 화면을 `data-*`로 읽는다 — `data-screen="result"` · `data-result` · `data-void` ·
  `data-field`(rewards · grain · materials · card · chance · drawPick · voidWhy · refund) ·
  `data-pick` · `data-action`(again · home) · 카드 줄의 `data-officer` · `data-grade`.
  마크업을 바꾸면 `tools/smoke_meta.ts`의 결과 검사(1380줄 근처)를 같이 고친다.
  **스모크는 화면 글자가 아니라 속성으로 건다.**
- CSS 이름이 겹치면 오류 없이 **화면을 봐야만** 안다. 새 클래스는 접두사를 붙인다
  (도적떼 결과가 `.rrs-`다 — 겹치지 않게 다른 접두사로). `border:` 단축 속성은 9분할
  `border-image`를 지운다. 배경 위 팝업은 `.scr-bg > *` 규칙에서 빼야 제자리에 뜬다.
- 연출을 넣으면 「움직임 줄이기」(`prefers-reduced-motion`)에서도 끝 상태가 바르게 서야 한다.
  같은 요소의 애니메이션을 바꿀 때 **키프레임 이름이 같으면 다시 안 돈다**(격언 두루마리에서 밟았다).
- 결과 화면 배경 음악은 승/무/패로 갈린다(`audio/bgm.ts`의 `trackForResult`). 화면을 나누거나
  이름을 바꾸면 이 연결이 끊기지 않는지 본다.
- 문구는 열 개 언어 전부 채운다(`i18n/strings/*.json`, `result.*` 키). 가장 긴 번역으로
  단추 · 제목이 넘치지 않는지 본다. i18n JSON은 줄 끝이 섞여 있다 — CLAUDE.md의 CRLF 항목대로
  고치고 `git diff --stat`의 줄 수가 고친 양과 맞는지 본다.
- 700px(프레임 최대 폭)에서 눈으로 확인한다. 좁은 미리보기만 보고 판단하지 말 것.

■ 눈 확인 방법
- 결과 화면은 전투를 끝내야 나와서 손으로 가기 번거롭다. 시안 단계에서는 CLAUDE.md의
  「로그인이 필요한 화면도 눈으로 확인할 수 있다」 방식(style.css를 public/에 잠깐 복사 +
  마크업 흉내 HTML + Playwright)이나, 실제 컴포넌트를 esbuild로 묶은 시험 페이지(스크래치패드,
  커밋 안 함)를 쓴다. 승 · 무(고르기 전 · 고른 뒤) · 패 · 성립 안 함, 카드 0 · 1 · 2장, 3v3 · 5v5를 다 찍는다.
- 구현 뒤에는 실제 흐름으로도 본다 — AI 대전에서 [항복]으로 패배 화면, `npm run look:online`으로
  온라인 결과 화면.

■ 확인
- `npm run typecheck` · `npm test` · `npm run smoke:meta`(결과 화면을 지난다).
- 서버가 꺼져 있으면 `npm run dev` · `npm run server-api` · `npm run server`.
- 작업 브랜치에서 하고, main 합치기는 보고하고 확인받은 뒤에 한다. history에 기록한다.

설계를 먼저 제안하고, 내가 확정하면 구현해 줘.
```

## 참고 (2026-10-12 확인)

### 지금 화면의 구조 (`ResultScreen.tsx`)

| 자리 | 내용 | `data-*` |
|---|---|---|
| 제목 | `result.win` · `result.draw` · `result.lose` (색만 다름) | 루트 `data-result` |
| 한 줄 | `outcome` 문자열(결말 사유) | — |
| 보상 칸 | 군량 · 재료 · 장수 카드 0~2장(썸네일 + 이름 + 등급 배지) | `rewards` · `grain` · `materials` · `card`(+`data-officer` · `data-grade`) |
| 무승부 | 보상 셋 중 택1 단추 + 「고르기 전까지 반영 안 됨」 | `drawPick` · `data-pick` |
| 예상 승률 | `result.expected` — `winChance(power.mine, power.theirs)` | `chance`(+`data-chance`) |
| 단추 | [다시 편성] · [도시로] | `data-action="again"` · `"home"` |
| 성립 안 함 | 제목 `result.void` + 사유 + 환불 한 줄, 보상 · 승률 없음 | `data-result="void"` · `data-void` · `voidWhy` · `refund` |

CSS는 `style.css` 1437줄 근처 `.scr-result` 규칙 십여 줄뿐이다.

### 이어진 자리

- `App.tsx`가 `screen.name === 'result'`로 띄운다. 들어오는 길은 AI 대전 · 온라인 대전 둘(도적떼는 `RaidResultScreen` 따로).
- 음악: `trackForResult(result, voided)` — 승 · 무 · 패마다 곡이 다르고, 성립하지 않은 판은 원래 하나였던 결과곡(`result`)으로 물러난다.
- 보상 반영: 승 · 패는 화면에 오기 전에 반영(AI는 서버 재생 검증 `/battle/ai-result`, 온라인은 `BattleRoom` 정산 `settled`).
  무승부는 이 화면에서 고른 뒤 `/battle/draw-result`. 서버가 안 닿으면 로컬로 물러난다.
