# 삼국지 영걸전 데이터 추출 — 세션 정리 (2026-07-23)

이 문서는 이 세션에서 시도한 작업과 결과를 정리한 것입니다. 특히 **장수 얼굴 추출**을 위한 압축 코덱 분석 시도를 상세히 기록합니다 (향후 참고용).

## 1. 능력치 추출 (성공)

- **위치:** `BAKDATA.R3`, 오프셋 4352부터 **21바이트 고정 레코드**.
- **레코드 구조:** `[0-5]` 이름(CP949, 2~3자, 널패딩) … `[14]` 얼굴/그래픽 ID … `[16]` 병과 … `[17]` 통솔 · `[18]` 무력 · `[19]` 지력.
- 필드 검증: 여포(무100/지21), 이유(무25/지90), 조조(지94) 등 캐릭터 특성과 일치.
- 269명(중복 이름·능력치 0 NPC 제외).

## 2. 소속 추출 (부분/근사)

- **소속은 BAKDATA에 캐릭터별 바이트로 저장돼 있지 않음** (모든 바이트 열을 검증했으나 세력을 분리하는 바이트 없음).
- 유일한 신호는 idx14(얼굴 ID)의 세력별 대략적 구간. 얼굴 ID가 여러 캐릭터에 중복되어(예: 손견·우칙·조진=77) 경계에서 오분류 발생.
- 도메인 지식으로 보정 + 애매한 항목은 `비고`에 `검토` 표시.

## 3. 얼굴 추출 — 압축 코덱 분석 (자체 추출은 실패, 인터넷 세트로 대체)

### 3.1 FACEDAT.R3 구조 (완전 해독)

```
[2바이트 헤더 00 00]
[인덱스 테이블: 239개 × 6바이트]  = [누적끝오프셋 상위16][이미지 크기 2][누적끝오프셋 하위16]
   - 크기 필드(rec+2)가 신뢰값. 이미지는 테이블 뒤(offset 1436)부터 크기순 연속 배치.
   - 상위16비트는 64KB 랩에서 한 레코드 늦게 증가 → 오프셋은 '크기 누적합'으로 계산.
[압축 이미지 239개]  각 1177~1695 bytes
[꼬리 679 bytes]  → 아마 240번째 얼굴(인터넷 세트는 240개였음)
```

### 3.2 얼굴 ↔ 장수 매핑 (완전 해독)

- 얼굴 번호 = BAKDATA 레코드의 **idx14** 값.
- 인터넷 BMP 파일 번호 N = **얼굴 ID (N-1)** (1-1.bmp=유비=얼굴0, 16-1.bmp=간옹=얼굴15로 확인).

### 3.3 렌더링 포맷 (디스어셈블로 해독) — MAIN.EXE `draw_face` @ CS:0xD5FC

- **EGA 16색 planar, 640px 폭(80 bytes/row)**, 비디오 세그먼트 0xA000.
- EGA **write mode 2** (GC reg5=0x02, Map Mask=0x0F). 소스 바이트 → 변환테이블 색인 → 픽셀 색(하위 4비트).
- **소스 1바이트 → 2×2 픽셀 블록** (화면 디더링의 정체). TL=xlat_53cc[b], TR=xlat_54cc[b], BL=xlat_55cc[b], BR=xlat_53cc[b].
- **자기수정 코드**: 인너루프 폭·di 스트라이드를 런타임 패치 → 치수는 호출자가 전달.
- 변환 테이블 3개: MAIN.EXE 파일오프셋 0x53CC/0x54CC/0x55CC (각 256B, CS 오버라이드 xlatb). → `얼굴추출/xlat_*.bin`.
- **실제 얼굴 크기: 64×80** (인터넷 BMP로 확인).

### 3.4 압축 코덱 — 시도했으나 미해결

- **LZSS 계열**로 파악(플래그 바이트 LSB-first, 리터럴 1B/매치 2B, 4096 링버퍼). 각 이미지 = 4바이트 헤더 + byte 4부터 압축.
- 시도한 것들 (모두 실패):
  - 표준 Okumura LZSS (r=4078, 링버퍼 fill 0x20 및 0x00)
  - 토큰 비트배치 전수탐색 (오프셋/길이 비트수, 바이트순서, MSB/LSB, threshold)
  - 링버퍼 크기 변형 (2048/4096/8192), 거리기반 LZ77
  - 여러 RLE 변형
- **판정 근거:** ground truth(스크린샷)와 대조 시, 실제 출력은 "주황 테두리 → 색6/색1 교대 문양"인데 내 디코더는 처음부터 노이즈(대부분 색6). 압축해제 크기도 상수여야 하는데(고정 치수) 가변으로 나옴 → 매치 인코딩이 표준과 다름.
- 실제 압축해제 루틴(별도, 세그먼트에 흩어진 far-call)을 끝까지 특정하지 못함.

### 3.5 런타임 메모리 덤프 시도 — 실패

- `dosbox_debug.exe`(디버거 내장 빌드) 발견 → MEMDUMPBIN으로 압축해제된 버퍼를 뜨려 함.
- **디버거 콘솔 창이 키보드 입력을 전혀 받지 않음** (SVN-Daum 빌드 + Windows 11, Pause 키 없는 노트북에서 break 불가). 포기.

### 3.6 스크린샷 방식 — 성공 (부분)

- 게임 실행 후 장수정보 화면 → Ctrl+F5. 캡처는 `dosbox/main_*.png`.
- 8종 얼굴을 잘라 `얼굴추출/스크린샷_얼굴/`에 저장. 게임 UI 프레임 포함(64×80 원본과 달리 화면 렌더 버전).
- 한계: 게임 내에선 보유/조우한 장수만 뜸 → 전체 239개는 불가.

## 4. 결론

- **얼굴 자체 추출은 미해결** (KOEI 고유 압축 코덱을 정적 분석으로 못 깸, 런타임 덤프는 환경 제약으로 실패).
- **대체 해결:** 인터넷에 이미 추출된 세트 확보 (`영걸전 원본얼굴/` 240개 64×80 BMP).
- 이 세션의 기여: **각 BMP 번호가 어느 장수인지 매핑** (`영걸전 원본얼굴/파일_장수_매핑.csv`) + 포맷/구조 문서화.

### 참고: 파일번호 ↔ 장수
`파일_장수_매핑.csv` 참조. 예) 4-1.bmp=조운, 16-1.bmp=간옹, 137-1.bmp=이유, 149-1.bmp=여포.
