## 0. 요지

지금 전투 화면은 **판 위아래에 장수 카드 줄**이 있고, 명령 판·배치 판·살펴보기가
**판 위에 떠서** 판을 가린다. 개편 후에는 세 칸이다.

```
#frame (세로 격자)
├ #top      ┌ #order (순서 판) ┐┌ #gameinfo (게임 정보) ┐   ← #cards-north 자리
├ #board    Phaser 캔버스 + #log(판 왼쪽 위 3줄 + [...]) + 장수 팝업
└ #bottom   ┌ #cmd (왼쪽 판) ┐┌ #ctx (오른쪽 판) ┐          ← #cards-south 자리
```

- 판 크기(`--board`, 정사각)와 `battle/layout.ts`의 `BoardDims`는 **그대로**다.
  도적떼 방어전(25×15)·튜토리얼(`DemoBattle`)이 같은 무대(`BattleStage.tsx`)를 쓰므로 함께 넘어간다.
- 판 위에 떠 있던 것(`#control`의 사분면 배치 `ui/panelSlot.ts`, `#prep`, `#inspect` 끌기)은 없어진다.
  **판을 가리지 않는 것**이 이번 개편이 얻는 가장 큰 것이다.

### 고유기술 물음 (확정 5)

맵을 보며 판단하도록 **맥락 판(오른쪽)**에서 묻는다. 이때 왼쪽 판은 **내 장수 정보**다.

```
┌ #cmd (내 장수 카드) ┐┌ #ctx ─────────────────────┐
│ [기물][S][이름]      ││ 고유기술을 쓰시겠습니까?     │
│ 초상  HP/AT/MP       ││ [ 고유기술 배너 ]  ← 누르면 상세(애니메이션 없음) │
│ 무 지 통 · 버프      ││ [ 사용 (SP n) ]             │
└──────────────────────┘│ [ 미사용 ]                  │
                        └─────────────────────────────┘
```

- 뜨는 조건 = `commandsFor().unique` (지금의 `.ctl-prompt` 조건과 같다).
- [사용]·[미사용] 뒤에야 **본래 명령 6칸**이 뜬다. 조준이 필요한 기술이면 [사용] 뒤 조준 흐름.

### 전투 기록 [...] (확정 7)

- 시스템 로그가 찍히는 자리(판 왼쪽 위)의 **첫 줄**에 `[...]`.
- 로그가 **찍히는 동안에는 숨고**, 다 찍혀 더 낼 것이 없으면 드러나 누를 수 있다.
- 누르면 전투 기록(지금의 `#history`)이 열린다. 항복 단추는 기록에서 빠져 게임 정보 판으로 간다.
- HUD의 ⋯(`[data-action=history]`)는 없어진다.

## 2. 엔진에 더한 것 (1단계, 완료)

`packages/rules/src/commands.ts` — 전부 읽기 전용, 난수 없음.

| 함수 | 쓰는 자리 |
|---|---|
| `skillStatus(state, unit)` → `none·sealed·used·poor·ready` | 순서 판 표시등 · 배치 고유기술 목록 · 장수 팝업의 고유기술 줄. 옛 살펴보기(`inspectPanel.ts`)의 제 계산(「SP 부족」이 없었다)은 6단계에서 팝업째 걷었다 |
| `meditateGain(state, unit)` | 명상 확인창 「MP를 N 회복합니다」 |
| `castEffects` · `castIntent` · `castCandidates` · `canCast` | 책략·아이템·고유기술 조준. `ControlModal`의 `effectsOf`·`intentFor`·`candidatesFor`를 엔진으로 옮긴 것 — 4단계에서 `ControlModal`째 걷었다(사본 없음) |
| `commandsFor(state, side)` → 6칸 + `unique` + 책략별 켜짐 | 명령 판. 제어권이 없으면 `null`. **[책략]은 쓸 수 있는 책략이 하나라도 있을 때만** 켜진다(예전엔 배우기만 하면 켜 두고 목록 안에서 껐다) |
| `turnForecast(state, n)` → `{unit, side, at, active}[]` | 순서 판. 「다들 차례를 그냥 넘긴다」고 가정한 예보 — 엔진의 `endTurn()`과 같은 순서(시간 1 → WT 되돌리기 → 보정 1턴 소진)로 WT만 돌린다. 통솔이 높은 장수는 두 번 나올 수 있다. 버프·스킬로 바뀌면 화면이 다시 부른다(확정 4) |

**동점 순번** — `UnitState.turnRank`(0..n−1 순열). `createBattle()`이 시드로 한 번 뽑는다
(**판의 첫 난수 소비** — 그래서 판마다 `rngCursor`가 인원 수 − 1만큼 앞서 시작한다).
`grantControl()`은 더 이상 그 순간 난수를 뽑지 않고, 「다음 차례의 적」
(`nextEnemiesInTurnOrder`)도 WT 다음에 이 순번을 본다. 셋이 같은 셈(`byTurnRank`, `state.ts`)이다.

- 설계 때는 「전투 시작(`running`)할 때 뽑는다」로 적었는데, **판을 만들 때**로 바꿨다 —
  유닛이 생기는 곳이 `createBattle()` 하나뿐이고 배치 사이에 WT가 안 바뀌어서, 그러면
  **배치 화면의 순서가 처음부터 정확하다**(「?」로 비워 둘 칸이 없다).
- 대가: 같은 시드라도 예전과 다른 판이 된다. 배포 순간에 진행 중인 판만 영향을 받는다
  (서버의 AI 재생 검증도 새 규칙으로 처음부터 다시 계산하므로 판 사이에는 문제없다).

회귀: `packages/rules/test/commands.test.ts` — 예보를 **엔진을 실제로 돌린 순서와 맞춘다**
(3v3·5v5 × 12시드, 지금 차례가 있을 때, WT 보정, 1 차이 동점). 예보에서 시간 1 · 보정 ·
동점 순번 · 봉인 순서를 하나씩 깨 보고 전부 잡히는 것을 확인했다. 기존 회귀 넷(동점 난수 ·
`rngCursor`가 0에서 시작한다는 가정 셋)은 새 규칙으로 고쳤다.

`smoke:ui`는 완주한다. 동점 순번으로 seed 3의 차례 순서가 바뀌어 **두 군데를 고쳤다** —
턴을 넘긴 뒤 다음 차례가 또 사람이라 말풍선 검사가 「기록에만 있다」로 거짓 실패했고(사람
차례면 넘겨 AI가 움직이게 한다), `sp=25` 새 판에서 AI가 먼저 서며 고유기술 연출(11.7초)이
20초 대기를 먹었다(60초로). ⚠ **「상태 배지 설명」은 개편 전에도 건너뛰고 있었다**(그 순간
걸린 상태가 없다) — 안 도는 갈래다. → 6단계에서 `?status=1`(남군 군주가 버프 · 디버프를 든 채 시작)로 **언제나** 돌게 했다.

## 3. 화면 구조의 세부

- **왼쪽 판 `#cmd`:** 배치 = 고유기술 목록 / 내 차례 = 명령 6칸(고유기술 물음 중에는 내 장수 카드) / 적 차례 = 그 적 장수 카드.
  - **명령 판의 첫 줄은 「명령을 선택하세요」**, 그 다음 줄부터 버튼 여섯(2열 × 3행)이다 (2026-09-27 기획자 확정).
- **오른쪽 판 `#ctx`:**

| 상태 | 표시 |
|---|---|
| 배치 | 배치 시간 · [준비완료] · [책략 확인] (`#ctx-prep`. 전투 중의 `#ctx-flow`와 같은 칸, 단계마다 하나만 보인다) |
| 내 차례, 고유기술 물음 | 확정 5의 패널 |
| 내 차례, 명령 전 | 비어 있음 — 안내는 왼쪽 명령 판 첫 줄이 한다 |
| 명령을 고른 뒤 | 「이동할 위치를…」·「대상을…」 + [취소] / 책략·아이템 목록 |
| 대상을 고른 뒤 | 확인창(시전 확률 · 공격 데미지·치명타 · 명상 회복량 · 차례 마침) |
| 적 차례, 대상을 고르기 전 | **비어 있음** (2026-09-27 기획자 확정) |
| 적 차례, 대상을 고른 뒤 | 지목된 대상 카드 |

- `ControlModal`(977줄, `ui/controlModal.ts`)은 **흐름(명령 → 조준 → 확인 → 제출)을 상태 기계로 떼어 내고** 그리기를 `#cmd`·`#ctx` 둘로 가른다.
  → 4단계(2026-10-06): `ui/commandFlow.ts`(DOM 없음, `test/commandFlow.test.ts`) · `commandPanel.ts` · `contextPanel.ts`. `controlModal.ts`는 지웠다.
- **장수 카드**(97·98쪽 — [기물][등급][이름] · 초상 · HP/AT/MP · 무지통 · 버프/디버프)는 컴포넌트 **하나**(`ui/officerCard.ts`)로 세 곳(적 차례 왼쪽, 대상 오른쪽, 팝업)에서 쓴다. 속은 옛 `InspectPanel`의 그리기를 가져왔다.
- **순서 판의 줄을 누르면 카메라가 그 장수에게 간다** (2026-10-06 기획자 확정). 카드 줄이 하던
  「카드를 누르면 그 장수 위치로」(28쪽, 옛 `cardFocus`)를 순서 판이 이어받는다 — 2단계에서 카드 줄과 함께 걷혔다.
  **줄을 누르면 살펴보기도 함께 뜬다** — 판의 장수를 누를 때와 같다(2026-10-06 기획자 확정). → 6단계에서 장수 팝업이 됐고, 카메라도 판에서 누른 것과 같은 규칙이다(6단계 확정 2·3).
- 순서 판의 WT 칸은 지금 카드의 대기시간과 같은 단위 — **일, 소수 둘째 자리**(`0.25일`)로 적고,
  **지금 차례인 줄은 「차례」**다 (2026-09-27 기획자 확정).
- **위 칸의 나눔** (2026-10-06 기획자 확정 — 목업대로): 전투 중 순서 판 : 게임 정보 = **1 : 1**(93쪽).
  **배치 · 정찰 중에는 순서 판이 위 칸 전체**(두 열 1~5 · 6~10)를 쓰고 게임 정보는 숨는다(90쪽 — 목업에 게임 정보 상자가 없다).
- **주사위가 도는 동안 순서 판의 동점 줄이 반짝인다** (2026-10-06 기획자 확정 — §5-1 끝의 「고려할 만하다」를 받았다).
  쪽지(「설종 → 곽도」)는 그대로 뜬다.
- 게임 정보의 [항복]은 **내 차례에만 켜진다** — `Playback.submit()`이 그 밖의 의도를 조용히 버리기 때문이다(예전 기록 안의 [항복]은
  언제나 눌려 아무 일이 없었다). [턴 가져오기]는 상대 차례 · 마감 0 · `validate(forceSkipTurn)`일 때만 켜진다.
  ⚠ 3단계에서 **[턴 넘기기]가 실제로는 한 번도 서버에 닿지 않았다**는 것이 드러났다 — `submit()`이 상대 차례(`aiThinking`)의
  의도를 전부 버렸다. `forceSkipTurn`만은 통과시키고 회귀(`transport.test.ts`)로 고정했다.
- 「지목된 대상」은 적의 의도에서 온다 — 이벤트(`attacked`·`tacticCast` 등의 대상)로 오른쪽 판을 채운다.
  `tacticCast` · `uniqueSkillCast` · `itemUsed`에는 대상이 없었다 → 4단계에서 엔진이 `target?: UnitId`를 싣게 했다
  (장수를 겨눌 때만 — 칸을 겨눈 것은 카드를 안 띄운다).

### 5-2. 그림을 만들 때 쓴 프롬프트 (기록)

화풍 기준: 장수 초상과 같은 **먹선 스케치 + 옅은 회색 담채**, 배경은 양피지·목판. 판 위에 겹쳐
그리므로 **배경은 투명(또는 크로마키 초록)**이 필요하다.

> **참고:** 「중국 고대 12주사위」로 가장 알려진 유물은 진(秦)대의 **14면 주사위(骰子)**다 —
> 열두 면에 一~十二, 나머지 두 면에 글자가 있다. 12면체(정십이면체, 오각형 면)로 할지
> 이 14면체로 할지 먼저 정하면 프롬프트의 모양 줄만 바꾸면 된다. 아래는 12면체 기준이다.

Fixed camera, three-quarter top-down view, the die stays centered in frame,

- 영상 도구는 대개 투명 배경을 못 내므로 **크로마키 초록**으로 받는다 — 받은 뒤 WebM(알파)이나 PNG
  시퀀스로 뽑는 것은 `tools/`에 도구를 붙이면 된다(`build_burst.py`가 스프라이트를 굽는 것과 같은 결).
- **마지막 프레임이 프롬프트 A의 정지 그림과 같은 각도**여야 이어 붙일 때 튀지 않는다 —
  A를 먼저 뽑고, 영상 도구에 그 그림을 **끝 프레임(end frame) 참조**로 주는 것이 가장 확실하다.
