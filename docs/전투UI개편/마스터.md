# 전투 UI 개편 — 마스터 (세션을 여는 곳)

pptx 89~98쪽(「UI update260926-」)의 전투 화면 개편을 **여러 세션에 걸쳐 한 단계씩** 구현한다.
이 파일은 **입구**다 — 새 세션은 여기서 시작해 진도를 보고, 한 단계를 구현하고, 진도를 고치고 닫는다.

## 문서 셋 — 역할이 갈린다

| 파일 | 무엇을 정하나 | 언제 고치나 |
|---|---|---|
| **마스터.md** (이 파일) | 세션 절차 · 규칙 · 여는 프롬프트 | 절차가 바뀔 때만 |
| [**로드맵.md**](로드맵.md) | **어디까지 했나** — 단계 · 할 일 체크 · 완료 조건 · 상태 | **세션마다** (시작할 때 🔶, 끝날 때 ✅) |
| [**설계.md**](설계.md) | **무엇을 어떻게 만드나** — 쪽별 요구 · 기획자 확정 사항 · 화면 구조 · 엔진 함수 | 기획자가 새로 정하거나 바꿀 때 |

진도를 설계에 적지 않고, 설계를 로드맵에 옮겨 적지 않는다 — 두 군데 적으면 한쪽만 낡는다(CLAUDE.md).
원본 기획은 `docs/삼국 약식 체스.pptx` 89~98쪽(읽기 전용).

## 세션 절차

1. **읽는다** — `CLAUDE.md` → `HANDOFF.md`(§7 「진행 중」) → 이 파일 → `로드맵.md` → 그 단계가 가리키는 `설계.md`의 절.
2. **진도를 확인한다** — 로드맵 표의 **첫 번째 ⬜**(🔶가 있으면 그것부터)가 이번 세션의 단계다.
   직전 세션의 `history/` md와 `git log`로 실제 상태가 표와 맞는지 본다. 어긋나면 **코드가 정본**이다.
3. **표를 🔶로 고친다.**
4. **서버를 띄운다** — `npm run dev`(5173) · `npm run server-api`(8787) · `npm run server`(2567).
   `smoke:ui`는 5173만 있으면 된다.
5. **구현한다** — 그 단계의 체크 항목만. 다음 단계의 일을 당겨 하지 않는다(한 번에 한 층씩 화면으로 확인하기 위해서).
   설계에 없는 판단이 필요하면 **기획자에게 묻는다** — 정해지면 `설계.md`에 「(날짜 기획자 확정)」으로 적는다.
6. **검증한다** — 로드맵의 「공통 완료 조건」 전부. 스모크는 **끝까지 완주**해야 통과다.
7. **보여 준다** — 700px 스크린샷으로 기획자에게. 확인을 받으면 ✅.
8. **닫는다** — 로드맵 표 ✅ + 날짜 + history 파일명 · `history/YYYY-MM-DD_전투UI개편_N단계_….md` ·
   커밋 · 푸시(기획자가 원할 때).

## 이 트랙의 규칙

- **한 세션 = 한 단계.** 단계가 끝나면 기획자의 눈 확인을 받고 나서 다음 세션으로 간다.
- **화면이 판정하지 않는다** — 켜짐 · 후보 · 확률 · 예보 · 회복량은 엔진(`packages/rules/src/commands.ts` 외)이 낸다.
  화면에 공식이 필요해지면 엔진에 함수를 더한다.
- **씬의 디버그 API(`window.__battle.scene.debug*`)는 살린다** — 스모크 · `raid_play` · `smoke_meta`가 쓴다.
- **전투는 단계 사이에도 끝까지 둘 수 있어야 한다** — 옛 판을 걷기 전에 새 판이 그 일을 받는다. 임시로 옮긴 것은 주석에 적는다.
- 새 CSS는 접두사를 붙인다(CLAUDE.md — `.panel`처럼 흔한 이름 금지).

## 여는 프롬프트 (새 세션에 그대로 붙인다)

```
전투 UI 개편을 이어서 하자. docs/전투UI개편/마스터.md 의 세션 절차대로 진행해 줘 —
로드맵.md에서 다음 단계를 확인하고, 그 단계만 구현하고, 검증 · 스크린샷까지.
```
