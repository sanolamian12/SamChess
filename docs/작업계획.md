# 작업 계획 — 진행 상황 통제 문서

> **이 파일과 [`HANDOFF.md`](../HANDOFF.md) 둘이 한 쌍이다.**

> 이 파일은 **앞으로 무엇을 어느 순서로 하는가**(진행 통제)를 적는다.

## 0. 이 문서를 쓰는 법

### 새 세션을 열 때

**전문은 [`HANDOFF.md`](../HANDOFF.md) 맨 위의 「새 대화를 여는 프롬프트」에 있다.** 요지는 이렇다.

```
SamChess 작업을 이어간다. 먼저 이 두 문서를 순서대로 읽어줘.

1. HANDOFF.md 전체 — 현재 상태의 정본
2. docs/작업계획.md — 진행 통제. 「지금 어디까지 왔는가」가 §2 표에 있다

읽고 나서 상태를 확인해줘:
  npm run extract && npm run typecheck && npm test

그다음 §2 표에서 **아직 ⬜인 가장 위 세션**을 골라 진행한다.
설계안을 먼저 보여주고, 내가 확인하면 구현으로 넘어가자.
```

### 세션을 마칠 때 — **반드시** 이 넷을 한다

1. **§2 표의 상태를 갱신한다** (⬜ → ✅). 부분만 됐으면 🔶로 두고 §3의 해당 항목에 **어디까지 됐는지** 적는다
2. **§4 「열린 질문」에서 답이 나온 것을 §5 「결정 로그」로 옮긴다**
3. 규칙·수치·계약이 바뀌었으면 **`Design/GDD.md`와 `HANDOFF.md`에도 반영한다** — 이 파일은 계획이지 사양이 아니다.
   다시 밟으면 안 될 것은 **`CLAUDE.md`**에도 한 줄 남긴다
4. **`history/{날짜}_{제목}.md`에 「왜 그렇게 정했고 어디서 넘어졌는가」를 남긴다** —
   이 파일들과 역할이 갈린다. 여기는 **지금**, `history/`는 **그때**다

> **이 파일이 사양의 출처가 되면 안 된다.** 확정된 것은 GDD로, 굳은 계약은 HANDOFF로 간다.
> 여기 남는 것은 「순서」와 「아직 안 정해진 것」뿐이다.

### D — 부대 전투력 산출식 (44쪽) ✅ 2026-08-17

44쪽이 「전투 통계 기반으로 산출식을 도출하는 게 좋겠음」이라고 못박아서, 그대로 했다.
사양은 **GDD §7.1**로 옮겨 적었고, 경위는
[`history/2026-08-17_부대전투력.md`](../history/2026-08-17_부대전투력.md)에 있다.

| 붙은 것 | 자리 |
|---|---|
| **산출식** — `battlePower` · `unitPower` · `winChance` · `MATCH_BAND` | [`meta/src/power.ts`](../packages/meta/src/power.ts) |
| **측정 하네스** — 표본 추출 · 로지스틱 회귀 · 보정 검사 · 분포 보고 | [`tools/power_fit.ts`](../tools/power_fit.ts) (`npm run power`) |
| 회귀 22건 (고정 표본 · 단조성 · 대칭 · 계약) | [`meta/test/power.test.ts`](../packages/meta/test/power.test.ts) |

```
power(팀) = Σ 유닛별 기여        winChance = σ((내 전투력 − 상대) / 100)
```

**설계에서 셋을 바꿨다.**

- **`tools/balance.ts`를 확장하지 않고 형제 도구로 뒀다.** balance의 Lv1 기본 출력이
  HANDOFF §7 기준선과 글자 단위로 비교되는 자산이라 표본 추출을 갈아 끼울 수 없고,
  애초에 **표본 요구가 다르다** — 회귀에는 양쪽 레벨·능력 선택을 **독립으로** 굴린
  표본이 필요하다(고정 정책이면 hp/mp/at이 레벨과 공선이라 분리되지 않는다).
- **기물을 뺐다** (기획자 확정). 회귀에서는 유의했지만(3v3 최대 8.0%p) 전투력에 넣으면
  사람이 그 숫자를 보고 기물을 고르거나 배제하게 된다.
- **고유기술을 「보유 0/1」이 아니라 등급 더미 셋으로** 나눴다. SP 코스트로 두었더니
  헌제(7)가 표본에 없어 외삽되어 **실측 최약체가 D급보다 세게** 나왔다.

**검증** — 적합에 쓰지 않은 새 시드 5천 판으로 보정 검사: 예측 승률 11개 구간이 전부
실제와 **±3%p 이내**. Δ등급점수 × Δ평균레벨 표도 두 방향 모두 어긋난 칸 없이 단조
(왼쪽 위 0.0% → 오른쪽 아래 97.1%).

**밟은 지뢰 둘** ★

- **기물 지시변수 다섯이 완전 공선이었다.** 각 진영이 King + (n−1)개를 가져 **합이 상수**라
  차분의 합이 0이 된다. 표준오차가 **6435**로 폭발해서 드러났다 — 기준 기물(Pawn)을
  빼야 한다. 숫자는 그럴듯하게 찍히므로 **표준오차를 안 봤으면 그대로 믿었을 것**이다.
- **표본에 없는 값으로 외삽했다.** 위 `skillCost` 건. 회귀는 관측 범위 밖에서 조용히 틀린다.

### B — 레벨/스킬 관리 · 재설계 (39쪽) ✅ 2026-08-17 ★ 저장 형식 v2

**형식 변경의 진짜 자리였다.** 사양은 **GDD §4.2 · §4.3 · §8.3**으로 옮겨 적었고,
경위는 [`history/2026-08-17_레벨스킬관리_저장형식v2.md`](../history/2026-08-17_레벨스킬관리_저장형식v2.md)에 있다.

```
v1   statPicks ['hp','hp','at',…]                 길이 = level − 1
     tactics   ['공포','화계','진화',…]            ← Lv6·7이 둘씩 들어와 어긋난다
v2   growth[]  [{stat:'mp', tactics:['화계','진화']}, …]   길이 = level − 1, 언제나
```

| 붙은 것 | 자리 |
|---|---|
| `GrowthStep` · `OfficerInstance` (v2) | [`meta/src/types.ts`](../packages/meta/src/types.ts) |
| 파생 함수 둘 · `growthPreview` · `applyRespec` · `cardsSpentOn` · `checkGrowth` | [`meta/src/profile.ts`](../packages/meta/src/profile.ts) |
| **되접기** — v1 → v2 · 손상 복구 · 멱등 | [`meta/src/migrate.ts`](../packages/meta/src/migrate.ts) **(신규)** |
| **화면** — 관리 · 고르기 · 재설계 확인 팝업 | [`screens/LevelUpScreen.tsx`](../packages/client/src/screens/LevelUpScreen.tsx) |
| 회귀 29건 | [`meta/test/growth.test.ts`](../packages/meta/test/growth.test.ts) **(신규)** |

**설계에서 셋을 바꿨다.**

- **둔갑천서를 「되감기」로 바꿨다** (§5-29, 기획자 확정). 원안은 「레벨 유지 + 다시
  고르기」였는데 그러면 **재설계 전용 절차가 한 벌 더** 생긴다. 쓴 카드를 전부
  돌려주고 Lv1로 되돌리면 기억할 것이 없어지고 **절차가 레벨업 하나로 모인다.**
- **되접기를 `storage.ts`가 아니라 meta에 뒀다.** 되접기는 화면에 안 뜨는 종류라
  meta에 있어야 `npm test`가 잡는다. `storage.ts`에는 읽고 쓰는 일만 남았다.
- **책략 설명을 팝업이 아니라 그 자리에 폈다.** 둘 중 하나를 고르는 중이라 계속
  보여야 한다. 재설계 확인은 팝업인데, 그쪽은 **한 번 묻고 사라지는 것**이라 성격이 다르다.

**검증** — `npm test` **282건**(성장·되접기·재설계 회귀 **29건** 추가) ·
`smoke:meta`가 레벨업 두 걸음 · 증분 미리보기 · **재설계 후 카드가 정확히 돌아오고
그것으로 같은 레벨까지 다시 올라가는 것** · **v1 저장분을 실제로 되접는 것**까지 걷는다.
마지막 것은 되돌려 보고 잡히는 것을 확인했다.

> **`power.test.ts`는 안 깨졌다.** 인수인계 노트의 예상과 달랐다 — 그 테스트는
> `RosterEntry` 모양을 직접 만들어 `OfficerInstance`를 지나지 않는다. 끊길 수 있었던
> 경로는 `toRosterEntries` 하나뿐이었고, 그래서 「v1과 v2가 같은 전투력을 낸다」를
> 회귀로 따로 박았다 — 안 깨진 것이 우연이면 안 된다.

**밟은 지뢰 넷** ★ — **C1·C2·E가 같은 자리를 지난다**

- **단위 테스트는 「그 함수가 실제로 불리는가」를 모른다.** `migrateProfile()`을
  조목조목 검증해도 `loadProfile()`이 그걸 부르는지는 아무도 안 본다 — 옛
  「버전이 다르면 버린다」 한 줄이 되살아나도 `npm test`는 조용히 통과한다.
  스모크가 **v1 저장분을 실제로 넣고 새로고침**한다(되돌려 보고 잡히는 것을 확인했다).
- **되접기만 하고 저장을 안 하면 옛 형식이 디스크에 남는다.** 동작은 멀쩡하지만
  (멱등이라 접속마다 다시 되접힌다) **손상 복구가 굳지 않고** v1 → v3 경로를
  언제까지고 살려 둬야 한다. 지금은 원문과 다르면 그 자리에서 저장한다.
- **상태가 셋인 화면을 `A ? … : …`로 접었다.** 레벨업 화면에 「재설계 — Lv2 고르는 중
  (1/0)」이 떠 있었다. **700px 스크린샷을 찍고서야 봤다** — 타입도 테스트도 조용하다.

  걸었더니 되접기가 이미 school로 정규화해서 걸릴 입력이 없었고, **처음 쓴 테스트가
  틀린 기대**였다. 그물은 남기되 주석에 「지금은 안 걸린다」를 명시했다.
  → **교훈: 방어를 넣었으면 그것이 발동하는 입력을 만들어 본다. 안 만들어지면
  그건 방어가 아니라 가정이고, 가정은 주석에 적어야 한다.**

#### 문을 하나로 — [출정하기] → 30초 온라인 탐색 → 없으면 AI (§5-32) ★

**기획자 확정 2026-08-18.** 지금 병영에는 「AI 대전」과 「온라인 대전」 문이 각각 있는데,
**[출정하기] 하나로 합친다.**

```
[출정하기] → 「상대를 찾는 중…」(최대 30초)
                ├ 온라인 상대를 찾았다  → 「찾았습니다!」 + 상대 부대 표 + [전투준비]
                └ 30초 안에 못 찾았다   → AI 상대를 **내 전투력에 맞춰** 생성 → 같은 화면
```

- **바뀌는 것은 상대가 사람인지 AI인지뿐이고, 나머지 틀은 전부 같다** — 그래서 C1이
  보상·전적을 이미 같게 만들어 뒀다(§5-30·31). F는 **문만** 합치면 된다
- **AI 상대도 전투력으로 뽑는다** — 온라인 매칭이 `MATCH_BAND`로 고르는 것과 같은 눈금이라야
  「상대가 바뀐 것뿐」이 성립한다. `makeAiPicks`를 등급 점수에서 전투력 기준으로 개편한다
- 30초는 **기획자 지정**이다. 대기 화면에 남은 시간을 보여 줄지는 F에서 정한다
- ⚠ **거절(「다시 찾기」) 프로세스는 온라인에만 있다**(§5-15). AI로 넘어간 뒤에는 거절할
  상대가 없다 — 문이 하나가 되어도 **이 경계는 남는다.** 화면이 지금 어느 쪽인지 알아야 한다

#### 그 밖에

- **「AI 연습 대전」 → 「AI 대전」으로 개칭**(§5-8). 설명문의 「전적 기록을 하지 않습니다」는
  **버린다** — 2026-08-18에 뒤집혔다(§5-31). 지금 문구는 「보상과 전적은 온라인 대전과
  똑같다. 전적에는 [AI]로 남는다.」이고 C1이 이미 갈아 뒀다
- **AI 갈래는 완성한다** — 「대전 상대를 생성중입니다..」 → 전투력 기준 `makeAiPicks` →
  「찾았습니다!」 + 상대 부대 표 + [전투준비]

#### 온라인 매칭의 군량 프로세스 (§5-15·§5-16) ★

「다시 찾기」는 **매칭 거절 패널티**다. 취지는 **거절당하는 쪽을 지키는 것** —
상대가 계속 거절만 당하지 않도록 **거절하는 쪽**이 군량 **−1**을 낸다.

> 45쪽 목업 글자는 **「다시 찾기 (군량 3소모)」**이지만 **−1로 확정됐다.** 화면 문구는
> **「다시 찾기 (군량 1소모)」**로 적는다. 목업과 갈리는 자리라 여기 남긴다.

**참가비는 여전히 기물 수만큼이다** — `grainCost(mode)` = 3v3 **3** · 5v5 **5**
([`roster.ts`](../packages/meta/src/roster.ts)). 거절 −1은 **그 위에 얹히는 별도 지출**이라,
거절하려면 참가비를 남겨 둔 채로 낼 수 있어야 한다. 그래서 경계가 이렇게 갈린다.

| 잔여 군량 | 출전 | 거절 |
|---|---|---|
| `< cost` | ✕ 불가 | — |
| `= cost` (3v3 **3** · 5v5 **5**) | ○ | **✕ 불가 — 매칭된 상대와 반드시 싸운다** |
| `> cost` | ○ | ○ (거절할 때마다 −1) |

**군량 체크는 「상대를 찾는 화면」으로 넘어가기 전에 한다.** 딱 최소면 안내문을 먼저 띄우고
**[확인]을 받은 뒤에** 매칭을 시작한다 — 들어간 뒤에 「거절이 안 된다」를 알면 늦다.

```
「대전을 위한 최소군량만 있을 때는 상대 매칭 시 거절을 할 수 없습니다.」
                                                        [확인] [취소]
```

- **거절을 반복하면 바닥에 닿는다.** `−1`씩 줄다 `cost`에 이르면 그때부터 거절할 수 없으니,
  **매칭 화면 안에서도 [다시 찾기]가 사라져야 한다** — 진입 전 안내문만으로는 못 막는 자리다
- **AI 대전에는 이 프로세스 전체가 없다.** 상대를 「생성」하는 것이라 거절당하는 상대가 없다.
  AI는 예전처럼 `grain >= cost`만 본다
- 매칭은 서버가 붙어야 진짜로 돌므로, F는 **버튼·안내문·군량 차감까지** 만들고
  「다시 찾기가 실제로 다른 상대를 물어 온다」는 **Colyseus 세션**이 잇는다

**출전 군량은 [전투준비]에서 낸다.** 지금은 편성 화면의 「출전」에서 내지만
(`spendGrain`), 위 표가 **참가비를 내기 전의 잔여 군량**을 기준으로 갈리므로
차감 시점이 매칭 뒤로 옮겨진다. 매칭만 하고 안 싸웠는데 참가비를 떼면 거절 −1과
이중으로 물리기도 한다.

> **판정은 `@samchess/meta`에 둔다** — `canDeclineMatch(profile, mode)` ·
> `MATCH_DECLINE_GRAIN = 1`. 화면이 `grain > cost`를 다시 적으면 참가비가 바뀌었을 때
> 조용히 어긋난다. 「화면이 미리 보여 주는 숫자는 엔진이 낸다」와 같은 결이다.

> **이 순서의 근거는 2026-08-04에 순서를 뒤집었던 것과 같다** — 서버가 반드시 검증해야 할 것
> (부대·전투력·매칭 기준)을 오프라인에서 굳혀 두면 프로토콜을 두 번 손대지 않는다.

**완료 조건** — 세 갈래가 각각 옳은 다음 화면으로 가는가 · AI 상대가 **내 부대와 가까운

## 4. 열린 질문 ★ 답이 나오면 §5로 옮긴다

> **지금 막혀 있는 세션은 없다.** 4-1·4-2는 D에서, 4-4는 C1에서 닫혔다.
> **4-5는 질문이 아니라 「C1이 알면서 남긴 할 일」**이다 — 다음 세션이 훑고 가면 된다.

### ~~4-1. 전투력 표시 자릿수~~ — **닫힘 (D)**

42쪽의 `000`은 자릿수 힌트가 아니라 **아무 뜻 없는 예시**였다(기획자 확인). 그래서
자릿수에 눈금을 맞추지 않고 **눈금의 뜻**에 맞췄다 — `POWER_SCALE = 100`, 「격차 100 =
예상 승률 73%」. 결과는 **세 자리에서 네 자리**(3v3 209~1304 · 5v5 253~1302)이고,
화면은 `1,211 점`으로 찍는다. → §5-21

### ~~4-2. 카드 보상 격차 보정의 구간·상한~~ — **닫힘 (기획자 확정)**

**구간을 두지 않는다.** 예상 승률로 카드 등급을 나누면 악성 유저끼리 짜고 큰 이변을
만들어 좋은 카드를 한 계정에 몰아줄 수 있다. **상한은 B급.** 예상 승률은 **보상이 아니라
기록**으로 쓴다. → §5-22 · C1

### ~~4-4. 예상 승률을 랭킹 정렬 기준으로 쓸지~~ — **닫힘 (C1)**

**쓰지 않는다.** 「전적에 표시」와 「랭킹에 반영」을 가른다 — 정렬 기준이 되면 두 계정이
짜고 큰 이변을 만들어 1위를 살 수 있다. 카드가 안 걸려 피해는 작지만 가르는 값이 0이다.
→ §5-33 · GDD §7

### 4-3. AI 대전에 부상이 걸리면 — **G2에서**

§5-8로 AI 대전에도 부상·회복이 걸린다. 지금 오프라인 사이클은 전부 AI 대전이라
**연달아 돌려 보기가 제약된다** — 개발용 통로가 하나 필요해질 것이다.
