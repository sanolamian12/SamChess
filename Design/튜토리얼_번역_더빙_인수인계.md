# 튜토리얼 문구 번역 · 더빙 — 새 세션 인수인계 (2026-11-11)

S급 튜토리얼 30판 플레이테스트는 2026-11-11에 끝났다. 그 세션의 기록은 `history/2026-11-11_S급튜토리얼_플레이테스트_세션정리.md`에 있다.

남은 일은 둘이고 **이 순서로** 한다.

1. **번역** — 튜토리얼 문구(`tut.*`)를 아홉 언어로 옮긴다.
2. **더빙** — 튜토리얼 대사를 Gemini TTS로 받는다. 대사 번역이 있어야 하므로 번역 뒤에 한다. 다만 KR 더빙은 번역이 필요 없어 먼저 시작할 수 있다(§2-4).

판의 내용(배치 · 대본 · 수치)은 끝난 것이다. 번역 · 더빙 세션은 **판 파일을 고치지 않는다.** 대사를 바꿔야 할 일이 생기면 기획자에게 먼저 묻는다.

  - 담을 때는 `git hash-object -w --no-filters <파일>` + `git update-index --cacheinfo 100644,<해시>,<파일>`.
  - `git diff --cached --stat`의 줄 수가 고친 양과 맞는지 본다.
- **dev 서버:** 워크트리에서 `npm run dev`(5173). `?tutorial=s-{장수id}`는 로그인 · API 없이 돈다.
- **화면 언어 바꾸기:** 게임 설정의 언어. 저장 열쇠는 `localStorage['samchess.lang']`(`en` · `ja` …).
  - 더빙 언어는 화면 언어를 따라간다(`DUB_FOR`, 더빙을 따로 고르는 단추는 없다).

## 1. 번역

### 1-1. 범위

**`ko.json`의 `tut.*` 598키(약 17,300자)를 아홉 언어로 옮긴다.**

| 묶음 | 키 | 무엇 |
|---|---|---|
| `tut.s.*` | 502 | S급 30판의 안내 · 대사(`say{n}`) · 끝맺음 · 판 소개 |
| `tut.b1` · `b2` · `b3` | 55 | 기본 세 판의 안내 |
| `tut.basic-1~3` | 12 | 기본 세 판의 제목 · 소개 |
| 나머지 | 29 | 공용 — `tut.goal.*` · `tut.lose.*` · `tut.intro.*` · 단추(`tut.next` · `tut.ok` …) · `tut.status.*` |

- **아홉 언어:** `en` · `es_419` · `it` · `ja` · `mn` · `pt_BR` · `pt_PT` · `zh_Hans` · `zh_Hant`.
- **지금 상태:** 아홉 언어 모두 `tut.*`가 **0키**다. 없는 키는 `t()`가 한국어로 물러나므로 지금은 다른 언어 화면에서도 한국어가 뜬다.
- **안 쓰는 키는 없다:** `tut.s.*` 중 판이 쓰지 않는 것은 `tut.s.sub` · `tut.s.open` 둘뿐이고 이 둘은 화면 공용이다. 모두 옮기면 된다.
- **새 키 하나:** 판에서만 쓰는 이름 `alias.*` 4키(`alias.jang-gan` · `alias.yellow-turban-a~c`)는 **이미 열 언어에 있다.**

### 1-2. 지킬 것

- **자리표시자** `{name}` · `{n}` · `{d}` · `{pct}`는 그대로 둔다.
  - 한국어 전용 조사 자리 `{j}` · `{o}`는 `tut.*`에 없다.
- **장수 이름은 데이터의 다국어 이름과 같게 적는다.**
  - 출처는 `packages/data/generated/officers.json`의 `nameI18n`이다. 화면의 카드 · 순서 판이 이 이름을 쓰므로 대사 속 이름이 다르면 어긋난다.
  - 대사의 화자 이름(패널 머리)은 코드가 `nameI18n`으로 그리고, 문구 안의 이름만 번역자가 맞춘다.
- **「기술명」도 데이터의 다국어 이름과 같게 적는다.**
  - 출처는 고유기술 · 책략 데이터의 `nameI18n`이다.
  - 한국어 문구의 「」 62줄은 대부분 기술명이다.
- **판 위 칸 이름(G5 · M13 …)과 단추 이름([이동] · [공격] · [대기])은 화면 글자와 같아야 한다.**
  - 단추 이름은 그 언어의 명령 판 문구(`cmd.*`)를 본다.
- **한 장은 짧게.**
  - 안내 판은 크기가 고정이고 3줄 칸이다. 한국어는 70자 상한이 걸려 있다(`client/test/tutorialStrings.test.ts`).
  - 키릴(몽골어)은 글자가 넓어 잘 넘친다(컬렉션 번역 때 몽골어만 7개가 잘렸다).
- **역사 표기는 그 언어의 관습을 따른다.** 예: 위수 = Wei River / 渭水. 기획자가 고른 사실(「관중을 가로질러 황하로 드는 큰 강」 등)은 바꾸지 않는다.

### 1-3. 검사 — 먼저 만들 것

지금 있는 검사는 한국어만 본다. 번역을 넣기 전에 아래 셋을 붙이면 번역이 옳게 들어갔는지 기계가 판정해 준다.

1. **열 언어 키 검사.**
   - `client/test/battleStrings.test.ts`의 `BATTLE` 목록처럼 「열 언어에 `tut.*` 키가 다 있는가」와 자리표시자가 같은가를 본다.
   - `tutorialStrings.test.ts`에 더하는 것이 자연스럽다.
2. **`tools/tutorial_lines.ts`에 언어 인자.**
   - 지금은 한국어만 실제 판 폭에서 접어 본다.
   - `localStorage['samchess.lang']`을 심고 돌리게 하면 언어마다 3줄 넘침을 잡는다.
3. **`tools/tutorial_ux.ts`를 다른 언어 화면으로 한 판 이상.**
   - 컬렉션 때처럼 그 언어로 찍은 화면을 본다 — 「번역의 끝은 키 개수가 아니라 그 언어로 찍은 화면이다」(CLAUDE.md).

### 1-4. 나누는 법 (제안)

598키를 한 번에 넣기보다 **판 묶음 단위**로 넣고, 기획자가 한두 언어(en · ja)로 한 판씩 눈으로 확인한다.

- 기본 세 판 + 공용 키부터 넣는다. 처음 들어오는 사람이 보는 화면이라서다.
- 그다음 S급 30판을 묶어 넣는다.

## 2. 더빙

### 2-1. 지금 있는 것 — 아직 git에 없다

10-30에 준비한 도구 · 대본이 **본 폴더 `SamChess`의 작업 트리에 커밋 안 된 채** 있다. 다른 세션은 「담지도 지우지도 않는다」로 두고 있다(HANDOFF).

| 파일 | 무엇 |
|---|---|
| `tools/tutorial_dub_script.ts` | 판 파일 + 문구에서 대본을 뽑는다 → `lines.json` · `대본.md` · `cast.json` 뼈대 |
| `tools/tutorial_dub_generate.py` | Gemini TTS 호출(`gemini-3.8-flash-tts`) · 프롬프트 · 자르기 · 다시 받을 화자 찾기 |
| `Design/튜토리얼더빙/README.md` | 방법 · 범위 · 순서 — **먼저 읽는다** |
| `Design/튜토리얼더빙/cast.json` | 화자 → 목소리 · 프로필(영어). 62명 모두 **비어 있다** — 사람이 채운다 |
| `Design/튜토리얼더빙/lines.json` · `대본.md` | 10-30에 뽑은 대본 — **낡았다**(아래) |

**첫 일 — 워크트리로 옮겨 커밋한다.**

1. 위 여섯 파일을 워크트리의 같은 자리로 복사해 커밋 · push한다.
2. 곧바로 본 폴더의 커밋 안 된 사본을 지운다.
   - 남겨 두면 본 폴더가 main을 당길 때 「untracked working tree files would be overwritten」으로 막힌다.
   - 지우기 전에 복사본과 같은지 `diff`로 본다.
3. 본 폴더 세션의 HANDOFF 줄(§7 「이 세션이 손대지 않는 것」)도 「더빙 파일은 main에 들어갔다」로 고친다.

### 2-2. 대본 뽑기 도구 고칠 것 (11-11에 확인)

11-11의 대사로 다시 뽑아 보면 `판 30 · 대사 138줄 · 화자 62명`이 나온다. 10-30 대비 새 줄 22 · 바뀐 줄 22 · 없어진 줄 8이다. 다만 이 수에는 아래 문제가 섞여 있다.

- **안내 장(`GuideNote` — `{note, focus}`)을 대사로 센다.**
  - 제갈량 판에 글 없는 줄이 하나 생긴다(「KR 번역 없음 1」의 정체).
  - 도구의 `isSay`가 「문자열이 아니면 대사」로 재기 때문이다. meta의 `isSay()`를 쓴다.
- **대사를 빠뜨린다.**
  - 도구는 `guide`의 단계 · `outro`만 훑는다. 차례 뒤 안내(`GuideTurn.after`) · 끝 장면(`finale.steps[].lines`) · 판을 여는 안내(`opening`)의 대사가 빠진다.
  - 문구 파일의 대사 키는 **152개**인데 도구가 뽑는 것은 137개다(주유 say5 · 6 · 7 · 10 · 11 등).
  - meta의 `stageLines(stage)`가 판의 모든 줄을 낸다 — 그것으로 바꾸고 **판에서 나오는 차례**인지 확인한다(`before` · `after` 앞뒤 문장이 그 차례에 기댄다).
- **이 판에서만 다른 이름(`alias`).**
  - 주유 판의 장간은 데이터상 `chae-jung`이라 화자 이름이 「채중」으로 나온다.
  - 화자 이름은 `stage.alias`가 있으면 그 문구(`alias.jang-gan`)로 적는다.
  - 목소리 열쇠를 채중과 따로 둘지(장간은 다른 인물)는 기획자에게 묻는다.
- **S급 차례 · 고유기술 음성(KR)**은 아직 안 뽑는다 — README의 범위표대로 더한다.

### 2-3. 범위 (2026-10-30 기획자 결정 — README 「정해 둔 것」)

| 음성 | 언어 | 대사 글 |
|---|---|---|
| 튜토리얼 대사 `tut.s.*.say*` | KR · EN · JP · PT · CA 다섯 | 문구 파일 — PT는 `pt_BR`, CA는 `zh_Hans` 글을 만다린으로 |
| S급 고유기술 시전 | KR만 새로 | 기존 KR 음원에서 받아 적는다 |

- S급 장수는 KR에서 셋(차례 · 고유기술 · 튜토리얼)을 한 프롬프트에 몰아 같은 목소리로 받는다.

### 2-4. 순서

1. §2-1 옮기기 → §2-2 도구 고치기 → 대본 다시 뽑기.
2. `cast.json` 채우기 — 목소리 · 프로필. 기획자와 함께 고른다. 같은 판의 두 화자가 같은 목소리면 도구가 경고한다.
3. **KR 먼저.**
   - KR은 번역이 필요 없어 번역 세션과 따로 시작할 수 있다.
   - 화자 한 명(`--only`)으로 들어 본 뒤 전부 받는다.
4. 번역 세션이 대사(`say*`)를 en · ja · pt_BR · zh_Hans로 넣으면 다시 뽑아 「번역 없음 0」을 보고 나머지 넷을 받는다.
5. 맞추기는 음원이 들어온 뒤에 한다.
   - `tools/build_audio.py`에 `sync_tutvoice`를 더해 `public/tutvoice/{판}.say{n}.{더빙}.mp3`로 옮긴다.
   - 대사 패널(`TutorialBattleScreen.tsx`)이 그 장을 띄울 때 `currentDubLang()`으로 틀고 넘기면 끊는다.
   - 파일이 없으면 조용히 넘어간다. `stewardVoice.ts`와 같은 결이다.

**준비물:** `pip install google-genai`, PowerShell `$env:GEMINI_API_KEY="…"`(키는 기획자가 넣는다). 음원은 `assets/`라 git 밖이다.
