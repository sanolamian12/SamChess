# 2026-09-02 — 레벨업 도장 그림 교체 · 레벨업 액자 철회 · 장수 카드 액션 애니메이션 · 등급순 기본 정렬

> 현재 상태는 [`HANDOFF.md`](../HANDOFF.md)에, 사양은 [`Design/GDD.md`](../Design/GDD.md)에
> 있다. 이 문서는 **왜 그렇게 정했고 무엇을 확인했는가**만 적는다.

## 1. 요청

앞 세션([`2026-09-02_궁궐_장수일람_레벨업패널_레벨업연출.md`](2026-09-02_궁궐_장수일람_레벨업패널_레벨업연출.md))에서
만든 장수 일람 화면을 이어서 다듬어 달라는 요청 — 레벨업 도장 그림 교체, 그 도장을
넣으며 같이 붙었던 줄 전체 금색 액자 제거, 카드 개수 강조색 진하게, 장수 정보
패널의 정적 그림을 움직이는 것으로, 마지막으로 장수 일람 기본 정렬 변경까지
다섯 가지 마이너 수정이 이어졌다.

## 2. 레벨업 도장 — `stamp.png` → `stamp2.png`

사용자가 `assets/icons/stamp2.png`(3프레임, 빨간 쉐브론 도장)를 새로 만들어 왔다.
`tools/build_ui.py`의 `SPRITES` 딕셔너리 키만 `"stamp"` → `"stamp2"`로 바꾸고
`--force`로 다시 구웠다 — 출력 id(`levelup-stamp`)는 그대로라 `style.css`의
`.ofc-levelup-seal`은 안 건드렸다. 두 원본의 종횡비가 둘 다 ~3:1(3162×1052,
2306×760)이라 `build_sprite()`의 3프레임 가정이 그대로 맞았다.

## 3. 레벨업 액자 철회

레벨업 대상 줄을 두르던 금색 액자(`levelup-frame.png`, 앞 세션에서 네 번 갈아
넣은 그 그림)를 **다시 걷어냈다** — 이름 옆 도장 애니메이션 하나만으로 신호가
충분하다는 판단. `.scr-officers .ofc-row[data-levelup="1"]::before` 규칙과 그
`position: relative` 짝을 통째로 지웠다. `data-levelup` 속성 자체(`OfficerListScreen.tsx`)는
스모크 훅으로 남겨 뒀다 — CSS만 걷어내고 화면 쪽 마킹은 그대로 둔 것.

## 4. 레벨업 준비 완료 색 — 더 진하게

장수 정보 패널의 [레벨/스킬 관리] 버튼에서 카드 개수가 파란색으로 강조되는
`.btn .sub.levelup-ready` 색을 `#5b9bf0`(옅은 하늘색) → `#1a56c9`(진한 파랑)로.

## 5. 장수 정보 패널 — 정적 초상화 → 전투 액션 시트 애니메이션

카드를 클릭했을 때 뜨는 장수 정보 패널의 왼쪽 그림이 그동안 정지된 보드 타일
초상화(`portraits/{id}.png`, `primary="portrait"`)였다. 이미 전투 연출용으로
구워져 있던 5칸 액션 시트(`public/actions/{id}.png`, `tools/build_action_sheets.py`
산출물 — 대기·이동·공격·책략·피격)를 재사용해 **가만히 서 있지 않고 움직이는
캐릭터**로 바꿨다.

- `ui/art.ts`에 `actionSheetUrl()`·`ACTION_FRAME_COUNT` 추가.
- `OfficerArt.tsx`에 `OfficerActionArt` 컴포넌트 신설. CSS 스프라이트 기법
  (`background-size: 500% 100%` + 퍼센트 `background-position`, 좌우반전은
  `transform: scaleX(-1)`)으로 5칸 × 반전 = 열 가지 자세를 낸다.
  시트가 없는 장수는(비주류·미배포) `Image()` 프로브가 로드 실패를 잡아
  기존 `OfficerArt`(초상화 우선)로 조용히 물러난다.
- `RankingCommon.tsx`의 장수 카드에서 `OfficerArt primary="portrait"`를
  `OfficerActionArt`로 교체.
- CSS: `.ofcard-art.ofc-action-art { aspect-ratio: 1/1; background-repeat: no-repeat; }` —
  `<div>`라 `object-fit`이 안 먹으니 시트 칸의 실제 모양(정사각)을 `aspect-ratio`로
  대신 맞췄다.

**타이밍 — 두 번 조정.** 처음엔 1~3초마다 무작위 자세로 계속 갈아 끼우는
단순한 형태였다가, "대기로 시작해서 3초, 그 뒤 동작 하나를 1~2초, 다시 대기로
돌아와 3초, 반복"이라는 구체적 박자 요청을 받아 상태 기계로 다시 짰다 —
`STAND`(0번 칸, 좌우반전 없음 — 반전까지 무작위면 "돌아왔다"는 기준이 안 선다)
와 `randomAction()`(1~4번 칸 + 무작위 반전)을 `standing` 플래그로 번갈아
스케줄하는 재귀 `setTimeout`.

**크기 변화 — 사용자 질문에 답하며 실측.** 애니메이션 전환 후 캐릭터가 작아
보인다는 지적에, 왼쪽 칸 폭 비율(`flex: 3 1 0`)은 그대로 두고 종횡비만
초상화(96:120, 세로가 긴)에서 시트(1:1, 정사각)로 바뀐 결과임을 확인했다.
추가로 "일부만 유독 낮아 보인다"는 재질문에 실측으로 답했다:
- 초상화(`build_portraits.py`)는 440×540 원본을 **정규화 없이 그대로** 96×120로
  축소한다 — 캐릭터가 캔버스를 채우는 비율이 그림마다 다르다(알파 경계상자
  실측: 세로 채움 79%~100%, 표준편차 3.6%).
- 액션 시트(`build_action_sheets.py`)는 몸통 높이를 항상 칸의 90%로 정규화한다
  (실측: 91%~99%, 표준편차 1.4% — 훨씬 균일).

그 결과 초상화에서 이미 캔버스를 꽉 채우던 장수(여포·장비·방덕·마등·유도 등,
채움비 97~100%)는 새 정사각 프레임과 겹쳐 체감 키가 20~25% 줄어 보이고, 초상화에
여백이 넉넉했던 장수(호진·송비·주유·능통·여범 등, 채움비 79~83%)는 거의 안
줄어(~3%) 보인다 — 애니메이션 코드의 결함이 아니라 **두 에셋 파이프라인이
원래부터 서로 다른 정규화 기준으로 만들어졌던 것**이 새로 노출된 것이었다.
사용자는 액션 시트 쪽(더 균일한 쪽)을 그대로 쓰기로 하고 칸 비율은 안 건드리기로
결정 — 추가 변경 없음.

Playwright로 실제 로그인 화면까지는 확인했지만(계정 생성이 실제 Supabase
연동을 요구해 여기서 막힘), CSS 스프라이트 계산 자체는 실제 `actions/gwan-hae.png`를
정적 HTML에 얹어 별도로 검증했다 — 프레임 0·2·반전된 4가 각각 이웃 프레임
번짐 없이 정확히 잘리는 것을 스크린샷으로 확인.

## 6. 장수 일람 기본 정렬 — 가나다순 → 등급순

`OfficerListScreen`의 `useState<OfficerSort>('name')`를 `'grade'`로. 정렬 함수
자체(`GRADE_RANK` 기반, 동점이면 가나다)는 앞 세션에 이미 있어 상태 초깃값
한 줄만 바꿨다.

## 7. 검증

- `npm run typecheck` 매 단계 통과(`exactOptionalPropertyTypes`가 `OfficerArt`
  물러나기 경로의 `className` 타입을 한 번 걸러냈다 — `className ?? 'art'`로 수정).
- Playwright로 CSS 스프라이트 크롭·반전 수식을 실제 자산에 대해 별도 검증.
- 초상화 vs 액션 시트 채움 비율 실측(Python, 알파 경계상자)로 "일부만 작아
  보인다"는 사용자 관찰이 실제 데이터로 뒷받침됨을 확인.

## 8. 곁가지

- `packages/client/public/icons/`·`packages/client/public/actions/`는 `.gitignore`
  대상이다(에셋 방침 그대로) — 이번에 커밋되는 것은 `tools/build_ui.py`의 교체
  로직과 `packages/client/src/` 아래 소스뿐, 구운 결과 이미지 자체는 로컬에만
  있다.
- 마지막 등급순 정렬 변경 전, "장수 정보 패널 그림 비율을 넓혀서 예전 크기에
  가깝게 키울까"라는 후속 확인 질문을 던졌으나 사용자가 "지금 그대로 두자"로
  결정 — 별도 변경 없음(이 문서 §5 끝 문단).
