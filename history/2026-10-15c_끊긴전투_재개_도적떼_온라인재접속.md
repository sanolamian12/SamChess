# 끊긴 전투 이어 하기 — 도적떼 재개 · 온라인 재접속 (2026-10-15)

기획자가 농지 전투 도중 브라우저를 끄고 다시 들어오자 메인에 「도적과 싸우는 중 · [항복]」만 남아 **항복밖에 할 수 없었다.**
전투 종류마다 「끊긴 판을 어떻게 되살리나」를 함께 정리하고 권장안 셋을 그대로 정했다. 도적떼는 `raid-resume`,
온라인은 그 위의 `online-reconnect` 브랜치에서 하고 main에 `--ff-only`로 합쳤다.

## 1. 확정한 것 (기획자)

| 전투 | 끊겼을 때 | 근거 |
|---|---|---|
| 사람 vs 사람 | **Colyseus 재접속 열쇠를 기기에 저장 → 다시 붙는다** | 판정 주체가 서버라 판 상태는 필요 없다. 서버는 이미 60초를 기다리고 있었고 **클라이언트에 돌아오는 길이 없었다** |
| 도적떼 | **둔 수를 서버에 덧붙여 두고 → [전투 재개]로 그 자리에서** | 브라우저에 두면 되돌리기(저장해 두고 다른 수로 다시 두기)가 열린다. 서버가 덧붙이기만 받으면 막힌다 |
| AI 대전 | 이번엔 안 한다 — 같은 장치(도적떼)를 그대로 쓸 수 있다 | |
| 튜토리얼 | 필요 없다 | |
| 앱 배포 | 재개와 무관 — 배포를 정할 때 판단(Capacitor 등) | 기기 저장소는 브라우저에도 있다. 앱은 보존을 안정시킬 뿐 신뢰는 못 준다 |

부하 — 도적떼는 내 차례마다 작은 요청 하나(수 하나, 응답은 저장된 길이 `{have}`만). 사람 vs 사람은 이미 매 수를 서버가 실시간으로 처리하므로 더 가볍다.

## 2. 도적떼 재개

- **엔진** `replayPrefix()` — `replayLocalMatch()`와 **같은 루프**(`drive()`)이고 의도가 떨어지면 다음 사람 차례에서 멈춘다.
- **meta** `raid.battle.intents`(서버 소유) · `appendRaidIntents(profile, from, intents)` — 이어지는 자리(`from` = 저장된 길이)만, 겹치는 앞부분은
  글자까지 같을 때만(다시 보낸 요청), 덧붙인 뒤 **재생이 되는 수만**. `startsWithRaidIntents()` — 정산은 덧붙여 둔 수로 시작하는 기록만.
  `raidAbandonRemainingMs()` · `raidAbandoned()`. `migrateProfile()`이 `intents`를 담는다.
- **서버** `POST /raid/intents` `{from, intents}` → `{have}`. `/raid/result`는 저장된 수로 시작하지 않으면 409(상태는 안 바꾼다 — 정직한 클라는 재개하면 된다).
- **클라** `RaidIntentUploader`(한 번에 하나, 앞 요청이 끝나면 쌓인 것을 한꺼번에 — 계정 저장 큐와 같은 규칙. 판을 막지 않는다) ·
  `LocalTransport`의 `intentLog`(앞부분) · `onIntent`. `RaidBattleScreen`이 저장된 수를 `resumeRaidState()`로 재생해 띄운다
  (마지막 수가 판을 끝냈으면 곧장 정산). 메인 · 농지의 단추는 **[전투 재개]**(남은 시간 = 시작 + 60분), 옛 [항복]은 걷었다(항복은 판 안에서).
  App의 `fightRaid`가 상태를 보고 시작 / 재개를 가르고, 재개는 계정을 다시 읽고 들어간다.
- **버그** — 끊긴 판이 60분을 넘겨 서버가 항복으로 정산하면 **아무 알림도 없었다**(알림 조건이 「응전 마감」만 봤다). 「전투가 끊긴 채 끝났다」를 띄운다.
- GDD §5.11 「전투 중에 끊기면」 개정.

## 3. 온라인 재접속

- `OnlineTransport` — `reconnectionToken` · `onDrop()`(우리가 닫지 않았는데 방을 떠났다). **판의 끝을 실은 통 뒤의 이탈은 끊김이 아니다**(`over`) —
  서버가 성립하지 않은 판을 접으며 끊는 것을 재접속으로 읽으면 결과 화면 위에서 다시 붙으려 한다.
- `reconnectBattle(token, side)` — `client.reconnect()` 뒤 **리스너를 걸고 `resync`를 보낸다.** 서버(`BattleRoom`)는 `resync`를 「돌아왔다」(`joined`)와 같이 처리해
  스냅샷 한 통을 보낸다.
- `meta/onlineResume.ts` — 방에 붙는 순간 열쇠 · 진영 · 상대 · 부대 · 모드 · 시드 · `aliveAt`을 기기에 적는다. 판 도중 5초마다 `aliveAt`을 민다. 결과로 가면 지운다.
- App — 들어올 때(저장 세션 · 로그인) 표가 있고 같은 계정이며 `aliveAt`이 60초 안이면 「끊긴 대전에 다시 붙는 중…」 → 같은 자리로. 판 도중 끊기면(`onDrop`) 같은 길.
  못 붙으면 표를 지우고 「대전에 돌아가지 못했다 — 서버가 판정한 결과가 반영됐다」 + 계정을 다시 읽는다.

## 4. 밟은 것

- **재접속 스냅샷이 리스너보다 먼저 왔다** — 서버는 돌아온 사람에게 곧장 스냅샷을 보내는데, 그 통이 클라의 `reconnect()` 약속이 풀리기 **전에**
  같은 소켓 묶음으로 도착해 「onMessage() not registered for type 'sync'」로 버려졌다(`smoke:online`이 잡았다). 붙기 전에는 리스너를 걸 방이 없어
  **걸고 나서 다시 청하는**(`resync`) 길밖에 없다. CLAUDE.md의 「리스너를 거는 시점」이 세 번째로 나왔다.
- **「표가 남았다」는 타이밍이었다** — 결과 화면은 서버의 보상 통보를 몇 초 기다린 뒤에 넘어간다. 검사를 「결과로 넘어가면 지워지는가」(최대 20초)로 고쳤다.
- 가리개(「다시 붙는 중」)는 로컬에서 너무 빨리 지나가 화면에서는 못 봤다 — `look:online`은 「봤는지」만 적고 판정은 「같은 판으로 돌아왔나」로 한다.

## 5. 검사

- `npm test` **892 pass**(884 → 엔진 `replayPrefix` 1 · meta 덧붙이기 7). 「되접어도 `intents`가 남는가」는 migrate에서 빼면 떨어지는 것을 확인했다.
- `npm run smoke:raid` 완주 — 한 수 → 새로고침 → [전투 재개] → **같은 시각 · 같은 난수 자리 · 같은 배치** → 항복 정산 / 끊긴 채 60분 → 알림 · [전투 재개] 없음.
- `npm run smoke:online` 완주 — 판 도중 소켓을 끊음 → `onDrop` → 열쇠로 다시 붙음 → 끝까지(다시 붙은 쪽 로그 = 상대 로그의 꼬리).
- `npm run look:online` 완주 — 브라우저 둘 · 진짜 대기열, A가 판 도중 새로고침 → 같은 판 · 같은 진영 → 결과로 가면 표가 지워진다.
- `npm run smoke:ui` 통과 · `npm run smoke:meta` 통과.

## 6. 아직 안 된 것

- **AI 대전 재개** — 도적떼와 같은 장치를 붙이면 된다(서버에 판 시작을 기록하는 자리가 아직 없다 — AI 대전은 시드를 클라가 정한다. 붙이려면 시작을 서버가 굳히는 단계부터).
- 온라인 재접속 유예는 60초 그대로다 — 모바일에서 앱 전환이 길면 못 돌아온다. 늘리려면 `TIMING_INVARIANTS`(유예 ≤ 제어 20초 × 넘기기 3번)를 함께 본다.
- 재접속한 쪽의 대화창(시스템 메시지)은 다시 붙은 때부터다(스냅샷에 로그가 없다 — 설계대로).
- 대기열 단계(매칭 확인 중)에서 끊긴 것은 다루지 않는다 — 참가비 전이라 잃는 것이 없다.
