# 2026-08-17 — 장수 일람 · 상세 (PPT 37·38)

> 이 문서는 **왜 그렇게 정했고 어디서 넘어졌는지**를 적는다.
> 현재 상태의 정본은 [`HANDOFF.md`](../HANDOFF.md), 구현 기준은 [`Design/GDD.md`](../Design/GDD.md) §8.2,

## 1. 무엇을 했나

PPT **37·38쪽**. 궁궐 안에 **장수 일람 → 상세 → 고유기술 팝업**을 세웠다.
트랙 `A → D → B → C1 → C2 → E → F`의 **A**다.

**룰 엔진도 그림·소리 파이프라인도 건드리지 않았다.** 메타의 조회 함수와 화면뿐이다.

| | 붙은 것 | 파일 |
|---|---|---|
| 1 | 궁궐 두 갈래 — **[장수 일람] [도시 관리]**(잠김) | `screens/PlaceScreen.tsx` |
| 2 | **일람** — 표 6열 · 검색 · 정렬 4종 · 레벨업 Flag · 요약 줄 | `screens/OfficerListScreen.tsx` **(새 파일)** |
| 3 | **상세** — 정보 · 서사 자리 · 세 갈래 | `screens/OfficerDetailScreen.tsx` **(새 파일)** |

| 5 | **레벨/스킬 관리** — 옛 화면을 그대로 옮김 | `screens/LevelUpScreen.tsx` **(새 파일)** |
| 6 | 줄 만들기·검색·정렬·요약·**AT 범위** (순수 함수) | `meta/src/officers.ts` **(새 파일)** |

옛 `screens/OfficerScreen.tsx`는 **지웠다** — 넷으로 갈라졌다.

## 2. 이 세션에서 정해진 것

- **[E]는 개수가 아니라 있고 없음(`Y/N`)** — 헌제 한 명뿐이라 세는 것이 뜻이 없다 (GDD §4.1).
  38쪽 목업의 `[E]: Y/N`이 그대로 옳았다.
- **능력치 정렬의 동점은 가나다로 갈린다** — 무력 45가 8명이다. 안 정하면 같은 목록을
  두 번 그릴 때 순서가 흔들린다.
- **자리만 만든 것의 처리가 두 갈래다** (아래 §3).
- **[레벨/스킬 관리]는 잠그지 않는다** — 원안을 뒤집었다 (아래 §3).
- **레벨업 카드 표는 엑셀이 맞다** — GDD §4.3이 낡아 있었다 (아래 §3).

## 3. 왜 그렇게 만들었나

### 화면은 고르기만 하고 정렬도 판정도 하지 않는다 ★

줄 만들기·검색·정렬·요약·AT 범위를 전부 `packages/meta/src/officers.ts`에 뒀다.
화면(`OfficerListScreen`)이 하는 일은 **어느 함수를 부를지 고르는 것**뿐이다.

두 가지가 이유다.

- **「레벨업 Flag」는 규칙이다.** 화면이 `카드 >= 필요분`을 다시 적으면 규칙이 바뀌었을 때
  **배지만** 조용히 어긋난다. `canLevelUp()`을 그대로 부른다 — 전투 UI가 `validate()`에
  묻는 것, 편성이 `validateRoster()`에 묻는 것과 같은 결이다.
- **정렬은 눈으로 확인할 수 없다.** 「가나다순」이 진짜 한국어 사전 순인지, 동점에서
  순서가 흔들리지 않는지는 스크린샷으로 알 수 없다. 순수 함수로 떼면 테스트가 고정한다 —
  `screens/backdrop.ts`를 화면에서 떼어 낸 것과 같은 이유다.

### `AT`는 언제나 범위다

38·39쪽이 `AT: 2-4`라고 적어 둔 것은 장식이 아니다. 데미지가 **매 타격마다 따로 내림**
(`floor(AT × 배수)`)이라 `AT 2.5`는 평타 2 · 크리티컬 5다 — **홀수 번째 AT 선택은
크리티컬일 때만 값을 한다**(GDD §4.2). 단일 숫자로 적으면 「찍었는데 왜 그대로지」가 된다.

계산은 `FORMULA.damage`를 반드시 지난다(`atRange()`). 전투 화면은 이미 `attackRange()`에
묻고 있는데 그쪽은 `BattleState`를 요구해 **편성 밖에서는 쓸 수 없다** — 그래서 meta에
같은 공식을 **부르는** 함수를 뒀다. 공식을 옮겨 적지 않은 것이 핵심이다.

### 자리만 만든 것은 두 갈래로 나뉜다 ★

이번 화면에는 「나중에 채운다」가 넷이다. **처리가 갈린다.**

| | 무엇 | 처리 | 왜 |
|---|---|---|---|
| **글** | 인물 서사 · 기술 유래 (G1) | **줄째로 사라진다** | 「인물 소개: (없음)」은 데이터가 빠진 것인지 원래 없는 것인지 구별이 안 된다 |
| **단추** | [전적 보기] (C1) · [도시 관리] (C2) | **눌리지 않게 두고 왜인지 적는다** | 눌리는데 아무 일도 없으면 「고장인가」가 남는다 |

글 쪽은 `assets/`가 없으면 건너뛰는 규약, 단추 쪽은 환경설정의 `ID 기억`·`화면 모드`를
잠가 둔 처리와 각각 같다. **둘을 섞으면 안 된다** — 빈 줄을 남기거나 죽은 단추를 열면
둘 다 「고장」으로 읽힌다.

> 타입에는 `OfficerData.story?` · `UniqueSkillData.origin?`를 열어 뒀지만 **추출기는
> 건드리지 않았다.** 엑셀에 열이 더해지면(G1) 값이 채워지고 **화면은 손대지 않는다.**
> 이름만 잡아 두는 것과 다르다 — 배경 넷째 칸(`extra`)에서 「이름을 지어 붙이면 그게
> 뜻인 것처럼 굳는다」를 겪었는데, 여기는 **쓸 자리와 뜻이 목업에 이미 적혀 있다.**

### [레벨/스킬 관리]를 잠그지 않았다 — 원안을 뒤집었다 ★

작업계획 §3-A의 원안은 「[레벨/스킬 관리] [전적 보기]는 **B·C1에서 열림**」이었다.
그대로 하면 **지금 유일한 성장 통로가 끊긴다.**

- AI 대전은 카드를 주지 않는다(2026-08-04 확정). 성장을 시험할 길이 장수 관리 화면의
  개발용 지급 하나뿐이다.
- 그 화면으로 가는 문을 잠그면 **오프라인 사이클이 A와 B 사이에서 멈추고**,
  `smoke:meta`의 레벨업 검사도 죽는다 — 회귀 그물에 구멍이 난 채로 D·B를 지나게 된다.

그래서 옛 레벨업 UI를 `LevelUpScreen.tsx`로 **그대로 옮겨** 물려 뒀다. B(39쪽)가
증분 미리보기·재설계 마법사와 함께 통째로 갈아 끼운다. [전적 보기]는 원안대로 잠갔다 —
기물별·모드별 전적은 **데이터 자체가 아직 없다**(C1이 만든다).

> **판단 기준은 「데이터가 있는가」였다.** 레벨업은 규칙도 화면도 이미 있고 모양만
> 낡았다. 전적은 모델이 없다. 앞의 것을 잠그는 건 손해뿐이고, 뒤의 것을 여는 건 거짓말이다.

### GDD §4.3이 엑셀과 달랐다

작업 전 대조에서 걸렸다.

| Lv | 6 | 7 | 8 | 9 | 누적 |
|---|---|---|---|---|---|
| GDD §4.3 | 15 | 20 | 25 | 30 | 116 |
| 엑셀 · `growth.json` | **12** | **15** | **22** | **25** | **100** |

**엑셀이 맞다**는 기획자 확인을 받아 GDD를 데이터에 맞췄다(§4.3 · §12 파급 두 곳).
코드는 처음부터 `growth.json`을 읽고 있었으므로 **동작은 바뀌지 않았다** — 사람이 읽는
문서만 낡아 있었다.

> **이런 어긋남은 실행해도 안 잡힌다.** 데이터의 단일 출처는 엑셀 → `npm run extract`이고
> GDD는 따라 적는 곳인데, 그 「따라 적기」에 자동 대조가 없다. 초상화·연출 이미지·시각
> 효과는 추출기가 대조해 빌드를 막지만 **GDD 본문은 사람이 읽어야 안다.**

### 「AT +1」이 화면에만 남아 있었다

레벨업 선택지가 `'AT +1'`로 손으로 적혀 있었다. AT 성장은 2026-08-12에 **0.5로 내렸고**
(GDD §4.2 · §12), 데이터도 엔진도 0.5인데 **글자만 낡았다.** 지금은 `GROWTH.statChoices`에서
읽는다 — 단일 출처는 `tools/extract_data.py`의 `statChoices`다.

## 4. 밟은 지뢰 ★ — 셋 다 CSS라 오류가 안 나고 화면을 봐야 알았다

### 접두사를 붙여도 같은 파일 안에서 겹친다

「전역 CSS에 흔한 이름을 새로 쓰지 않는다」를 지켜 `.ofc-` 접두사를 붙였는데,
그 안에서 **`.ofc-head`를 두 번 썼다.**

```
.ofc-head   표 머리   → display: grid   (일람의 열 맞추기)
.ofc-head   상세 머리 → display: flex   (그림 + 능력치)
```

나중 규칙이 이겨 한쪽이 조용히 무너진다. `.ofc-thead` / `.ofc-bio`로 갈랐다.

> **교훈: 「흔한 이름을 쓰지 않는다」는 전역만의 규칙이 아니다.** `head`·`row`·`bio`는
> 접두사 뒤에서도 흔하다.

### 기존 규칙이 선택자 하나 더 많아 새 규칙을 이겼다

요약 줄이 **한 줄이 아니라 세 줄로 쌓였다.**

```
.scr .foot   { flex-direction: column }   ← 선택자 둘 (0,2,0)
.ofc-tally   { flex-direction: row    }   ← 선택자 하나 (0,1,0)  ✗ 진다
```

`.scr .foot.ofc-tally`로 올려 고쳤다. 상세의 카드 줄도 같은 자리였다.

> 스크린샷을 보고서야 알았다 — 「보유 카드」 / 「0 / 3장」 / 「레벨업 가능」이 세 줄로
> 세로로 쌓여 있었다.

### 팝업이 화면 한가운데가 아니라 내용 맨 아래에 붙었다 ★

가장 값진 것. 배경 위에 놓는 화면 둘이 **자식 전부**에 `position: relative`를 건다.

```css
.scr-bg  > * { position: relative; z-index: 2; }   /* 어둠 위로 올린다 */
.scr-dim > * { position: relative; }
```

`.modal-back`도 그 자식이라 `position: absolute`가 덮이고, `inset: 0`이 무시되어
**흐름대로 맨 아래에 붙는다.** 어둠막이 화면을 덮지도 않는다.

**환경설정 팝업(`SettingsModal`)도 원래 그랬다.** 2026-08-15에 붙인 뒤로 계속.
`smoke:meta`가 「떠 있는가」와 「언어가 다섯인가」만 보고 있어서 **못 잡았다.**

```css
/* 팝업은 그 규칙에서 뺀다 — 선택자가 한 칸 더 세야 이긴다 */
.scr-bg > .modal-back, .scr-dim > .modal-back { position: absolute; }
```

> **교훈: 「있는가」와 「제자리에 있는가」는 다른 검사다.** 커맨드 패널에서 이미 밟았다 —
> 「`dataset`만 보고 자리는 맞다고 판단해 한참 헤맸다. `getBoundingClientRect()`를 재야
> 한다」(2026-08-12). 그때 배운 것을 팝업에는 적용하지 않고 있었다.

## 5. 구조

```
meta/src/officers.ts        규칙 — 줄 · 검색 · 정렬 · 등급 요약 · AT 범위
   ↑ 부르기만 한다                (순수 함수. FORMULA.damage를 경유한다)
screens/OfficerListScreen   표 · 검색칸 · 정렬 단추 · 요약 줄
   ↓ onOpen(officer)
screens/OfficerDetailScreen 정보 · 서사 자리 · [일람으로][레벨/스킬 관리][전적 보기]
   ├→ SkillModal            배너 · 효과 · 유래 자리
   └→ LevelUpScreen         ← B(39쪽)가 통째로 갈아 끼운다
```

**「지금 어느 장수를 보고 있는가」는 화면 상태가 든다** (`App.tsx`의 `Screen` 유니온).
프로필에 넣으면 저장 형식이 화면 사정에 끌려간다 — 그러면 B·C1이 올릴 버전 둘 말고도
이유 없는 버전이 하나 더 생긴다.

## 6. 확인

```
npm run extract    → 검증 통과
npm run typecheck  → exit 0
npm test           → 231/231   (장수 일람 13건 추가)
npm run smoke:meta → 통과 — 궁궐→일람→정렬→검색→상세→팝업→레벨업→복귀→저장
npm run smoke:ui   → 통과 — 22개 (팝업 CSS 수정이 전투 화면을 안 건드리는지)
```

새 테스트 13건. **눈으로 못 보는 것만** 골랐다.

| 확인 | 왜 |
|---|---|
| 가나다순이 사전 순인가 | 「정렬됐다」는 스크린샷으로 구별이 안 된다 |
| 동점이면 가나다로 갈리는가 (무력 45 셋) | 안 정하면 순서가 흔들린다 |
| 레벨업 Flag가 3장에서 켜지는가 (2장은 안 켜짐) | 경계 하나 차이 |
| `[E]`가 개수가 아니라 `Y/N`인가 | 헌제를 넣어 봐야 안다 |
| `AT 2 → 2-4`, `2.5 → 2-5`, `3 → 3-6` | 매 타격 내림의 귀결 |
| 데이터에 없는 장수 id를 버리는가 | 이름이 바뀌면(장요→장료) 옛 저장분이 그렇다 |

스모크는 **전부 `data-*`로 걸었다** — `data-screen` · `data-sort` · `data-field` ·
`data-levelup` · `data-tally` · `data-modal`. 열 이름과 정렬 이름은 다국어로 바뀐다.

> **레벨업 Flag는 「켜지는 것」까지 본다.** 개발용 카드 지급을 **두 번** 누른다 —
> 한 번(5장)이면 Lv1→Lv2에 3장을 쓰고 2장만 남아 Flag가 다시 꺼져서, 「꺼져 있다」만
> 확인하게 된다. 10장이면 7장이 남아 Lv2→Lv3(5장)이 서므로 켜지는 쪽을 볼 수 있다.

눈으로도 봤다 — **프레임 700px**에서 궁궐·일람·상세·기술 팝업·레벨업 다섯 장.
요약 줄이 세 줄로 쌓인 것과 팝업이 아래에 붙은 것을 그때 잡았다.
