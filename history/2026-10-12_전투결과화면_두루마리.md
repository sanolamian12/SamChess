# 전투 결과 화면 — 결말별 배경 · 두루마리 장 넘기기 (2026-10-12)

대전 결과 화면(`ResultScreen.tsx`)이 화풍 없는 첫 모양(제목 · 보상 줄 · 단추가 세로로 놓인 `.scr`) 그대로였다.
결말마다 다른 배경 위에 두루마리 하나를 펼치고 **장을 넘겨 읽는** 화면으로 다시 잡았다. 작업 브랜치 `result-screen-design`.

## 1. 기획자 확정

| 물음 | 확정 |
|---|---|
| 배경 | **같은 전장 4칸** — 승리(맑은 아침) · 무승부(흐린 황혼) · 패배(비) · 성립 안 함(새벽 안개). 시간대는 안 탄다 |
| 시안 세 안 | **B(두루마리 전황보)** — A(전공 장부) · C(양 진영 대조) 기각 |
| 두루마리 | 승리 = 황금 · 무승부와 성립 안 함 = 비취 · 패배 = 낡은 것(Gemini Pro, 기획자가 받아 옴) |
| 넘기기 | 누르거나 **5초**. 무승부 택1은 고를 때까지 기다린다 |
| 나가는 단추 | **마지막 장에서만** — 택1 중에 나가 보상을 놓치는 길을 닫는다 |
| 지난 장 다시 보기 | 없음(5초면 충분) |
| 낙관(勝 · 和 · 敗) | **뺀다** — 한자를 읽는 사람만 알아본다 |
| 전과의 장수 그림 | 초상화가 아니라 **꼬마 캐릭터**(판 위의 그 그림) |

## 2. 그림

- **배경** `assets/Backgrounds/battleResults.jpg`(2752×1536, 4칸) → `build_backgrounds.py`의 `STRIPS`에
  `"battleResults": ("result", RESULTS)` → `public/backgrounds/result-{win,draw,lose,void}.jpg`. 칸 경계를 확대해 옆 칸이
  딸려 오지 않은 것을 봤다. 가운데(높이 30~75%)가 비어 있어 두루마리가 그 자리에 선다.
- **두루마리** `assets/icons/battle_end_{win,draw,lose}.jpg`(검은 바탕 JPG) → `build_ui.py`의 `FRAMES` + `FRAME_BLACK_BG`
  → `public/ui/result-scroll-{win,draw,lose}.png`(960px, 바탕을 걷은 PNG).
- 프롬프트는 이 세션에서 기존 배경(open · each · ext · buildings)을 보고 썼다 — 같은 수채화풍, 가운데를 비운 구도, 16:9 4칸.

## 3. 화면

- `ScreenChrome` + `resultBackdrop()`(새 경로 함수). 장은 **결말 → 보상 → 전과**, 성립하지 않은 판은 **결말 → 환불** 두 장이다
  (승/무/패 제목 · 보상 · 승률 · 전과가 안 뜬다 — 「무승부를 당했다」로 읽히지 않게).
- **펼침은 한 그림을 세 겹으로** — 종이는 `clip-path`로 가운데에서 열리고, 같은 그림을 축 기둥만 남게 자른 두 겹이 가운데에서
  끝으로 미끄러진다. 세 그림 모두 축이 끝에서 12% 안쪽이라 **12.5% 하나**로 잡았다(CSS 주석에 「셋은 한 값」).
  종이는 붓질 질감이라 세로로 늘리지 않고 **비율을 고정**해 장마다 내용을 맞췄다.
- 글자는 격언 두루마리와 같은 마스크로 쓸어 입히고(`brs-wipe-in`) 쓸어 지운다(`brs-wipe-out`) — 키프레임 이름이 갈려 있어 다시 돈다.
- **보상** — 카드는 장터 · 도적떼 결과와 같은 `.mkt-card` 액자, 뽑기와 같은 `mkt-rise` · 후광(`Halo`, S · A · E).
- **전과** — 꼬마 장수(`OfficerActionArt`, 동작 시트)가 줄지어 서고 머리 위에 **[공격] 아이콘 + 격파 수**, 퇴각한 장수는
  정지 그림 흑백에 「퇴각」. 부대 이름(AI는 「AI」) · 예상 승률(`winChance`).
- 결과 화면에 **판의 기록(`record: BattleOutcome`)을 늘 넘긴다** — 전에는 무승부의 `pending`에만 있었다. 표시 전용이고
  보상의 정본은 그대로 서버다. 격파 · 퇴각은 엔진의 `countKills` · `countFallen`(서버 재생과 같은 함수).
- 「부상」이 아니라 **「퇴각」**이라 적는다 — 실제 부상은 방패 아이템(`fallenAfterShield`)을 거친 뒤라 다를 수 있다.

## 4. 밟은 것

- **전과 장이 종이를 넘쳤다**(5v5 · 3v3 둘 다) — 「퇴각」 표지를 한 줄로 두면 넘친다. 그림 발치에 겹쳤다.
  처음엔 겹치는 자리를 줄 전체 높이(%)로 잡아 **표지가 이름을 가렸다** — 그림을 감싼 `.brs-fig` 바닥으로 옮겼다.
- **격파를 글자로 적으면 몽골어 · 스페인어에서 다섯 칸이 서로 겹쳤다**(「0 бут цохив」 · 「3 derrotados」) — 아이콘 + 숫자로,
  문구는 `title` · `aria-label`로 남겼다.
- **몽골어 제목 「Ялагдал」이 종이를 넘쳤다** — 붓글씨 서체에 키릴이 없어 넓은 세리프로 물러난다. `titleSize()`가
  글자 폭(한글 · 한자 · 가나 1em, 나머지 0.65em)으로 크기를 줄인다.
- 마지막 장에서 단추가 흐름에 서면 **두루마리가 위로 밀렸다** — 단추를 바닥에 겹쳐 띄웠다.
- 움직임 줄이기에서 `.brs-roll`만 끄면 `.brs-roll.l`(두 클래스)이 이겨 축이 계속 움직인다 — 두 칸 세기로 적었다.
- **Windows Python의 텍스트 쓰기가 `ResultScreen.tsx`를 CRLF로 바꿨다**(CLAUDE.md 그 함정) — git 경고로 알아채고 LF로 되돌렸다.
  JSON 열 개는 줄마다 제 줄 끝을 쥐고 고쳤고 CRLF 줄 수가 **더한 줄 수만큼만** 늘었다.

## 5. 문구

`result.*`가 다른 언어에 21개 중 4개만 있었다(나머지는 한국어로 물러나 있었다). **열 개 언어를 다 채우고**
`battleStrings.test.ts`의 검사 목록에 `result.`를 보탰다. 새 키 7개(`noCard` · `squadNone` · `ai` · `vs` · `kills` · `fallen` · `tap`),
안 쓰게 된 `result.card` · `result.pickNote`는 지웠다(타입 검사가 정본).

## 6. 검사

- `npm run typecheck` 통과 · `npm test` **832 / 832**.
- `npm run smoke:meta` **완주** — 결과 화면을 장마다 넘기며 읽는다(보상 장의 군량 · 카드 등급, 전과 장의 장수 셋 · 예상 승률),
  **마지막 장 전에 [도시로]가 없어야** 하고 마지막 장에는 있어야 한다. 단추를 늘 띄우게 깨 본 화면에서 그 검사가 잡는 것을 봤다.
  첫 실행은 결과 화면 앞의 온라인 매칭 「다시 찾기」 검사(「거절했는데 같은 상대다」)에서 떨어졌고 다시 돌리자 통과했다 — 이번 변경과 무관해 보인다.
- 눈 확인은 실제 컴포넌트를 esbuild로 묶은 시험 페이지(스크래치패드, 커밋 안 함)로 700px에서 했다 —
  승(카드 2 · S 1장) · 무(고르기 전 · 군량 고른 뒤 카드 0) · 패 · 성립 안 함, 3v3 · 5v5, 열 개 언어 중 여섯, 펼침 프레임, 움직임 줄이기.

## 7. 남은 것

- **실제 흐름의 눈 확인** — AI 대전 [항복]으로 브라우저에서 직접, `npm run look:online`으로 온라인 결과 화면.
  스모크는 흐름을 지났지만 사진은 시험 페이지 것이다.
- 무승부 택1 · 성립 안 함은 스모크가 지나지 않는다(무승부는 실측 0.02%, 성립 안 함은 온라인 이탈) — 시험 페이지로만 봤다.
- 판 위에서 전투가 끝나는 순간 → 결과 화면 사이의 연출(이번 범위 밖).
- 펼침 900ms의 첫 순간(축이 가운데 붙어 있는 모습)이 빨리 지나간다 — 실제 화면에서 보고 늘릴지 정한다.
