# 컬렉션 — 전투 효과 · 배지 · 발동 띠 (2026-10-14 b)

같은 날 앞 세션(`2026-10-14_대자보종이_죽간상세_컬렉션다국어_농지결과.md`)이 넘긴 ① 전투 효과 + 배지를 했다.
완성한 컬렉션의 능력치 · 고유기술 SP −1 · 진영 SP +1이 판에 실리고, 장수 카드에 배지 둘, 전투가 시작될 때 발동 띠가 뜬다.
`collection-battle` 브랜치에서 하고 main에 `--ff-only`로 합쳤다.

## 3. 밟은 것

- **온라인 판에는 부상 · 태학 개량이 한 번도 안 실렸다.** `MatchScreen`이 전투력을 재려고 만든 명단(`toRosterEntries(profile, picks)` — 시각 없음)을
  그대로 대기열에 보냈고, 서버는 그 명단으로 판을 만든다. AI 대전은 `BattleScreen`이 판 시작 시각으로 따로 만들어서 멀쩡했다.
  컬렉션 효과를 같은 규약(「시각을 줘야 실린다」)으로 붙이다 드러났다 — 기획자가 A안(셋 다 싣는다)을 골랐다. CLAUDE.md에 적었다.
- **`skill.spCost`를 읽는 자리가 엔진 넷 · 화면 셋이었다** — 하나로 모았다(`uniqueSkillCost`). 고유기술 팝업(`SkillModal` · `skillPanel`)은
  기술 자체의 설명이라 데이터 값 그대로 두었다.
- **발동 띠가 판을 통째로 덮었다** — 데모가 117개를 다 완성한 것으로 치자 양쪽 합 16줄. 세 줄 + 「외 N개」로 접었다.
- 그림 원본 자리 — 의뢰서 ②가 `assets/Collections/ui/`라고 적었지만 실제 등록 칸 그림은 `assets/icons/`에 있고 `build_ui.py`도 거기서 읽는다. ⑤는 `assets/icons/`로 적었다.

## 4. 검사

- `npm run typecheck` 통과 · `npm test` **871 pass**(860 → `rules/bonus.test.ts` 7 · `meta/collection.test.ts` 4)
  - 조건 셋(with · min · vs) 켜짐/꺼짐 · 능력치 여섯 + WT · SP 비용이 검사 · 단추 · 적용에서 같은 값 · 다른 기술을 가리키면 안 먹음 · 진영 SP 둘 켜져도 1 · 부상과 겹침
  - `completedAt` 경계(같은 시각 포함 · 1ms 앞 제외) · 시각 없으면 안 실림 · `battlePower` 그대로 · 도시 효과는 판에 안 감 · 계정 → 판 통째로
- `npm run smoke:ui` 완주 — 새 두 단계(배지 = 엔진 `bonuses` · SP 칸 = 데이터 − 1 · 진영 SP 1 · 상대 카드 · 띠 줄 수 · 띠 동안 판 정지).
  발동 배지를 일부러 빼고 돌려 **그 단계에서 떨어지는 것을 확인**했다.
- 700px 스크린샷으로 카드 · 툴팁 · 띠를 봤다(CSS 임시 표지).

## 5. 아직 안 된 것

1. **그림 셋** — 의뢰서 ⑤. 받으면 `assets/icons/`에 넣고 `npm run ui`, 카드 크기(26px · 22px)에서 다시 본다.
2. **② 도시 효과 + 대자보 순위** — 앞 세션 §7 프롬프트 ② 그대로.
3. 온라인 명단은 여전히 **클라이언트가 주장하는 값**이다(서버가 계정에서 다시 만들지 않는다) — 컬렉션 효과도 그 공백 위에 얹혔다. 원래 있던 공백이다.
4. 발동 띠는 온라인 두 탭으로는 아직 안 봤다(재생기 경계는 같다 — `prep → battle` 한 번).
