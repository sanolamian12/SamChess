## 1. 무엇을 했나

H1이 「누가 상태를 만드는가」를 이음매 하나로 모아 뒀다. H2a는 **그 저편에 진짜 서버를
세웠다.** 계약(`BattleTransport` · `ServerMsg`)은 **한 글자도 안 바꿨다.**

```
H1   [Playback] ──▶ [BattleTransport] ──▶ LocalTransport ──▶ 룰 엔진 (같은 프로세스)
H2a  [Playback] ──▶ [BattleTransport] ──▶ OnlineTransport ──ws──▶ [BattleRoom] ──▶ room-logic
                                                                     (얇은 껍데기)   (순수)
```

## 2. 왜 순수 층과 껍데기를 갈랐나 ★

여기서 굳는 규칙은 전부 **기다려야 일어나는** 것들이다 — 배치 30초 · 정찰 30초 ·
제어 20초 · 넘기기 3번 · 재접속 유예 60초 · 유휴 2분 · 이탈 표 네 줄.
사람 손으로 확인하려면 탭 둘을 띄우고 분 단위로 세야 하고, **그러면 아무도 다시 안 본다.**

`step(room, event, nowMs)`가 시각을 인자로 받으므로 가짜 시계로 한 판을 통째로 민다.
되접기를 `@samchess/meta`에 둔 것(§5-28)과 같은 이유이고, 실제로 **회귀 24건이
브라우저 없이** 표 네 줄을 전부 돈다.

껍데기(`BattleRoom`)가 하는 일은 넷뿐이다 — 자리 배정 · 사건을 `step()`으로 넘기기 ·
`out`을 진영별로 뿌리기 · 250ms마다 시계 한 번 보기.

## 3. 여기서 굳은 계약 다섯 ★

### ① 전선의 `phase`는 **받는 사람의 걸음**이다 — `waiting`이 사는 자리

`waiting`(「나는 준비를 마쳤고 상대를 기다린다」)은 **한쪽만의 사실**이라 공유 상태의
`phase`에 넣을 수 없다 — 넣으면 아직 배치 중인 상대가 판을 못 만진다. 그렇다고 안 넣으면
`BattlePhase`에 적혀 있는 값이 **아무도 만들지 않는 값**으로 남는다(실제로 그랬다:
`Playback`의 `case 'waiting'`은 H1 내내 한 번도 안 돌았다 — §5-52의 그 함정이 이미 하나
심겨 있었던 것이다).

권위 상태는 `deploy` 그대로 두고 **떼면서 관점을 넣었다.**

```ts
toWire(state, side)   // ready[side] && phase === 'deploy'  →  phase: 'waiting'
```

떼는 자리는 여전히 하나이고, `BattlePhase` 하나가 재생기의 걸음 하나로 곧게 떨어진다.
마감도 자연히 갈린다 — 배치 중이면 `DEPLOY_MS` 잔여, 준비를 마쳤으면 `WAITING_MS` 잔여.
**오프라인에서는 여전히 한 번도 안 나타난다**(사람이 언제나 마지막에 누른다).

### ② 20초를 재는 자리가 **화면에 하나 더 있었다**

`controlModal.ts`가 `FORCE_SKIP_AFTER_MS = 20_000`을 두고 `performance.now()`로 스스로
재고 있었다. H1이 「상수가 두 벌이면 어긋나도 화면은 아무 말도 안 한다」로 `timing.ts`를
만들었는데, **재는 시계까지 두 개인 자리가 남아 있었다.**

지금은 제어 단계에도 `deadlineInMs`를 싣고 화면은 그것만 읽는다 — `ServerMsg`에 필드를
더하지 않았다(마감을 나르는 통로가 이미 있었다). 오프라인은 `null` 그대로라 동작이 안 바뀐다.

### ③ 성립하지 않은 판은 **엔진의 결말이 아니다**

배치 중 이탈 · 양쪽 이탈 · 양쪽 유휴는 전적도 보상도 없고 **환불만** 있다.
서버가 마지막 통에 `close: RoomClose`를 실어 보내고, 받는 쪽은 `applyBattleResult`를
**아예 안 부른다.** 결과 화면은 재사용하되 승/무/패 제목도 보상 칸도 예상 승률도 안 띄운다 —
띄우면 「무승부를 당했다」로 읽히고, 그건 §5-68이 **일부러 안 준 것**이다.

**정찰 이후 이탈만은 여기 안 온다** — 서버가 사라진 쪽 대신 `{t:'surrender'}`를 적용하면
평범한 결말이 나오고 보상표가 그대로 걸린다. 엔진에 새 규칙이 없다.

### ④ 배치 프리셋은 **서버가 깐다**

예전에는 `BattleScreen`이 깔았다. 그러면 북군(P2)의 프리셋이 「내가 언제나 남군」인
오프라인에서 **한 번도 안 돈다.** 판정이 서버로 오면서 자리도 함께 왔고, 이제 진짜로
두 사람의 프리셋이 각각 깔린다. 어긋나면 여전히 **아무 말 없이 안 깐다**(§5-45).

### ⑤ 시간 셋의 **관계**가 규칙이다

```
WAITING_MS === RECONNECT_GRACE_MS              같은 기다림을 잰다
RECONNECT_GRACE_MS <= CONTROL_MS * SKIP_TO_WIN 돌아온 사람은 3번에 닿기 전에 도착한다
ROOM_IDLE_MS > RECONNECT_GRACE_MS              돌아오는 중인 사람이 먼저 잘리지 않는다
```

셋 중 하나만 고치면 **화면은 아무 말도 하지 않는다.** `timing.ts`의
`TIMING_INVARIANTS`가 관계를 적고 회귀가 고정한다.

## 4. 밟은 지뢰 여섯 ★

### ① Colyseus 0.17 서버 + 0.16 클라이언트는 **말이 안 통한다**

`npm install colyseus`가 준 것은 서버 **0.17.10**인데 `colyseus.js`의 최신은 **0.16.22**다
(0.17용 JS 클라이언트가 아직 없다). 붙여 보니 `consumeSeatReservation`에서
`Cannot read properties of undefined (reading 'name')` — **좌석 예약의 모양이 바뀌었다.**

버전을 맞추려니 다음 벽이 셋 더 있었다.

| 시도 | 무엇이 막았나 |
|---|---|
| `colyseus@0.16.5` | 배포된 `package.json`에 **`workspace:^`**가 남아 있어 `npm install`이 죽는다 |
| `colyseus@0.16.4` | ESM 진입점이 **redis 드라이버·인증까지 전부 import**해서 안 쓰는 것을 설치 안 하면 부팅이 안 된다 |
| `@colyseus/core@0.16.25` | 역시 `"@colyseus/greeting-banner": "workspace:^"` |

**정답은 메타 패키지를 안 쓰는 것**이었다 — `@colyseus/core@0.16.22` +
`@colyseus/ws-transport@0.16.5`. 「방·전송·재접속만 쓴다」(§5-54)는 결정이
**의존성에서도 그대로** 서고, 안 쓰는 것이 부팅을 막을 일이 없다.

> **교훈: 버전 짝은 회귀가 못 잡는다.** 타입 검사도 단위 테스트도 통과하는데
> 소켓에서만 죽는다. `smoke:online`이 **진짜 서버를 띄워** 그 자리를 지킨다 —
> 이 스모크가 처음 한 일이 정확히 이 벽을 찾아 준 것이다.

### ② 첫 통을 **안 흘려 줬다** — 화면이 아무것도 안 그렸다

`connectBattle()`이 `opened` 메시지로 첫 스냅샷을 받아 `initial`을 만들고 끝냈다.
그런데 `Playback`은 `initial`로 시작하되 **`onChange`가 한 번은 와야** 화면이 자기를
맞춘다(마감도 그 통에 실려 온다). `LocalTransport`는 `open()`에서 첫 통을 내보내는데
`OnlineTransport`는 안 내보냈다 — 스모크가 「첫 통이 안 왔다」로 잡았다.

지금은 그 통을 큐에 넣어 뒀다가 `open()`에서 흘린다. **같은 계약을 채운다는 것은
메서드 이름이 같다는 뜻이 아니다.**

### ③ 화면을 떠날 때 **방금 넘긴 방을 닫았다**

`MatchScreen`이 사라질 때 붙어 있던 방을 닫도록 했는데, [전투준비]로 **전투 화면에 넘긴
방**까지 닫힌다 — 전투가 시작되자마자 상대에게 「사라진 사람」이 된다. `handed` 플래그
하나로 갈랐다.

> 반대로 **안 닫으면** [뒤로 가기]를 누른 것뿐인데 상대가 재접속 유예 60초를 기다린다.
> 양쪽 다 조용히 틀리는 종류라 「누가 방을 소유하는가」를 코드에 적어 뒀다.

### ④ 서버가 **자기 자신을 import하면 뜬다**

`packages/server/src/index.ts`가 `server.listen()`까지 하고 있었다. 스모크가
`BattleRoom`만 빌리려고 import하는 순간 **포트를 잡는다.** 배럴(`index.ts`)과
부팅(`main.ts`)을 갈랐다.

### ⑤ 두 탭은 `localStorage`가 같아 **계정이 하나**다

예고돼 있던 지뢰다. `?seat=2`가 저장 키에 접미사를 붙인다 — 그리고 **재접속용 키
(`deviceId`)도 함께 갈라야** 한다. 안 가르면 서버가 둘을 한 사람으로 보고 두 번째
접속을 **재접속으로 처리한다.** 「계정을 갈랐다」와 「사람을 갈랐다」는 다른 일이다.

### ⑥ 회귀가 **도달할 수 없는 상태**를 만들고 있었다 (두 번)

- 「먼저 3번 누른 쪽이 이긴다」를 처음엔 매 바퀴 `control(r).foe`로 눌렀다 — 제어권이
  오가므로 **누르는 사람이 바뀌어** 아무도 3에 못 닿는다. 고친 방법은 `presser`를
  고정하고 **제 차례에는 정상으로 두게** 하는 것이다. 그게 곧 「한쪽만 손을 놓은 판」의
  진짜 모양이라, 검사가 규칙을 더 정확히 적게 됐다.
- 「돌아오면 아무 일도 없다」를 `유예 × 3` 뒤에 확인했는데 그건 **유휴 상한(2분)을
  넘긴 시각**이라 방이 유휴로 접혔다. 시간 셋이 맞물려 있다는 것이 검사에서 먼저 드러났다.

## 5. 검사가 실패하는 상태를 만들어 봤다 (셋)

| 무엇을 깼나 | 잡혔나 |
|---|---|
| 배치 마감의 자동 준비를 **끊긴 쪽에도** 걸었다 | 회귀 **3건** 실패 (이탈 표 첫 줄이 통째로 죽는다) |
| `toWire`의 관점 한 줄을 지웠다 | 회귀 1건 + `smoke:online` 실패 |

## 6. 무엇을 안 했나 (H2b)

**대기열이 없다.** 지금 사람을 만나는 길은 개발용 통로 `?match=room` 하나이고, 방 이름을
고정해 탭 둘이 만난다. H2b가 가져갈 것:

- `queue-logic.ts` + 대기열 방 — `MATCH_BAND`로 짝짓기
- **거절은 두 사람의 사건**(§5-63) — −1 · 대기열로 · 그 사람과 다시 안 붙는다
- **참가비를 「방이 열린 순간」에**(§5-60) — [전투준비] 뒤에 「상대를 기다리는 중」 한 걸음
- `?match=online` 흉내 제거 (그때 「다시 찾기」가 진짜로 돈다)

**서버는 아직 참가비·거절 군량을 검증하지 않는다**(§5-61 · H3). 계정이 브라우저에 있어
전투만 서버로 보내도 결과를 지어내면 그만이다 — **둘은 같은 세션에서만 뜻이 있다.**
아는 채로 두고 `room-logic.ts` 머리에 적어 뒀다.

## 7. 확인한 것

```
npm test          409/409 (380 → +24 room-logic · +3 넘기기 · +2 환불)
npm run typecheck exit 0
npm run smoke:ui   통과 (갱신 없이)
npm run smoke:meta 통과 (갱신 없이)
npm run smoke:online 통과 — 방 · 진영 · waiting · 마감 · 한 판 271턴 · 로그 동일성 · 이탈 유예
```

그리고 **브라우저 탭 둘**로 실제 한 바퀴를 돌려 봤다 — 계정 둘(`?seat=1|2`) → 부대 편성 →
[출정하기] → 서로를 찾음(`부대1` ↔ `부대2`) → [전투준비] → **진영이 갈려**(P1 / P2)
배치 단계. **북군(P2) 화면이 처음으로 떴다.**
