## 2. 바꾼 것은 원본 폴더 하나뿐이다

클라이언트는 이미 `portraits/{장수id}.png`를 보고 있었다
([`BattleScene.ts:93`](../packages/client/src/battle/BattleScene.ts#L93)). 이름도 크기도 그대로고
알파만 생겼으므로 **화면 코드는 한 줄도 손대지 않았다.**

파이프라인의 층이 이렇게 나뉘어 있던 덕이다.

```
assets/Chars-noback/{한글이름}.png      ← 원본 (git에 없다)
        ↓ build_portraits.py            ← 여기만 바꿨다
public/portraits/{로마자id}.png         ← 화면이 아는 유일한 이름
        ↓ BattleScene / art.ts
```

> 에셋 교체가 화면 코드를 건드리지 않고 끝났다. **원본 폴더명과 화면이 아는 경로 사이에
> 변환 층이 하나 있으면 이런 교체가 공짜가 된다.**

### 폴백 — 없는 장수만 원본에서

`TILE_SOURCES = (Chars-noback, Chars)` 순으로 찾는다. 배경 제거를 아직 안 돌린 신규 장수가
생겨도 빌드가 멈추지 않고, 대신 **어느 장수가 원본에서 왔는지 이름을 찍어 알린다.**

조용히 폴백하면 그 장수만 배경이 붙은 채로 판에 서 있게 되는데, 260장 중 1장이면 눈으로
찾기 어렵다. 지금은 260/260이 전부 `Chars-noback`이다.

## 3. 밟은 지뢰

### 3-1. 프리멀티플라이 — 맞는 걱정이었지만 이미 해결돼 있었다

440×540 → 96×120은 4.5배 축소라 한 픽셀이 20여 픽셀의 평균이 된다. **투명 픽셀의 RGB가
그 평균에 섞이면 실루엣 가장자리에 배경색이 번진다.** 원본에 실제로 지울 색이 남아 있다 —
확인해 보니 도구가 만든 255장은 알파 밑이 검정(0,0,0)이고, **손으로 만든 예제 5장은
양피지색(222,181,114)이 그대로 남아 있다.**

그래서 `RGBa`(알파를 곱해 둔 형식)를 거치도록 고쳤는데, **출력이 바이트 단위로 같았다.**
합성 이미지로 따로 재 보니 Pillow 12는 RGBA를 그냥 `resize`해도 투명 픽셀의 색을
섞지 않는다.

```python
a[:, :4] = [255, 255, 255, 255]   # 불투명 흰색
a[:, 4:] = [255,   0,   0,   0]   # alpha=0, 밑은 빨강
# naive · premul 둘 다 경계가 흰색으로 나온다 — 빨강이 번지지 않는다
```

`RGBa` 경유는 남겼다. 이 성질은 Pillow 버전에 딸린 것이고 원본에는 실제로 지울 색이 있다.
다만 **주석에 "이렇게 안 하면 번진다"고 적을 뻔했다** — 재 보지 않았으면 없는 문제를
해결했다고 문서에 남겼을 것이다.

> 고치기 전에 재고, **고친 뒤에도 재서 정말 달라졌는지 볼 것.** 전후 픽셀 차이가 0이면
> 그 수정은 (지금 환경에서는) 아무 일도 하지 않은 것이다.

### 3-2. 개명하면 `public/`에 찌꺼기가 남는다

`public/portraits/`에 `i-gwak.png`가 남아 있어 260명인데 파일이 261장이었다.
같은 세션 앞부분의 「이각」 개명으로 생긴 것이다 — id가 `i-gwak` → `i-gak`으로 바뀌었는데
**생성기는 대응 장수가 없는 출력을 알리기만 하고 지우지는 않는다.**

지웠다. 자동 삭제는 넣지 않았다 — 생성 스크립트가 말없이 파일을 지우는 쪽이 더 위험하다.
**장수 이름을 바꿨으면 `public/portraits/`의 옛 id를 지울 것.**

## 4. 검증 — 눈으로 봤다

수치로는 잡히지 않는 종류의 변경이라 두 가지로 확인했다.

**(a) 판 색 위에 합성해 3배 확대** — 알파가 들어간 그림은 배경에 따라 다르게 보인다.
중립(`0x23262c`) · P1 진영 녹색(`0x1e3a2f`) · P2 진영 적색(`0x3a1e24`) 셋 위에 올려 봤다.
테두리 잔상도 배경색 번짐도 없었다.

**(b) 실제 화면** — `npm run dev` 띄우고 `npm run shot -- --zoom 2`.
기본 줌은 셀이 30px대로 줄어 타일이 안 보이므로 `--zoom`이 필요하다. 콘솔 오류 없음.

**발밑 풀밭·자갈은 남아 있고, 그게 맞다.** `2026-08-07_장수_이미지_배경제거.md` §4-3에
기록돼 있다 — 예제 5건이 전부 풀밭을 남겨 뒀고, 그걸 지우는 「정련 패스」는 예제 IoU가
0.99 → 0.91로 떨어져 삭제했다. 배경이 아니라 캐릭터의 받침으로 다룬다.

## 5. 새 대화로 이어갈 때

- **타일 뒤에 불투명한 판을 깔지 말 것.** 알파가 살아 있어서 판이 그대로 비치는 게
  이번 변경의 전부다. 소속 색을 깔고 싶으면 반투명으로, 그리고 세 판 색 위에서 다시 볼 것.
  주의 문구는 `ui/art.ts` 맨 위에 있다.
- `assets/Chars/`는 **원본 보관용으로 남긴다.** 지우지 않는다 —
  `remove_char_background.py`의 입력이고, 배경 제거를 다시 돌릴 때 필요하다.
- 장수를 추가하면 `Chars`뿐 아니라 **`Chars-noback`에도 넣어야 한다.**
  안 넣으면 그 장수만 배경이 붙은 채로 나오고, `npm run portraits`가 이름을 찍어 알린다.
- 하단 패널·정보 팝업의 수묵화(`CharsInBattle`, 197/260명)는 이번 변경과 무관하다.
  없는 장수는 지금도 보드 타일 그림으로 대신한다(`setOfficerArt`).
