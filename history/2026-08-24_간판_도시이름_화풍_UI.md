# 2026-08-24 — 간판·도시 이름 짓기 화면에 화풍 UI를 입힌다

> 이 문서는 **한 대화 세션의 기록**이다. 프로젝트의 현재 상태와 규칙은
> [`HANDOFF.md`](../HANDOFF.md)와 [`Design/GDD.md`](../Design/GDD.md)가 정본이며,
> 여기는 "무엇을 왜 그렇게 정했는가"와 "어디서 넘어졌는가"를 남긴다.
>
> 같은 날 앞선 세 세션(트랙 9 가챠 로직·그림·장터 UI 1차 초안)과는 무관한
> 별도 작업이다. **트랙 9 밖 — HANDOFF §7 로드맵에 없던, 사용자가 이번
> 세션에서 새로 꺼낸 화면 디자인 작업**이다.

## 왜 이 작업인가

간판(로그인)·도시 이름 짓기 두 화면의 입력 필드·버튼이 CSS 색상만 입힌
민무늬 사각형이었다 — `assets/market/`·`assets/map/`엔 이미 손그림 채색 +
잉크선 윤곽의 삼국지 화풍이 잡혀 있는데(카드 액자·장터 간판 등) 이 두
화면만 거기서 비어 있었다. 사용자가 "이미지 생성 AI에게 위임할 프롬프트를
만들어 달라"고 요청했고, 받아 온 그림을 코드에 실제로 배선하는 것까지
이번 세션에서 이어졌다.

## 한 일 — 세 단계로 나뉜다

### 1단계 — 디자인 프롬프트 작성 (구현 없음)

`HANDOFF.md`·`TitleScreen.tsx`·`NewGameScreen.tsx`·`style.css`·
`assets/market/`·`assets/ui/`의 기존 그림을 훑어 화풍(양피지색·나무 갈색·
붉은 술 장식·9분할 프레임 기법)을 앵커 문구로 뽑고, 텍스트 필드 1종·버튼
3종(primary/secondary/ghost)·아이콘 6종·도시 이름 짓기 화면의 새 배경까지
이미지 생성 AI에 넘길 프롬프트를 정리해 전달했다. 코드는 건드리지 않았다.

### 2단계 — 사용자가 만들어 온 그림 검수

사용자가 `assets/icons/`를 만들어 그림을 채워 넣었다. 처음 받은 세트를
확인하고 문제 넷을 짚었다:

- `button_back_arrow.png`(라벨 포함판)의 글자가 "뒤로설정"으로 다른 아이콘
  프롬프트의 낱말이 섞여 들어가 있었다 (말이 안 되는 조합).
- 확인(checkmark) 아이콘의 "아이콘만" 버전이 세트에서 빠져 있었다(6종×3벌
  중 확인만 2벌).
- 파일명에 공백이 섞여 있었다(`button_back arrow_blank.png` 등) — 나머지는
  전부 언더스코어 규칙을 따르는데 하나만 어긋났다.
- 도시 이름 짓기 배경(`create_city.jpg`)의 비석에 뜻이 안 통하는 한자가
  새겨져 있었다 — 이 화면은 사용자가 입력한 실제 도시 이름을 그림 **위에**
  얹는 구조라, 그림 자체에 어떤 글자도 박혀 있으면 안 된다는 것도 함께
  짚었다.

또한 **라벨 포함/빈칸/아이콘만 세 벌 중 어느 쪽을 정본으로 쓸지**를
코드 구조로 판단해 알려줬다 — `.btn`은 아이콘과 라벨을 DOM에서 따로 그리고
`t()`로 다국어 텍스트를 렌더링하는 구조라, **아이콘만("justicon") 버전이
이 프로젝트의 i18n 구조와 맞물린다.** 라벨 포함판은 다국어 전환 시 그림을
언어별로 다시 구워야 해서 게임 에셋으로는 안 쓰기로 했다.

사용자가 문제 넷을 반영해 다시 만들어 왔다 — `assets/icons/`가 justicon만
남긴 6종(설정·뒤로·닫기·확인·전투/출정·기록)과 필드 1종·버튼 3종·새
배경(`create_city.png`, 글자 없이)으로 정리됐다.

### 3단계 — 실제 배선

1. **`tools/build_ui.py`(신설) + `npm run ui`** — `assets/icons/`를 굽는다.
   - 필드·버튼 프레임 4종(`textfield`·`button_primary`·`button_secondary`·
     `button_ghost`)은 **알파 경계상자로 트리밍만** 하고 폭 상한(960px)에
     맞춰 `public/ui/{field-frame,btn-primary,btn-secondary,btn-ghost}.png`로
     낸다. `build_frames.py`의 카드 액자와 달리 **Python이 9분할로 미리
     자르지 않는다** — 원본이 이미 독립된 완성 에셋(양피지·목판이 캔버스에
     꽉 차 있다)이라 자를 조각이 따로 없고, 9분할은 CSS `border-image`가
     그림을 그대로 받아서 한다.
   - 아이콘 6종은 `build_market.py`의 아이콘류와 같은 방식(알파 경계상자 →
     정사각 채움 → 128px 축소)으로 `public/icons/{settings,back,close,
     confirm,battle,records}.png`로 낸다.
   - 배경은 다른 배경 그림들처럼 JPG로(`public/backgrounds/new-city.jpg`,
     quality 88) 낸다.
2. **`style.css`에 `.scr-title`·`.scr-new` 공용 절 추가** — 두 화면이 같은
   프레임을 나란히 쓰는 것을 셀렉터 레벨에서도 드러냈다. `.field`는
   두루마리 프레임 배경 + 먹색 글자(`#3a2c1e`, 다른 화면의 밝은 글자와
   반대라 셀렉터를 반드시 이 두 화면으로 좁혀 씀)로, `.btn.primary`는 옥색
   목판, "계정 생성" 전용 `.btn`(primary가 아닌 것)은 참나무 목판으로
   덮었다. `border-image-slice` 값은 실측이 아니라 눈으로 잡은 값이다(아래
   검증 참조).
3. **`NewGameScreen.tsx`** — 원래 배경이 아예 없는 맨 화면(`<div className="scr scr-new">`)
   이었던 것을 `ScreenChrome` + `new-city.jpg` 배경으로 감쌌다. 내부의
   중복된 `<h1>제목</h1>`은 뺐다 — `ScreenChrome`이 이미 브랜드 제목을
   띄우고, 다른 `.scr-bg` 화면(`TitleScreen` 등)도 안에서 따로 제목을 안
   띄우는 것과 맞춘 것이다.
4. **아이콘 6종·`.btn.ghost`는 이번엔 화면에 안 붙였다** — 두 화면
   어디에도 아이콘이 들어갈 빈 버튼이 없다. `ScreenChrome`의 톱니바퀴는
   `GearIcon` 주석에 이미 "에셋 파이프라인에 걸리면 그림을 못 받은 사람
   화면에서 설정 버튼 자체가 사라진다"는 이유로 **의도적으로 인라인 SVG로
   남겨 뒀다**는 것을 코드에서 확인했고, 그 결정을 뒤집지 않았다. 뒤로가기
   버튼도 이 두 화면엔 없다(전부 텍스트 화살표 "← …"로 다른 화면에 이미
   있다). `public/icons/`·`btn-ghost.png`는 구워는 뒀으니 나중에 필요한
   화면이 생기면 그때 붙인다.

## 검증

- `npm run typecheck` — 통과.
- **`npm run ui`로 실제로 구워서 dev 서버 + Playwright로 두 화면 다
  스크린샷을 찍어 확인했다.**
  - 타이틀 화면은 인증 없이 바로 뜬다 — 이메일·비밀번호 필드, 입장(옥색)·
    계정 생성(참나무) 버튼이 예상대로 배치됐다. 입력한 이메일 텍스트가
    스크롤 프레임 위에서 먹색으로 잘 읽힌다.
  - 도시 이름 짓기 화면은 로그인 없이 볼 방법이 없어서(Supabase 이메일
    로그인이 정본), **세션 동안만** `App.tsx`의 `useState<Screen>` 초기값을
    `{ name: 'newgame' }`으로 잠깐 바꿔 띄우고 스크린샷을 찍은 뒤 **원래
    `{ name: 'title' }`으로 되돌렸다** — `git diff`로 무변경 확인, 커밋에는
    전혀 안 남는다(`MarketScreen`을 확인할 때 썼던 것과 같은 방법,
    2026-08-24 `장터_UI_1차초안` 참조). 새벽 배경에 글자가 안 박혀 있는
    것, 필드·버튼이 타이틀 화면과 같은 톤으로 앉는 것을 확인했다.
- `.gitignore`에 `packages/client/public/icons/` 한 줄을 추가했다 — 다른
  빌드 산출 이미지 폴더(`public/ui/`·`public/backgrounds/` 등)와 같은
  이유로 커밋 대상이 아니다.

## 이번 범위 밖 (다시 볼 자리)

- **`border-image-slice` 값이 눈대중이다.** `build_frames.py`의 카드
  액자처럼 원본에서 정확한 픽셀 경계를 재서 넣지 않았다 — 스크린샷 확인
  선에서는 괜찮아 보였지만, 다른 화면 폭·폰트 크기에서 캡(모서리 장식)이
  늘어나 보이면 이 값부터 의심할 것.
- **아이콘 6종·`.btn.ghost`가 아직 어느 화면에도 안 쓰인다.** 그림은
  `public/icons/`에 준비돼 있다 — 확인/닫기 팝업이나 뒤로가기 버튼을
  이미지로 바꾸는 화면이 생기면 그때 연결한다.
- **다른 화면의 버튼·필드는 그대로다.** 이번 세션은 간판·도시 이름 짓기
  두 화면만 대상이었다 — "게임 전체에 일관되게 적용 가능하도록" 화풍
  프롬프트와 아이콘 세트를 준비해 둔 것이지, 지금 다른 화면(궁궐·병영·
  장터 등)의 버튼을 전부 바꾼 것은 아니다.

## 새 대화로 이어갈 때

- 사용자가 실제 기기/브라우저에서 두 화면을 보고 피드백을 줄 차례다 —
  `border-image-slice` 조정이 1순위로 나올 가능성이 높다.
- 아이콘 6종을 처음 쓸 화면이 정해지면 `public/icons/{id}.png` 규약
  (`settings`·`back`·`close`·`confirm`·`battle`·`records`)을 그대로 쓰면
  된다.
