# 2026-08-25 — 도시 생성 화면 다듬기 · 계정 초기화(테스트용) · 도시 이름 변경

> 이 문서는 **한 대화 세션의 기록**이다. 프로젝트의 현재 상태와 규칙은
> [`HANDOFF.md`](../HANDOFF.md)와 [`Design/GDD.md`](../Design/GDD.md)가 정본이며,
> 여기는 "무엇을 왜 그렇게 정했는가"와 "어디서 넘어졌는가"를 남긴다.
>
> 같은 날 앞선 세션([`history/2026-08-25_간판_다국어_환경설정_화풍.md`](2026-08-25_간판_다국어_환경설정_화풍.md))이
> 간판·환경설정을 다듬었다면, 이번은 사용자가 도시를 실제로 하나 만들어
> 써보다가 "도시를 다시 만들 방법이 없다"는 것을 발견하면서 시작된 세션이다.
> 거기서 계정 구조(도시 여러 개 vs 하나) 논의 → 테스트용 초기화 버튼 →
> 도시 생성 화면 다국어·레이아웃 → "같은 이름이면 같은 다섯 명" 문구가
> 파밍을 부추기는지 → 도시 이름 중복 문제 → 랭킹 노출을 앞둔 이름 변경
> 기능까지, 한 화면을 계기로 꼬리를 물고 이어진 세션이다.

## 왜 이 작업인가

사용자가 "Sydney"라는 도시로 온보딩을 테스트하다가, 도시를 한 번 만들면
메인 화면에 고정되고 다시 도시 생성 화면으로 돌아갈 방법이 없다는 것을
발견했다. 거기서 "계정당 도시를 여러 개 둘까, 하나만 두고 철거 후
재건축을 시킬까"를 물어왔고, 그 논의가 실제 작업으로 이어졌다.

## 한 일 — 다섯

### 1. 계정 구조 결정 — 멀티시티 대신 "단일 도시 + 테스트용 초기화"

`PlayerProfile.cityName`이 프로필에 붙은 단일 필드이고 군량·전적·로스터·
매칭 등 거의 모든 시스템이 "프로필 하나 = 도시 하나"를 전제로 짜여 있어
멀티시티는 그 전제를 깨는 큰 작업이라고 판단해 권했다. 그리고 지금
당장 필요한 건 게임 기능으로서의 "도시 철거"가 아니라 **테스트용
탈출구**라는 것도 짚었다 — 사용자가 동의했다.

- **서버**: `packages/server-api/src/routes.ts`에 `DELETE /profile` 추가
  (인증 필요, 기존에 스모크 정리용으로만 쓰던 `profileStore.deleteProfile()`을
  그대로 재사용).
- **클라이언트**: `storage.ts`에 `deleteProfileOnServer()`(호출 후 캐시도
  비움), `MainScreen.tsx`에 로그아웃 옆 `[테스트] 도시 삭제` 버튼,
  `App.tsx`가 삭제 후 로그인은 유지한 채 `newgame` 화면으로 바로 보낸다.
- **의도적으로 비공식 표기**: 버튼 라벨을 `[테스트]`로 대괄호를 쳐
  일부러 안 다듬었다 — 실제 게임 기능이 아니라 나중에 없앨 개발용
  통로임을 표시로 남겼다.

### 2. 도시 생성 화면(`NewGameScreen.tsx`) 다국어 + 레이아웃

기존에는 한국어 문구가 JSX에 하드코딩돼 있었다. `t()` 기반으로 옮기고
10개 언어 파일에 번역을 채웠다(간판·환경설정에 이어 세 번째로 다국어가
채워진 화면).

- **한국어는 존댓말로**: "먼저 도시 이름을 정한다" → "먼저 도시 이름을
  정해 주세요." 등. 이 화면 하나만의 톤 결정이고, 기존 다른 화면들의
  평서형(-다) 문구는 건드리지 않았다.
- **레이아웃**: 안내 글(`.newgame-guide`)과 입력칸·버튼(`.newgame-form`)을
  분리했다 — 후자는 그대로 `margin-top: auto`로 화면 아래에 붙잡아 두고,
  전자는 그림 속 반석보다 위(헤더 바로 아래)로 옮겼다. 이후 "한 줄만 더
  아래로" 피드백을 받아 `.newgame-guide`에 `margin-top: 1.4rem`을 더했다.
- **되짚어 지운 문구**: "시작하면 S·A·B·C·D 등급 장수를 한 명씩 받는다.
  같은 이름으로 시작하면 늘 같은 다섯 명이 나온다"를 처음엔 그대로
  다국어로 옮겼다가, 사용자 질문("계정을 지우고 다시 만들어도 같은
  이름이면 똑같은 다섯 명이 나오는가?")에 "그렇다"고 답하면서 **그 사실을
  화면에 알리는 것 자체가 문제**라고 짚었다 — 계정 생성이 무료인 지금
  구조에서, 이름이 시드라는 것을 알려 주면 "좋은 다섯 명이 나오는 이름을
  검색해서 쓰는" 파밍을 사실상 안내하는 꼴이 된다. 사용자가 동의해
  문구와 10개 언어 번역 전부를 지웠다(내부 결정론 로직 자체는 그대로 —
  QA용으로는 여전히 유용하다).

### 3. 이용약관/연령 고지 — 어디에 넣을지 정리만 하고 구현은 안 함

"상점 현금결제·연령층 안내가 필요할 것 같은데 오프닝과 도시 생성 중
어디에 넣어야 하는가"라는 질문에, **오프닝 화면의 "계정 생성" 단계**가
맞다고 답했다 — 약관·연령 고지는 계정을 만드는 시점에 동의를 받는 게
표준이고(스토어 심사도 그 시점을 본다), 도시 이름을 짓는 화면은 이미
로그인된 계정이 들어오는 곳이라 결제·약관과 무관하다는 이유였다.
**이번 세션에서 실제 문구·UI는 만들지 않았다** — 스토어 등록 시점까지
미루기로 했다.

### 4. 도시 이름 중복 → 이름 변경 기능

"도시 이름이 랭킹·매칭 화면에 노출될 텐데 중복 검사를 하는가"라는
질문에 코드를 확인한 결과 **중복 검사가 아예 없었다**(DB도 `uid` 기준
한 행이라 `cityName`에 유니크 제약이 없고, 어떤 라우트도 다른 계정과
대조하지 않는다). 사용자가 "계정 id + 도시 이름을 조합하면 어차피
유니크해지니 검사는 필요 없고, 대신 도시 생성 후 이름을 바꿀 수 있게
하자"는 방향을 정했고, 규칙(비용 발생 + 쿨다운)까지 함께 정했다.

- **결정한 값**: 쿨다운 3일, 비용은 재설계(둔갑천서)와 같은 금화 —
  둘 다 사용자에게 직접 물어(`AskUserQuestion`) 정했다. 새 상수를
  늘리지 않고 이미 있는 기준을 재사용한 것.
- **`packages/meta`**(순수 규칙):
  - `types.ts`: `PlayerProfile.cityNameChangedAt?: number` 추가(없으면
    한 번도 안 바꾼 것).
  - `profile.ts`: `CITY_RENAME_GOLD`(= `RESPEC_GOLD`), `RENAME_COOLDOWN_MS`
    (3일), `CITY_NAME_MAX`, `canRenameCity(profile, name, nowMs)` /
    `applyRenameCity(profile, name, nowMs)`. 다른 시계 관련 함수들
    (`syncGrain`·`applyCityUpgrade`)과 같은 규약으로 `nowMs`를 인자로
    받는다 — meta는 시계를 스스로 안 읽는다.
  - `migrate.ts`: `cityNameChangedAt`을 되접기에서 놓치면 서버가 매
    `GET /profile`마다 재구성하는 되접기 과정에서 조용히 사라져
    쿨다운이 무의미해진다 — `exactOptionalPropertyTypes` 때문에
    `undefined`를 직접 대입할 수 없어 조건부 스프레드로 넣었다.
- **UI**: `CityScreen.tsx`에 도시 이름 옆 `[이름 변경]` 버튼 → `RenameModal`
  (입력칸 + 비용 안내 + `canRenameCity()`가 낸 실패 사유를 그대로 표시 +
  유효할 때만 확인 버튼 활성화). `NewGameScreen.tsx`의 안내 문구도
  "나중에 도시 관리에서 바꿀 수 있다 — 금화가 들고 3일간 재변경 불가"로
  바뀌어 처음부터 규칙을 알려 준다.
- **i18n**: `city.rename*`·`newgame.rename` 키를 10개 언어 파일 전부에
  채웠다(한국어는 존댓말 유지).

- `npm test` — 444개 중 442 통과. **실패 2개는 이 세션 시작 전부터

## 이번 범위 밖 (다시 볼 자리)

- **이용약관/연령 고지 실제 문구와 UI는 아직 없다** — 자리(오프닝 계정
  생성)만 정했다.
- **`packages/client/test/backdrop.test.ts`의 게임 제목·언어 목록
  기대값이 낡았다** — "만민의 삼국지" → "만인의 삼국지", 5개 언어 →
  10개 언어로 갱신이 필요하다. 이번 세션이 만든 문제는 아니라 손대지
  않았다.
- **`[테스트] 도시 삭제` 버튼은 실제 출시 전 제거 대상**이다 — 라벨의
  `[테스트]` 표기가 그 표시다.
- **도시 이름 변경의 악용 여지**: 랭킹 매칭 직전 개명으로 상대를
  혼란시키는 것은 3일 쿨다운 + 금화 비용으로 어느 정도 억제되지만,
  실제 랭킹/매칭 화면이 아직 없어 실전 검증은 못 했다.
- **가챠(`gachaPool`) 필드가 `migrate.ts`에서 아예 되접히지 않는 것을
  발견했다** — 이번에 고치지는 않았지만, `cityNameChangedAt`을 추가할 때
  같은 함정(되접기에서 놓치면 매 저장마다 조용히 사라진다)에 걸리지
  않으려고 대조하며 알게 됐다. 트랙 9(상점) 쪽을 다시 볼 때 확인이 필요하다.

## 새 대화로 이어갈 때

- 도시 이름 변경 기능은 규칙(`packages/meta`)과 화면(`CityScreen`) 모두
  끝났다 — 실제로 브라우저에서 눌러 보는 수동 확인은 아직 안 했다.
- 이용약관/연령 고지를 실제로 만들 때는 `TitleScreen.tsx`의 "계정 생성"
  쪽에 붙인다(이번 세션에서 정한 자리).
- `gachaPool` 되접기 누락은 트랙 9 작업을 다시 열 때 같이 고치는 것을
  고려할 것.
