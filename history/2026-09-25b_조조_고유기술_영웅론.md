# 조조 고유기술 교체 — 「화용도 의석조조」 → 「영웅론」 (2026-09-25)

S급 30명의 고유기술을 훑어본 뒤, 조조의 기술을 새로 설계해 갈아 끼운 세션이다.
옛 기술(사망 시 1회 부활)은 엔진·화면에서 **통째로 걷어 냈다.**

---

## 1. 왜 바꿨나

- 「화용도 의석조조」는 **관우가 주인공인 일화**(관우가 의리로 조조를 놓아줌)라, 조조가 무엇을
  해내는 기술이 아니었다.
- 효과도 「죽기 전에 걸어 두는 보험」 하나라 판에 직접 개입하지 않았다. 같은 조조군의 순욱(조종)·
  가후(확정 환술)·곽가(사후 저주)와 비교해 존재감이 약했다.
- 조조의 능력치(무 75 · 지 94 · 통 98)와 「사람을 꿰뚫어 보는」 인물상에 맞는 기술로 바꾸기로 했다.

후보로 **협천자이령제후**(아군 전체 WT 단축) · **망매지갈**(아군 MP·회복) · **영웅론**(상대 고유기술
견제) 셋을 냈고, 기획자가 **영웅론**을 골랐다. 지금 S급에 상대 고유기술에 맞서는 기술이 없어
역할이 겹치지 않는다.

## 2. 일화 — 청매자주논영웅(靑梅煮酒論英雄)

허도에 몸을 의탁한 유비가 채소밭을 가꾸며 뜻을 감추던 때, 조조가 푸른 매실에 술을 데우며
천하의 영웅을 논한다. 유비가 꼽는 이름을 하나하나 깎아내린 끝에:

> **「지금 천하의 영웅은 오직 그대와 이 조조뿐이오.」** (今天下英雄，惟使君與操耳)

유비는 수저를 떨어뜨리고, 마침 친 천둥을 핑계로 둘러댄다.

- **정사**: 『삼국지』 선주전 — 영웅 문답과 떨어뜨린 수저
- **배송지 주(『화양국지』)**: 천둥으로 둘러댄 대목
- **연의 창작**(21회): 청매·데운 술의 무대, 영웅 후보를 깎아내리는 문답

위 대사가 **성우 대사**다(기획자 지정).

## 3. 확정 규칙 (기획자 확정)

| 항목 | 결정 |
|---|---|
| 효과 | 적 1명의 고유기술을 **봉인** |
| 봉인 기간 | **게임 끝까지** — 「차동풍」으로 횟수를 돌려받아도 막힌다, 「결계」로 안 풀린다 |
| 시전 중인 적 | **그 자리에서 무산**(SP·횟수 환불 없음 — 시전 중 사망과 같은 규약) |
| 대상 | **고유기술이 남은 적만** — 사용 횟수가 있거나 시전 중, 아직 봉인 안 됨. 이미 쓴 적은 조준 불가 |
| SP · 시전 지연 | SP 6 그대로 · 지연 없음(발동 직전을 끊는 카운터라 제가 늦으면 뜻이 없다) |

**「이미 걸린 효과를 지운다」는 넣지 않았다.** 엔진은 상태가 어느 고유기술에서 왔는지 기록하지 않고,
고유기술 효과가 상태 하나로 끝나지도 않는다(여러 유닛에 흩어짐 · 조종/WT 보정/지형/사후 예약 ·
되돌릴 수 없는 회복·최대 HP 2배). 「지운다」가 기술마다 다른 뜻이 되어 UI가 그 차이를 다 설명해야
한다. 대신 **「시전 중이면 무산」**이 목록 방식이 원했던 「발동 중인 것을 막는다」의 핵심을 한 번의
클릭으로 준다.

## 4. 구현

### 4.1 데이터 (`tools/extract_data.py`)

- **`SKILL_REDESIGNS`** 새 표 — 원본 **오기 정정**(`SKILL_NAME_FIXES`·`SKILL_TEXT_FIXES`)과 달리
  기술 자체를 **바꾼** 것. 이름이 바뀌면 id도 바뀌어(`hwa-yong-do-ui-seok-jo-jo` → `yeong-ung-ron`)
  `sam_skills.csv`의 열 언어가 하나도 안 붙으므로, 이름·한자·효과 서술과 **열 언어 이름·효과·유래**를
  한 벌로 들고 간다. 키는 엑셀의 옛 이름.
  - 엑셀에 옛 이름이 없어지면, 또는 CSV가 새 id를 채우면 **스스로 알린다** — 그때 지운다.
- `SKILL_EFFECTS["영웅론"]` — `applyStatus skillSealed (cleansable false)` + `cancelCasting`,
  둘 다 `{kind: 'enemyOne', requires: 'uniqueSkillLeft'}`.
- 「오라매핑」 시트 대조는 재설계한 기술을 **옛 이름**으로도 찾는다(엑셀은 읽기 전용).
- 시각효과 — `skillSealed`는 **침묵(22)과 같은 그림**을 나눠 쓴다(23장이 다 쓰이고 있다).
- **`SKILL_ART_PENDING` · `SKILL_ART_RETIRED`** — 재설계 직후 그림이 들어오기 전에 `npm run extract`가
  막히지 않게 하는 장치. 영웅론은 그림이 다 들어와 PENDING에서 뺐다(지금 빈 집합). 옛 화용도 그림이
  남아 있으면 「치워도 된다」고만 알린다.

### 4.2 엔진 (`packages/rules`)

- `StatusId`에 **`skillSealed`** 추가(디버프), **`revivePending` 삭제**.
- `TargetSpec.enemyOne`에 **`requires?: 'uniqueSkillLeft'`** — 조준 규칙이라 `validate()`를 거치는
  화면 후보·AI 조준·서버 검증에 한 번에 선다.
- `Effect`에 **`cancelCasting`** — 시전 중이면 `uniqueSkillFizzled { cause: 'sealed' }`를 내고 지운다.
- `validate()`의 `castUniqueSkill` — 봉인이면 거부. **횟수를 건드리지 않고 여기서만 막는다.**
- `uniqueSkillLeft()` · `isSkillSealed()`를 `effects.ts`에서 내보낸다(화면이 같은 물음을 한다).
- **부활 제거** — `state.ts`의 `revive()`, `unitRevived` 이벤트. `countFallen()`(부상 판정)이 로그가
  아니라 끝난 상태를 보는 설계는 그대로 둔다.

### 4.3 화면 (`packages/client`)

- 봉인 상태 표시 — 판 위 기술 뱃지 **빨강**(`COLOR.skillSealed`), 카드 `data-state="sealed"`(빨강 ·
  취소선), 살펴보기 「봉인됨」. 봉인을 「다 씀」보다 **먼저** 본다(봉인은 횟수를 안 건드린다).
- 전투 로그 — 「관우가 시전하던 「온주참화웅」이 봉인되어 무산됐다.」 쓰러져 무산된 것과 가른다.
- 겨눌 적이 하나도 없으면 물음창이 안 뜨므로, 카드를 누르면 「지금 고를 수 있는 대상이 없습니다」를 적는다.
- 부활 연출(점멸 뒤 새 자리로 옮기기 · 카메라가 쓰러진 자리를 보는 처리) 제거.
- 새 문구 6개 × 열 언어, 옛 부활 문구 3개 삭제. **줄 단위로 넣었다** — JSON을 다시 쓰면 원본의
  빈 줄 묶음과 CRLF가 사라져 파일 전체가 diff로 뜬다(한 번 그렇게 했다가 되돌렸다).

### 4.4 AI

바꾸지 않았다. 조준 가능한 적 중 **HP가 가장 낮은 적**을 봉인한다(기존 `chooseSkillTarget` 규약).
시전 중인 적을 우선하도록 바꿀 수 있다 — 기획자 판단으로 남겨 둠.

## 6. 검증

- `npm run extract` 통과 · `npm run typecheck` 통과 · `npm test` **787/787**.
- 회귀 3건(`skills-s.test.ts`): 봉인이 게임 끝까지 막는다(차동풍 포함) · 남은 적만 겨눈다 ·
  시전 중인 적은 무산되고 차례가 와도 발동하지 않는다.
- **세 가드를 하나씩 깨 봤다** — 봉인 검사 · 조준 조건 · 무산 처리 각각을 끄면 회귀가 1건씩 빨개진다.
- **안 한 것**: `smoke:ui`와 실제 브라우저에서 영웅론을 발동해 보는 확인. 연출 흐름·성우 타이밍은
  눈과 귀로 아직 안 봤다.
