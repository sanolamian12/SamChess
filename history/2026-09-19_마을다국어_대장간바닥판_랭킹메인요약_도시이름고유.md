## 1. 마을·성 안 이름표 — 다국어와 줄 나누기

- **[마을로]·[궁성으로]와 산 너머 건물(태학·농지·병원)의 이름·소개가 한국어로 떴다.**
  한국어 키는 있었고 아홉 언어 파일에만 없었다(`t()`가 한국어로 물러난다). 11개 키를
  채웠다 — `city.gate.*` · `place.academy/farm` · `place.*.sub` · `city.bld.farm/academy/hospital/market`.
  용어는 각 언어가 이미 쓰는 말에 맞췄다(군량 = 스페인어·이탈리아어 Grano, 브라질 Grãos,
  포르투갈 Cereais …).
- 번역이 들어오자 `backdrop.test.ts`의 「번역이 없으면 한국어로 물러난다」가 깨졌다 —
  **그 예시가 하필 `city.gate.go`였다.** 이제는 「지금 영어에 없는 키」를 골라 잰다.
  뒤따라 깨진 테스트는 앞 테스트가 언어를 되돌리기 전에 던져서였다(`finally`로 되돌린다).
- **소개 줄이 번역되자 넘쳤다** — SVG `<text>`는 스스로 줄바꿈을 안 한다.
  `screens/wrapLabel.ts`가 **단어 단위로** 끊는다(띄어쓰기 없는 말은 글자 수로).
  한 줄 글자 수는 **로마자 언어 20 · 몽골어·한중일 15**(`labelWrapWidth`, 기획자 지정 —
  로마자는 15자면 대개 세 줄이었다). 건물 이름 글자는 40 → **36**(90%).

## 2. 대장간 — 제작 목록의 [뒤로 가기]를 바닥에

목록 화면(`frg-body-flow`)은 몸통이 높이를 안 채워 [뒤로 가기] 판이 목록 바로 밑에 떠
있었다. 제작 목록일 때만 몸통을 세로 flex로 채우고 판을 `margin-top: auto`로 민다
(`.frg-body-craft`). 지급 관리 화면은 그대로다(요청이 제작 목록이었다).

## 3. 랭킹 — 메뉴 위쪽에 「우리 도시」 요약, 세 판은 [뒤로 가기]

여러 차례 좁혀 갔다. 최종 모양:

```
[성문] 도시 : 2위                    0 점
[깃발] 부대 : 1위   선봉대         230 점
[투구] 장수 : 10위   차주            0 점
```

- 세 판(도시·부대·장수) 바닥에 있던 「내 도시 / 내 부대(상위 3) / 내 장수(상위 3)」를
  **랭킹 메뉴 위쪽**으로 옮겼다 — 부대·장수는 **첫째 하나만**. 세 판의 그 자리엔
  대장간과 같은 **[뒤로 가기] 명령 판**(`RankingBackPanel`).
- 한 줄씩이고 **줄 전체가 5 : 2**(아이콘·제목·순위·이름 : 점수). 판 전체가 한 그리드이고
  줄은 `display: contents`라 칸 경계가 세 줄에서 한 세로선에 맞는다. 처음 3 : 1이었는데
  점수가 커지면 넘칠까 봐 넓혔다. 점수는 「0 점」으로 **패널 오른쪽 끝**.
- 글자는 **짧게** — 「도시 랭킹」「도시 총점」이 아니라 「도시」「점수」. 외국어에서 줄마다
  접히던 것이 열 언어 모두 한 줄에 든다(브라우저로 열 언어 · 420폭 · 세 자리 점수 확인).
  글자 크기는 도시 랭킹 표의 데이터 줄과 같다(.81rem).
- 아이콘은 아래 세 단추의 것과 **같은 크기**(1.7rem)로, **검정 바탕 → 금테(`ui/stat-frame.png`)
  → 아이콘**을 겹쳐 띄운다(액자에 담는 게 아니라 쌓는다).
- **순위는 서버가 낸다** — 새 `GET /ranking/mine`. 전에는 「내가 몇 등인가」를 아무도 안 냈다
  (top 5만 줬다). top 5와 **같은 훑기**라 비용도 같다(이 DB에서 1~4초). 계산은 meta의 순수
  함수 `myRanks()` — **공동 순위**(나보다 **높은** 점수 수 + 1). 이름·점수는 제 프로필로 내므로
  서버가 안 닿으면 순위만 「—위」다. 서버가 가리킨 부대·장수가 화면이 고른 것과 다르면 그
  순위는 안 쓴다.
- **동점은 id 순**(`sortSquadRows`·`sortOfficerRows`의 `total`). 새 계정은 장수가 전부 0점인데,
  Postgres `jsonb`가 키를 다시 늘어놓아 **저장 전의 화면과 서버가 서로 다른 「최고 장수」**를
  골랐다(서황 ↔ 차주) — 그러면 순위가 「—」로 빠진다. 회귀가 고정한다(순서를 뒤집어도 같은 장수).

### 부대 랭킹 글자가 컸던 까닭

도시 판(.62rem)과 부대 판 글자가 달랐는데 **부대 쪽은 의도한 값이 아니었다** —
줄이 단추(`button.rk-clickable`)라 그 규칙의 `font: inherit`(세기 0,1,1)가 `.rk-row`의
.62rem(0,1,0)을 이겨 판의 1rem을 물려받고 있었다. 세 판 모두 **.81rem**(둘의 가운데)을 한
자리(`.scr-ranking .rk-row:not(.rk-thead)`)에 적었다.

### 세 판 공통 손질

- **[정렬 필터] 제거** — 늘 총점 순. 쓰이지 않게 된 `ranking.sort.*` 문구와 `.rk-sortrow` 규칙도 지웠다
  (`SortMenu` 자체는 장수 일람·전적이 계속 쓴다).
- **[검색] 단추 제거** — 입력이 멈추고 **0.5초** 뒤 스스로 검색(`RANK_SEARCH_DEBOUNCE_MS`),
  검색창이 폭 전체. 실측: 치는 동안 요청 0, 마지막 글자 0.52초 뒤 한 번.
- **1~3위만** — 검색해도 셋(서버 `RANK_LIMIT` 3, 화면도 한 번 더 자른다 — 서버를 다시 안 띄운
  채로도 약속을 지킨다).

## 4. 도시 이름은 계정 사이에 고유하다

「검증성」으로 검색해 보니 같은 이름이 줄줄이 나왔다. 랭킹에서 도시 이름이 **유일한 공개
식별자**(이메일은 안 싣는다)라 겹치면 누가 누군지 가릴 수 없다.

- **정리**: `@samchess.test` 테스트 계정 **203개 삭제** — 프로필은 `on delete cascade`로 함께
  지워졌다(스모크성 45 · 검증성 28 등 도시 90개). 기획자 계정(「테스트도시」)만 남았다.
- **DB**: `profiles_city_name_key` — `lower(data->>'cityName')` 고유 인덱스(`sql/schema.sql`,
  `npm run db:migrate`로 적용 완료). **미리 조회해서 막지 않는다** — 조회와 쓰기 사이에 남이
  끼면 통과한다. 인덱스는 동시에 들어와도 하나만 받는다. 서버는 그 위반(23505)을
  `CityNameTakenError` → **409 `city_name_taken`**으로 돌린다(`PUT /profile` · `/city/rename`).
- **이름은 서버 소유**(`SERVER_OWNED_FIELDS`에 `cityName`·`cityNameChangedAt`). `PUT`으로 겹치는
  이름을 올릴 수 있으면 그 행의 저장이 **전부** 막힌다(행 전체가 한 칸). 정하는 길은 첫 저장과
  `/city/rename` 둘뿐. 이름은 저장 전에 `normalizeCityName()`(NFC + 앞뒤 공백 제거)을 지난다.
- **새 도시 화면**: `createProfileOnServer()`로 **서버가 받아 준 뒤에야** 들어간다. 겹치면
  「이미 다른 도시가 쓰는 이름이다 — 다른 이름을 고른다.」, 못 닿으면 들여보내지 않는다.
  빈 이름은 단추가 잠긴다(예전엔 「무명성」으로 물러났는데 이제 그 이름도 한 도시만 가진다).
- **이름 변경**: 겹치면 같은 문구로 거절되고 금화는 안 나간다. 궁궐 판의 거절 문구가 양피지
  위에서 거의 안 보이던 것도 짙은 붉은 먹색으로(`.plc-status .note`).
- **스모크는 도시 이름에 무작위 꼬리** — 7개 도구(`smoke_meta`·`smoke_account`·`*_ux` …).
  `smoke_account`에 **8b** 추가: 둘째 계정으로 ① 대소문자·공백만 다른 이름으로 생성 → 409,
  행 안 남음 ② 남의 이름으로 변경 → 409, 금화 그대로 ③ `PUT`으로 이름 변경 → 무시.
  서버 소유 목록에서 이름을 빼 보니 ③이 깨졌다(검사가 산 것을 확인).
- `smoke_account`의 옛 두 걸음이 **낡아 있었다** — 읽을 때 서버가 찍는 `grainAt`(H3d)과
  서버 소유가 된 카드(A2)를 몰랐다. 새 검사까지 닿게 고쳤다.

## 밟은 것

- **Windows에서 Python 텍스트 모드 쓰기는 CRLF를 만든다** — 편집 스크립트가 11개 파일을
  CRLF로 바꿔 놓았다(`.gitattributes`는 `eol=lf`). 전부 LF로 되돌리고 이후 편집은 Node·Edit로.
  `ko.json`은 `JSON.stringify`로 다시 쓰면 **무리 사이 빈 줄이 사라진다** — 그 파일만은 글자
  치환으로 고친다.
- 새 서버 경로는 **떠 있는 서버를 다시 띄워야** 보인다. 확인은 둘째 인스턴스(포트 8799)를 띄우고
  Playwright가 그 요청만 돌려보내는 식으로 했다(떠 있는 사람의 서버는 안 건드린다).
