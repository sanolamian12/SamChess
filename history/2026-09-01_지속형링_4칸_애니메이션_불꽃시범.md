# 2026-09-01 — 지속형 링을 4칸 애니메이션으로 (「불꽃」류 시범)

> 현재 상태는 [`HANDOFF.md`](../HANDOFF.md)에, 사양은 [`Design/GDD.md`](../Design/GDD.md)에
> 있다. 이 문서는 **왜 그렇게 정했고 무엇을 확인했는가**만 적는다.

## 1. 요청

기획자가 `assets/SpecialStatus/`의 지속형 링 30장 중 「불꽃」 계열 6장
(`4`·`8`·`10`·`11`·`12`·`15`)을 시범 삼아 `{n}-new.jpg`로 새로 그려 넣었다.
전부 2×2 배열이고, 의도는 **좌상단부터 시계방향으로 0.5초마다** 돌려 움직이는
이펙트처럼 보이게 하는 것 — 아직 배경 투명 처리는 안 한 원본이었다.

「이 프로젝트에 이미 있는 투명 처리 코드로 될지 검토하고 구현해 달라」는
요청이라 검토부터 했다.

## 2. 검토 — 기존 코드로는 안 됐다, 이유가 둘

### (1) 알파 채널이 없다

`tools/build_status_fx.py`의 기존 자르기는 **이미 알파 채널이 있는 그림**의
경계상자를 잡는 전제다. 그런데 `4-new.jpg` 등은 2048² **검정 배경 위의 가산
(additive) 불꽃**이고 JPEG라 알파 채널 자체가 없다 — `im.convert("RGBA")`를
그대로 태우면 전체가 불투명해진다.

맞는 공식은 이미 이 저장소에 있었다 — `tools/strip_reveal_bg.py`의
`strip_black_bg`(상점 리빌 이펙트용, 2026-08-24): `alpha = max(R,G,B)`로 밝기를
투명도 삼고, 색은 그 알파로 나눠 되살린다(비-예비승산 복원). 안 그러면 검정과
섞인 우중충한 회색 테가 가장자리에 남는다. 같은 공식을 `build_status_fx.py`에
`load_screen_alpha()`로 옮겼다.

### (2) 화면이 지속형 링을 정지 이미지로만 그린다

`BattleScene.syncRing()`은 `vfx:{id}` 텍스처 한 장을 `setTexture()`로 박아
넣을 뿐 프레임 개념이 없었다. 게다가 다시 그리는 주기 자체가 **2초**
(`SWAP_MS`, 겹친 링을 갈아 끼우는 용도)라, 4칸 띠를 그냥 넣어도 실제로는
2초에 한 번만 갱신됐을 것이다 — 옆으로 눌린 그림 하나가 뜨고 끝.

## 3. 구현

### `tools/build_status_fx.py` — `{n}-new` 규약

숫자 파일에 `-new` 접미사가 붙은 원본이 있으면, 같은 번호의 정지 이미지 대신
**그 파일로 `public/vfx/{n}.png`를 굽는다**(원본 `n.png`는 안 지워도 대조용으로
남길 수 있다). 검정→투명 변환 뒤에는 알파벳(`A`~`G`) 일회성 띠와 **같은 자르기**
(공통 경계상자·정사각·시계방향 4칸 펴기)를 그대로 탄다 — 검정이 알파 0이
되고 나면 `bbox()`가 똑같이 통하기 때문이다.

```
files 훑기 → 일반본으로 먼저 채우고 → -new로 덮어쓰기 (순서 무관하게 결과 같음)
target.isdigit() and not is_new → build_ring()   (기존과 동일, 정지)
그 외                            → build_strip(screen_alpha=is_new)
```

`*.png`만 훑던 glob에 `*.jpg`를 더했다 — 안 그러면 `-new` 원본이 애초에 안 잡힌다.

### `packages/client/src/battle/visualEffect.ts` — 프레임 타이밍

```ts
export const RING_FRAME_MS = 500;
export function ringFrame(elapsedMs: number, frameCount: number): number {
  if (frameCount <= 1) return 0;
  return Math.floor(Math.max(0, elapsedMs) / RING_FRAME_MS) % frameCount;
}
```

`ringAt()`의 `SWAP_MS`와 같은 결 — Phaser를 부르지 않는 순수 함수라
`test/visualEffect.test.ts`에서 헤드리스로 잡힌다.

### `packages/client/src/battle/BattleScene.ts` — 목록을 안 둔다 ★

어떤 상태 id가 애니메이션인지 **따로 표로 두지 않았다.** 대신 로드된 텍스처의
**폭이 높이의 4배인가**로 스스로 판별한다(`sliceAnimatedRings()`, 알파벳 일회성
띠와 같은 규약). 목록을 뒀으면 그림을 정지↔애니메이션으로 갈아 끼울 때마다
코드도 같이 고쳐야 하는데, 잊기 딱 좋은 자리다 — 도구가 굽는 순간 화면이
저절로 따라오게 만들었다.

`syncRing()`에서 애니메이션 텍스처면 `setFrame(ringFrame(...))`을 추가로 부른다.
그리고 **다시 그리는 주기에 0.5초 경계 감시를 더했다** — 안 그러면 프레임을
계산해도 2초에 한 번만 반영된다:

```ts
|| (this.animatedRingKeys.size > 0
    && Math.floor(this.ringClockMs / RING_FRAME_MS) !== framed)
```

`animatedRingKeys.size > 0`으로 감쌌다 — 애니메이션 링이 하나도 없는 판(지금
당장은 대부분)에서까지 갱신 주기를 4배로 올릴 이유가 없어서다.

## 4. 검증

- 6장 전부 구워서 프레임 4칸을 눈으로 확인 — 시계방향으로 서로 다른 불꽃
  모양이 잘 나뉘었고, 주황(`4`)·보라(`8`)·백색(`10`·`15`)·초록(`11`)·파랑(`12`)
  계열 각각 투명 처리가 깨끗하다(가장자리 회색 테 없음).
- `10`·`15`는 흰색/은색 계열이라 흰 배경 미리보기에서는 안 보이는데, 픽셀
  통계로 알파가 0~255 정상 분포하고 색이 흰색에 가까운 것을 확인했다 —
  **미리보기 배경의 착시**였지 추출 실패가 아니었다.
- `npm run typecheck` · `npm test` 통과. 회귀 2건 추가
  (`ringFrame`의 0.5초 경계, 프레임 1개일 때 언제나 0).
- 기존에 있던 무관한 실패 3건(`backdrop.test.ts` 다국어 2건,
  `data.test.ts`의 `B_specialstatus*.png` 미사용 경고 1건)은 `git stash`로
  대조해 **이 작업 이전부터 있던 것**임을 확인했다 — 이번 변경과 무관하다.

## 5. 곁가지

- `assets/SpecialStatus/`와 `packages/client/public/vfx/`는 **둘 다
  `.gitignore`에 있다** — 에셋은 리포에 없다는 기존 방침 그대로라, 이번에
  커밋되는 것은 위 코드 3개 + 테스트 파일 하나뿐이다. 원본 `{n}-new` 이미지는
  각자 로컬에 놓고 `python tools/build_status_fx.py`로 굽는다.
- 나머지 24장(정지 링 17 + 일회성 7)은 이번 규약과 무관하게 그대로다.
