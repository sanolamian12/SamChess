# 컬렉션 — 설명 글과 칸 대조 · 칸 정리 (2026-10-14 c)

기획자가 컬렉션을 하나씩 리뷰하다 **설명에 안 나오는 장수가 칸에 있고, 설명에 나오는 장수가 칸에 없는** 경우를 찾았다(백랑산 · 백기겁위영).
117개 전부를 대조해 보이고, 기획자 지시로 칸을 정리했다. `collection-slots` 브랜치 → main `--ff-only`.

## 1. 대조

- 목록 설명 + 상세 설명에서 장수 이름(한글 이름 · 자 · 별명)을 찾아 카드 칸과 맞췄다. 낱말과 겹치는 이름(장수 · 이유 · 정보 · 장소 · 자방 · 문장 · 오의 · 서성 …)은 문맥을 보고 걸렀다 — 오탐 아홉 갈래.
- 정리 전: 어긋남 92개 컬렉션 — 칸에만 94명(52개) · 설명에만 89명(60개) · 게임에 없는 인물 14개 컬렉션.

## 2. 정리 (기획자 확정)

1. 설명에 없는 장수는 칸에서 뺀다. 2. 칸이 5개 미만이면 설명에 나오는 장수를 먼저 나온 순서로 더한다. 3. 비용 · 등급 · 점수는 다시 낸다.
- **예외(시뮬레이션으로 먼저 드러난 15개)** — 그대로 하면 효과가 칸에 없는 장수를 가리키는 것 7 · SP 효과가 전설 밑으로 떨어지는 것 5 · 능력치가 등급 상한을 넘는 것 4.
  기획자 선택: 효과에 이름이 걸린 장수는 빼지 않는다 · SP 컬렉션은 칸을 건드리지 않는다 · 상한을 넘은 넷은 +2 → +1.
- 결과: 66개 컬렉션, 뺀 71명 · 더한 60명 · 자리가 없어 못 넣은 29명. 분포 일반 16 · 희귀 53 · 영웅 15 · 전설 30 · 천하 3, **만점 18,650 → 19,600**.
- 표는 `Design/컬렉션_설명_장수대조.md`(바뀐 것 · 그대로 둔 것), `Design/컬렉션_기획.md` §5 · §6을 새 데이터로 다시 적었다.

## 3. 밟은 것

- 「칸」 시트는 줄마다 수식이 **윗줄을 참조**하고(`I{r-1}`) 「컬렉션」 시트가 `칸!$A$2:$A$416`로 범위를 잡는다 — 10-13c와 같은 지뢰라
  칸 줄을 통째로 다시 쓰고 수식을 새 줄 번호로 만들었다(415 → 404줄, 범위 351곳 `$416` → `$405`). 원본은 고치기 전에 떠 두었다.
- 처음에 main에서 엑셀을 고쳐 버려, 커밋 전에 브랜치로 옮겼다.

## 4. 검사

- `npm run extract` 통과 · 시뮬레이션과 같은 분포 · 새 데이터로 대조를 다시 돌려 **남은 어긋남이 전부 예외(효과 장수 · SP 컬렉션 · 5칸 꽉 참)뿐**임을 확인.
- `npm run typecheck` · `npm test` 871 pass.
- ⚠ 칸 번호가 등록의 열쇠라, 칸이 바뀐 컬렉션에 부분 등록해 둔 **시험 계정**은 칸이 어긋난다(배포 전이라 실계정은 없다).
- 화면 확인(`tools/collection_ux.ts`)은 이번엔 안 돌렸다 — 데이터만 바뀌었고, 도구가 고르는 컬렉션(도원결의 · 인중여포 · 관도대전 · 가장 큰 칸)은 형태가 그대로다.
