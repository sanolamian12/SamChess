## 1. 한 일

### 1-1. 판 전용 배경음악 (`4e3a946`)

- `assets/Audio/bgm/`에 새로 온 4곡을 잇다 — 이미 이어진 12곡은 그대로.

  | 원본 | id | 나오는 곳 |
  |---|---|---|
  | `공성전.mp3` | `siege` | 공성전 판 전체(배치 · 정찰 포함) · 방어 기록 리플레이 |
  | `도적떼.mp3` | `raid` | 도적떼 방어전 판 전체 |
  | `기본 튜토리얼.mp3` | `tutorial` | 기본 1 · 2 · 3 |
  | `S급 튜토리얼.mp3` | `tutorialS` | S급 튜토리얼 |

- 판을 띄우는 화면이 `bootBattle({ bgm })`으로 싣고 `trackForPhase(phase, duel, theme)`가 배치곡 · 전투곡을 함께 대신한다. 일기토 · 설전 곡만 그 위에 선다.
  배치 → 전투의 함성은 단계로 그대로 튄다.
- 공성전 판정은 `ai.defender`(전적 갈래 `siege`와 같은 잣대). **선전포고 판은 야전 그대로**(기획자 확인 — 전적도 야전이다).
- 원본 이름 → id는 `build_audio.py`의 `BGM` 표 하나.

### 1-2. 기본 튜토리얼 금빛 깜빡임 (`097b603`)

- 다음에 누를 곳 하나를 금빛 네온으로 깜빡인다 — 명령 단추 · 책략/아이템 줄 · [확인] · 고유기술 [사용] · 판 위의 칸 · 장수.
- 어디인지는 `CommandFlow.hint()` 하나(지금 걸음 + 안내의 잠금). **켠 명령이 하나일 때만** 깜빡인다 — 안내 창 · 자유 차례(기본 3 마지막) · 대본 밖은 안 깜빡인다(기획자).
- 판 위는 씬의 금빛 테. 짙은 밑선을 넣었다가 기획자가 빼라고 해 금빛 네온만.
- 기본 튜토리얼만 켠다(`bootBattle({ tutorialHint })`) — S급은 그 조건만 넓히면 된다.
- 회귀 `tutorialHint.test.ts`: **깜빡이는 곳만 눌러 기본 세 판(8판)을 이긴다.** `tutorial_ux`: 누르는 것이 깜빡이던 것인가 · S급은 안 깜빡이는가.

### 1-3. 일기토 · 설전 준비 장면 (`e1495d9`)

- 대결 화면이 열린 때부터:

  | 시각 | 무엇 |
  |---|---|
  | 0초 | 배경음악만 |
  | 5초 | 건 쪽 그림(2.5초에 떠오름) + 말발굽(일기토) · 걸음 소리(설전, `dual_walking.mp3`) |
  | 7초 | 함성 |
  | 10초 | 받는 쪽 그림 + 말발굽 · 걸음 |
  | 12초 | 함성 |
  | 15초 | 징 + 「일기토 시작!」 · 「설전 시작!」 2초 |
  | 17~20초 | 첫 합 3 · 2 · 1 |
  | 둘째 합부터 | 5 · 4 · 3 · 2 · 1 |

- `timing.ts`: `DUEL_INTRO_MS` 17초 · `DUEL_FIRST_COUNT_MS` 3초 · `DUEL_COUNT_MS` 5초. 장면 안의 시각(5 · 7 · 10 · 12초)은 화면만 읽으므로 `duelLayer.ts`의 `INTRO_*`.
- 그림 둘은 `tick`이 **남은 시간으로 매 프레임** 띄운다 — 다시 지어도 · 재접속해도 그 자리부터.
- **앞 15초는 대결 곡의 기본 세기를 끝까지**(`boostBgm`, 0.55 → 1). 사용자 설정은 그대로 곱한다. 곡에 묶어 두어 곡이 바뀌면 저절로 풀린다.
- 시작 문구는 「일기토 시작!」 · 「설전 시작!」 그대로(기획자).

### 1-4. 튜토리얼 화면 개편 (`c19d573`)

- **갈래 둘** — 아래 명령 판 [전투 기초] [S급 장수 튜토리얼] [뒤로 가기](참나무 단추, 처음엔 전투 기초).
  고른 갈래는 금빛 번짐 + 붉은 먹 글씨 + 오른쪽 큰 확인 체크(`button_confirm`). 위의 「← 도시로」는 아래 [뒤로 가기]와 겹쳐 뺐다.
- **목록 판**(제목 판 아래, 장부 그림) — 한 줄에 얼굴 · 이름 · 한 줄 설명 · 오른쪽 표.
  - 얼굴: 기물 여섯 `ic_mode_5v5` · 책략과 아이템 = 전투 [책략] 그림 · 고유기술 = 새 그림 · 일기토 · 설전 = 대결 신청 그림 · S급 = 그 장수 초상.
  - 오른쪽 표: 완료 = 승리 메달 + 파란 붓글씨 「완료」 · 다음 목표 = 붉은 투구 메달이 위아래로 둥실 + 노란 「다음」 · 잠김 = 자물쇠 + 회색 「잠김」.
  - 몽골어는 세 표 글씨를, 일 · 중은 「다음」 · 「잠김」 글씨를 줄였다(몽골어에서 가로 스크롤이 생겼다).
- **전투 기초 다섯** — 기물 여섯 → 책략과 아이템 → 고유기술 → 일기토 → 설전. 일기토 · 설전은 판이 없어 「준비 중」(`data-soon`, `data-tutorial` 없음).
- **S급** — 가진 장수만, **그 전투의 역사 순서**(`S_TUTORIAL_HISTORY`, 사수관 190 → 철롱산 253). 30명 빠짐없이 담는지 테스트가 본다.
  같은 해 안의 순서는 이 세션이 정했다(기획자 확인 전):
  - 208: 조운 장판 단기 → 장비 장판교 → 주유 고육지책 → 방통 연환계 → 제갈량 동남풍 · 화공
  - 213: 감녕 유수구 야습 → 손권 유수구 수비
  - 215: 노숙 익양 대치 → 장료 합비
  - 219: 황충 정군산 → 방덕 번성 → 서황 번성 구원 → 여몽 형주 기습
- **S급은 다섯 줄씩 쪽 넘김** — 처음엔 「다음 목표」가 있는 쪽부터, 짧은 끝 쪽은 빈 칸으로 채워 판 높이가 같다.
- 내관 안내의 S급 줄은 [S급 장수 튜토리얼] 단추를 가리킨다(문구 그대로).
- 새 그림 둘(`assets/icons/new/튜토리얼_고유기술` · `튜토리얼_다음`)은 `build_ui.py`가 `public/icons/tutorial/`로 굽는다.

### 1-5. 튜토리얼 승리 장면 · 첫 클리어 보상 (`c19d573`)

- 마지막 판을 이기면 대전 · 도적떼와 같은 **승리 두루마리**(`TutorialResultScreen`, 승리곡) — 「승리」 + 「「…」 클리어!」 → 카드 공개 → 보상 → [튜토리얼 목록으로].
- **보상은 처음 끝낼 때만** 군량 1 · 자재 1 · C~D급 장수 카드 1장(기획자) — 전투 기초 · S급 모두. 다시 한 판이면 「처음 클리어 보상은 이미 받았습니다」.
- 서버가 서버 시드로 반영한다: meta `completeTutorial` → `grantRewards`(전투 보상의 추첨을 떼어 함께 쓴다). `POST /tutorial/complete`는 `{ profile, rewards }`.
- 수치는 `TUTORIAL_REWARD`(`meta/tutorial.ts`) — 엑셀 보상표에 줄이 없어 코드에 적었다.
- 데모(`?tutorial=`)도 승리 두루마리로 끝난다(보상은 화면 안에서 계산, 서버에 안 남김).
- 실제 서버로 두 번 보내 확인 — 첫 번째 0 → 1, 두 번째 `null` · 계정 그대로, 잠긴 판 409.

### 1-6. 카드 공개 판의 스크롤 (`5f18da9`)

- 받은 카드 공개 판에 세로 스크롤바가 떴다 — 도는 후광이 판보다 커서(209px) `.modal`의 `overflow-y: auto`가 걸렸다.
  `.modal.mkt-done.mkt-reward { overflow: hidden }`. 전투 승리의 카드 공개도 같은 판이라 함께 고쳐졌다.

## 2. 규칙 · 결정

- **대결 하나가 재접속 유예(60초)보다 길어졌다**(최대 88.5초) — 「대결은 유예 안에 든다」 불변식을 뺐다(기획자).
  **대결 도중 유예를 넘기면 대결 도중이라도 항복한다**(엔진은 어느 단계에서든 `surrender`를 받는다). `room-logic.test`가 「유예 직전까지 대결 중 → 넘기면 항복」을 고정한다.
  설계서 `Design/일기토_설전_설계.md` §3-7의 숫자도 고쳤다.
- **튜토리얼 판은 재생 검증이 없다** — 판을 안 두고 완료만 보내도 첫 클리어 보상을 받는다. 판마다 한 번 · 작은 보상이라(최대 33판) 남긴 공백이고 `tutorial.ts` 주석에 적었다.
- **새 계정은 창고가 가득 차 있어 튜토리얼 군량 보상이 「없음」으로 보인다** — 전투 보상과 같은 「들어간 만큼만 적는다」. 바꿀지는 기획자 결정 대기.

## 3. 고친 버그 · 교훈

- **개발 서버는 어느 폴더에서 떴는지부터 본다.** 5173이 워크트리 `SamChess-tut`의 Vite였다 — `public/`은 이쪽을 가리키는 링크라 새 mp3는 받아지는데
  곡을 고르는 코드는 옛것이라 「음악이 반영 안 된다」로 보였다. `netstat`로 PID → 실행 경로를 확인했다.
- **새 서버 코드는 게임 API를 다시 띄워야 실린다** — `/tutorial/complete`의 응답 모양을 바꾼 뒤 8787을 다시 띄웠다(`--watch` 없음).
- **데모 프레임과 앱 프레임은 다르다** — 데모의 결과 화면이 위 절반만 찼다. 앱은 메타 화면에 `#frame.meta`(flex)를 거는데 데모는 전투용 3단 그리드였다.
- **앞선 튜토리얼을 끝낸 셈 치는 루프는 「지금 판 앞까지」만** — 데모가 기본 1에서 기본 2 · 3까지 끝내려다 `locked`로 던졌다.
- **검사는 깨 보고 믿는다** — 깜빡임 회귀(`[확인]` 힌트를 지우면 11개 모두, 책략 줄을 지우면 2개 실패), 첫 클리어 한 번만(늘 주면 1개 실패),
  카드 공개 스크롤(고치기 전 `overflowY: auto` · 넘침 209로 실패)을 각각 확인했다.
- **판 위 금빛은 종이 지도 · 초록 이동 칸 위에서 묻힌다** — 두께 · 바깥 번짐을 키웠다. 색은 실제 바탕 위에서 프레임 사진으로 봤다.
- **연출 소리의 시각은 소리로 못 듣는다** — 페이지의 `HTMLMediaElement.play`를 감싸 무엇이 몇 초에 울렸는지 기록해 봤다. 배경음악 세기도 요소의 `volume`을 시각별로 쟀다.
