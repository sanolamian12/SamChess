# 2026-08-25 — 간판 화면 리디자인 · 10개 언어 다국어 인프라 · 환경설정 팝업 화풍

> 이 문서는 **한 대화 세션의 기록**이다. 프로젝트의 현재 상태와 규칙은
> [`HANDOFF.md`](../HANDOFF.md)와 [`Design/GDD.md`](../Design/GDD.md)가 정본이며,
> 여기는 "무엇을 왜 그렇게 정했는가"와 "어디서 넘어졌는가"를 남긴다.
>
> 전날(2026-08-24) 간판·도시 이름 짓기 화면에 화풍 UI를 처음 입힌 세션의
> 바로 다음 걸음이다 — 그 세션이 "필드·버튼에 그림을 입힌다"였다면, 이번은
> "그 화면을 실제로 써 보면서 나오는 디테일을 잡는다"였다. 한 세션 안에서
> 여러 차례 스크린샷을 주고받으며 다듬어 나간, 전형적인 반복 피드백
> 세션이다.

## 왜 이 작업인가

트랙 9(상점/가챠)나 Colyseus 트랙과 무관한, 사용자가 화면을 직접 써보며
낸 디자인 피드백 세션이다. 간판 화면을 테스트하다가 자동완성 배경이
깨지는 것을 시작으로, "이 김에 다국어도 테스트해보자" → "언어를 바꿔도
버튼이 안 바뀐다" → "그럼 다국어 인프라부터 제대로 놓자" → "환경설정
팝업도 게임 화풍으로" → "언어별로 레이아웃이 깨진다" 순으로 범위가
자연스럽게 넓어졌다.

## 한 일 — 크게 넷

### 1. 간판 화면(`TitleScreen.tsx`) 리디자인

- **자동완성 배경 버그**: 크롬이 저장된 로그인정보를 자동입력하면 강제로
  옅은 파란 배경을 씌우는 표준 동작(`:-webkit-autofill`)이 원인이었다 —
  두루마리 그림 자체는 투명 배경 PNG로 정상이었다. `box-shadow` inset
  트릭으로 우회했다.
- **붓 아이콘**: 이메일·비밀번호 입력칸 오른쪽 아래에 인라인 SVG로 작은
  붓을 그려 "여기 글씨를 쓴다"는 신호를 줬다(`GearIcon`과 같은 이유로
  그림 파일을 새로 안 늘렸다).
- **버튼 정렬·폰트**: "계정 생성"이 왼쪽 정렬로 어긋나 있던 걸 발견해
  가운데 정렬로 통일했고, 이 화면에만 Song Myung(명조 계열) 폰트를 입혔다.
- **붓글씨 애니메이션 제목**: 성문 그림 위에 "만인의 삼국지"(원래
  "만민의 삼국지"였던 것을 이때 개명)가 7초 주기로 먹으로 쓰였다가
  흐려지며 사라진다. Nanum Brush Script + `-webkit-text-stroke`로 두께를
  흉내 냈다("만인의" 반 줄 위 + 한 글자 왼쪽, "삼국지" 반 줄 아래 + 한 글자
  오른쪽으로 어긋나게, 흰 글자 + 먹색 테두리).
- **다국어로 확장하며 겪은 실패 하나**: 이 두 줄 어긋난 배치를 그대로
  다른 언어에 물려줬더니 영어("Everyone's Three Kingdoms")처럼 긴
  제목이 줄마다 다시 접혀 겹쳤다. **한국어만** 어긋난 두 줄이고, 나머지
  언어는 한 덩어리로 가운데 정렬 + 자동 줄바꿈으로 물러나는 것으로 고쳤다
  (`TitleScreen.tsx`의 `heroLang === 'ko'` 분기).
- **언어별 히어로 폰트**: 진짜 붓글씨체는 한글에만 있다(Nanum Brush
  Script, 한국어 전용). 한자권은 Noto Serif SC/TC/JP, 로마자권은 Cinzel
  Decorative, 몽골어(키릴)는 맞는 무료 서체를 못 찾아 시스템 세리프로
  물러난다 — `HERO_FONT` 표.

### 2. 다국어 인프라를 JSON 기반으로 재구성, 5개 → 10개 언어

기존 `i18n/index.ts`는 언어별 문구를 하나의 `const KO = {...} as const`
객체 + 빈 객체 넷(`en`, `pt`, `ja`, `zh`)으로 담고 있었다. 이번에 두 가지를
동시에 했다:

- **문구를 `strings/{lang}.json` 열 개 파일로 분리했다.** `ko.json`만
  전체(지금까지 화면에 적은 문구 전부, 140여 키)이고 나머지 아홉은 **화면을
  다국어로 채울 때마다 느는 중**이다 — 이번 세션에서는 간판·환경설정 화면이
  쓰는 키(약 20개)만 채웠다. 없는 키는 `t()`가 한국어로 물러나는 기존
  동작 그대로다. `packages/data/generated/*.json`이 이미 쓰는
  `with { type: 'json' }` 가져오기를 그대로 따랐다 — `packages/client/tsconfig.json`의
  `include`에 `src/**/*.json`을 추가해야 했다(안 그러면 `tsc --build`가
  "file list에 없다"로 막는다).
- **언어를 5개(`ko`·`en`·`pt`·`ja`·`zh`)에서 10개로 늘렸다** —
  `assets/Languages/`의 장수 이름 번역 파일 목록(`roster_en`·`roster_es_419`·
  `roster_it`·`roster_ja`·`roster_kr`·`roster_mn`·`roster_pt_BR`·
  `roster_pt_PT`·`roster_zh_Hans`·`roster_zh_Hant`)을 그대로 따랐다 —
  어느 언어를 지원할지 새로 정하지 않고 이미 있는 답을 따랐다.
- **더빙(성우) 언어 매핑**: `assets/Audio/Specialskills/{KR,EN,JP,PT,CA}`
  다섯 폴더 기준으로, 텍스트 열 언어 → 더빙 다섯 언어 매핑 표
  (`dubLangFor()`)를 만들어 뒀다. 문화권이 가장 가까운 쪽으로 붙였다
  (포르투갈어 두 갈래·이탈리아어·스페인어 → PT, 중국어 두 갈래·몽골어 →
  CA). **아직 재생 코드에 안 이어져 있다** — 고유기술 성우 대사를 트는
  자리 자체가 이 저장소에 없다(배경음악 재생기만 있다). 나중에 그 자리가
  생겼을 때 바로 쓸 수 있게 미리 만들어 둔 표다.
- **번역 신뢰도**: 영어·스페인어(중남미)·이탈리아어·일본어·포르투갈어
  (브라질/포르투갈)·중국어(간체/번체) 여덟은 비교적 자신 있게 옮겼다.
  **몽골어는 자신 있는 언어가 아니라 원어민 검수가 필요하다**고 사용자에게
  명시했다.

### 3. 환경설정 팝업(`SettingsModal.tsx`) 게임 화풍 리스킨

사용자가 이미지 생성 AI로 새 에셋 넷(패널·명패·칩 2종)을 만들어
`assets/icons/`에 넣었고, 그걸 받아 실제로 배선했다.

- **에셋 넷**: `panel_settings.png`(세로 두루마리, 9분할), `plate_settings.png`
  (청동 명패, 제목 배경), `chip_neutral.png`/`chip_selected.png`(나뭇결/
  옥색 칩, 언어 버튼·토글 배경).
- **`.modal[data-modal="settings"]`로 좁혀서 스타일을 입혔다** — `.modal`/
  `.opt`는 증축·재설계·부대삭제 등 다른 확인창도 같이 쓰는 범용 이름이라,
  거기까지 나무판이 번지면 안 된다(CLAUDE.md "전역 CSS에 흔한 이름을 새로
  쓰지 않는다"와 같은 결).
- **`btn-ghost.png`를 처음 실제로 연결**했다가(닫기 버튼), 사용자가 "닫기를
  입장 버튼과 통일해 달라"고 해서 다시 `btn-primary.png`(옥색)로 바꿨다 —
  `.scr-title .btn.primary`와 같은 그림·같은 슬라이스를 이 화면(어느
  화면에서나 뜨는 팝업이라 `.scr-title` 스코프를 못 물려받는다)에도 따로
  적었다.
- **레이아웃 반복 조정**(스크린샷 기반 피드백 루프):
  ID/로그인 상태를 한 줄로(`[로그인 안 함]` 대괄호 표기) → 언어 이름을
  "Language"와 한 줄로, 칩 10개는 그 아래 한 줄로 → 언어 칩 4열 → 5열
  2행으로 → 배경음악/화면모드를 "둘 중 하나" 칩 형태로(끔/가로 왼쪽,
  켬/세로 오른쪽) 통일.

### 4. 버그 셋 — 전부 "화면을 실제로 봐야만 안다" 계열

세 버그 모두 **처음엔 다르게 보였지만 근본 원인은 하나씩**이었다. 이
저장소가 이미 여러 번 겪은 패턴("조용히 무시하는 경로는 없는 것처럼
보인다" 등)의 새 사례들이다.

#### (a) `chip_neutral`/`chip_selected` 크기가 다르게 보임

사용자가 두 그림을 포토샵에서 겹쳐 확인했을 때는 **완전히 같은 600×398
캔버스, 같은 자리**였다. 그런데 화면에서는 선택/미선택 칩 크기가 달랐다.

- **1차 진단(틀림)**: `chip_selected.png`에만 있는 은은한 빛번짐(glow)이
  알파 경계상자 트리밍에 걸려 다르게 잘린다고 보고, 그 파일에만 더 높은
  알파 문턱값을 줘서 번짐을 잘라내는 방식으로 고쳤다.
- **진짜 원인**: 두 원본이 **이미 같은 캔버스에 맞춰 그려져 있었다** —
  즉 트리밍 자체가 잘못이었다. 각자 독립적으로 알파 트리밍하면 원본이
  이미 맞춰 둔 짝을 깨뜨린다.
- **고친 법**: `tools/build_ui.py`에 `FRAME_NO_TRIM` 집합을 추가해 이
  둘은 트리밍을 아예 건너뛰고 원본 캔버스 그대로 쓰게 했다. **한 쌍으로
  겹쳐 그린 프레임은 따로 안 자른다**는 새 규칙이 생겼다.

#### (b) 배경음악/화면모드 칩 크기가 언어마다 다르게 어긋남

언어마다 어느 쪽 낱말이 더 긴지 뒤집힌다 — 한국어는 "가로"·"세로"가 더
길고, 스페인어는 거꾸로 "Desactivado"가 더 길다. 고정된 `rem` 값으로는
언어마다 다시 잴 수 없어, `useTwoChipSize`라는 훅을 만들어 **네 칩 중
가장 긴 것을 실제로 재서** 나머지 셋에 맞추도록 했다(자리가 모자라면
폭 대신 글자 크기를 줄인다).

#### (c) CN↔TW를 오갈 때만(사용자 관찰) 칩 크기가 어긋남 — 실제로는 모든 전환마다

가장 오래 걸린 디버깅이었다. `MutationObserver`로 실제 DOM의 `style`
속성 변화를 밀리초 단위로 추적해서야 잡았다.

- **1차 진단(틀림)**: "이전과 값이 같으면 다시 안 그린다"는 최적화가
  React state 갱신을 건너뛰어 문제라고 보고 그 최적화를 없앴다 — 증상이
  그대로였다.
- **2차 진단(틀림)**: `ResizeObserver`가 자기 자신이 감싼 컨테이너(버튼들이
  들어있는 `root`)를 관찰하고 있었는데, 그 컨테이너 크기를 **자기 자신이
  바꾸는** 구조라 "지운다 → 리사이즈 감지 → 다시 잰다 → 크기를 입힌다 →
  (자연 크기와 다르니) 또 리사이즈 감지 → …"로 끝없이 도는 루프였다.
  이걸 걷어냈지만 — 증상이 그대로였다.
- **진짜 원인**: 폭을 React state(`box`)로 들고 `style` prop으로 네 버튼에
  내려주는 구조였는데, 측정을 위해 먼저 `c.style.width = ''`로 지운 뒤
  다시 잰 값이 **직전에 React가 이미 적용해 둔 값과 우연히 같으면**,
  React의 style diff가 "바뀐 게 없다"고 보고 DOM을 다시 안 건드린다.
  React는 자기가 마지막으로 그린 값과 그 뒤에 내가 DOM을 직접 건드린
  것을 모른다 — 그래서 지운 상태가 그대로 남는다. `document.fonts.ready`
  프라미스 콜백 두 개(스테일 클로저 하나 + 최신 클로저 하나)가 거의 같은
  시각에 겹쳐 풀리면서 이 경합이 쉽게 드러났고, 두 언어의 자연스러운
  폭이 우연히 비슷할수록(CN/TW처럼 한자 1~2자) 더 자주 걸렸다.
- **고친 법**: React state를 거치지 않고 처음부터 끝까지 DOM을 직접
  쓰도록 바꿨다 — `useFitText`가 원래부터 하던 방식과 통일했다. 10번
  연속 CN↔TW를 자동화 스크립트로 오가며 재현 테스트해 확정했다.

#### (d) 명패·ID 상태·언어 이름이 번역에 따라 두 줄로 접힘

포르투갈어("DEFINIÇÕES", "[Sessão não iniciada]"), 몽골어("ТОХИРГОО"),
스페인어("Español (Latinoamérica)")에서 발견됐다. `useFitText`라는 훅을
새로 만들어 `white-space: nowrap`으로 줄바꿈을 막아 두고, 실제 폭이
넘치면(`scrollWidth > clientWidth`) 그 비율만큼 글자 크기를 줄이도록
했다. 같은 이유로 `ResizeObserver` 자기관찰 루프를 여기서도 안 썼다.

## 검증

- `npm run typecheck` — 매 단계마다 통과 확인.
- **전부 dev 서버 + Playwright 스크린샷으로 실제 렌더를 보고 확인했다** —
  이 프로젝트의 기존 관행("화면을 봐야만 안다")을 그대로 따랐다. 특히
  칩 크기 버그는 `page.evaluate()`로 `getBoundingClientRect()` 실측값을
  같이 받아 눈으로 보는 것 이상으로 확정했고, 마지막 버그는
  `MutationObserver` + 콜스택 추적까지 동원했다.
- 10개 언어를 하나씩 켜서 간판·환경설정 화면을 스크린샷으로 순회
  확인했다(한국어·영어·일본어·중국어 간/번체·몽골어·포르투갈어 브라질/
  포르투갈·스페인어·이탈리아어).

## 이번 범위 밖 (다시 볼 자리)

- **9개 비한국어 JSON은 간판·환경설정 화면 키만 채워져 있다.** 나머지
  120여 키(메인·궁궐·병영·장터·전투 결과 등)는 전부 한국어로 물러난다 —
  "이 화면 다국어 지원 해줘"라고 화면 단위로 요청하면 그 화면이 쓰는 키만
  아홉 파일에 보태면 되고, 코드는 안 건드린다는 것이 이번에 세운 새 작업
  방식이다.
- **몽골어 번역은 원어민 검수가 필요하다** — 자신 있게 옮긴 나머지
  여덟 언어와 신뢰도가 다르다.
- **더빙 언어 매핑(`dubLangFor`)은 아직 아무 재생 코드도 안 부른다** —
  고유기술 성우 대사 재생기 자체가 이 저장소에 없다. 그 자리가 생기면
  `i18n/index.ts`의 이 표를 그대로 쓰면 된다.
- **몽골어(키릴 문자) 히어로 폰트가 시스템 세리프로 물러나 있다** — 맞는
  무료 붓글씨/장식 서체를 못 찾았다. 더 화려한 것을 원하면 폰트 후보를
  다시 찾아봐야 한다.
- **`useTwoChipSize`/`useFitText`는 지금 `SettingsModal.tsx` 안에만
  있다.** 다른 화면에서도 "번역마다 버튼 크기가 다르다"·"제목이 두 줄로
  접힌다" 같은 문제가 나오면 이 두 훅을 공용 자리로 옮기는 것을 고려할
  것 — 지금은 딱 이 화면 하나가 필요해서 지역적으로 뒀다.
- **`docs/삼국 약식 체스.pptx`가 이 세션 시작 전부터 수정된 상태였다** —
  이번 커밋에는 포함하지 않았다(`docs/*.pptx`는 읽기 전용 규칙). 누가 왜
  건드렸는지는 확인이 필요하다.

## 새 대화로 이어갈 때

- 다국어를 계속 채워 나가려면: 화면 이름을 말하면 그 화면이 쓰는
  `StringKey`들을 찾아 `strings/{9개 언어}.json`에 보태는 흐름이면 된다.
- 환경설정 팝업 디자인은 이번 세션에서 사실상 마무리됐다 — 추가 피드백이
  없으면 다음은 다른 화면(궁궐·병영·장터 등)의 화풍 리스킨이나, 나머지
  화면의 다국어 채우기가 자연스러운 다음 걸음이다.
