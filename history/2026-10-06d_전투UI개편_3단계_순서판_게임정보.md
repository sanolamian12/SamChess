## 2. 만든 것

- **`ui/orderPanel.ts`** — 엔진의 `turnForecast()`를 그대로 그린다. 예보는 **상태 객체가 바뀔 때만** 다시 부르고,
  매 프레임에는 WT 글자만 고친다(예보 시각 + 화면 지연 `state.time − displayTime` — 옛 카드 · 타일 게이지와 같은 보정).
  표시등은 `skillStatus()` 값을 `data-state`로 건다. 줄 클릭 → 씬의 `focusFromOrder`, 표시등 클릭 → `StatusPopup.showRaw('skill')`
  (전파를 끊어 카메라와 겹치지 않는다).
- **`ui/gameInfo.ts`** — 전투 N일차 · SP(정수) · 턴오버(`state.skips`) · 남은 시간(`Playback.remainingSec`, AI는 `null` → 「-」).
  단추 하나가 [항복](내 차례) ↔ [턴 가져오기](그 밖)로 바뀐다. ⋯(기록)은 임시로 귀퉁이에.
- **`BattleScene`** — 옛 `cardFocus`를 `orderFocus`로 되살렸다(카메라 3순위, 연출 · 확인창 다음). `selectUnit`이 언제나 풀고
  `focusFromOrder`만 다시 세우는 순서도 옛 것 그대로다(뒤집으면 팝업을 닫아도 확대가 남는다). 손으로 옮긴 화면이면 자동으로 되돌린다.
  주사위가 굴린 동점 무리를 `diceTied`로 들고 있다가 `dice.active` 동안 순서 판에 넘긴다. `#top[data-mode=deploy|battle]`.
- [항복]을 `SystemLog`(기록 안)에서 뺐고, 커맨드 패널의 「턴 넘기기」 단추를 지웠다(상대 차례엔 안내 문구만 — 4단계가 갈음).
- 문구 7키 × 10언어(`hud.info.*` · `hud.takeTurn*` · `hud.order.title`). `hud.more`에서 「· 항복」을 뺐다.
- **데모에 `?deploy=1`** — 데모는 기본 배치로 곧장 전투에 들어가서 배치 중 위 칸에 **도달할 수 없었다**(스모크도 눈 확인도).
  `createDemoBattle(…, { deploy: true })`가 `createBattle()`의 배치 단계를 그대로 둔다.

## 3. 넘어진 곳

### 3-1. [턴 넘기기]가 한 번도 서버에 안 닿고 있었다

게임 정보에 [턴 가져오기]를 달며 `submit({t:'forceSkipTurn'})`을 따라가 보니, `Playback.submit()`이 **`awaitingInput`이 아니면
전부 버린다** — 그런데 상대 차례의 단계 이름이 바로 `aiThinking`이다. 커맨드 패널의 「턴 넘기기」는 켜져도 눌러 봐야 아무 일이 없었다.
켜지려면 온라인에서 실제로 20초를 기다려야 하고 AI 대전엔 마감이 없어, 스모크는 「꺼져 있다」만 확인해 왔다.
`forceSkipTurn`만 `aiThinking`에서 통과시키고 회귀를 붙였다(`transport.test.ts` — 수정을 되돌리면 「[턴 가져오기]를 버렸다」로 실패하는 것을 확인).

### 3-2. 줄 끝 — 1,700줄짜리 diff

키를 더하고 `hud.more`를 `sed -i`로 고쳤더니 `git diff --stat`이 JSON마다 1,700줄이 바뀌었다고 했다. 이 저장소의 i18n JSON은
**CRLF로 저장돼 있는데** git-bash의 `sed -i`가 LF로 바꿨다. 한편 Python으로 고친 `.ts`들은 거꾸로 CRLF가 됐다(Windows 텍스트 쓰기).
게다가 확인에 쓴 `grep $'\r'`이 CR을 못 봐서 한 번 더 헛돌았다. JSON은 되돌리고 Node `fs`로 이웃 줄의 줄 끝을 맞춰 다시 넣었고,
나머지는 HEAD의 줄 끝(LF)에 맞췄다. 바이트로 세는 것은 `python … .count(b'\r\n')`. CLAUDE.md에 적었다.

### 3-3. 일본어 스모크가 판 밖을 눌렀다

`resetView()`와 같은 `evaluate` 안에서 `worldView`를 읽어 **확대된 옛 화면**으로 좌표를 잡았다(y = −59). 기준 실행에서는 통과했다 —
내 차례 확대가 언제 끝나는지에 따라 붙었다 떨어지는 검사였다. 옮기고 한 프레임 기다린 뒤 잰다.

### 3-4. 주사위가 `networkidle`보다 먼저 끝난다

배치 중 반짝임을 보려고 `?deploy=1`을 `networkidle`로 열었더니 주사위(약 5.4초)가 이미 끝나 있었다. `domcontentloaded`로 열고 바로 지켜본다.

### 3-5. 결과 화면 뒤의 `null.dataset` — `smoke:meta`가 잡았다

처음엔 위 칸(`#top`)을 매 프레임 `getElementById`로 찾았다. 판이 끝나 결과 화면이 무대를 걷은 뒤에도 씬이 한두 프레임 더 돌아
`null.dataset`으로 콘솔 오류가 났다 — `smoke:ui`(데모 — 결과 화면이 없다)는 못 보고 **`smoke:meta`(항복 → 결과 화면)만** 잡았다.
다른 판들처럼 만들 때 한 번 잡아 두게 고쳤다(떨어져 나간 원소에 쓰는 것은 해가 없다).

### 3-6. `smoke:meta`의 도시 랭킹 필터 — 한 번 떨어졌다 (이번 변경과 무관)

첫 실행에서 「도시 5v5 AI 전적이 1/1/0이 아니다: 3/0/1」 — 필터를 바꾼 뒤 **고정 600ms**만 기다리고 읽어, 서버 왕복이 늦으면
옛 줄(3v3)을 읽는다. 다시 돌리면 통과한다. 랭킹 화면은 손대지 않았다 — 고치려면 「줄 글자가 바뀔 때까지」 기다리게 하면 된다(남겨 둔다).

## 4. 스모크

`tools/smoke_ui.ts`:

- 「HUD 한 줄」 → **게임 정보**: 날짜 형식 · SP가 상태의 내림과 같은가 · 턴오버 · AI의 남은 시간 「-」 · 단추가 차례에 맞는가 · `#hud`가 없는가.
- **순서 판**(새로): 5줄이 `turnForecast(state, 5)`와 같은가(Node에서 같은 엔진으로 다시 셈) · 지금 차례 줄 · WT 표기 · 표시등 = `skillStatus` ·
  진영 색 · 1 : 1. **줄 클릭** → `debugOrderFocus` · 카메라 칸 · 확대 · 살펴보기 · 테, 다시 누르면 풀림. **표시등 클릭** → 고유기술 설명, 카메라는 그대로.
- **게임 정보 [항복]** → 판이 끝나고 P2 승(내 차례를 기다린 뒤).
- **배치 중 위 칸**(새로, `?deploy=1&seed=1`): 줄 수 = 전원 = 예보 · `data-mode=deploy` · 게임 정보 숨김 · 위 칸 전체 · 두 열 ·
  주사위가 도는 동안 반짝이는 줄 수 = 동점 수, 끝나면 안 반짝인다.
- 기록 안에 [항복]이 **없는가**로 뒤집었고, 상대 차례 커맨드 단추 검사는 「단추 없음 + 게임 정보 [takeTurn-]」으로.
- **깨 보기** — `orderFocus` 세우기를 지우면 「카메라 대상이 null」, 반짝임을 끊으면 「반짝이는 줄이 0개 — 동점은 2명」으로 잡혔다.

`raid_play.ts` · `smoke_meta.ts`의 항복도 `.hud-more` → 게임 정보의 [항복]으로 옮겼다.
