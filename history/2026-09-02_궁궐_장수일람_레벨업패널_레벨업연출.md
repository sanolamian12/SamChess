# 2026-09-02 — 궁궐 화풍 통일 · 장수 일람 재설계 · 레벨업 패널 · 레벨업 연출

## 1. 요청

랭킹 화면(`OfficerRankingScreen` 등)에 이미 적용된 양피지·목판·금테 화풍을 궁궐
플로우(`PlaceScreen` → 장수 일람 → 장수 카드 → 레벨/스킬 관리) 전체에 일관되게
맞춰 달라는 요청으로 시작해, 한 화면씩 반복 피드백을 받으며 다음까지 확장됐다:
장수 일람의 검색·정렬·페이지네이션 재설계, 장수 카드 재사용, Level & Skills를
전면 화면에서 카드 위 이중 모달 패널로 전환, 포르투갈어 번역에서 터진 레벨업
배지 오버플로우 버그 수정, 마지막으로 레벨업 대상 표시의 "진급 강조"를 3프레임
애니메이션 도장으로 바꾸는 것까지.

## 3. Level & Skills — 전면 화면 → 카드 위 이중 모달 패널

기존에는 [레벨/스킬 관리]가 전면 화면(`LevelUpScreen`)으로 전환됐다 — 카드가
이미 보여준 그림·능력치·인물 소개를 다시 그리는, 화풍도 다른 옛 평면 화면이었다.
새로 만든 `LevelUpPanel.tsx`는 **카드를 떠나지 않고** 그 위에 겹쳐 뜬다.

- **이중 모달**: `.lvp-back`이 `.modal-back`보다 높은 `z-index`로 화면 전체를
  덮어, 뒤 카드의 [X]를 포함한 모든 컨트롤이 눌리지 않는다. 앞 패널만 조작된다.
- **위치**: 판의 윗변이 카드 그림(`.ofcard-art`)이 끝나는 지점과 정확히
  일치해야 했다 — 두 모달이 `position: absolute; inset: 0` 형제라 CSS만으로는
  안 되고, `useLayoutEffect`에서 `getBoundingClientRect()`로 실제 좌표를 재서
  `marginTop`으로 앉힌다.
- **내용 재구성**: HP·MP·AT·스탯 찍은 횟수·지원책/환술을 나눠 적던 것을
  "보유 책략" 버튼형 목록 하나로 합치고 학파는 색으로만 구분(지원책 초록,
  환술 보라). 레벨업/재설계 버튼은 조건부 enable 유지, 우상단 X로 닫는다.
  → 이후 5가지 폭 다듬기: (1) 개발용 카드+5/금화+10 치트를 `MarketScreen`으로
  이전(카드+5는 전체 장수 목록으로 확장), (2) 안내 글자 폰트 크기 통일, (3)
  "Lv1은 아직 올린 적이 없다" 문구 삭제, (4) [레벨 업]·[재설계] 버튼 화풍 통일,
  (5) 스탯 찍은 횟수 표시 재추가.
- `Picker`·`RespecModal`은 새로 그리지 않고 `LevelUpScreen.tsx`에서 `export`해
  그대로 재사용 — 두 화면이 따로 그리면 언젠가 어긋난다.

## 4. 레벨업 표시 버그 — 포르투갈어에서 뷰가 깨짐

레벨업 대상 행에 붙던 "레벨업" 텍스트 배지가 언어별로 길이가 달라, 포르투갈어
"Subir de nível"에서 카드 수 숫자와 이름 일부를 가려 뷰가 깨졌다(사용자 스크린샷
으로 확인). 언어 길이에 흔들리지 않는 **그래픽 신호**로 바꿨다: 줄 전체를 두르는
금테 프레임(`levelup_frame.png`) + 이름 옆 인장 아이콘.

프레임 적용은 세 차례 기법을 바꿨다:
1. 줄 자신에 `border-width`+`border-image` 직접 적용 → 레이아웃 높이가
   늘어나 다른 행과 간격이 달라짐.
2. `background: … 100% 100%`로 늘려 씌움(`_frame2`) → 정교한 코너가
   심하게 뭉개짐("그림이 엄청 깨진다"), `inset`이 음수라 가로 스크롤도 생김.
3. **`::before` 오버레이(레이아웃에 기여하지 않음) + `border-image` 9분할**
   (`_frame3`에서 정착) + `inset: 0`(오버플로우 방지) — 뭉개짐도 스크롤도 없음.
   기법은 유지한 채 그림만 사용자가 "안 예쁘다"고 판단해 원래
   `levelup_frame.png`로 되돌렸다. **교훈: 뭉개짐은 그림이 아니라 기법(늘려
   씌우기 vs 9분할) 탓이었다.**

## 5. 레벨업 도장 — 3프레임 애니메이션

프레임+인장 조합을 적용하고도 "Level up=진급 강조가 잘 안 난다"는 피드백을
받아, 먼저 어울리는 이미지 생성 프롬프트 3종(리본 배지·인장+화살/버스트·
금색 별 계급장, 작은 크기에서도 읽히는 굵은 실루엣 강조)을 제안했다. 사용자가
`assets/icons/stamp.png`(가로로 3프레임, 0.5초씩 재생 의도)를 만들어 왔다.

- `tools/build_ui.py`에 `build_sprite()` 추가 — 3프레임을 **합집합 알파
  경계상자**로 동시에 잘라(개별 트리밍 시 프레임마다 여백이 달라 재생 중
  미세하게 흔들린다) `public/icons/levelup-stamp.png`(384×128, 프레임당
  128×128)로 굽는다. 처음 구현에서 스프라이트 캔버스 크기를 리사이즈 전
  `side`값으로 잘못 잡아 2802×934의 텅 빈 캔버스가 나온 버그를 실측(Read로
  이미지 확인)으로 잡고, `ICON_SIZE * frames`로 고쳤다.
- `.ofc-levelup-seal`을 정지 `<img>`에서 `background-image` 스프라이트 +
  `steps(3)` 애니메이션(1.5초 주기)으로 바꾸고, 두 자리(`OfficerListScreen`의
  행, `RankingCommon`의 카드 버튼)의 JSX를 `<img src>`에서 `<span role="img">`로
  교체했다.
- **버그와 수정**: 종료 키프레임을 `background-position: 100% 0`으로 두면
  `steps(3)`이 만드는 세 단계값(0/33.3/66.7%)이 실제 프레임 경계(0/50/100%,
  `(요소폭−배경폭)×p` 공식에서 나온다)와 안 맞아 중간 프레임에서 두 그림이
  겹쳐 보였다. `100 × N/(N−1)` = **150%**로 종료 지점을 고쳐 해결 — Playwright로
  `getComputedStyle().backgroundPosition`이 정확히 `0% / 50% / 100%`로
  찍히는 것과 세 프레임이 겹침 없이 갈라지는 것을 스크린샷으로 확인했다.

## 7. 곁가지

- 새/변경된 i18n 키(`palace.*`, `officers.*`, `officer.*`, `levelup.*`,
  `respec.*`)를 매 단계 **10개 언어 전부**에 채워 넣었다 — `t()`가 누락 키를
  한국어로 조용히 대체하는 설계라 실행으로는 안 잡히는 공백이다. 그 와중에
  `zh_Hans`/`zh_Hant`의 `officers.col.grade`가 `officers.col.level`과 똑같은
  글자("等级")로 잘못 들어가 있던 기존 버그를 사용자 스크린샷으로 발견해
  같이 고쳤다("品级"로 분리).
- 개발용 치트(카드+5 전체 장수 목록, 금화+10)는 `MarketScreen`으로 옮기며
  디자인은 신경 쓰지 않았다 — 개발용이라는 성격 그대로.
- `assets/icons/`는 git에 없다(에셋 방침) — 이번에 커밋되는 것은
  `tools/build_ui.py`의 처리 로직과, 그 로직이 구운 결과물
  (`packages/client/public/icons/levelup-stamp.png` 등)뿐이다.
