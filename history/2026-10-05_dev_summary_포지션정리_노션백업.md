## 2. 밟은 것

### 2-1. 대량 병렬 전송은 출력 안전 필터에 걸린다 ★
History 30개 중 4개, 포지션 하위 52개 중 17개가 **본문을 보내는 도중 출력이 막혔다.** 조각을 4.5KB → 2.5KB로 줄여 다시 돌려도
에이전트 병렬로는 3개가 또 막혔다. 막힌 조각을 열어 보니 테스트 결과 표 같은 평범한 기록이었다.
그 3개를 **메인 세션이 조각 하나씩 순서대로** 넣자 39조각이 한 번도 안 막혔다 — 기획자가 「대량으로 처리하다 보니 막힌 것 아니냐」고 짚은 대로다.
**이제의 규칙** — 노션에 긴 글을 옮길 때는 처음부터 한 곳에서 작은 조각으로 차례차례 넣는다. 에이전트 14개 동시 투입은 하지 않는다.

### 2-2. 권한 판정 거부 → 허용 규칙
한 묶음(클라이언트 W07~W09 · 디자인 W01~W02)은 자동 권한 판정이 노션 수정을 거부했다(사유 「Excess Sensitive Detail」).
우회하지 않고 멈춰 알렸고, 기획자 요청으로 `.claude/settings.json`의 `permissions.allow`에 넣었다:
`mcp__claude_ai_Notion__notion-fetch` · `notion-create-pages` · `notion-update-page`.

### 2-3. 노션이 바꿔 저장하는 것
- 표 칸이 `+ `로 시작하거나 문장 중간의 ` + `가 **글머리표(•)**가 된다. History 2건은 `\+`로 고쳤고, 시스템 README 9월 W06 칸 ·
  시스템 W01 · 서버 W06의 것은 **기획자 판단으로 그대로 둔다**.
- 언어 없는 코드 블록에 `javascript`가 붙고, `CLAUDE.md`가 자동 링크가 되고, 굵게 안의 인라인 코드가 `****`로 쪼개진다. 보이는 내용은 같다.

### 2-4. 에이전트가 도중에 종료되면 「어디까지 들어갔나」를 따로 재야 한다
두 에이전트가 API 안전 장치로 강제 종료돼 보고 없이 끝났다. 읽기 전용 확인 에이전트로 페이지마다
