# 2026-08-16 — 배경이 천천히 움직인다

> 이 문서는 **왜 그렇게 정했고 어디서 넘어졌는지**를 적는다.
> 현재 상태의 정본은 [`HANDOFF.md`](../HANDOFF.md), 구현 기준은 [`Design/GDD.md`](../Design/GDD.md) §8.1.
> 배경 그림 자체를 붙인 경위는 [전날 기록](2026-08-15_간판_도시_자리_화면.md)에 있다.

## 1. 무엇을 했나

기획자 요청 — **「각각의 사진이 2초나 3초 간격으로 약간씩 움직이는 형태로」.**

간판·도시·궁궐·병영·장터의 배경이 이제 **2.6초마다 자세를 하나씩 짚으며** 아주 조금
밀리고 확대된다. 여덟 자세를 돌아 한 바퀴 약 21초다.

**룰 엔진도 그림 파이프라인도 건드리지 않았다.** 화면 층뿐이다 —
`npm run backgrounds`가 굽는 열넉 장은 그대로고, 어느 그림을 띄울지 정하는
`backdrop.ts`도 그대로다. **움직임은 그 뒤에 얹히는 별개의 층이다.**

| | 붙은 것 | 파일 |
|---|---|---|
| 1 | 여덟 자세표 + `transform` 계산 (순수 함수) | `screens/backdropMotion.ts` **(새 파일)** |
| 2 | 걸음 세기 — 시계와 「동작 줄이기」를 읽는 유일한 곳 | `screens/useBackdropDrift.ts` **(새 파일)** |
| 3 | 그림을 `.scr-art` 층으로 분리 | `screens/ScreenChrome.tsx` |
| 4 | 층·쌓임 순서·전환 | `style.css` 「배경 화면」 절 |
| 5 | 회귀 4건 | `client/test/backdrop.test.ts` |
| 6 | 스모크 — 그림만 움직이는가 | `tools/smoke_meta.ts` |

## 2. 이 세션에서 정해진 것

- **간격은 2.6초** — 기획자가 말한 「2초나 3초」의 가운데. `DRIFT_MS` 한 곳이다.
- **쉬지 않고 흐르는 대신 자세를 짚는다.** 영상 편집의 켄 번스는 한 방향으로 계속
  흐르는데, 기획자 지정이 「간격」이라 **여덟 자세를 하나씩 서며** 간다.
  `ease-in-out`이라 자세마다 부드럽게 섰다 다시 떠난다 — 21초에 한 바퀴.
- **밀리는 거리는 최대 1.5%** (700px 화면에서 약 10px). 「약간씩」이 그 정도다.
- **편성 화면(`.scr-dim`)은 멈춰 둔다.** 거기 그림은 「여기가 병영이다」만 말하고
  거의 불투명한 어둠 아래로 물러나는 자리라, 움직여도 보이지 않는다.
- **「동작 줄이기」를 켠 사용자에게는 움직이지 않는다.** 배경이 흔들리면 어지러운
  사람이 있고, 브라우저가 그 뜻을 `prefers-reduced-motion`으로 알려 준다.

## 3. 왜 그렇게 만들었나

### 그림을 화면 div에서 떼어 냈다 ★

원래 배경은 `.scr-bg` **그 자체**의 `background-image`였다. 전날 기록에 그렇게 정한
이유까지 적혀 있다 — 「`<img>`로 깔면 쌓임 순서를 일일이 정해야 한다」.

**움직임이 그 전제를 뒤집었다.** 그 div가 제목·기어·ID칸·단추를 전부 담고 있어서,
거기에 `transform`을 걸면 **글자와 단추가 함께 흔들린다.** 배경만 움직이려면
그림이 제 층에 있어야 한다.

그래서 예전에 피했던 대가를 지금 치른다 — 쌓임 순서를 손으로 정하게 됐다.

```
.scr-art (z 0)   움직이는 그림
.scr-bg::before  (z 1)   위아래 어둠
.scr-bg > *      (z 2)   제목 · 내용
```

**셋은 함께 봐야 뜻이 통한다.** 하나만 지우면 어둠이 글자를 덮거나 그림이 어둠을
덮는다 — 어느 쪽도 오류가 나지 않고 화면만 이상해진다.

> `.scr-bg > *`가 `.scr-art`에도 걸리므로 `.scr-bg > .scr-art`로 **더 구체적으로**
> 눌러 둔다. 순서가 아니라 구체성으로 이긴다 — 규칙 순서를 옮겨도 안 깨지도록.

### 확대는 장식이 아니라 안전 여백이다 ★

배율 1인 그림을 옆으로 밀면 **반대쪽에 바탕색 띠가 드러난다.** 먼저 1.06배로 키워
두면 한쪽에 `(1.06−1)/2 = 3%`의 여유가 생기고, 그 안에서만 움직인다.

지켜야 하는 부등식은 하나다.

```
밀리는 거리(s × x / 100)  <  여백((s − 1) / 2)
```

`transform: scale(s) translate(x%, y%)`에서 **`scale`을 먼저 적었으므로** 밀리는
거리도 배율만큼 커진다. 순서를 뒤집으면 이 계산이 조용히 어긋나므로 테스트가
문자열 순서까지 고정한다.

> **이건 이미 밟아 본 자리다.** 「띠 그림을 등분해 자르면 옆 칸이 딸려 온다」와
> 증상이 똑같다 — 화면에서는 **「끝에 이상한 줄이 있네」**로만 보인다.
> 그래서 여덟 자세를 **전부** 검산하는 테스트를 먼저 썼다.

### 자세를 난수로 고르지 않는다

「자연스럽게」를 노리면 난수가 먼저 떠오른다. 쓰지 않았다.

굴리면 **여백을 넘는 자세가 어쩌다 한 번** 나오는데, 그건 재현이 안 된다.
스크린샷 한 장으로는 영영 못 잡고 「가끔 오른쪽에 줄이 보인다」는 제보만 남는다.
정해진 여덟 자세를 돌면 테스트가 **전부** 검산할 수 있다.

`backdropMotion.ts`는 시계도 난수도 모른다 — `backdrop.ts`가 `bandForHour(h)`로
시각을 밖에서 받는 것, 룰 엔진이 `Date.now()`를 금지하는 것과 같은 결이다.
시계를 읽는 것은 `useBackdropDrift.ts` 하나뿐이고, 그 파일만 React를 안다
(`i18n/index.ts` ↔ `i18n/useLang.ts`와 같은 갈래).

### 걸음 수를 0으로 되돌리지 않는다

`step`은 계속 늘어나는 정수이고, 여덟으로 접는 것은 `driftPose()`가 한다.
`0`으로 되감으면 **그 한 번만 이동 거리가 커져 그림이 튄다.**

### 머무는 시간과 옮기는 시간을 같게 뒀다

`transition-duration`이 `DRIFT_MS`와 같아서 한 걸음이 끝나는 순간 다음 걸음이
시작된다. 옮기는 시간을 짧게 하면 「움직였다 → 멈췄다」가 반복되어 **끊겨 보인다.**
지금은 `ease-in-out` 덕에 자세마다 속도가 0에 가까워졌다 다시 붙으므로,
「간격」은 느껴지되 끊기지는 않는다.

## 4. 밟은 지뢰 ★

### 스모크가 그림을 화면 div에서 찾고 있었다

층을 뗀 직후 `smoke:meta`가 **첫 항목에서 막혔다.**

```
✗ 간판(night) 배경 그림이 지정되지 않았다 (.scr-title)
```

`backdropOf()`가 `.scr-title`의 `background-image`를 읽는데, 그림이 `.scr-art`로
옮겨 갔으니 빈 값이다. 지금은 `:scope > .scr-art`가 있으면 그쪽을, 없으면 제
자신을 본다 — 층이 없는 화면(편성의 `.scr-dim`)도 있어서다.

> **다행히 이번엔 스모크가 곧바로 잡았다.** 전날 「스모크가 옛 길을 그대로 걷고
> 있었다」와 같은 자리인데, 그때는 화면 골격이 바뀌어 경로가 막힌 것이었고
> 이번엔 **검사 대상이 한 층 아래로 내려간 것**이다. 어느 쪽이든
> **화면 구조를 바꾸면 스모크도 함께 본다.**

### 「글자가 안 흔들린다」는 스크린샷으로 확인할 수 없다

자세가 최대 10px이라 **스크린샷 두 장을 눈으로 비교해서는** 글자가 1~2px 따라
움직여도 알아채지 못한다. 층을 도로 합치는 되돌림이 언제든 조용히 들어올 수 있는
자리다. 그래서 스모크가 **좌표로** 잡는다.

```
✓ 배경 움직임 — 걸음 0 → 1, 글자는 제자리
```

그림의 `transform`은 **달라져야** 하고, 제목의 `getBoundingClientRect()`는
**같아야** 한다. 둘을 한 검사에 묶었다.

> CLAUDE.md의 「스모크는 글자가 아니라 `data-*`로 건다」에 맞춰 걸음 수를
> `data-drift`로 내보낸다.

### 여백 검산은 눈이 아니라 훑기로 확인했다

테스트가 여덟 자세를 검산하지만 그건 **계산**이고, 실제 배치에서 그림이 틀보다
작아지는 일이 없는지는 다른 문제다. 브라우저에서 **한 바퀴(21초)를 0.4초마다
훑어** 걸음 0~8을 전부 지나며 틈을 쟀다.

```
프레임      : 700×1400
본 걸음     : 0,1,2,3,4,5,6,7,8
최악의 틈   : -12.043 px — 여백 안 드러남 ✔
```

음수는 **그림이 틀 밖으로 그만큼 넘쳐 있다**는 뜻이다. 가장 불리한 자세에서도
12px 남았다.

> **프레임 700px으로 봤다.** 전날 「저해상도 원본을 그대로 썼다」에서 얻은
> 교훈 그대로다 — 480px에서는 어긋남이 잘 안 보인다.

## 5. 구조

```
screens/backdrop.ts          어느 그림인가 (시각 · 도시 레벨)   ─┐
screens/backdropMotion.ts    어떤 자세인가 (여덟 자세 · 안전 여백) ├─ 둘 다 순수 함수
                                                                 │   시계도 난수도 모른다
screens/useBackdropDrift.ts  지금 몇 번째 걸음인가 ───────────────┘   ← 시계는 여기만
  ↓
screens/ScreenChrome.tsx     .scr-art 층에 그림 + transform
  ↓  style.css               그림 0 → 어둠 1 → 내용 2 · transition 2.6s ease-in-out
TitleScreen · MainScreen · PlaceScreen
```

**「어느 그림인가」와 「어떻게 움직이는가」를 갈라 놓았다.** 그림을 갈아 끼우는 일
(시간대 추가·자리 추가)과 움직임을 손보는 일이 서로를 건드리지 않는다.

### 손잡이

| 상수 | 지금 | 무엇 |
|---|---|---|
| `DRIFT_MS` | `2600` | 한 자세에 머무는 시간. 줄이면 부산해진다 |
| `DRIFT_ZOOM` | `1.06` | 안전 여백. **자세를 키우면 이것도 함께 올린다** |
| `DRIFT_PATH` | 여덟 자세 | `x`·`y`는 최대 1.5%, `z`는 1.000~1.018 |

`DRIFT_PATH`만 키우고 `DRIFT_ZOOM`을 그대로 두면 **테스트가 먼저 걸린다.**

## 6. 확인

```
npm run typecheck  → exit 0
npm test           → 218/218   (배경의 움직임 4건 추가)
npm run smoke:meta → 통과 — 「그림은 움직이고 글자는 제자리」 포함
```

새 테스트 4건.

| 확인 | 왜 |
|---|---|
| 밀어내는 거리 < 확대 여백 (여덟 자세 전부) | 넘으면 바탕색 띠가 드러난다 |
| 걸음은 늘고 자세만 감긴다 (음수 포함) | 되감으면 그 한 번만 그림이 튄다 |
| 한 걸음이 2% 미만, 간격이 2~3초 | 「약간씩」의 정의 |
| `transform`은 `scale`이 먼저 | 순서를 뒤집으면 여백 계산이 어긋난다 |

눈으로도 봤다 — **프레임 700px**에서 몇 초 간격으로 두 장을 찍어, 성문과 산줄기는
확실히 옮겨 갔는데 제목·「입장」·「계정 생성」은 픽셀 하나 움직이지 않았다.
