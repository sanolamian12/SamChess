# 2026-09-03 — 전적 보기, 카드 위 모달 패널로 전환

> 현재 상태는 [`HANDOFF.md`](../HANDOFF.md)에, 사양은 [`Design/GDD.md`](../Design/GDD.md)에
> 있다. 이 문서는 **왜 그렇게 정했고 무엇을 확인했는가**만 적는다.

## 1. 요청

장수 일람(`OfficerListScreen`) → 장수 카드(`OfficerCardModal`) → [전적 보기]가
예전엔 전면 화면(`RecordsScreen`)으로 넘어갔다 — [레벨/스킬 관리]가 `LevelUpPanel`
(2026-09-02)로 갈아 끼워지기 전과 같은 처지였다: 카드가 이미 보여준 정보를
다시 그리는, 화풍도 다른 옛 화면. `LevelUpPanel`과 같은 「카드 위에 겹쳐 뜨는
모달」 틀로 바꿔 달라는 요청으로 시작해, 스크린샷 피드백을 받으며 세부를
다듬었다.

## 2. `RecordsPanel.tsx` — 카드 위 셋째 모달

`LevelUpPanel`이 다진 `.lvp-back`/`.lvp-modal` 틀을 그대로 쓴다. 내용(기물별
표·모드별 합·최근 이력)은 `RecordsScreen.tsx`·`@samchess/meta`(`pieceRows`·
`modeRows`·`totalTally`·`recentMatches`)가 이미 낸 값을 그대로 그린다 — 화면이
숫자를 다시 세지 않는다는 원칙 그대로.

- `OfficerListScreen`에 `viewingRecords` 상태 하나를 더해 카드 위에 띄운다.
  `onRecords` prop은 `LevelUpPanel` 도입 때 `onLevels`가 지워진 것과 같은
  이유로 지웠다(`App.tsx` 호출부도 함께).
- `RecordsScreen.tsx`가 쓰던 `LogRow`·`RESULT_KEY`·`RECENT`를 `export`해
  재사용 — 이력 한 줄을 두 파일이 각자 그리면 언젠가 어긋난다.

## 3. 카드 오버레이 위치 훅을 공유로 뽑았다

`LevelUpPanel`이 "판의 윗변 = 카드 그림이 끝나는 지점"을 재던
`useLayoutEffect`+`getBoundingClientRect()` 로직을 `RankingCommon.tsx`의
`useOfficerCardOverlayPos()`로 옮겼다 — 전적 보기 판이 두 번째로 같은 계산을
필요로 하게 됐을 때, 각자 재게 두면 한쪽만 고쳐 어긋나는 패턴이 되므로.

- 기준점을 `'art'`(카드 그림 아래, `LevelUpPanel`의 기본값)·`'top'`(카드 자체가
  시작하는 지점) 둘로 갈랐다. 전적 보기 판은 `'top'`을 쓴다 — 표가 셋(기물별·
  모드별·최근 이력)이라 내용이 더 길어, 카드 그림 아래부터 시작하면 자주
  잘렸다("이 패널은 좀 더 길어도 되니까, 시작점을 장수 정보 패널과 똑같은
  y 위치에서" 피드백).

## 4. 필터 UI — 버튼 줄 → [정렬 필터]와 같은 틀

전체/온라인/AI 세 버튼을 늘 펴 두던 첫 구현을 "장수 일람의 필터 버튼과 필터
상태 표출 버튼과 같은 구성으로" 피드백을 받아 바꿨다 — 지금 기준을 보여주는
나무판(`.ofc-sort-current`) + 누르면 뜨는 팝업(`SortMenu`).

- `SortMenu`(`RankingCommon.tsx`)의 버튼 글자가 `t('ranking.sortBtn')`("정렬
  필터")로 고정돼 있었는데, 이건 정렬이 아니라 필터라 그대로 쓰면 어색하다 —
  `buttonLabel?: string` 옵션을 추가해 기존 네 자리(랭킹 셋 + 장수 일람)는
  그대로 두고 전적 보기 판만 "필터"(`records.filterBtn`, 새 i18n 키)로 바꿨다.

## 5. 총 출전/3v3/5v5 — 문장에서 표로

`sumText()`가 내던 "12전 · 7승 1무 4패 · 적격파 19" 한 줄짜리 문장을 "위 기물별
출전 표와 같은 표 형식으로" 피드백을 받아 표(`.rec-table.rec-sumtable`)로
바꿨다. 승·무·패를 각자 칸으로 가르니 문장 조립 함수(`sumText`)를 더 안 쓰고
`RecordTally`의 필드(`plays`·`wins`·`draws`·`losses`·`kills`)를 그대로 한 칸씩
그린다 — `RecordsScreen.tsx`(전면 화면, 이번엔 손대지 않았다)는 여전히 그
문장을 쓴다.

- 열이 여섯(구분·출전 수·승·무·패·적격파)이라 기물 표(넷)보다 폭 배분을 다시
  잡았다 — 「승/무/패」는 한 글자라 좁게, 「출전 수」만 기물 표와 같은 폭.
- "총 출전" 줄은 강조색(짙은 붉은 먹색 + 굵게, `.rk-mine .cap`과 같은 계열)을
  유지했다.
- 이어서 "3v3·5v5도 한 번도 출전한 적이 없으면 기물별 표처럼 흐린 폰트로"
  피드백을 받아 `data-plays={tally.plays}`를 붙였다 — 기물 표가 이미 쓰던
  `.rec-row[data-plays="0"] { opacity: .45 }` 규칙을 그대로 물려받는다(새 CSS
  없이 기존 신호 재사용). "총 출전" 줄은 대상이 아니다.

## 6. 양피지 위 색·모양 재작업

`.rec-*` 클래스가 원래 전면 화면(`RecordsScreen`, 어두운 배경) 기준으로 잡은
색이라, 이 판의 양피지(`panel-ledger.png`) 위에서는 다시 칠해야 했다 —
`LevelUpPanel`이 겪었던 `.lv-tap` 문제와 같은 결.

- **상자 → 종이 위 글씨**: 기물 표·이력 줄의 어두운 상자 배경을 걷어내고
  `.ofc-row`처럼 얇은 붓선 구분선만 남겼다("옅게 버튼 형식으로 되어 있는 것을
  걷어내고 텍스트가 바로 종이에 써져있는 것 같이 하자"). 출전 0인 행의
  옅은 회색(`opacity: .45`)은 그대로 뒀다 — 그건 이미 잘 보인다는 평가였다.
- **흰색·옅은 노란색 → 먹색**: `.place-panel`의 기본 글자색(`#e9dfca`, 어두운
  화면 기준)을 그대로 물려받던 자리(섹션 캡션·요약 숫자)와, 옅은 금색이던
  "종 출전"·승패 배지·기대 승률 색을 전부 먹색·짙은 색 계열로 다시 칠했다.
- **이력 표 텍스트 깨짐**: 여덟 칸짜리 이력 표가 전면 화면(훨씬 넓다)을
  기준으로 잡은 그리드라, 이 판(최대 21rem)에서는 `1fr` 칸(부대)이 짓눌려
  글자가 겹쳐 보였다. 행에 최소 폭을 주고 `.rec-rows`를 가로 스크롤하게 해
  칸이 눌리지 않게 했다.
- **빈 이력**: 최근 대전이 없으면 여덟 칸 머리글까지 통째로 안 그리고
  "아직 치른 대전이 없다." 문구만 띄운다 — 값 없는 머리글이 좁은 폭에서
  깨져 보이던 것의 근본 원인을 없앴다("최근 대전이 없다면 아예 이 틀을
  보여주지 말고, 문구만").
- **간격**: 기물별 표와 총 출전 표 사이가 `.place-panel`의 공용
  `gap: .35rem`만으로 붙어 있어("지금은 딱 붙어있거든") `margin-top: .5rem`을
  더했다.
- **안내문 삭제**: "AI 대전도 함께 센다. 아래에서 갈라 볼 수 있다."
  (`records.note`) 줄이 "이제 필요없을 것 같다"는 판단으로 이 패널에서만
  뺐다 — i18n 키 자체는 전면 화면(`RecordsScreen.tsx`)이 여전히 쓰므로
  안 지웠다.

## 7. 검증

- `npm run typecheck` · `npm test` — 매 단계 통과, 실패 3건은 이 작업 이전부터
  있던 무관한 것(i18n 폴백 테스트 2건 · Python 추출 빌드 1건)과 같은 개수
  (회귀 없음).
- 사용자가 실제 화면 스크린샷을 단계마다 첨부해 확인 — 별도의 Playwright
  구동은 하지 않았다(로그인·서버 인프라가 필요해 이 세션에서는 준비돼
  있지 않았다).

## 8. 곁가지

- 새 i18n 키(`records.filterBtn`·`records.col.category`)는 한국어(`ko.json`)
  에만 추가했다 — `t()`가 누락 키를 한국어로 조용히 대체하는 기존 설계를
  그대로 따른 것이다(다른 아홉 언어는 비워 뒀다, 다국어 배선은 후속 작업).
