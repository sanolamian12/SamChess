# 2026-09-01 — 지형 상호배타: 성지·화계·수계는 서로 덮어쓰지 못한다

> **여기는 「그때 왜 그렇게 정했고 어디서 넘어졌는가」다.** 지금의 사양은
> [`Design/GDD.md`](../Design/GDD.md) §3.8, 효과 정의는
> [`tools/extract_data.py`](../tools/extract_data.py)의 `TACTIC_EFFECTS`에 있다.

## 1. 무엇을 왜 바꿨나

사용자 질문에서 시작: "손권이 「수성지주」로 1×1 판에 성을 쌓았을 때, 적군이 그 위에
불 지형이나 물 지형을 만들 수 있나?" — 확인해 보니 **화계만** 가능했다.

- 「수계」는 `filter: 'empty'`가 걸려 있어 유닛도 지형도 없는 빈 칸에만 깔린다 —
  이미 안전했다.
- 「화계」는 유닛이 선 칸에도 깔 수 있어야 해서(GDD §12 표: "화계는 유닛이 선 칸에도
  가능") 애초에 필터가 아예 없었는데, 그 부작용으로 **지형이 있는 칸도 그냥 덮어쓸
  수 있었다.** 원인은 `createTerrain` 실행부(`effects.ts`)가 대상 칸의 기존 지형을
  무조건 지우고 새 지형을 얹기 때문 — 막는 자리는 순전히 조준 검증(`resolveTacticTarget`)
  쪽인데, 그게 「화계」에는 하나도 없었다.

1차 수정(같은 세션 앞부분)에서 화계를 막은 뒤, 사용자가 **반대 방향도** 요청했다 —
화계·수계가 있는 칸에는 「수성지주」도 못 짓게. 세 지형이 완전히 상호 배타적이어야
한다는 뜻이라 필터 하나를 세 곳 모두에 통일해서 적용했다.

---

## 2. 구현

`TargetSpec`의 타일 필터를 둘로 갈랐다 — 기존 `'empty'`(유닛도 지형도 없어야 함,
수계 전용)에 `'noTerrain'`(유닛은 있어도 되지만 지형은 없어야 함)을 신설해, 화계처럼
"유닛 위에는 깔되 다른 지형 위에는 못 까는" 경우를 표현했다.

| 붙은 것 | 자리 |
|---|---|
| `TargetSpec`에 `filter?: 'empty' \| 'noTerrain'` 추가 | [`rules/src/types.ts`](../packages/rules/src/types.ts) |
| `resolveTacticTarget` — `'empty'`·`'noTerrain'` 둘 다 "이미 지형이 있으면 거부", 유닛 검사는 `'empty'`에만 남김 | [`rules/src/effects.ts`](../packages/rules/src/effects.ts) |
| 「화계」·「수성지주」 효과 정의에 `filter: 'noTerrain'` 추가 (「수계」는 이미 `'empty'`라 그대로) | [`tools/extract_data.py`](../tools/extract_data.py) |
| `npm run extract`로 `tactics.json`·`uniqueSkills.json` 재생성 | — |
| 회귀 — 화계·수계가 성지를 못 덮어씀 / 성지가 화계·수계를 못 덮어씀, 양쪽 다 추가 | [`rules/test/tactics.test.ts`](../packages/rules/test/tactics.test.ts), [`rules/test/skills-s.test.ts`](../packages/rules/test/skills-s.test.ts) |

### 설계상 자연히 풀린 것

- `resolveTacticTarget`이 필터별로 "지형 검사"와 "유닛 검사"를 분리해 두 번째 필터값을
  받는 형태였다면 처음부터 이 문제가 안 생겼을 것 — 하지만 `'empty'` 하나로 두 조건을
  같이 묶어 표현하던 게 애초 설계였고, 「화계」가 그 필터를 통째로 뺀 것이 부작용의
  근원이었다. `'noTerrain'`을 얹는 것만으로 기존 `'empty'` 동작을 하나도 안 건드리고
  깔끔하게 풀렸다.
- 「수성지주」에 같은 필터를 붙이는 것도 대칭이라 특별한 분기 없이 그대로 적용됐다 —
  손권도 이제 화계·수계·다른 성지 위에는 지을 수 없다(원래 손권 자신이 실수로 자기
  화계 위에 성지를 짓는 것도 막힌다는 뜻인데, 이건 부가 효과이고 요청받은 건 아니지만
  대칭을 지키는 쪽이 필터 하나로 더 단순했다).

---

## 3. 결과

성지·화계·수계 셋이 이제 완전히 배타적이다 — 어느 쪽이든 먼저 깔린 칸 위에는 다른
지형을 겹쳐 지을 수 없다. `npm run typecheck`·`npm test` 통과(기존부터 있던 무관한
실패 3건 — 다국어 테스트 2건, 에셋 경고로 인한 추출 검증 1건 — 은 그대로, 이 세션
변경과 무관함을 `git stash`로 재확인했다).
