# 2026-09-11 — 간판 화면 재구성: 단추 셋과 입장 팝업

> 이 문서는 **한 대화 세션의 기록**이다. 프로젝트의 현재 상태와 규칙은
> [`HANDOFF.md`](../HANDOFF.md)와 [`Design/GDD.md`](../Design/GDD.md)가 정본이며,
> 여기는 "무엇을 왜 그렇게 정했는가"와 "어디서 넘어졌는가"를 남긴다.
>
> 같은 날 앞선 「전투 UI 다국어」 세션과는 별도의 대화다.

## 왜 이 작업인가

간판 화면에 이메일 칸 · 비밀번호 칸 · [입장] · [계정 생성] 넷이 그대로 서 있었다.
기획자가 **비밀번호 분실 대응 같은 것을 더 붙일 자리가 없다**고 짚었다 — 하나만
더 얹어도 화면이 꽉 차 보인다. 그리고 **언어 설정이 가장 먼저 와야 한다**고 봤다
(국제적으로 공급할 게임이라, 무슨 글자로 읽을지가 로그인보다 먼저다).

그래서 첫 화면은 **단추 셋**만 남기고, 로그인에 딸린 것은 전부 팝업으로 내렸다.

```
① 언어 (Language)   ← LanguageModal
② 크레딧 보기        ← CreditsModal (화면은 아직 없다)
③ 입장               ← LoginModal — 이메일·비밀번호·[비밀번호 초기화]·[계정 생성]
```

셋의 화풍은 전부 기존 것 그대로다 — ①②는 「계정 생성」이 쓰던 참나무 목판,
③은 「입장」이 쓰던 옥색 목판(`primary`), 팝업은 환경설정의 두루마리·청동 명패.
팝업 셋의 **[닫기]는 붉은 판**(`btn-forcedcancel.png`)이다 — 대장간의 [제작 취소]·
[장비 회수]가 이미 쓰는 그림·같은 9분할 값 그대로라 새로 굽지 않았다. 환경설정의
[닫기]는 **옥색 그대로 뒀다**(지정이 간판 팝업 셋에 대한 것이었다) — 그래서 셋을
이름으로 하나씩 적는다, `[data-action$="Close"]`로 묶으면 `settingsClose`가 딸려 온다.

## 한 일

### 1. 화면과 팝업 셋

| 파일 | |
|---|---|
| `screens/TitleScreen.tsx` | 단추 셋 + `modal` 상태 하나(`'login' \| 'language' \| 'credits' \| null`). 판정이 전부 빠져 나가 화면이 짧아졌다 |
| `screens/LoginModal.tsx` | 로그인·회원가입·비밀번호 재설정 셋. 붓 아이콘 입력칸이 여기로 따라 내려왔다 |
| `screens/LanguageModal.tsx` | 환경설정의 언어 줄과 **같은 칩·같은 `setLang()`**. 첫 화면에서 바로 닿는 지름길이다 |
| `screens/CreditsModal.tsx` | 「크레딧 화면은 준비 중이다」 한 줄. 「눌리는데 아무 일도 없는 단추」로 두지 않는다 |
| `screens/useFitText.ts` | `SettingsModal` 안에 있던 훅을 꺼냈다 — 청동 명패가 넷이 됐으므로 |

**팝업 상태는 값 하나다** — 불리언 셋으로 두면 「둘 다 떠 있다」가 표현 가능해진다.

**`data-action="enter"`는 팝업 안의 [입장]이 그대로 물려받았다.** 팝업을 여는
단추는 `loginOpen`이라 이름이 안 겹친다 — 스모크·도구 네 개는 **여는 클릭 한 줄**만
보태면 됐다.

### 2. 비밀번호 초기화 (`meta/auth.ts`의 `resetPassword`)

Supabase의 `/auth/v1/recover`를 그대로 부른다. 두 가지를 주석에 적어 뒀다.

- **없는 계정에도 200이 온다** — 어느 이메일이 가입돼 있는지 알려 주지 않으려는
  Supabase의 의도다. 그래서 화면은 「보냈다」까지만 말할 수 있다.
- **재설정 화면은 아직 우리 앱에 없다** — 메일의 링크는 대시보드의 Site URL로
  간다. 앱 안에서 받으려면 `redirectTo`와 복구 토큰 경로를 따로 만들어야 한다.

이메일이 비면 Supabase가 422를 주는데 그 문장이 사용자에게 아무것도 안 알려 줘,
**먼저 막고 한 줄로 말한다**(`title.resetNeedEmail`).

### 3. 「아이디·비밀번호 자동저장」 — 어디까지 했나 ★

기획자의 요청은 「로그인에 성공한 아이디와 비밀번호를 자동저장」이었다. 셋으로 갈랐다.

| | 어떻게 |
|---|---|
| **다시 안 적어도 들어간다** | **이미 된다.** 세션(리프레시 토큰)이 `localStorage`에 남아 `App.tsx`의 부팅이 간판 화면을 건너뛴다. 로그아웃하거나 토큰이 죽었을 때만 간판이 뜬다 |
| **이메일 기억** | 새로 했다 — `save(session)`이 성공한 이메일을 `samchess.lastEmail`에 남기고, 입장 팝업이 그 값으로 시작한다. **`signOut()`은 이 값을 안 지운다**(로그아웃은 「이 계정에서 나간다」이지 「이 기기를 남에게 넘긴다」가 아니다) |
| **비밀번호 기억** | **우리가 저장하지 않는다.** 평문으로 `localStorage`에 두면 같은 출처에서 도는 모든 스크립트가 읽는다. 대신 `<form>` + `autocomplete`(`username`·`current-password`)로 **브라우저·OS의 비밀번호 관리자**가 맡게 했다 — 그쪽은 OS 잠금 뒤에 있고 출처까지 검증한다 |

**`<form onSubmit>`이라야 비밀번호 관리자가 「저장할까요」를 띄운다** — 버튼
`onClick`만으로는 많은 브라우저가 그게 로그인인지 모른다. 폼으로 두니 Enter 처리도
공짜로 따라왔다. 대신 **폼 안의 버튼은 기본이 `submit`이라**, [비밀번호 초기화]·
[계정 생성]·[닫기]에 `type="button"`을 안 적으면 셋 다 로그인을 시도한다.

### 4. CSS — `[data-modal="settings"]` → `.mod-plank`

목판 화풍 열한 줄이 전부 `.modal[data-modal="settings"]`로 좁혀져 있었다. 팝업이
넷이 되면서 선택자 목록을 네 벌로 늘리는 대신 **「이 화풍을 입는다」는 뜻 하나를
클래스로** 꺼냈다. 세기가 클래스 둘이라 예전 속성 선택자와 같다 — `border:` 단축
속성과 겨루는 자리도 그대로다. `data-modal`은 계속 **어느 팝업인가**를 가리키고,
스모크는 그쪽으로 고른다.

### 5. 문구 — 여덟 키 × 열 언어

`title.language`·`title.credits`·`title.creditsSoon`·`title.loginTitle`·
`title.reset`·`title.resetSent`·`title.resetNeedEmail`·`title.close`.
아홉 언어 전부 채웠다(한국어로 조용히 물러나는 자리를 안 남겼다).

언어 단추만은 **어느 언어로 보든 영어를 함께 적는다**(「언어 (Language)」·
「Idioma (Language)」) — 모르는 글자로 굳어 버린 화면에서 언어 단추를 찾아야 하는
사람이 정확히 그 상황에 있기 때문이다.

### 6. [닫기]를 붉은 판으로 (같은 세션 뒤쪽 지정)

화면을 보고 나서 기획자가 [닫기]에 `assets/icons/button_forcedcancel.png`를 입혀
달라고 했다. **그림을 새로 굽지 않았다** — `npm run ui`가 이미
`public/ui/btn-forcedcancel.png`로 구워 두고 대장간의 [제작 취소]·[장비 회수]가
쓰고 있어서, 같은 그림·같은 9분할 값(`14% 10% 14% 13%`)을 그대로 가져왔다.
글자색만 밝은 미색으로 뒤집었다 — 참나무용 짙은 갈색(`#2c2013`)을 붉은 판에 쓰면
글자가 사라진다(대장간이 이미 밟은 자리다).

언어·크레딧의 [닫기]는 옥색(`primary`)이었는데 `btn wide`로 내렸다. 그 결과
**화면에서 옥색은 [입장] 둘뿐**이 됐다 — 「할 일은 하나」가 색으로 다시 선다.

## 검사

- `smoke:meta`의 간판 절을 늘렸다 — **단추 셋의 `data-action`과 그 순서**(언어가
  가장 위인 것이 지정 자체다) · 화면에 입력칸이 **하나도 안 남은 것** · 언어 팝업의
  언어가 환경설정과 같은 것 · 크레딧의 준비 중 안내 · 입장 팝업 안에 다섯(이메일·
  비밀번호·입장·초기화·계정 생성)이 다 있는 것.
- 눈검사 — 프레임이 가장 클 때(700px)로 간판·팝업 셋을 찍고, **가장 긴 번역**
  (포르투갈어 「Redefinir palavra-passe」)으로 한 번 더 찍었다. 콘솔 오류 0.

### 곁가지 — 스모크가 2026-09-02부터 장수 일람에서 막혀 있었다 ⚠

`smoke:meta`가 `[data-sort="might"]`를 30초 기다리다 죽고 있었다. 장수 일람의 정렬이
2026-09-02에 **늘 펴 둔 칩 → [정렬 필터] 팝업**(`SortMenu` 재사용)으로 바뀌었는데
스모크가 안 따라온 것이다. 「**스모크는 첫 실패에서 멈춘다 — `✗` 하나가 그 뒤 전부를
가린다**」(CLAUDE.md, 2026-09-07에 같은 것을 한 번 겪었다)가 그대로 재발했다.
이번 세션의 변경과는 무관하지만, 내 변경을 끝까지 확인하려면 지나가야 해서 고쳤다 —
정렬은 팝업을 여는 두 걸음으로, 검색은 그대로(장수 일람의 검색칸은 랭킹의 `SearchBar`와
달리 제출 버튼이 없는 **즉시 필터**다).

### 곁가지 — H3b 군량 재검증이 간헐적으로 실패한다 ⚠ (안 고쳤다)

그 뒤로 스모크를 세 번 돌렸는데 **판마다 다른 자리에서** H3b 확인이 깨졌다
(1판 통과 · 2판 「참가비가 server-api에 안 남았다」 · 3판 「거절 군량이 —」).
`waitServerGrain()`이 DB 행을 5초(20×250ms) 폴링하는데 Colyseus 셸이 부르는
`POST /internal/grain`이 그 안에 안 들어오는 것으로 보인다 — **경주이지 이번
변경과는 무관**하다(간판 절은 세 판 모두 통과했다). 이 세션에서는 안 건드렸다.

- `npm test` 556/557 — 남은 1건은 연출 이미지·시각효과 매핑 불일치로 **이전부터**
  있던 것이다(이 세션은 그 데이터를 안 건드렸다).

## 남은 것

- **크레딧 화면** — 팝업에 「준비 중이다」만 있다. 내용이 정해지면 화면으로 키울지
  팝업 안에 담을지 그때 정한다(지금 미리 고르면 둘 중 하나가 죽은 코드로 남는다).
- **비밀번호 재설정 화면** — 메일의 링크가 Supabase 기본 페이지로 간다. 앱 안에서
  받으려면 `redirectTo` + 복구 토큰 경로가 필요하다.
