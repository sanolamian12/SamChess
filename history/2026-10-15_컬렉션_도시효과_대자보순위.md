# 컬렉션 — 도시 효과 · 대자보 순위 (2026-10-15)

10-14 세션들이 넘긴 ② 도시 효과 + 대자보 순위를 했다. 완성한 컬렉션의 도시 효과 일곱 키가 계산 함수에 들어가고,
효과가 실제로 적용되는 화면 다섯 곳에 「컬렉션으로 바뀐 값」이 보이며, 대자보 판 줄의 「—위」가 채워졌다.
하다가 기획자와 수치 둘을 다시 정했다 — **오두미도 치료 −50%**, **도적떼 약탈 30%(도적 수와 무관) · 황건적 토벌 · 강동 호신 각 −10%p**.
이것으로 10-14에 남긴 컬렉션 세 세션(① 전투 효과 · ② 도시 효과 · ③ 다국어)이 모두 끝났다.
`collection-city` 브랜치에서 커밋 둘(`a7ca282` · `e8f7419`)로 하고 main에 `--ff-only`로 합쳐 push했다(`d013efd..e8f7419`, 앞 세션들의 커밋 5개 포함). 브랜치는 지웠다.

## 1. 확정한 것 (기획자)

| | 결정 |
|---|---|
| 오두미도 | 병원 치료 시간 **−5% → −50%**. −5%는 3초라 체감이 없었다. 쿨타임 5분은 그대로이고 치료 1분만 30초가 된다 |
| 화면 표시 | 넣는다 — 시간은 「~~기본~~ → 지금」, 양은 실제 값 + 붉은 인장(누르면 컬렉션마다 한 줄) |
| 도적떼 약탈 | **「도적 1명당 10%」 → 「출몰 순간 군량의 30%」(도적 수와 무관, B안)**. 패배는 30% × 살아 있는 도적 / 출몰한 도적 |
| 황건적 토벌 · 강동 호신 | −1%p · −2%p → **각 −10%p**(둘 다 전설 300이라 같은 크기로). 30% → 20% → 둘 다면 10% |

**약탈 개편의 세 안** (항복 기준) — A 「도적 1명당 30%」는 Lv4부터 전부(Lv5 150%)라 뺐고, C 「도적 1명당 6%」(Lv5 30%)는
농지 레벨에 따른 차이를 남기지만 컬렉션 하나가 −2%p/명이 된다. 기획자가 **B(한 번에 30%)**를 골랐다 —
Lv1 농지는 지금보다 아프고(10% → 30%), Lv5는 덜 아프다(50% → 30%). 「농지가 클수록 더 빼앗긴다」는 성질은 없어졌다.
처음 설계에서 컬렉션 둘을 다 모아도 화면이 「10% → 9%」 · 「10% → 8%」 두 줄만 말하고 실제 7%를 아무도 말하지 않던 것을
보다가 나온 개편이다 — 도적떼 알림에 **「약탈률 : ~~30%~~ → 10%」 줄**을 더해 합계를 meta(`raidLootPct`)가 말한다.

**−50% 밸런스 검산** (치료 1분 + 쿨타임 5분, 병원을 즉시 · 최적으로 쓸 때 부대 전멸 → 완치)

| 병원 | 3v3 | 5v5 |
|---|---|---|
| Lv1 | 13분 → 11.5분 | 25분 → 22.5분 |
| Lv2 | 7분 → 6분 | 13분 → 11.5분 |
| Lv3 | 1분 → 30초 | 7분 → 6분 |
| Lv5 | 1분 → 30초 | 1분 → 30초 |

병목이 쿨타임이라 줄어드는 것은 최대 2.5분이다. 병원 한 단계(Lv1 → Lv2는 13 → 7분)보다 훨씬 작아 희귀(카드 2장) 보상으로 넘치지 않는다.
설계 의도(「Lv3 3v3 · Lv5 5v5가 한 번에 끝난다」)도 그대로다.

## 2. 설계 — 판정 시각은 「그 일이 시작된 때」

판정은 `packages/meta/src/cityBonus.ts`의 `cityBonus(profile, key, atMs)` 하나다(`completedAt ≤ atMs`의 합). 서버도 같은 함수를 지난다.

| 키 | 계산 | 판정 시각 |
|---|---|---|
| grainCap · grainRate | `grainCap()` · `grainPerHour()`(소수, 한 톨 시간은 정수 ms로 반올림) | 지금 — **완성하는 순간 `applyRegisterSlot`이 먼저 `syncCity`** |
| forge | `forgeDurationMs()` · `forgeOrderRemainingMs(profile, now)` | 주문 `startedAt` |
| research | `researchMs()` — 남은 시간 · 거두기 · `doneAt` · `researchedUpgrades` 넷 다 | 연구 `startedAt` |
| heal | `applyHeal`이 장수에 `healCut`(%)을 적고 `injuryHealsAt` · `hospitalWards`가 읽는다 | 치료 시작 |
| raidResp · raidLoot | `raidResponseMs` · `raidLootPct` → `raidDeadline(profile, raid)` · `raidLoot(profile, raid, …)` | 출몰 `spawnedAt` |

- **치료만 값을 저장한다** — `isInjured(inst, now)`를 부르는 자리가 24곳이고 profile이 없다. 인자를 더하면 빠뜨린 곳이
  조용히 1분으로 돈다. 끝 시각이 아니라 **비율(%)**을 적어 `injuredAt`의 원칙(사건만 저장, 규칙은 매번 읽는다)을 지켰다.
  `migrateProfile()`에도 더했다(10-13의 「되접기가 새 필드를 버린다」).
- 도적떼는 저장하지 않고 `spawnedAt`으로 매번 다시 낸다 — 함수들이 계정을 받게 시그니처를 바꿨다.
- 「10% → 9%」 글(`effectLine`)과 계산(`raidLootPct`)이 같은 상수 `RAID_LOOT_PCT`를 읽는다.

## 4. 밟은 것

- **「~~1분~~ 54초」가 「1분 54초」로 읽혔다** — 옥색 단추 위에서 취소선이 안 보인다. 화살표를 넣고 새 값은 바탕 글자색 + 굵게.
- **인장이 문장 끝에서 혼자 줄을 넘겼다**(병원) — 인장을 그은 값 바로 뒤에(`Span`의 `mark`), 같은 `nowrap` 안에.
- **몽골어에서 도시 관리 줄의 인장이 말줄임에 잘려 나갔다** — 말줄임은 글(`.fx-t`)에만 건다.
- **태학 단추 옆에 세운 인장이 폭을 빼앗아 몽골어 단추가 두 줄로 접혔다** — 단추 귀퉁이에 찍고, 바뀐 시간이 든 단추는 `nowrap` + 글자 0.9배. 넘침은 도구가 `scrollWidth`로 잰다.
- 단추 안에는 인장(단추)을 못 넣는다 — 대장간 상세 단추는 그은 값만, 인장은 주문 확인창에.
- `tools/raid_play.ts`가 약탈 식을 다시 적고 있었다(`× 2 × 10 / 100`, 「8」) — meta의 `raidLoot()`을 부르게 고쳤다.
- 확인 도구가 농지를 짓자 서버가 그날의 도적떼를 곧장 출몰시켜 알림이 화면을 막았다 — 앞 단계는 「오늘 것은 끝남」으로 심는다.

## 6. 아직 안 된 것

- 최대 군량은 장터 · 병영 자리 · 출정 화면에도 숫자로 나온다 — 값은 맞고(같은 `grainCap()`) 인장만 도시 관리 · 농지에 있다.
- 배지 · 발동 띠 그림, 등록 칸 그림, 라벨 그림 — 10-14 문서 그대로.
- 컬렉션 밖 아홉 언어 누락 문구 키 — 별도 세션(10-14 §7 ③).
- 새 번역(「약탈률 :」 · 시간 표기 · 바뀐 템플릿)은 원어민 검수 전이다.
- 추적되지 않은 `history/2026-10-14_대자보종이_죽간상세_컬렉션다국어_농지결과.md`가 저장소에 그대로 있다(이 세션이 만든 것이 아니라 커밋하지 않았다).

## 7. 배포 — 하지 않았다

기획자가 머지 뒤 「배포도 해줘」라고 했는데, 이 저장소에는 **배포 설정이 아직 하나도 없다**(호스팅 · 도메인 · 빌드/실행 설정 없음,
`docs/2026-08-24_개발_인프라_보고서.md`도 「배포는 다음 단계로 미뤄 뒀다」). 배포는 돈이 들고 공개 주소가 생기는 일이라 임의로
고를 수 없어 정할 것(클라이언트 정적 호스팅 · 대전 서버와 계정 API 두 프로세스 · Supabase 요금제 · 도메인)을 보였고,
기획자가 **「그럼 배포하지 말고 그냥 두자」**로 정했다. 「push」와 「배포」는 다른 일이다 — push는 GitHub에 올리는 것까지다.
