# 2026-09-23 시장 아이템 — 사양·데이터·엔진·인벤토리·화면

트랙 9(상점)가 2026-08-24부터 🔶로 멈춰 있었다. 이 세션은 **장터 재구성**에서 시작해 기획자와
**시장 아이템 16종**의 사양을 정하고, 데이터 → 엔진 → 인벤토리 → 화면까지 붙였다. 도중에
**대장간 병기가 3주 넘게 전투에서 아무 일도 안 하고 있었다**는 것이 드러나 함께 닫았다.

## 1. 사양 — 기획자와 정한 것

처음 질문은 「장터를 다른 화면처럼 현황판 + 바닥 명령 판으로」였다. 거기서 상품을 세다가
**「장수 아이템」이라는 새 품목군**으로 번졌고, 오간 결정이 전부 확정됐다.

| | 결정 | 뒤집힌 것 |
|---|---|---|
| 종류 | **Passive · Active 1회용 둘** | 처음엔 「Active 영구」를 포함한 셋이었다. 망원경을 **정찰 단계 공개**로 옮기며 Passive가 됐다 |
| 소모 | **모든 아이템이 1회용** — Passive는 참전으로, Active는 사용으로 | 처음엔 Passive가 영구였다 |
| 칸 | 장수 하나는 **병기 또는 아이템 하나** | |
| 소모 시점 | **판이 열리는 순간**(참가비와 같은 자리) | 「끝난 뒤」로 두면 같은 아이템을 여러 판에 쓴다 |
| 환불 | 성립하지 않은 판 전부 · 안 쓴 Active. **항복·패배해도 쓴 것은 안 돌아온다** | |
| 해금 | 시장 Lv2~Lv5, 부류(약·책·말·도구)마다 레벨당 하나 = **16종** | |
| 값 | 해금 레벨이 정하고 같은 레벨은 같은 값 — **2 / 4 / 8 / 16냥** | 가챠 단발(10냥)보다 확실히 싸야 한다 |
| 하루 매물 | 종류당 **`시장 Lv − 해금 Lv + 1`개** | **대장간 피라미드와 글자 그대로 같은 식**이다 |
| 보유 총량 | **`(시장 Lv − 1) × 20`** (Lv2 20 → Lv5 80) | 처음 「Lv2에 20씩 늘려 Lv5에 100」은 산수가 안 맞아 기획자가 정정 |
| 전투력 | **반영하지 않는다. 매칭도 안 본다**(A안) | |

### 사양을 정하며 잡은 것

- **망원경은 시대가 안 맞는다**(17세기) → **척후기**(斥候騎). **폭약**도 화약이 당대 물건이라
  한대의 **유황·역청 질항아리**로 그렸다.
- **해금 레벨이 「세기」이자 「흔함」을 동시에 정한다 ★** 대장간은 상한이 **보유**라 낮은 레벨
  병기를 많이 가져도 그냥 낡은 무기였다. 시장은 상한이 **하루 매물**이라 **낮을수록 싸고 많이
  풀린다** — Lv2 칸이 이 게임에서 가장 많이 흐르는 주력이다. 그래서 청낭서가 「모든 아군」에서
  **「착용 장수만」으로 좁혀지고** 폭약이 **Lv3로 물러났다.**
- **마비산 지속은 90**(한 사이클). 100으로 두면 통솔이 높은 장수에게만 두 턴이 되어 **같은
  아이템이 장수마다 다르게 돈다.** (다만 화면 표기는 `time 100 = 1일`이라 90은 **0.9일**로 뜬다 —
  책략은 200을 써 「2일」로 떨어진다. 기획자가 90으로 확정했다.)
- **손자병법서의 ±1은 반감 뒤, 하한 0** — 약한 공격이 완전히 무효가 되는 것이 의도다(값으로 보정).

## 2. 데이터 — `docs/시장 아이템.xlsx` 신설

대장간(`docs/대장간 장비.xlsx`)과 **같은 규약**이고 열 둘이 다르다: 대장간의 「종류(무기/방어구)」
자리를 **부류(약·책·말·도구)**와 **종류(패시브/액티브)** 둘로 갈랐다.

**번호가 그림 시트의 4×4 자리다** — `행 = (번호−1)//4`, `열 = (번호−1)%4`. 추출기가 번호와
(부류, 해금레벨)이 어긋나면 실패시킨다(어긋나면 아이콘이 통째로 밀린다).

### 추출기 — `extract_market_items()`

대장간과 **두 군데만 다르다**.

1. **효과가 (종류, 레벨)이 아니라 품목마다 다르다** → `MARKET_ITEM_EFFECTS`(액티브 6, Effect DSL) ·
   `MARKET_ITEM_PASSIVES`(패시브 10)를 **id로** 짠다.
2. **효과가 엔진 DSL이라 엑셀 칸에 안 들어간다** → 엑셀의 「효과」 열은 **화면 문장**이고
   `MARKET_ITEM_TEXT`와 **글자까지 같은지** 대조한다. 대장간이 정규식으로 값을 되읽는 것과
   목적이 같다(부저추신 사고: 효과를 고치고 설명을 안 고치는 것).

검사 아홉 갈래를 **하나씩 깨서 각각 제자리에서 실패하는 것**을 확인했다 — 효과 문장 · 레벨별 값 ·
패시브/액티브 표 짝 · 표 누락 · **번호 ↔ 그림 자리** 등.

### 그림 — `npm run market-items`

`assets/icons/market_items.png`(681², 4×4) → `public/market-items/{id}.png` 16장.

★ **등분해 자르지 않았다.** 681은 4로 나누면 170.25인데 알파가 빈 홈으로 찾은 실제 경계는
**열 171·338·508 / 행 166·338·512**로 등분 자리(170·340·511)와 **최대 3px 어긋나** 있었다 —
배경 띠(`build_backgrounds.py`)가 이미 밟은 자리다. 홈이 정확히 셋이 아니면 **자르지 않고 멈춘다.**

⚠ **해상도가 대장간의 1/3이다**(칸 117×111 ~ 172×157 vs 폭 480). 도구는 **키우지 않는다** —
크게 띄우는 상세 패널을 만들려면 원본 시트를 더 큰 해상도로 다시 받아야 한다.

## 3. ★ 병기가 전투에서 아무 일도 안 하고 있었다

패시브를 어디에 얹을지 보려고 길을 따라가 보니 **기댈 레일이 없었다**.

- `RosterEntry`에 장비 필드가 **없었다**.
- `toRosterEntries()`가 `equippedBy()`를 **안 불렀다**.
- 엔진에서 `barrier`·`criticalDamage`·`criticalRate`·`attack`을 읽는 곳이 **한 줄도 없었다** —
  `EquipmentEffect`가 쓰이는 데는 데이터 타입 선언과 **검증 테스트**뿐이었다.

즉 대장간에서 금화를 내고 만들어 지급한 병기가 **화면에만 뜨고 전투에서는 아무 효과가 없었다**
(2026-09-09 대장간 도입 이후 줄곧). 시장 아이템이 **같은 칸을 다투는** 사이라 길을 하나로 놓으며
함께 닫았다.

### `RosterEntry.held` 하나 — 가르는 자리도 하나

`packages/rules/src/held.ts` 신설. `heldEffectOf(id)`가 `equipmentById` → `marketItemById` 순으로
찾고, **액티브는 들고만 있는 동안 아무것도 안 준다**(쓸 때 `effects`가 돈다). 두 표의 id가 안
겹치는 것을 회귀가 고정한다.

| 들어간 것 | 자리 |
|---|---|
| 병기 결정타 %p · 결정타 추가 데미지 · AT · 베리어 | `attackDamage()` · `criticalRateOf()` · `damageUnit()` |
| 말 WT −10/−20, 절영의 조건부 **−15로 교체**(합산 아님) | `wtBase`에 얹고, HP 따라 바뀌는 몫만 매 턴 다시 잰다 |
| 적로 1회 생존 | `damageUnit()` — 즉사도 여기를 지나 함께 막힌다 |
| 육도삼략 30% 반격 | `resolveAttack()` — **확률이 0이면 굴리지 않는다**(굴리면 `rngCursor`가 밀려 리플레이가 깨진다) |
| 태평요술 MP −1(하한 0) | `tacticMpCost()` — 태학 개량이 반영된 값에서 깎는다 |
| 우선 ±10%p | `illusionChance()` — **무조건인 0·100은 안 탄다** |
| 손자병법서 최종 ±1(하한 0) | `applyFinalDamage()` |

데미지를 내는 자리를 **`attackDamage()` 하나**로 모아 `resolveAttack`과 `forecastAttack`이 같은
함수를 부른다 — 화면이 공식을 다시 적으면 **표시만** 조용히 어긋나는 자리였다.

> **변이 확인에서 한 자리가 비어 있었다** — `criticalDamage`를 지워도 아무 검사가 안 깨졌다.
> 시험에 쓴 청룡언월도(Lv5)에 그 키가 없어서다. 청강검(Lv4) 검사를 더해 메웠다.

⚠ **이제 병기가 실제로 세진다.** 결정타 +30%p·평타 +1이 붙는데 **전투력은 이것을 안 본다**(확정) —
매칭이 그 격차를 못 본다. 병기는 **영구**라 아이템(A안)과 성격이 다르다, 한 번 재 볼 값이다.
⚠ **판 도중에 병기를 옮기면 서버 재생이 어긋난다** — 부상은 `nowMs`, 태학은 `startedAt`으로
시각을 고정해 풀었는데 병기는 **시각이 아니라 상태**라 그 방법이 안 통한다. 낮은 심각도로 남긴다.

## 4. 인벤토리 — 서버 것과 클라이언트 것이 갈린다

`packages/meta/src/market.ts` 신설. 저장 형식은 **필드 셋**이고 **버전은 그대로 6**이다(더해지기만 했다).

| 필드 | 임자 | 왜 |
|---|---|---|
| `marketOwned` `{아이템: 개수}` | **서버** | 금화로 산다 |
| `marketTaken` `{day, counts}` | **서버** | 하루 매물을 재는 값 |
| `marketInPlay` `{장수, 아이템}[]` | **서버** | 판이 도는 동안 빠져 있는 것 |
| `marketCarry` `{장수: 아이템}` | **클라이언트** | 총량을 안 바꾼다(대장간 지급·농지 파수꾼과 같은 결) |

★ **`marketInPlay`가 필요했던 이유** — 소모할 때 `marketCarry`가 비워지므로, 판이 끝났을 때
「무엇이 나갔나」를 알 방법이 없다. **클라이언트에게 물으면 환불이 보유를 늘리므로 아이템을 찍어
낼 수 있다.** 그래서 서버가 기억한다(`forgeOrder`·`hospitalBusy`와 같은 자리).

★ **날이 바뀌면 `marketTaken`은 「없는 것」이 된다** — 지우지 않고 날짜만 비교한다. 지우려면
누군가 그 순간 계정을 만져야 하는데, **아무도 안 들르는 계정도 다음 날이면 매물이 차 있어야**
한다(군량 충전과 같은 결). 날짜 경계는 도적떼와 **같은 KST 자정 하나**를 쓴다.

**「한 판에 1인 1개」가 구조로 선다** — `marketCarry`가 장수 하나에 값 하나인 표라 두 개를 들
자리가 없다. **지급은 안 지운다**: 아이템이 소모되면 `heldFor()`가 병기를 보므로 **저절로 돌아온다.**

### 소모·환불을 전투 흐름에 이었다

| 갈래 | 빠지는 곳 | 돌아오는 곳 |
|---|---|---|
| AI 대전 | `POST /battle/fee`(참가비와 한 요청) | `settleOutcome()` |
| 온라인 | `BattleRoom`이 명단을 받는 순간(`'items'`) | 방이 접히면 `chargeGrain(…, 'refund')` · 결말은 `settleOutcome()` |
| 도적떼 | `/raid/start`(`guardsOf()`가 낸 명단) | `/raid/result` · `/raid/surrender` · 재생 실패 |

**온라인만 두 걸음이다** — 참가비는 대기열에서 걷히는데 **그때는 누가 나갈지 모른다.** 명단은
`BattleRoom`에 도착하므로 거기서 `'items'`(군량은 안 건드리는 액션)로 한 번 더 부른다.
**보내는 것은 장수 이름뿐**이고 무엇을 들었는지는 서버의 `marketCarry`가 정한다.

### 서버 경로

`POST /market/item`(아이템 한 개) · `POST /market/grain`(군량). 둘 다 `gold`가 서버 소유라
전용 경로가 있어야 한다 — **하루 매물은 서버 시계가 재는 값**이라 클라이언트가 재면 시계를
되감아 계속 살 수 있다.

## 5. 화면

### 장터 재구성

**현황판**(재화 한 줄 + 장수 카드 · 보유 아이템 · 군량 충전) + **바닥 명령 셋**
([금화 충전] · [용병 장터] · [물자 장터]). 대장간처럼 **한 파일 안의 하위 보기**라 새 `Screen`
변형을 안 늘렸고 뒤로가기가 장터 홈 하나로 모인다.

- **용병 장터** — 가챠 · 카드 정리 · 재설계(잠김) · **장수 아이템 16줄**
- **물자 장터** — 군량 · 건축 자재 · 초기화 아이템(잠김, 「궁궐·태학에서 쓴다」)
- **금화 충전** — 골드팩 셋(결제 미연결)

### 출전 준비의 지참 판

부대를 고르면 부대원 수만큼 줄이 서고 각 줄에서 아이템을 고른다. 빈 칸의 이름이 「없음」이 아니라
**「병기 그대로 — 대감도」**다 — 안 들면 병기가 서므로 **무엇을 들고 나가는지**를 말해야 한다.
사는 곳은 장터지만 **판마다 다시 정하는 것**이라 여기서 고른다.

### 눈으로만 잡힌 것 넷

1. **개발용 판이 홈에 통째로 펼쳐져 있었다** — 260명 목록까지 나와 「바닥 명령 판」이 바닥이
   아니었다. `SAMCHESS_DEV_GRANTS=1`로 가리고 용병 장터 안으로 옮겼다.
2. **지참 판 색이 양피지와 안 맞았다** — 어두운 판(`.mkt-`) 색을 그대로 가져와 기물 이름이 거의
   안 보이고 구분선이 검었다.
3. ★ **지참 판이 끼어들며 부대 줄이 사라졌다** — `.srt-list`가 478 → 342로 눌려 고른 줄이
   양피지 밖으로 밀리고 **아래 판 뒤로 숨었다.** DOM에는 그대로 있어 「있는가」 검사는 통과했다.
   `flex-shrink: 0`으로 고치고, 스모크에 **「고른 줄이 판 안에 있는가」를 좌표로 재는 검사**를 넣었다.
4. **잠긴 이유가 `title`(마우스 올림)뿐이었다** — **모바일에는 올림이 없어** 영원히 안 보인다.
   군량 칸이 「창고가 가득 찼다」로 자주 막히면서 드러났다. 칸 안 붉은 글자로 적고, 스모크도
   `title`이 아니라 **글자를 읽어** 확인한다.

### `npm run smoke:market-ux` (신설)

계정을 심고 한 바퀴 — 현황판 · 명령 셋 · **아이템 16줄** · **아이콘 16장이 실제로 뜨는가**(404면
폭 0) · **줄이 칸을 넘치지 않는가** · 구매(**금화 500 → 498 · 매물 4 → 3**, 서버까지) ·
군량이 가득이면 막고 **이유를 글자로** · 지참 줄 셋 · 고른 것이 남는가 · 콘솔 오류 0.

## 6. 마지막에 붙인 셋 (군량 · 청낭서 · 척후기)

- **군량 구매** — 자재 구매를 그대로 베꼈다. ★ **가득 찼을 때만 막고 넘치는 분은 상한에서
  자른다**: 「통째로 들어갈 때만 판다」로 두면 병영 Lv1(상한 20)에서 20짜리 묶음이 **영원히 안
  들어가** 군량을 아예 못 산다. `syncGrain`으로 **먼저 정산한다.**
- **청낭서** — `fallenAfterShield()` 하나를 만들고 `applyInjuries`를 부르는 **두 자리**에 걸었다.
  출처는 `marketInPlay`(정산 직전까지 살아 있다). 거르는 자리를 `applyInjuries` **밖**에 둔 것은
  안에서 거르면 병원 시험용 강제 부상까지 면제되기 때문이다.
- **척후기** — `toWire(state, side)`가 척후기 없는 쪽에는 상대의 `tactics`를 **지워서** 보낸다.
  ★ **로컬 전송(`transport.ts`)도 `toWire`를 지나서 AI 대전에서도 진짜로 가려진다**(세션 중간에
  「AI는 화면 가리기로만 남는다」고 적었던 것이 여기서 뒤집혔다). 엔진이 AI의 수를 낼 때 쓰는
  것은 떼기 전의 권위 상태라 영향이 없다. **뗄 것이 없으면 원본을 그대로 돌려준다**(통마다 유닛
  맵을 새로 안 만든다).

> ★ **검사 하나가 기본값과 같은 값을 보고 있었다** — 「먼저 정산한다」가 **병영 Lv1 상한(20)이
> 묶음 크기와 같아서** `min(상한, …)`이 같은 값으로 잘라 내 **정산을 통째로 빼도 통과**했다.
> 창고를 키우고 상한이 묶음보다 넉넉한지 먼저 단언하게 고쳤다.

## 8. 남은 것

| | |
|---|---|
| **액티브 사용** | `useItem` 의도가 엔진에 없어 **여섯 종을 들 수는 있는데 쓸 방법이 없다.** `incomingDamageZero`(마비산)도 엔진에 없는 상태다 |
| **초기화 아이템 판매** | 둔갑천서·연구 되돌리기의 **보유 개수**(서버 소유 + 되접기), 구매 경로, 궁궐·태학을 금화 직불 → 아이템 소모로 |
| **결제(골드팩)** | 난이도가 아니라 **결정**이 먼저다(모의 vs 실 PG) |
| 아이템 그림 해상도 | 대장간의 1/3. 크게 띄우려면 원본 시트를 다시 받아야 한다 |
| 아이템 이름·해설 번역 | 엑셀의 `이름_{lang}`·`해설_{lang}` 열이 비어 있다(지금은 한국어로 물러난다) |
| ⚠ 병기가 전투력에 안 잡힌다 | 이제 실제로 세지는데 매칭이 그 격차를 못 본다 |
| ⚠ 판 도중 병기 교체 | 서버 재생이 어긋난다(낮은 심각도) |

`settleCarried(profile, [], true)`의 `usedBy`가 **언제나 빈 배열**이다 — 액티브를 쓸 방법이
없어서고, `useItem`이 붙으면 그때 실제로 쓴 장수를 넘긴다(코드에 ⚠로 적어 뒀다).
