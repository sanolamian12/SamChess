# 2026-09-22 Pawn 원거리 개편 · 기물 균형 재측정

HANDOFF §7 후보 「Pawn 개편 — 같은 줄 둘 공격 → 원거리 공격」을 처리한 세션. 기획자가 같은 날
태학 세션에서 제기했고, 태학 **증폭+**가 Pawn의 두 대상 공격에 충전 둘을 한 번에 다 써서 **둘 다
크리티컬**이 나던 문제(GDD §5.12)를 함께 푸는 것이 목적이었다.

커밋: `a4bb5e5`(개편) · 이 문서와 재측정 기록(후속 커밋)

## 1. 사거리와 대상 수를 먼저 정했다

옛 Pawn은 이동 8방향 1칸 · 공격 **직교 1~2칸(8칸) · 최대 2명** · 위협 범위 33이었다.
후보 마스크마다 위협 범위를 `threatRange()`와 같은 방식(이동 목적지 전부의 공격 칸 합집합, 원점 포함)으로
계산해 기획자에게 보였다.

| 공격 마스크 | 칸 | 위협 범위 | 인접 공격 |
|---|---:|---:|---|
| 옛: 직교 1~2 | 8 | 33 | 가능 |
| **마름모(맨해튼 ≤2)** | 12 | **37** | 가능 |
| 맨해튼 =2 고리 | 8 | 37 | 불가 |
| 직교 1~3 | 12 | 45 | 가능 |
| 직교 2~3 | 8 | 45 | 불가 |
| 체비셰프 =2 고리 / 8방향 2칸 | 16 / 8 | 49 | 불가 |
| 맨해튼 2~3 | 20 | 57 | 불가 |

(비교: Rock 41 / Queen 39 / Bishop 37 / King·Knight 25)

**기획자 확정: 대상 1명 · 마름모 ≤2 (12칸, 위협 37).**

- 대상 1명 — 증폭+ 이중 소모가 **규칙 층에서** 사라진다. 「공격 1회당 충전 1」 같은 예외를 따로 둘 필요가 없다.
- 마름모 — 둘째 대상을 잃는 대신 칸이 8 → 12, 대각 1칸이 새로 닿는다. 37은 Bishop과 같고 Rock(41)은 안 넘는다.
- **사각지대(붙으면 못 쏜다)는 넣지 않았다** — AI(`ai.ts`)가 거리 벌리기를 따로 배워야 하고,
  진영이 5행 깊이로 밀집한 초반에 Pawn이 무력해진다.

위협 범위 33은 CLAUDE.md의 「임의로 바꾸지 않는 확정 수치」였다 — 이번 것은 **기획자 결정으로
의도적으로 고친 것**이고 목록도 37로 고쳤다.

## 2. 구현

| 자리 | 바뀐 것 |
|---|---|
| `tools/extract_data.py` | `diamond(n)` 추가, Pawn `attack=diamond(2), targets=1, threat=37` → `npm run extract` |
| `packages/data/generated/pieces.json` | 생성물 (Pawn 공격 마스크 12칸 · `maxTargets` 1) |
| `packages/rules/src/ai.ts` | 대상 수를 `unit.piece === 'Pawn' ? 2 : 1`에서 **`getPiece(piece).maxTargets`**로 — 데이터가 정한다 |
| `battle.ts` · `pieces.ts` · `types.ts` | 옛 규칙을 말하던 주석 |

**화면은 안 바뀌었다** — 전투 UI는 처음부터 대상을 1명만 보냈고(`BattleScene.ts`의 `targets: [clicked.id]`),
공격 범위 표시는 `attackCells()`가 기물 데이터를 그대로 읽는다. 언어 파일에도 옛 규칙 문구가 없었다.
엔진의 다중 대상 루프(`battle.ts`의 `for (const id of intent.targets)`)와 `maxTargets` 검증은
그대로 두었다 — 지금은 전 기물 1이라 한 번만 돈다.

### 회귀

- `data.test.ts` — 위협 범위 Pawn 37, 공격 칸 12, **전 기물 `maxTargets === 1`**, 마름모 모양
  (대각 1칸은 닿고 대각 2칸은 안 닿는다).
- `battle.test.ts` — 옛 「Pawn은 2명까지 동시 공격」을 원거리 규칙으로 갈았다(대각 1 · 직교 2는 대상,
  대각 2는 사거리 밖, 둘 지정은 거부). **증폭+(충전 2)를 받은 Pawn이 한 번 쏘면 충전 1이 남는다**를 새로 넣었다.

`npm run typecheck` · `npm test` 687건 통과.

## 3. 기물 균형 재측정

`npm run power`(모드당 2만 판, 시드 20260817 — 옛 GDD §11-9 표와 같은 조건, 517초).
기물 효과는 Pawn = 0 기준, 능력치를 통제한 뒤의 전투력 점수다.

| | Queen | Knight | Rock | Pawn | Bishop |
|---|---:|---:|---:|---:|---:|
| 3v3 이전 (08-17) | +20.8 | +18.0 | +16.4 | 0 | −11.3 |
| **3v3 개편 후** | **+26.8** | +21.7 | +18.6 | 0 | −7.3 |
| 5v5 이전 (08-17) | +11.4 | +9.5 | +8.7 | 0 | +4.1 |
| **5v5 개편 후** | +11.8 | +9.6 | +10.2 | 0 | +5.4 |

칸마다 표준오차 3v3 ≈3.2 · 5v5 ≈3.6.

- **3v3** — 나머지 넷이 평균 +4점 올랐다. 기준이 Pawn이니 **Pawn이 약 4점(≈승률 1%p) 약해진 것**이다.
  둘째 대상을 잃은 손해가 넓어진 사거리보다 조금 크다. 여전히 Bishop보다는 위(Bishop z −2.2).
- **5v5** — 평균 +0.8, 사실상 그대로. Pawn은 개편 전에도 5v5 최하였다.
- 기물 조합만으로 갈리는 승률 폭: 3v3 8.0 → 8.4%p · 5v5 2.8 → 2.9%p.

`npm run balance`(200판)도 돌렸지만 기물당 표본 ~155회라 오차가 ±4%p다(Pawn 48.2 → 52.3%) —
판단에 쓰지 않았다.

### `POWER_MODELS`는 유지 (기획자 확정)

기물을 뺀 최종 모형의 계수가 전부 표준오차 1배 안팎에서만 움직였다.

| 특징 | 3v3 기존 → 새 | 5v5 기존 → 새 |
|---|---|---|
| at | 39.67 → 39.66 | 22.59 → 23.00 |
| hp | 6.57 → 6.59 | 3.63 → 3.61 |
| might | 1.47 → 1.45 | 0.78 → 0.77 |
| skillS | 34.1 → 30.8 (SE 3.5) | 16.5 → 17.4 (SE 2.5) |
| mp | 0.60 → **0** | 0.55 → 0.64 |

3v3 mp가 0이 된 것은 값이 변해서가 아니라 |z| 1.3이 「<2면 0」 문턱에 걸린 것이다. 옮겨 적으면
**잡음 때문에 모든 부대의 전투력과 매칭 상대가 흔들린다** — CLAUDE.md의 「다시 재는 것은 언제나
의도된 변경이어야 한다」에도 어긋난다. 기물은 원래 전투력 식에 안 들어가므로 Pawn 개편이 식을 바꿀
이유도 없다.
