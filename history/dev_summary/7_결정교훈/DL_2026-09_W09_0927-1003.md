# 결정 · 교훈 — W09 · 2026-09-27 ~ 10-03

> **이번 주 요지** — 전투 UI 개편(pptx 89~98쪽)의 물음 12개를 기획자가 확정했고, 그중 첫째가 **WT 동점 처리 규칙을 바꿨다**. 구현에서는 동점 순번을 뽑는 시점을 「전투 시작」에서 「판을 만들 때」로 옮겼다. 진행 방식은 「한 세션에 한 단계」로 정해 문서를 마스터 · 로드맵 · 설계 셋으로 갈랐다. 교훈은 둘 — **작은 결함은 결과를 안 바꿔 검사가 헛돈다**, **스모크가 우연한 차례 순서에 기대고 있었다**.

## 결정

### 출정하기에서 지참품 판을 뺀다 (09-26, 기획자 지정)
- **무엇을**: `SortieScreen`의 지참 판을 걷었다. 지참 기능 자체는 장터(`market/ItemShop.tsx`)에 그대로 둔다. 문구 `sortie.items*`는 열 언어에 남긴다.
- **왜**: 부대를 고르면 지참품 판이 서면서 명령 판을 화면 밖으로 밀어내 [대전상대 찾기]를 누를 수 없었다. 기획자: 「지참품 정책은 따로 정한다. 이 화면에서는 빼 달라.」
- **남는 것**: 예전에 출정 화면에서 지정한 아이템은 계정(`marketCarry`)에 남아 다음 판에 소모되는데 출정 화면에서는 안 보인다 — 거두려면 장터에서.

### 전투 UI 개편 — 세 칸 구조와 12개 확정 (09-27, 기획자 확정)
- **구조**: 판 위아래의 카드 줄과 판 위에 떠 있던 판(명령 · 배치 · 살펴보기)을 걷고 **위(순서 판 · 게임 정보) / 가운데(판) / 아래(명령 판 · 맥락 판)** 세 칸으로 간다. 판을 가리는 것이 없어진다.
- **확정 12개** (전부 `docs/전투UI개편/설계.md`에 있다):

| # | 물음 | 확정 |
|---|---|---|
| 1 | 동점 추첨 시점 | 한 번 뽑고 **전투 도중 동점도 같은 순번** |
| 2 | 주사위 그림 | 기획자가 만든다 → 같은 세션에 영상이 왔다 |
| 3 | 이동 | **[이동]을 눌러야 범위가 깔린다** (지금은 차례가 오면 바로 깔린다) |
| 4 | 순서 예보가 틀릴 때 | 그대로 보여 주고 바뀌면 다시 그린다 |
| 5 | 고유기술 쓰는 자리 | 오른쪽 판에 「고유기술을 쓰시겠습니까?」 / 배너(누르면 상세, 애니메이션 없음) / [사용 (SP n)] / [미사용], 왼쪽은 내 장수 정보. 그 뒤에 명령 6칸 |
| 6 | 봉인 표시 색 | **빨강**(넷째 색) |
| 7 | 전투 기록 | 시스템 로그 자리 첫 줄의 `[...]` — 로그가 찍히는 동안 숨고, 다 찍히면 드러나 누르면 기록 |
| 8 | AI 대전의 시간 | 남은 시간 `-`, [턴 가져오기] disabled |
| 9 | SP 표기 | 정수 |
| 10 | 명령 판 | **첫 줄 「명령을 선택하세요」**, 그 아래 버튼 |
| 11 | 적 차례, 대상 고르기 전 오른쪽 판 | 비워 둔다 |
| 12 | 순서 판 WT | 일, 소수 둘째 자리 · 지금 차례는 「차례」 |

- [턴 가져오기]는 새 규칙이 아니다 — 지금의 `forceSkipTurn`(상대가 20초를 넘기면 켜지고 3번이면 승리)의 이름과 자리만 바꾼다. 「턴오버」는 `state.skips[side]`.

### 동점 순번은 「판을 만들 때」 뽑는다 (09-27, 구현 판단 — 설계를 고침)
- **무엇을 → 무엇으로**: 예전 규칙은 WT가 동시에 0이 되는 순간 시드 난수로 뽑았다. 기획자 확정 #1로 「한 번 뽑아 계속 쓴다」가 됐고, 설계 문서에 적었던 「**전투 시작 때** 뽑는다」를 구현에서 「**판을 만들 때**(`createBattle()`)」로 바꿨다.
- **왜**: 유닛이 생기는 곳이 `createBattle()` 하나이고 배치 사이에 WT가 안 바뀐다 — 이러면 배치 화면의 순서가 처음부터 정확하다. 예전 방식으로는 배치 화면이 순서를 미리 적을 수 없었고 주사위를 보여 줄 때도 없었다.
- **대가**: 판의 첫 난수 소비가 되어 `rngCursor`가 인원 − 1만큼 앞서 시작하고, 같은 시드라도 예전과 다른 판이 된다. 배포 순간 진행 중인 판만 영향.

### 주사위는 투명 WebM이 아니라 알파 WebP 스프라이트 (09-27, 구현 판단)
- **왜**: 사파리가 알파 WebM을 못 튼다 — iOS가 과녁이다.
- 바탕은 「투명이든 검정이든 좋은 쪽으로」(기획자)에 대해, 배경을 걷되 판 가운데를 먹빛으로 가장자리가 풀리게 가라앉혀 **검정 바탕의 느낌을 살린 쪽**을 골랐다.

### 로드맵 7단계(주사위)를 먼저 했다 (09-27, 구현 판단)
기획자의 주사위 영상이 같은 세션에 와서 2단계보다 앞서 7단계를 끝냈다.

### 개편은 한 세션에 한 단계 — 문서 셋으로 가른다 (09-27, 기획자 지정)
- 기획자: 「한 단계씩 진행하자. 로드맵 파일을 만들고, 새 세션을 만들 때마다 진도를 체크하고 구현하는 식으로. 마스터 파일은 별도로.」
- `docs/전투UI개편/`:

| 파일 | 정하는 것 |
|---|---|
| `마스터.md` | **입구** — 세션 절차(읽기 → 진도 확인 → 🔶 → 구현 → 검증 → 스크린샷 → ✅ · history · 커밋) · 규칙 · 여는 프롬프트 |
| `로드맵.md` | **진도** — 단계 표(⬜/🔶/✅) · 단계별 체크 항목 · 공통 완료 조건 |
| `설계.md` | **무엇을** — 쪽별 요구 · 확정 사항 · 화면 구조 · 엔진 함수 · 주사위 (옛 `docs/NEXT_전투UI개편.md`를 옮겼다) |

- 진도를 두 번 적지 않도록 설계의 진행 표는 로드맵을 가리키는 한 줄로 바꿨다. HANDOFF §7에 「진행 중」 안내를 넣었다.

## 교훈 — 밟은 지뢰

### 작은 결함은 결과를 안 바꿔서 검사가 헛돈다 — 결과가 실제로 뒤집히는 입력을 만든다
- **무슨 일이**: 순서 예보 회귀(`commands.test.ts`)를 넣고 예보 코드를 넷(시간 1 · 보정 · 동점 순번 · 봉인 순서) 일부러 깨 봤더니, 둘(시간 1 · 보정)이 **안 잡혔다.**
- **왜 조용했나**: 작은 보정은 차례 **순서**를 안 바꿨다. 검사는 순서를 비교하므로 틀린 코드도 같은 답을 냈다.
- **어떻게 잡았나**: 일부러 깨 보는 단계에서.
- **이제의 규칙**: 순서가 실제로 뒤바뀌는 판을 만들어 넷 다 잡히게 했다 — 「검사를 넣었으면 실패하는 상태를 만들어 본다」의 또 한 예.

### 스모크가 「다음 차례가 AI」라는 우연에 기대고 있었다
- **무슨 일이**: 동점 순번 변경으로 seed 3의 차례가 바뀌자 `smoke:ui`의 「기록에만 있다」 검사가 거짓 실패했다 — 턴을 넘긴 뒤 다음 차례가 또 사람이라 아무도 행동하지 않아 말풍선(4초 뒤 사라짐)이 없었다. 같은 변경으로 `sp=25` 새 판에서 AI가 먼저 서며 고유기술 연출(11.7초)이 대기 20초를 먹었다.
- **왜 조용했나**: 예전 순서에서는 우연히 늘 AI가 다음이었다.
- **어떻게 잡았나**: 원래 코드로 먼저 완주를 확인한 뒤 바꿔서, 막힌 자리가 변경 때문임을 갈랐다.
- **이제의 규칙**: 사람 차례면 넘겨서 AI가 움직이게 하고, 대기는 60초로 늘렸다. 아울러 「상태 배지 설명」 검사는 **개편 전에도 건너뛰고 있던 안 도는 갈래**였다(원래 코드로 다시 돌려 확인) — 로드맵 6단계에 넣었다.

### 구멍 채우기는 가장자리에 걸린 물체에서 틀린다 — 둘레에 빈 테를 두른다
- **무슨 일이**: 주사위 영상의 배경을 걷을 때, 첫 프레임에서 주사위가 화면 가장자리에 걸려 모서리와 주사위 사이에 갇힌 배경이 **검은 조각**으로 붙었다.
- **왜**: 바깥과 이어지지 않은 배경 영역은 「구멍」으로 보여 채워졌다.
- **이제의 규칙**: 구멍 채우기 전에 **둘레에 빈 테를 둘러 범람**시킨다(`tools/build_dice.py`). 세 바탕 대조 그림(`--preview`)으로 확인한다.
