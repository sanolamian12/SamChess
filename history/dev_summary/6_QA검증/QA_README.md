# 6. QA · 검증 (공통)

## 무엇을 정리하는가

**「무엇으로 확인했나」의 기록이다.** 포지션이 아니라 모든 포지션에 걸친 공통 섹션이다.
이 프로젝트에서 가장 비싼 실수는 **조용히 틀리는 것**이었다 — 화면은 멀쩡해 보이고 테스트도 통과하는데
실제로는 틀려 있는 것. 그래서 매주 「무엇을 어떻게 확인했고, 무엇은 확인하지 못했나」를 따로 모은다.

포지션 문서에는 「검증했다」 한 줄만 남고, 상세는 여기에 있다.

## 담는 것

| 소제목 | 내용 |
|---|---|
| **회귀 테스트** | `npm test`에 새로 넣거나 고친 검사. 무엇을 고정했고, 일부러 깨 봤을 때 실제로 잡혔는가 |
| **스모크** | 실제 브라우저·서버를 띄워 화면을 끝까지 눌러 보는 검사(`smoke_ui`, `smoke_meta`, `smoke:online`, `smoke:raid` 등). 신설·수리·완주 여부 |
| **실측·시뮬레이션** | 수천 판 밸런스 실측, 전투력 회귀, 경제 시뮬레이션 — 판 수, 결과, 표준오차 |
| **확인하지 못한 것** | 알면서 남긴 검증 공백. 다음에 누가 무엇을 봐야 하는가 |

## 이 프로젝트에서 반복해서 배운 검증 원칙

- 검사가 **기본값과 같은 값**을 확인하면 아무것도 확인하지 않는 것이다.
- **도달할 수 없는 갈래**에 걸린 검사는 한 번도 돌지 않는다. 검사를 넣었으면 실패하는 상태를 만들어 본다.
- 스모크는 첫 실패에서 멈춘다. 고쳤으면 **끝까지 완주한 것을 보고** 통과라고 말한다.
- 「있는가」와 「제자리에 있는가」는 다른 검사다.
