### 「고르기」 판 — 증분과 결과의 뜻을 갈랐다 (09-03)
「고르기」 UI(`Picker`)는 전면 화면과 같은 컴포넌트라 구조 변경은 양쪽에 다 간다(화풍은 `.scr-officers`로만 좁힘).

| 자리 | 전 | 후 |
|---|---|---|
| 판이 뜨는 y | 카드 그림 아래(`'art'`) | 카드 시작점(`'top'`) — 판 안 스크롤이 잘 안 생긴다 |
| HP·MP·AT 줄 | 어두운 상자 하나 | 칸(80%) + 체크 칩 |
| 책략 택1 | 이름 단추 둘 나란히 + 설명 상자 따로 | 두루마리 두 장 위아래(위 지원책 · 아래 환술) |
| [뒤로] | 있음 | 없음 — 우상단 [X] |

**회색 증분과 실제 결과는 다른 값이다.** 안 고른 줄이 `+0`으로 보이는 게 아깝다는 요청에 줄마다
`growthPreview(inst, 그 줄의 stat)`을 꺼내 썼더니 결과 칸까지 가정치가 됐다(`MP 5 +2 → 7`). 칸마다 뜻을 갈랐다.

| 칸 | 뜻 | HP를 골랐을 때 MP 줄 |
|---|---|---|
| `now` | 지금 값 | `5` |
| `add` | 고르면 오를 양 — 회색, 실제로는 안 더해진다 | `+2` |
| `next` | 실제로 적용될 값 — 안 고른 줄은 `now` 그대로 | `5` |

`next`·`range`는 「지금 고른 것」 기준 그대로, **`add`만 줄마다 따로 물어 얹는다.** 숫자는 언제나 엔진이 낸다.
두루마리 두 장이 둘 다 늘 펼쳐지니 견주기도 되고 높이도 안 흔들려, 높이를 고정하던 `.lv-desc-stack`(두 설명을 같은 그리드
칸에 겹쳐 안 고른 쪽만 `visibility: hidden`)을 지웠다. 설명 안의 이름 칩도 뗐다(제목과 중복). → 결정·교훈 참조

### 장수 카드가 레벨업을 안 따라오던 것 — 스냅샷 제거 (09-03)
레벨업 직후 판을 닫으면 카드가 옛 Lv·HP·책략을 보여 줬다. `OfficerListScreen`이 카드를 열 때 그 순간의 행을 state에
**복사**해 두고 있었다.

```ts
const [cardOf, setCardOf] = useState<OfficerId | null>(null);
const card = cardOf ? cardRows.find((r) => r.officer === cardOf) ?? null : null;
```

카드는 id만 들고 행은 매 렌더 다시 찾는다. 레벨업뿐 아니라 재설계·전적 반영도 함께 실시간이 되고, 장수가 계정에서
빠지면 `null`이 되어 카드가 닫힌다.

### 현황판·건물 관리 분리, 로딩 가리개, 완료 팝업, 자재 구매 (09-05)
