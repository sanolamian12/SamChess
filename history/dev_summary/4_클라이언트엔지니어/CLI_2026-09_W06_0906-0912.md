### 실제 플레이로 드러난 동작 결함 (09-10)

- **완성 알림이 최대 1분 늦게 떴다.** 1분짜리 주문에서 카운트다운은 0인데 완성 팝업은 **117초** 뒤에 떴다. 정산(`syncCity` → `collectForgeOrder`)은 `App.tsx`의 tick이 하는데 그 주기 `GRAIN_TICK_MS`가 **60초** — 시간당 차는 군량에 맞춘 값이다. `ForgeScreen`에 남은 시간이 0이 되는 순간 정산하는 effect를 더했다. **여기서 다시 거두지 않고 `syncCity()`를 그대로 부른다** — 정산의 자리는 여전히 하나이고(`collectForgeOrder`를 화면이 직접 부르면 두 번째 구현이 된다) 이 화면은 「지금 몇 시인지」만 넣는다. 거두고 나면 `forgeOrder`가 없어져 조건이 다시 참이 되지 않으므로 되풀이하지 않는다. 고친 뒤 **59초**.
- **교체가 조용히 일어났다.** `equipOfficer()`는 이미 다른 병기를 낀 장수를 고르면 그것을 말없이 풀어 준다. 규칙은 맞는데 화면의 유일한 예고가 「병기」 칸의 이름이었고 그 칸은 「없음」과 같은 색·같은 크기였다. 장수 124명 계정으로 눌러 보니 아무 표시 없이 한 병기가 벗겨졌다. **확인창**을 붙였다 — [회수]가 이미 확인을 받으므로 같은 무게로 맞추고, 낀 것이 없으면 안 묻는다(잃는 것이 없는 수다). 키 `forge.assign.swapConfirm` 10개 언어. 한국어 조사는 `{officer}은(는)` 꼴이다 — `eventText.ts`의 `josa()`는 코드가 문장을 짓는 자리의 것이라 i18n JSON 안에서는 쓸 수 없고, `result.void.refunded`가 이미 `{n}을(를)` 관례를 쓴다. 색 구분(`data-held`)은 디자인 문서.
- **장수 카드에 낀 병기 줄.** 대장간 쪽에는 내내 보였는데 장수를 직접 열면 안 보였다. 처음에 `OfficerDetailScreen`을 고쳤는데 실제로 장수 일람에서 줄을 누르면 뜨는 것은 **`OfficerCardModal`(`RankingCommon.tsx`)**이었다 — 스크린샷을 보고서야 알았다(→ 결정·교훈 참조). `OfficerDetailScreen`도 여전히 닿는 화면이라(레벨/전적 화면의 「뒤로」) 둘 다 넣었다. **카드는 프로필을 모른다** — `OfficerRankRow`만 받는다(랭킹의 다른 계정 장수도 같은 카드로 뜬다). 그래서 `levelsSub`와 같은 방식으로 `equip?: EquipmentData`를 caller가 넘긴다. 랭킹 쪽은 안 넘기고, 없으면 **줄째로 사라진다**(고유기술 배너·인물 소개와 같은 규약). 책략 줄이 「습득한 책략이 없음」을 남기는 것과 갈리는데, 책략은 모든 장수가 언젠가 갖지만 병기는 계정에 15개뿐이라 대부분의 장수에게 영영 없다.

### 시전 지연의 화면 — 자세와 오라는 「상태」에서 나온다 (09-07)

시전은 30 동안 이어지고 그 사이 다른 유닛의 턴이 여럿 지나간다. **연출 트랙 한 통으로는 못 버틴다** — 지속형 링이 상태를 매 프레임 다시 묻는 것과 같은 이유로, 자세도 오라도 `unit.casting`에서 나온다.
- **자세** — `frameOf()`가 평상(`idle`)일 때만 `POSE.cast`로 덮는다. 연출 큐가 할 말이 있으면 그쪽이 이긴다(시전 중에 얻어맞으면 피격 그림이 떠야 한다).

### 전투 UI 다국어 — 1차(로그 + 상시 표시)와 2차(나머지 전부) (09-11)

메타 화면은 `t()`로 열 언어를 쓰는데 **전투 화면만 `t()`를 한 번도 안 불렀다.** 일본어로 두면 이랬다:
```
孫権이 「火計」를 시전했다.      ← 이름만 일본어, 문장은 한국어
책략이 성공했다! (E5 성지)
```

**① 문장은 통째로 키 하나, 조사는 값에 붙인다.** 「누가 무엇을 했다」는 언어마다 어순이 달라 조각을 이어 붙이면 한국어 어순이 굳는다. 그래서 `ko.json`에 문장을 통째로 둔다(`"log.moved": "{who} 이동했다. ({from} → {to})"`). 그러면 조사가 갈 곳이 없어지는데 「유비**가**」/「관우**가**」는 값에 따라 달라지므로, `eventText.ts`의 `subj()`·`quoted()`가 **한국어일 때만** `josa()`를 부르고 다른 언어는 이름이 그대로 들어가 문장 쪽의 `が`·`'s`가 제자리를 지킨다. 장비 이름 다국어(09-10)는 값만 갈아 끼우면 됐지만 이쪽은 문장 구조가 언어마다 바뀐다.

**② 엔진의 한국어 이름표는 화면이 id로 다시 고른다.** `rules/src/types.ts`의 `STATUS_META`(22) · `TERRAIN_META`(3)는 `label`·`desc`를 한국어로 갖는다. 룰 엔진은 UI 언어를 알면 안 되므로(서버도 같은 엔진을 돌린다) 표는 그대로 두고, 새 파일 **`i18n/engineLabel.ts`**가 id를 열쇠로 화면의 문구 표에서 다시 고른다(`pickTacticNameById`와 같은 규약). `kind`(버프/디버프)는 번역할 것 없는 판정값이라 계속 엔진에서 온다. 키를 `` t(`status.${id}.label`) `` 꼴로 부르므로 **엔진에 상태가 늘면 타입 검사가 먼저 막는다**(`t()`가 `StringKey`만 받는다). 아홉 언어 쪽은 그 보호가 없어 `battleStrings.test.ts`가 막는다.
