### 쪽 넘김 한 컴포넌트로 — `Pager` (09-14)
쪽 넘김 구현이 **두 벌**이었다 — 대장간(`.frg-pager`, `{page} / {total}`)과 장수 일람(`.ofc-pager`, `{cur} / {max} 쪽`). 같은 화살표 목판(`PagerButton`)을 쓰는데 줄의 나머지가 따로 잡혀 있었다. `PagerButton.tsx`의 **`Pager`**로 모았다 — 쪽 번호와 [이전]·[다음]을 그리고 [처음]·[끝]은 `ends`로 켠다.
- `actionPrefix` — 대장간 지급 목록 위에 장수 선택 팝업이 뜨므로 한 화면에 쪽 줄이 **둘** 겹친다. 스모크가 집는 이름을 가른다(`assignPrevPage` 대 `prevPage`).
- 쪽 넘김이 있는 화면은 넷이 전부였다 — 궁궐 장수 일람, 장수 선택 팝업, 대장간 제작 목록, 대장간 지급 목록(주 후반에 부대 목록 · 출정하기가 더해졌다).

### 병영 · 부대 목록 — 현황판 · 필터 · 검색 · 정렬 (09-16)
- **병영 현황판** — 숫자는 전부 기존 함수가 낸다(`grainCap()`·`grainCost()`·`squadCap()`·`accountTally()`; 화면이 3·5를 글자로 박으면 정원이 바뀌는 날 표시만 어긋난다). 전적은 **계정 전적**(장수 전적을 더하면 출전 수가 사람 수만큼 부풀려진다). **[출정하기]는 여전히 안 잠근다** — 잠기는 이유가 둘(군량·장수 수)이고 모드마다 갈려서, 둘 중 싼 3v3도 못 낼 때만 숫자를 붉히고 한 줄을 적는다. 문 셋은 판때기의 직계 자식(스모크가 `.place-panel > .btn`으로 센다).
- **부대 목록** — 필터(3v3 · 5v5 · 전체) · 검색은 부대 랭킹의 `Dropdown`·`SearchBar`를 그대로(**`Dropdown`만 `export`로**). `FilterSelect`·`ModeSelect`는 값 묶음이 `RecordFilter`·`BattleMode`로 고정이라 「전체」가 섞인 세 값에 안 맞는다. 검색은 **부대 이름과 장수 이름 둘 다**, 장수 이름은 **한국어 평문과 지금 언어의 이름을 둘 다** 맞춘다(meta는 언어를 모른다).
- 고르는 줄: `Dropdown`에 `buttonLabel`을 더해 닫힌 상자가 값 대신 「분류」·「정렬」을 적게 했다(안 주면 예전 그대로라 랭킹 셋은 안 바뀐다). 최종은 **[분류]·[정렬] 단추 둘, 1:1** — 안 골랐을 땐 이름, 고른 뒤엔 값(`buttonLabel`을 고르기 전에만 준다).
- **정렬 셋** — 부대 이름 · 장수 이름 · 전투력(큰 쪽이 위, 성립 안 하는 부대는 맨 아래 — 「0점」이 아니라 「값이 없다」). 장수 이름 순은 **첫 사람만 보지 않는다**(첫 사람이 같으면 둘째, 그다음) — 같은 King을 여러 부대에 넣는 것이 흔해서다. 이름은 지금 언어의 것으로 견준다.
- **검색은 0.5초 디바운싱, [검색] 단추 없음** — `SearchBar`에 `debounceMs`를 더했다. 랭킹은 전체 유저를 훑는 서버 요청이라 「누르거나 Enter」를 지키고, 여기는 내 부대 열 개를 메모리에서 거르는 것이라 타이핑마다 걸러도 값이 안 든다. 어느 쪽인지는 부르는 쪽이 정한다.
- **[부대 삭제]는 편성 화면으로** — 이미 저장된 부대일 때만 뜨고, 지우고 나면 목록으로 돌아온다. 지우는 자리는 `App.tsx`에서 규칙(`removeSquad`)을 부른다(예전 목록은 `profile.squads.filter(...)`를 제 손으로 했다). 중간 단계(아래 단추 하나 + 고르는 팝업, 팝업은 필터·검색을 안 타고 `profile.squads` 전부를 보여 준다)는 같은 날 걷었다.
- 표 머리 여섯과 「필수」가 한국어 상수였다 → 장수 일람의 키(`officers.col.*`·`officers.sort.*`)를 빌렸다.

### 병영 개편 — 편성 화면 하나가 셋으로 (09-17)
흐름은 **새로 만들기와 고치기가 하나**가 됐다.

```
부대 목록 ─(줄)→ 부대 현황 ─[부대 관리]→ 부대 편집 ─[부대 배치 설정]→ 배치 편집 ─[수정 완료]→ 저장 → 부대 현황
            └[새 편성]→ 이름·인원 → 새 부대 편성 ─[부대 배치]──────→ 배치 편집 ─[편성 완료]→ 저장 → 부대 현황
```

| 쪽 | 화면 | 요점 |
|---|---|---|
| 65 | 병영(`PlaceScreen`) | 현황판에 최근 부대 셋(`RecentSquads`, 전적은 `sumTally(squad.record)`) |
| 66 | 부대 목록(`SquadListScreen`) | 한 쪽 다섯, `Pager`(`ends`) |
| 67 | 부대 현황(`SquadViewScreen`, 신설) | 읽기 전용 · 판 높이 다섯 줄 고정 |
| 68·71 | 부대 편집 / 새 부대 편성(`SquadMembersScreen`, 신설) | 포지션 드롭다운 · [선택]/[교체] · 변경 전/후 또는 부대 요약 |
| 69·72 | 부대 배치 편집(`SquadDeployScreen`, 다시 씀) | 판 전체 · 가상의 상대 · 남군/북군 작업본 둘 |
| 70 | `SquadNameScreen` | 「12자까지(현재 N자)」 |

- `SquadEditScreen.tsx`는 **지웠다.** `App.tsx`의 화면은 `squadView {id}` · `squadEdit {draft, base: Squad | null}` · `squadNew {initial?}` — **`base`가 `null`이면 신규.** 부대 현황은 부대를 값이 아니라 **id로 들고 매번 프로필에서 다시 찾는다**(레벨업·치료 뒤에도 옛 줄을 안 보이게).
- **저장은 배치 편집의 마지막 단추에서만** — 예전 편성 화면은 기물을 빼면 저장된 배치를 조용히 지웠다.
- **부대 편집** — 포지션 목록에서 King · 이 줄 · 다른 줄이 쓰는 기물을 **애초에 뺀다**(엔진 유닛 id가 `{진영}-{기물}`이라 한 부대에 같은 기물이 둘일 수 없다). 장수가 다른 줄에 이미 있으면 **두 줄이 맞바꾼다.** 장수 고르기는 대장간 지급 팝업(`OfficerPickModal`)을 그대로 쓰고(기획자 지정), 병기 데이터(`item`)가 제목에만 쓰이고 있어 제목을 밖에서 받게만(`title: string`) 바꿨다. [부대 배치 설정]은 부대원이 원본과 달라야 켜진다(`samePicks`), 신규는 성립하면. 「왜 안 되는지」는 **다 채운 뒤에만** 적는다.
- **배치 편집** — 20×25 전체에 전투 지도(`ui/chessmap.png`). **가상의 상대**(3v3 `R·K·Q`, 5v5 `R·B·K·Q·N`)를 엔진 기본 배치 자리(`defaultDeployPos`)에 두고 옮길 수도 있지만 저장은 우리 편 좌표만. 한 번 누르면 설 수 있는 빈 칸, 두 번 누르면 범위(다른 기물을 장애물로). [남군]·[북군]은 작업본 둘(`cells.P1`·`cells.P2`)과 진영별 상대 작업본을 함께 들고, 마지막 단추가 **둘 다** 넘기며 저장 가능 여부는 두 진영 모두 `isDeployable`에 묻는다. **기본 배치와 같은 진영은 `null`로 저장한다**(→ 결정·교훈 참조). 새 부대를 한 번도 안 만지고 끝내면 「부대가 기본 배치로 설정됩니다.」를 묻는다. [기본 배치로]는 목업에 없지만 예전 기능이라 툴바 오른쪽에 작게 남겼다.
- 기물 글자 — King과 Knight가 둘 다 `K`였다(예전 편집기의 `piece[0]`도 같았다). 체스 기보 약속대로 **Knight는 `N`**(`LETTER` 표).
- `squad.new.limit`의 `{n}`은 **코드 포인트로 센다** — `validateSquadName`이 `[...trimmed].length`로 세므로 표시와 판정이 같은 자를 쓴다.
