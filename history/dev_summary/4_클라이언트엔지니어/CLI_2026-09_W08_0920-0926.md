### 농지 손질 · 파수꾼 관리 · 알림 · 방어전 결과 (09-22)

- 「도적단 출현」은 셋으로 접는다(`raidText.ts`의 `raidStateText()` · `RaidTone`) — **출현**(대기 `09:31 후 전투` · 전투 중) · **약탈**(패배·항복, `군량 감소 N`) ·
  **퇴치 완료**(승리). 규칙의 결말은 여섯이라 접은 것이고, **무승부는 약탈이 없어** 「약탈 (군량 감소 0)」이 되지 않게 「물러감 (약탈 없음)」으로 갈랐다. 남은 시간은
  `mm:ss`(메인 단추는 `m:ss`).
- **파수꾼 관리** — 줄 수 = 농지 레벨(`guardSlots`). 빈 줄의 기물은 King → Rock → Queen → Bishop → Knight(부대 편성의 처음 포지션 차례)에서 아직 안 쓴 것.
  King 줄은 언제나 맨 위. [선택]/[해제] 토글.
- [선택]은 **부대 편집·대장간 지급과 같은 장수 일람 팝업**(`OfficerPickModal`) — 줄을 누르면 장수 카드, 체크 → [선택하기]. **부대에 든 장수는 목록에서 빼지 않고
  흐리게 못 고른다** — `OfficerListPanel`의 고르기 모드에 `blocked?: (officer) => string | null`을 더했다(`PickMode`). 부대 편집·대장간은 안 넘기므로 동작이 그대로다.
- 규칙이 거부하면(King보다 Rock을 먼저 등) **팝업을 닫고** 이유를 줄 밑에 띄운다. 빈 자리에서 다른 자리의 파수꾼을 고르면 그 장수가 **옮겨 온다** — 그래서 이미
  King인 장수를 빈 Rock 자리로 고르면 King이 비어 거부된다(규칙대로).
- **알림** — 본문 세 줄(도적 규모 · 아군 · 항복 시 피해) + 단추 셋([항복] · [전투 준비] · [지금 전투], 파수꾼이 없으면 [파수꾼 배치]). 항복 시 피해는 **서버가
  항복을 정산할 때 부르는 `raidLoot()` 그대로**다(화면이 다시 적지 않는다). 마감 1분 전 알림도 같은 본문·같은 단추 셋.
- 메인의 [전투하기 m:ss]는 도시 이름과 한 줄, 오른쪽 끝. 전투가 걸려 있으면 같은 자리가 [항복].
- **방어전 결과** — 판정 문구 · `남은 도적 : N 명` · `약탈당한 군량 : N/없음` · 이겼을 때만 보상 판 · 바닥 [농지로]/[메인으로](나가는 문이 둘이라 뒤로 화살표는 없다).
  `data-screen="raidResult"`는 판 전체를 감싼 `.rrs-frame`에 둔다 — `ScreenChrome`이 데이터 속성을 안 받는다. 이긴 화면은 가짜 승리 계정으로 실제 컴포넌트를 그리는
  임시 Vite 페이지(`_preview.tmp.html`, 지웠다)로 찍었다.

**버그 — 방어전 위에 「도적떼 출몰!」이 늦게 떴다.** [지금 전투]를 누르면 「이미 전투가 시작됐다」고 하고 안 닫혔다. **시작 요청이 두 번 나갔다** — 첫 요청이 판을
열었고, 둘째가 `raid.started`로 거부됐는데 그 실패 처리가 이미 넘어간 방어전 위에 알림을 열었다. 새 농지 [도적단 퇴치]에 두 번 누르기 막이가 없었다(더블클릭이 유력).

- `fightRaid()`를 **ref로 한 번만** 보낸다(`raidBusy` state는 다음 렌더에야 단추를 막는다) · 농지 단추도 요청 중에 막는다(`fightBusy`).
- 실패가 도착했을 때 **지금 화면이 판 안이면 알림을 안 연다** — 클로저의 `screen`은 누른 순간의 값이라 `screenRef`로 묻는다.
- 알림은 `NO_ALERT` 화면에서 **아예 그리지 않고**, 그 화면에 들어가면 남은 알림을 거둔다(예전엔 `NO_ALERT`가 「띄울지」를 정하는 effect만 막고 이미 켜진 알림의 그리기는 안 막았다).

### 등급 배지 컴포넌트 · 랭킹 전용 로딩 화면 (09-22)

- 배지 마크업 `<span class="gr" data-grade="S"><img src="icons/grade-s.png" alt="S"></span>` — 전투 UI(DOM)는 `ui/grade.ts`의 `gradeBadge()`, 메타 화면(React)은
  `screens/GradeBadge.tsx`. **그림이 404면 예전의 색 글자 배지로 물러난다**(`data-fallback`). React 쪽은 실패를 **등급별로** 기억한다. 등급 값은 언제나 `data-grade`에 있다.
  보상 카드의 「S급 카드」를 배지 하나로 바꾸며 안 쓰게 된 `result.cardGrade` 키를 10개 언어에서 지웠다. 타일 배지의 `S9`는 디버그 값(`debugTileBadges`)이라 그대로.
- **`screens/RankingLoading.tsx`** — 랭킹은 들어가는 순간 서버를 부른다(메뉴 `GET /ranking/mine`, 세 판 `GET /ranking`). 그동안 「—위」·빈 표가 한 박자 늦게 채워져
  「덜 그려진 화면」으로 읽혔다. 규약 넷(`BusyVeil`과 같은 생각):
  1. **첫 응답까지만 덮는다** — 필터·검색으로 다시 부를 때는 표만 옅어진다(`.rk-table-wrap[data-loading]`). `useRankingRows()`가 `ready`(첫 응답 — 성공이든 실패든)를 돌려준다.
  2. **뜸 180ms · 머무름 450ms** — `useRankingLoading()`. 짧은 왕복엔 안 보이고, 떴으면 번쩍이지 않게 잠깐 머문다.
  3. **가두지 않는다** — 판 아래 [뒤로](`data-action="rankingLoadingBack"`).
  4. **실패해도 걷힌다** — 「—위」·「불러오지 못했다」 안내는 원래 화면이 말한다.
  문구는 기존 `ranking.loading`을 써서 번역을 더하지 않았다. 「움직임 줄이기」에서는 메달·원반이 멈춘다.

### 농지·도적떼 91키를 여덟 언어로 — 에이전트 분업 (09-22)

09-21 첫 구현의 문구 67키는 한국어·영어만이었다(나머지 여덟 언어는 한국어로 물러남). 09-22에 농지 화면 · 파수꾼 · 도적떼 알림 · 결과 화면 문구 72개 + 파수꾼 거부 이유
(`reason.raid.*`) 14개 + 결과 화면 보상 칸(`result.*`) 5개 = **91개를 8개 언어**로 채웠다(영어는 `result.*` 5개만). 언어마다 에이전트 하나씩 나눠 맡겼고, **각 언어 파일에
이미 있는 용어를 먼저 읽게** 했다. 합치기 전에 스크립트로 자리표시자(`{n}` 등)가 한국어와 같은가 · 빠진 키 · 한글이 남았나를 봤다. 알림 본문 여섯 줄은 뒤에 따로 직접
번역했다. 쓰지 않게 된 문구 15개(옛 고르기 팝업·안내문)와 옛 본문 문장 4개(`raid.alert.body` 등)는 10개 언어 파일에서 지웠다.

⚠ 영어의 `result.*`는 이번 5개만 있어, **일반 대전 결과 화면**을 영어로 보면 보상 칸만 영어다.
