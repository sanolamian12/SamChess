# 4. 클라이언트 엔지니어

## 개요

**화면이 실제로 움직이게 만드는 사람.** 기획서의 화면을 React 화면으로 만들고, 전투를 재생하고,
연출·소리·10개 언어를 화면에 잇는다. 모든 기능이 마지막에는 화면을 지나기 때문에
**9주 내내 가장 바쁜 자리**였다 — 디자인 엔지니어가 CSS와 마크업을 직접 맡아 이 부담을 나눈다.

화면은 판정하지 않는다. 숫자는 엔진이 내고, 화면은 그것을 보여 주고 사람의 의도를 전달할 뿐이다.

## 역할

| 축 | 하는 일 |
|---|---|
| **화면 기능** | 간판·도시·궁궐·병영·장터·대장간·병원·농지·랭킹 화면의 흐름과 상태, 팝업·쪽 넘김 같은 공용 부품 |
| **전투 화면·연출** | 전투 재생기(`Playback`), 입력, 카메라, 공격·피격 자세, 고유기술 연출의 단계와 타이밍. 「맞기 전」 HP를 연출 층이 들고 있는 것 같은 표시 규칙 |
| **사운드 연결** | 배경음악·효과음·음성 더빙을 언제 틀고 언제 멈출지. 소리 파일 자체는 외주이고 가공은 디자인 엔지니어가 한다 |
| **다국어 인프라** | 10개 언어 전환 구조와 화면 연결. 번역 원고는 외주이고 검수는 게임 디자이너가 한다 |

## 다루는 것

- `packages/client` — React 화면, 전투 화면(`battle/`), 연출(`poses.ts`, `PoseDirector`), 다국어(i18n)
- `tools/smoke_*.ts` — 실제 브라우저로 화면을 끝까지 눌러 보는 스모크 (QA와 함께)

## 다른 포지션과의 계약

- **← 시스템 엔지니어**: 화면이 보여 주는 숫자(공격 예상·성공률·레벨업 증분)는 엔진 함수에서 받는다. 화면이 공식을 다시 적지 않는다.
- **← 서버 엔지니어**: 로컬 대전과 온라인 대전을 `BattleTransport` 하나로 똑같이 다룬다.
- **↔ 디자인 엔지니어**: **기능·상태·데이터 흐름은 이쪽, 모양(CSS·그림·치수)은 저쪽.** 연출은 타이밍과 순서가 이쪽, 그림과 애니메이션 원본이 저쪽이다.

## 이 자리에 필요한 역량

React·TypeScript, 상태 관리, 2D 연출 타이밍 감각, 브라우저 자동화 테스트(Playwright).
웹 하나로 PC·Android·iOS를 함께 노리므로 해상도 대응.
