# dev_summary — 포지션별 개발 기록

`history/*.md`는 개발하면서 매일 쌓이는 **작업 기록**이다(Claude가 세션마다 남긴 결정·참고·지뢰).
이 폴더는 그것을 **한 달 단위로 다시 짜서** 사장님이 읽도록 정리한 것이다 —
"이 게임을 다섯 명의 팀이 만들었다면 누가 무엇을 했는가"의 관점으로.

## 팀 구성 — 소수정예 기준

| # | 포지션 | 필요 시점 | 한 줄 정의 |
|---|---|---|---|
| 1 | 게임 디자이너 | 처음부터 (대표 겸임 가능) | 무엇을 만들지와 그 수치를 정한다 |
| 2 | 시스템 엔지니어 | 처음부터 | 규칙과 성장·경제를 결정적인 코드로 만든다 |
| 3 | 서버 엔지니어 | **출시 직전부터 상근** — 지금은 자리만 열어 둔다 | 서버를 판정의 주인으로 세우고 운영한다 |
| 4 | 클라이언트 엔지니어 | 처음부터 | 화면이 실제로 움직이게 한다 |
| 5 | 디자인 엔지니어 | 처음부터 | 화면이 어떻게 보일지 정하고 직접 입힌다 |

최소 기준선은 **1·2·4·5의 넷**이다. 출시 전에는 서버 일이 2번(시스템 엔지니어)에게 붙어 있다가,
결제·라이브 운영이 시작되면 3번이 갈라져 나온다. 8~9월에는 3번 폴더의 주간 문서가 드문드문하다 — 그게 정상이다.

외주로 도는 것: 사운드 제작, 10개 언어 번역, 장수 일러스트. 팀은 그것을 **받아서 잇는 일**을 한다.

## 규칙

- **주는 일요일~토요일.** 한 주는 **시작일이 속한 달**에 넣는다 (8/30~9/5는 8월).
- 파일 이름: `{약자}_{월}_W{주번호}_{시작MMDD}-{끝MMDD}.md` — 주번호는 8/2 주를 W01로 놓고 이어 센다.
  약자를 앞에 붙여 **모든 파일 이름이 폴더 밖에서도 겹치지 않게** 했다(한 폴더로 모아도 덮어쓰지 않는다).

  | 약자 | 폴더 | 뜻 |
  |---|---|---|
  | `MST` | 0_마스터 | Master |
  | `GD` | 1_게임디자이너 | Game Designer |
  | `SYS` | 2_시스템엔지니어 | System engineer |
  | `SRV` | 3_서버엔지니어 | Server engineer |
  | `CLI` | 4_클라이언트엔지니어 | Client engineer |
  | `DSN` | 5_디자인엔지니어 | Design engineer |
  | `QA` | 6_QA검증 | QA · Verification |
  | `DL` | 7_결정교훈 | Decisions & Lessons |

- 각 폴더의 `{약자}_README.md`에 그 포지션의 **개요·역할**과 **월간 업무 표**가 있고, 주간 문서가 세부다.
- 주간 문서는 요약이 아니다. 원문의 내용·수치·판단 근거를 살려 재배치했고, 각 절 끝에 원문 파일을 출처로 남겼다.
- 한 원문은 여러 포지션으로 쪼개진다. **결정과 교훈의 본문은 `7_결정교훈`에**, **검증 상세는 `6_QA검증`에** 있고 포지션 문서에는 한 줄로 남는다.
- 그 주에 일이 없던 포지션은 파일이 없다.
