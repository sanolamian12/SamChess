## 규칙·콘텐츠 기획

### 상점 가챠 모델 확정 (08-24)
Colyseus 트랙(H1~H3d)이 08-21에 끝난 뒤 다음 트랙이 정해지지 않은 상태에서, 상점 UI는 기획자가 직접 만들어 주기로 해 아직 없었다. 가격 정책은 `history/2026-08-21_트랙9_가격정책_초안.md`에서 사전 논의가 끝나 있어 **「상점 UI 없이도 할 수 있는 절반」**만 먼저 밟기로 했다. G1(인물 서사)·다국어도 후보였지만 원본 자료가 저장소에 없어(검색 0건) 제외했다.

사용자 확인을 거쳐 확정한 것:
- **가챠 등급 풀은 `S·A·B·E`** — 전투 보상 풀(`B·C·D`, §5-22 불변식)과 B만 겹친다. (기존 데이터의 `["S","A","B","C"]`를 바꿨다.)
- **모델은 계정별 유한 랜덤 어레이** — 고정 확률표가 아니라, 계정마다 등급 장수 카드를 섞은 유한 배열에서 복원 없이 하나씩 뺀다.
- **`gachaRates` 필드는 없앤다** — 이 모델엔 고정 rate가 없고, 등급별 확률은 「그 등급에 속한 장수 수」가 정한다(계산값이지 데이터가 아니다).
- **슬롯 수 = 장수 1명당 200장** = 레벨 9 누적 카드 100장 × 배수 2(`gachaSlotMultiplier: 2`). 계정 전체 배열은 25,200장이다. 이 200을 GDD에 숫자로 박지 않고 매번 `growth.json`에서 계산한다(→ 결정·교훈 참조).
- **소진은 정상 상한이 아니라 매크로 남용을 막는 안전장치**(확정안 §4.4) — 도달해도 뽑기 자체가 멈추면 안 된다.
- 고정 카드 수 팩(`cardPacks`)은 단발/10연 골드 가격(`gachaPull`)으로 바뀌었다.

GDD §6.2·§12, 작업계획 §5-109~114, HANDOFF §2·§7을 갱신했다.

### 계정 구조 — 단일 도시 + 도시 이름 변경 규칙 (08-25)
사용자가 「Sydney」로 온보딩을 테스트하다 도시를 다시 만들 방법이 없다는 걸 발견하며 「계정당 도시 여러 개 vs 하나 + 철거 후 재건축」을 물었다. `PlayerProfile.cityName`이 단일 필드이고 군량·전적·로스터·매칭이 「프로필 하나 = 도시 하나」를 전제하므로 **단일 도시**로 정리했고, 지금 필요한 것은 게임 기능으로서의 철거가 아니라 **테스트용 탈출구**(`[테스트] 도시 삭제`)라는 데 동의했다(→ 결정·교훈 참조).

도시 이름 중복 검사가 **아예 없다**는 것도 이때 확인됐다(DB가 `uid` 기준 한 행이라 `cityName`에 유니크 제약이 없고, 어떤 라우트도 다른 계정과 대조하지 않는다). 사용자가 「계정 id + 도시 이름 조합이면 어차피 유니크하니 검사는 필요 없고, 생성 후 이름을 바꿀 수 있게 하자」고 정했다. 규칙:
- **쿨다운 3일**, **비용은 재설계(둔갑천서)와 같은 금화**(`CITY_RENAME_GOLD = RESPEC_GOLD`) — 둘 다 사용자에게 직접 물어 정했다. 새 상수를 늘리지 않고 기존 기준을 재사용했다.
- 도시 생성 화면에서 처음부터 규칙을 알린다 — 「나중에 도시 관리에서 바꿀 수 있다 — 금화가 들고 3일간 재변경 불가」.
- 악용 여지(랭킹 매칭 직전 개명으로 상대 혼란)는 3일 쿨다운 + 금화로 어느 정도 억제되지만, 랭킹/매칭 화면이 아직 없어 실전 검증은 못 했다.

### 랭킹 3화면 — pptx 46~52쪽 (08-27)
사용자가 pptx 46~49쪽에 도시/부대/장수 랭킹을, 50~52쪽에 디자인 심화 가이드를 그려 넣었다. 첫 구현(탭 하나짜리 화면)을 심화 가이드를 받고 **메뉴 → 그 안의 화면 셋**(궁궐·병영과 같은 결)으로 다시 짰다. 확정된 기획:
- **「전·승·무」 세 열을 「승/무/패」 한 열로 접는다** — 총점이 **승×3 − 패 + 적 격파**이고 출전 수는 승+무+패로 다시 셀 수 있다.
- 모드·상대 필터는 리스트 박스(드롭다운) 둘을 한 줄에(모드 왼쪽·상대 오른쪽) — 처음 알약 버튼 줄을 사용자가 바꿨다.
- 위(서버 랭킹 top-5)는 스크롤, 아래(내 랭킹)는 화면 바닥 고정.
- 「총점」 같은 계산식 열 머리를 누르면 바로 아래 줄에 공식이 펼쳐진다 — 표 밑의 상시 안내문을 없앴다.
- **「아이디」 열은 뺀다** — 그래서 서버가 `auth.users`를 조인할 필요가 없어졌다.
- **부대 랭킹의 「전투력」 열은 없앤다**(한 차례 뒤집음) — 매칭용 `battlePower()`는 회귀 계수라 「왜 이 숫자인가」를 설명할 수 없어 `squadDisplayPower()`(등급 점수 × 레벨의 합)를 만들었다가, 행을 누르면 구성(등급·레벨·HP·MP·AT)이 이미 펼쳐지므로 요약 숫자가 필요 없다고 사용자가 뒤집어 함수째 제거했다(→ 결정·교훈 참조).
- **장수 랭킹에도 모드(3v3/5v5) 필터** — 장수 일람(전적 화면)은 이미 나눠 보는데 장수 랭킹만 없다는 지적.
- 외교(동맹 제안·도시 방문·원군 요청, pptx 47쪽 하단)는 세션 시작부터 범위 밖 — 상대 도시 상세 열람·장수 파견 같은 새 데이터 모델이 필요한 별도 기능이다.

### 장수 카드 — pptx 53쪽 (08-27)
- 초상은 전투 수묵화가 아니라 **「체스 게임에 들어갔을 때 기물로 쓰는 이미지」**(`assets/Chars/` → `portraits/{id}.png`)다.
- 이름(자·등급)이 중앙 상단 → 그 아래 두 단(왼쪽 기물 그림, 오른쪽 정보 다섯 줄) → 인물 열전.
- 다섯 줄 최종 순서(세 번 뒤집었다): **① 전적(승/무/패·적 격파) → ② 삼능력(무력·지력·통솔) → ③ 고유기술(있으면 이름, 누르면 설명 팝업 / 없으면 「고유 기술 없음」) → ④ 레벨·HP·MP·AT(AT는 「2-5」 범위) → ⑤ 배운 책략(칩, 없으면 「습득한 책략이 없음」)**. 다섯 줄 전부 **없어도 줄째로 안 사라진다**(처음엔 고유기술·책략이 없으면 숨겼다가 뒤집었다).
- 고유기술은 장수 고정값, 책략은 계정마다 다르다(같은 장수라도 레벨업으로 무엇을 배웠는지가 갈린다).
- 이후 세션(같은 날 둘째)에서 팝업으로 전환, 액자 제거, 비율 4:6 → 3:7, 「전적」 이름표, 삼능력 아이콘화, 전적 표기 「0 / 0 / 0」 등 여덟 차례 사용자 지정을 거쳤다(모양은 디자인 문서).

### 전투 연출 순서 요구 (08-26)
사용자가 보고한 연출 기획 요구가 수정 기준이 됐다:
- 적 책략: **책략 소리는 성공/실패와 무관하게 먼저** 나고, **성공했을 때만 0.5~1초 뒤** 디버프 띠·포커싱·피격 액션이 같이 난다.
