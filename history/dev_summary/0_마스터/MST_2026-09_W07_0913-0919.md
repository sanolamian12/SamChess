## 1. 도시 증축 조건 · 보관함 이관 (09-14)

**결과** — 도시 증축이 「자재만 모이면」에서 **건설 기회를 다 쓰고 · 보유 장수 총원(Lv2 10명 … Lv10 140명) · 그중 S·A급(Lv4부터 3명 … Lv10 15명, Lv11 헌제)**을 채워야 하는 것으로 바뀌었다. 무과금은 Lv3까지 열리고 첫 S·A 벽은 Lv4다. 보유 장수는 **풀 + 보관함**으로 세고 황제 판정도 같은 셈이며, 궁궐 증축 때 보관함 → 풀 이관이 붙었다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 게임 디자이너 | 기획자와 표를 1안 → 2안 → 3안 → 확정안으로 다듬고, 성향 셋 × 4,000회 시뮬레이션으로 도착 판 수 · 가챠 비용(Lv10까지 10연 3회 수준)을 냈다 |
| 시스템 엔지니어 | 조건 넷(기회 → 총원 → S·A → 자재)과 보관함 이관 · 황제 판정을 meta에 넣고, 추출기에 필요 장수 상수를 넣었다(저장 형식은 그대로) |
| 클라이언트 엔지니어 | 도시 화면이 자재가 모자라도 장수 이유를 함께 보이게 하고, 황제 표시를 새 판정으로 바꿨다 |

**맞물린 자리** — 기획자의 「궁궐 강제 선택」 안을 시뮬레이션에 넣자 풀만 세면 전투 먼저 계정이 **100% 정지** → 구현 쪽이 「풀 + 보관함」을 제안해 교착 0%로 기획에 반영됐다. 엑셀 「도시 건물」에 필요 장수 열이 없어 시스템이 추출기 상수로 임시로 받았다.

**검증** — `city.test.ts` 7건 신설, `smoke:meta` 도시 절을 새 조건에 맞추고 이관 검사를 일부러 깨서 그 자리에서 멈추는 것을 확인. **결정** — 증축 조건 확정안 · 「궁궐 강제 선택」 대신 「보유 = 풀 + 보관함」.
**남은 것** — 엑셀 필요 장수 두 열, 증축 화면의 진척 표시(「보유 장수 23/30 · S·A 2/3」), 방출 규칙.

## 2. 장수 성장 개편 — 레벨 상한 · 카드 추첨 · 카드 정리 (09-14)

**결과** — 시뮬레이션이 「상한이 걸리기도 전에 카드가 흩어져 장수가 안 큰다」(최소 과금 최고 Lv3)를 드러내 세 규칙을 함께 확정했다. **장수 레벨 상한 = 도시 레벨(최대 9)**, 승리 카드는 보유 장수 전원 + 새 B급에서 **가중치 추첨**(S1·A2·B3·C4·D5·E1, C·D면 1장 더), 패배 카드는 C·D 1장, 장터에 **같은 등급 3장 → 보유 장수 1명의 카드 1장** 정리가 생겼다. 규칙의 성질은 「C·D는 전투로, S·A는 가챠로 큰다」이다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 게임 디자이너 | 성장 시뮬레이션으로 문제를 찾고 기획자 결정 넷을 정리했다(무승부 택1은 승리와 같은 추첨으로 해석) |
| 시스템 엔지니어 | 상한 판정 · 가중치 추첨 · `recycle.ts`(카드 정리)를 meta에 넣었다 |
| 서버 엔지니어 | 레벨업 · 카드 정리를 서버 전용 경로(`/officer/levelup` · `/market/recycle`)로 받았다 |
| 클라이언트 엔지니어 | 결과 화면 카드 여러 줄, 레벨업 상한 이유, 장터 [카드 정리] 팝업, 두 번 누르기 방지 |

**맞물린 자리** — 시뮬레이션의 「플레이어 전략」 설정이 두 번 거짓 결과를 내(리사이클이 있으면 더 느리다 · 중간 과금이 최소 과금보다 느리다) 모델을 고친 뒤에야 기획자에게 숫자를 넘겼다.

**검증** — `recycle.test.ts` 10건 · 「이백 번 이겨도 새로 들어오는 장수는 B급뿐」 등, 상한 · 보유 장수만 · C·D 덤을 일부러 끄면 각각 1건씩 깨짐 확인. **결정** — 장수 성장 세 규칙(오전의 「패배 C·D 균등 1장」 · 옛 카드 정리 10장 설정을 대체).

## 4. 계정 쓰기 경합 · 서버 권위 A안 (09-14 ~ 09-16)

**결과** — 12일 동안 스모크를 막던 「거절 군량이 안 남는다」의 정체가 **잠금 없는 계정 쓰기 경합**이었다. 제품 경로의 모든 쓰기를 행 잠금 트랜잭션(`mutateProfile`) 하나로 모았다. 이어 `PUT /profile`이 금화 · 가챠 · 명단 · 카드까지 믿던 구멍을 **A안(행위별 전용 경로)**으로 단계적으로 닫았다(A1 금화 · 가챠 → A2 명단 · 카드). 가챠 시드는 서버가 내고, 개발용 지급은 기본으로 닫혀 있다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 서버 엔지니어 | 경합을 측정해 원인을 밝히고 행 잠금으로 고쳤다. 가챠 · 도시 이름 · 재설계 · 레벨업 · 카드 정리 · 개발용 지급 경로를 새로 열었다 |
| 시스템 엔지니어 | 서버 소유 필드 목록을 넓혔다 |
| 클라이언트 엔지니어 | 장터 · 레벨업 · 재설계 · 카드 정리가 서버 왕복이 되고, 못 닿으면 물러나지 않고 「서버에 닿지 못했다」를 말한다 |
| 게임 디자이너 | (기획자) A~D 네 안 중 A안 단계적 진행을 결정했다 |

**맞물린 자리** — 「레벨업은 통과시키고 부상만 지킨다」던 예전 권한 회귀가 곧 구멍이었다 → 행위가 서버로 옮겨 오자 회귀를 「규칙대로 올렸어도 `PUT`으로 온 레벨은 저장되지 않는다」로 뒤집었다. 서버 소유가 된 필드를 `PUT`으로 심던 스모크는 QA가 서버 쪽 심기로 바꿨다.

**검증** — 경합 측정 1/15 → **0/40**(잠금만 빼면 37/40). `smoke:meta`가 **12일 만에 완주**(✓ 62건, 뒤에 낡아 있던 검사 열한 자리를 함께 고침). 권한 회귀는 필드를 일부러 빼면 A1 2건 · A2 5건 실패. **결정** — 레벨업 · 카드 정리의 서버 검증 A안 단계적 · 개발용 지급 기본 닫힘.
**남은 것** — `PUT`은 아직 전적 · 이력 · 부대 전적을 믿는다(랭킹 부풀리기 가능). 저장 실패 · 세션 만료가 화면에 안 뜬다(제안만 함).

## 5. 부대 편성 정책 — 「소속」, 레벨 하향 폐지 (09-16)

**결과** — 2026-08-18의 「부대의 레벨은 상한이지 스냅샷이 아니다」를 기획자 결정으로 **뒤집었다.** 부대는 `{기물, 장수}`만 저장하고, 어느 부대에서든 장수의 **지금 보유 레벨**로 선다. 레벨이 바뀌는 자리는 궁궐(레벨업 · 둔갑천서)뿐이고, 바뀌면 그 장수가 속한 모든 부대에 곧바로 반영된다. 「일부러 약하게 나가기」는 둔갑천서로 되감고 카드를 일부만 다시 쓰는 길로 옮겨 갔다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 게임 디자이너 | 새 정책과 「약한 상대를 만나는 길」을 정리했다(코드 변경 없는 기존 절차) |
| 시스템 엔지니어 | 부대의 `level`과 성장 스택을 자르던 `cap` 인자까지 지웠다. 옛 부대의 레벨은 버리고 부대는 살린다(버전 그대로) |
| 서버 엔지니어 | AI 대전 재생 검증이 레벨을 읽지 않게 되어 레벨을 낮춰 자칭할 길이 없어졌다 |
| 클라이언트 엔지니어 | 편성 화면의 레벨 눈금 단추를 걷고 「Lv N」 읽기 전용으로 |

**검증** — 「한 장수를 두 부대에 넣고 궁궐에서만 Lv6으로 키우면 두 부대 모두 6」 등 `squads.test.ts` 회귀 넷. **결정** — 부대는 장수의 「소속」(2026-08-18 뒤집음).

## 6. 병영 개편 (09-16 ~ 09-18)

**결과** — 병영에 현황판(군량 · 부대 수 · 전적 · 참가비, 최근 부대 셋)이 서고, 부대 목록은 필터 · 검색 · 정렬 · 쪽 넘김을 갖췄다. pptx 64~72쪽대로 편성 화면 하나가 **부대 현황 · 부대 편집 · 배치 편집**으로 갈렸고, 새로 만들기와 고치기가 한 흐름이 되어 **저장은 배치 편집의 마지막 단추에서만** 일어난다. 기물을 바꾸면 옛 자리를 물려받은 판을 확인한 뒤 남군 · 북군 둘 다 저장한다. 군영 네 화면은 랭킹 · 궁궐 · 대장간과 같은 목판 · 장부 화풍으로 리스킨됐다(트랙 10d).
