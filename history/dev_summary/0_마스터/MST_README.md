# 0. 마스터

## 개요

**한 주에 어떤 기능이 나왔고, 그 기능에 포지션들이 어떻게 맞물렸는지를 보는 곳이다.**
포지션 폴더(1~7)가 「누가 무엇을 했나」라면, 마스터는 **개발 주제(기능) 축**으로 같은 한 주를 다시 엮는다.
기능 하나는 보통 여러 사람의 손을 지난다 — 기획이 사양과 수치를 정하고, 시스템이 규칙을 코드로 세우고,
서버가 권위 경로를 붙이고, 클라이언트가 화면을 움직이고, 디자인이 모양을 입힌다.
그 흐름과 이음매를 한눈에 보며 **팀을 조직하고 일을 배분하는(오케스트레이션) 관점**으로 쓰기 위한 폴더다.

**상세가 아니라 결과다.** 무엇이 가능해졌나 · 무엇이 확정됐나 · 무엇이 남았나.
구현 상세와 지뢰 이야기는 각 주제 끝의 링크를 따라 포지션 문서로 내려가서 본다.

## 주간 문서 읽는 법

| 절 | 내용 |
|---|---|
| **이번 주 한 줄** | 이 주의 성격 |
| **한눈에 — 주제 × 포지션** | 주제마다 누가 참여했나 (● 주도·핵심 / ○ 보조), 결과, 상태 |
| **주제별 절** | 결과 → 포지션별 맡은 몫 → **맞물린 자리**(누가 넘기고 누가 받았나, 어디서 어긋났다 맞췄나) → 검증·결정·남은 것 → 포지션 문서 링크 |
| **그 밖에** | 주제로 묶기에 작은 단독 작업 |
| **다음 주로 넘어간 것** | 이 주 끝에 열려 있던 일 |

포지션 약자: `GD` 게임 디자이너 · `SYS` 시스템 엔지니어 · `SRV` 서버 엔지니어 · `CLI` 클라이언트 엔지니어 · `DSN` 디자인 엔지니어
(QA·결정교훈은 열이 아니라 각 주제의 「검증」「결정」 줄로 들어간다.)

## 월간 업무

### 2026년 9월 (W06~W09)

> **도시의 빈 건물이 하나씩 「할 일이 있는 곳」이 되고, 경제와 서버 권위가 출시를 바라보는 모양으로 굳은 달.**
