## 1. 전투 규칙 완성 (07-31 ~ 08-02)

**결과** — CTB 스케줄러 위에 책략 18종과 고유기술 40종이 전부 들어갔다. 40종 중 스크립트가 필요한 것은 2종(소패왕전 · 차동풍)뿐이고 38종은 데이터(Effect DSL)로 접혔다. 턴 구조 · E급(Emperor) · 삼고초려 · 무승부 등 규칙의 빈칸이 기획자 확정으로 닫혀 GDD §12에 반영됐다. 회귀 테스트 12 → 113건.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 게임 디자이너 | S급 30종의 애매한 판정을 12개 질문으로 압축해 한 번에 확정, 확정 규칙을 GDD §12에 표로 반영 |
| 시스템 엔지니어 | 스케줄러 · 책략 · 고유기술 40종 구현, 스케줄러 정지 버그와 로그 deep clone의 O(턴²) 문제 해결(자동 대전 3판 152초 → 1.7초) |

**맞물린 자리** — 기획 문서(GDD §3.4)의 「이동 후 다음 중 하나」를 시스템이 그대로 구현했다가, 기획자가 「고유기술은 턴 맨 앞의 별도 단계」로 정정 → 엔진 수정. 삼고초려도 진영 변경으로 먼저 만들었다가 기획 판단으로 「영구 조종」이 됐다.

**검증** — 회귀 12 → 113건, 「로그는 얕게 복사한다」 테스트가 성능 회귀를 고정한다. **결정** — 턴 구조(고유기술 → 이동 → 행동) · E급 = Emperor, 헌제 King 금지 · 삼고초려 = 영구 조종 · 무승부 = `time 6000` + 총 HP 판정.

## 2. 밸런스 실측 5000판 (08-02)

**결과** — 기준 AI끼리 Lv1 5000판(22초)을 돌렸다. 선공 49.8% / 후공 50.2%, 기물별 47~52%로 고르고, 결착 최대 시간이 무승부 상한의 절반에도 못 미친다(판정승 0%). 등급별은 S 66.5 / A 59.4 / B 47.3 / C 46.6 / D 40.7%로 **A↔B 사이 12%p**가 가장 벌어진다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 게임 디자이너 | 실측 결과를 해석해 기물 밸런스 이상 없음을 확인, A↔B 격차를 기획 질문으로 남김 |
| 시스템 엔지니어 | 기준 AI + 밸런스 하네스(`tools/balance.ts`) 구축, 하네스는 비교 가능성을 위해 Lv1 고정 |

**맞물린 자리** — 하네스가 통계 도구이면서 엔진 버그 검출기 노릇을 했다 — 5000판 중 3판(전부 곽가)이 「무승부」로 묻혀 있던 스케줄러 정지와 「유인」 무시 버그를 잡아 시스템이 고쳤다.

**검증** — 통계 층이 단위 테스트와 다른 종류의 버그를 잡는다는 것이 확인됐다. **결정** — 비정상 종료는 무승부로 접지 않고 예외를 던진다.
**남은 것** — A↔B급 12%p 격차가 과금 설계상 의도인지 기획 확인.

## 4. 오프라인 풀 사이클 — 계정 · 편성 · 성장 · 배치 · 정찰 (08-04 ~ 08-07)

**결과** — React 메타 UI(계정 · 편성 · 성장)와 배치 · 정찰 화면이 붙어 계정에서 전투 결과 반영 · 레벨업 · 저장까지 한 바퀴가 돈다. 계정 규칙의 권위 `packages/meta`가 룰 엔진과 같은 자리에 섰다. GDD §12의 「미해결」이 전부 닫혔다.

| 게임 디자이너 | 미결 셋 확정(1:1 영구 삭제 · 레벨업 실패 없음 · AI 보상은 군량만), 배치 30초 · 정찰 30초 |

| 서버 엔지니어 | Colyseus를 이 사이클 뒤로 미루고, 온라인이 이어 붙을 자리 셋(`playback` · 마감 시각 · `storage.ts`)을 정리 |
| 클라이언트 엔지니어 | 메타 UI · 배치 · 정찰 화면 구현, 저장 자리 하나(`storage.ts`), 개발용 카드 지급(시험용 문) |

**맞물린 자리** — 기획의 「AI 보상은 군량만」 결정 때문에 오프라인으로는 카드가 안 늘어, 클라이언트가 규칙은 그대로 두고 개발용 카드 지급 문을 따로 뒀다. 서버는 화면 · 편성 규칙이 오프라인에서 먼저 굳게 순서를 양보했고, 클라이언트가 판정을 전부 엔진에 묻도록 짜 둬 온라인 전환 때 서버가 맡을 것은 타이머와 전송뿐이 됐다.

**검증** — 회귀 113 → 134건(메타 17건 포함), `smoke:meta` 신설(계정 → 편성 → 배치 → 정찰 → 전투 → 군량 → 레벨업 → 저장). **결정** — 작업 순서 변경(Colyseus보다 오프라인 먼저) · 미결 셋 확정 · 배치 중에도 상대 기물 공개.
**남은 것** — Colyseus 온라인 대전, 개발용 카드 지급은 온라인 · 상점이 붙으면 지운다.

**결과** — 장수 초상 260장 전부의 배경을 학습 모델 없이 지우는 도구를 만들었고(260장 39초), 보드 타일이 배경 제거본을 쓰게 되어 유닛이 판 위에 선다. 화면 코드는 한 줄도 안 바뀌었다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 디자인 엔지니어 | `remove_char_background.py` 신규, `build_portraits.py`가 배경 제거본 우선 · 폴백 시 이름을 알림, 260장 재생성 |

**검증** — 260장 전수 남은 넓이 31.1~53.6%, 이상 0장(여포 1장은 수동 seed), 양 극단 14장 + 무작위 86장 눈검사, 세 판 색 위 합성 확인. **결정** — 학습 모델 기각 · 여포는 손으로 · 폴백은 알리고 찌꺼기는 자동 삭제하지 않는다.
**남은 것** — 수묵화(`CharsInBattle`)는 197/260명, 장수 추가 시 `Chars-noback`에도 넣어야 한다.
