## 1. 상점 가챠 · 장터 화면 (08-24)

**결과** — 가챠 모델이 확정됐다: 등급 풀 `S·A·B·E`, 계정별 유한 랜덤 배열(장수 1명당 200장, 계정 25,200장), 고정 확률표 없음. 그 위에 장터 화면 1차 초안이 붙어 단발·10연 뽑기로 실제 금화가 차감되고 카드가 지급된다. 등급 색(S 보라·A 빨강·B 파랑·E 황금)이 게임 전체에 새로 적용됐다. 카드 정리·재설계·금화팩 세 칸은 자리만 두고 잠갔다(잠긴 이유를 화면에 적음).

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 게임 디자이너 | 가챠 모델·등급 풀·슬롯 수(레벨업 누적 카드 100 × 2)·등급 색 확정, 거래 칸 셋은 규칙 미정으로 잠금 |
| 시스템 엔지니어 | `gacha.ts` — 배열을 저장하지 않고 `{seed, drawn}`만 들고 다시 섞는 구조 + 금화 검증·지급을 묶은 구매 함수, `ECONOMY` 가챠 필드 갱신 |
| 클라이언트 엔지니어 | 장터를 별도 최상위 화면으로 — 재화 바·배너·단발/10연·개봉 결과 모달·잠긴 거래 칸 |
| 디자인 엔지니어 | 장터 그림 16장 + 카드 액자 6장 굽기 도구, 개봉 연출 배경 제거(체커보드 박제 JPG를 신호처리로 복원), 등급 색을 그림에서 역산 |

**맞물린 자리** — 기획이 「고급진 보라/빨강/파랑/황금」으로 넘긴 색 가이드를 디자인이 손으로 고르지 않고 개봉 연출 그림에서 역산 → 뽑기 화면에서 터지는 색과 배지 색이 갈리지 않는다. 화면은 버튼만 잠그고 금화 판정은 시스템의 구매 함수가 다시 한다(「화면이 판정하지 않는다」). 슬롯 수 200을 숫자로 옮겨 적지 않고 기존 레벨업 카드 함수에서 계산한다.

**검증** — 가챠 회귀 15건(12 + 구매 3), 장터에서 단발·10연 실제 차감·지급까지 스크린샷 확인. **결정** — 유한 배열 가챠·`gachaRates` 폐지, 10연은 개봉 연출 생략(피드백 1순위로 다시 볼 자리).
**남은 것** — 카드 정리 교환 규칙, 금화팩 결제 방식, 10연 연출 피드백, `gachaPool` 되접기(마이그레이션) 누락 수정.

## 2. 랭킹 3화면 · 장수 카드 (08-25 ~ 08-27)

**결과** — 메인 화면에 랭킹 자리가 새로 생겨(넷째 배경 칸 = 랭킹 확정) 한 번에 들어간다. pptx 46~53쪽대로 메뉴 → 도시/부대/장수 랭킹 세 화면, 위는 서버 top-5(스크롤)·아래는 내 랭킹(바닥 고정)이다. 장수 카드는 기물 그림 + 다섯 줄(전적 → 삼능력 → 고유기술 → 레벨·HP·MP·AT → 책략) 팝업으로 굳었고, 랭킹 전체가 목판·양피지 화풍으로 리스킨됐다. 부대에 처음으로 전적이 붙었다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 게임 디자이너 | 메인 랭킹 자리, 세 화면 기획(「승/무/패」 한 열, 아이디·부대 전투력 열 제외, 장수 랭킹 모드 필터), 장수 카드 구성 |
| 시스템 엔지니어 | 랭킹 행을 만드는 순수 함수(서버·클라 공용), 부대 전적(`Squad.record`) 신설, 장수 랭킹 모드 인자 |
| 서버 엔지니어 | `GET /ranking` — 전체 프로필 스캔으로 top-5·검색, 새 스키마 없음 |

**맞물린 자리** — 시스템이 만든 같은 순수 함수를 서버는 전체 스캔에, 클라는 「내 랭킹」에 써서 서버가 죽어도 내 것은 보인다. 기획이 「아이디」 열을 빼면서 서버의 사용자 테이블 조인이 필요 없어졌다. 부대 「전투력」 열은 시스템이 표시용 함수를 만들었다가 기획이 뒤집어 함수째 제거됐다.

**검증** — 랭킹 회귀 포함 전체 460/463(실패 3건은 무관한 기존 건), 2-인자 호출 하위 호환 확인. **결정** — 부대 전적은 이력에서 파생하지 않고 따로 센다, 외교(pptx 47쪽 하단)는 범위 밖.
**남은 것** — 붓선 구분선 그림 받기, 서버 전체 스캔(`SCAN_CAP`)은 지금 규모용 자리표시자.

## 3. 계정 구조 — 단일 도시 · 이름 변경 · 회원가입 (08-24 ~ 08-25)

**결과** — 실사용자가 보고한 회원가입 크래시가 고쳐졌다: Supabase 「Confirm email」이 켜져 있어 응답 모양이 달랐던 것으로, 이제 켜짐/꺼짐 어느 쪽이든 동작하고 확인 메일 → 로그인까지 사용자가 직접 확인했다. 계정은 「단일 도시」로 정리되고, 도시 이름은 3일 쿨다운 + 둔갑천서와 같은 금화로 바꿀 수 있게 됐다. 테스트용 탈출구로 `[테스트] 도시 삭제`가 생겼다. 「같은 이름 → 같은 다섯 명」 시드 안내 문구는 파밍 안내가 되어 지웠다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 게임 디자이너 | 단일 도시 결정, 이름 변경 규칙(3일·`RESPEC_GOLD`), 시드 문구 삭제, 이용약관·연령 고지 자리를 「계정 생성」 단계로 |
| 시스템 엔지니어 | 이름 변경 가능 여부·적용 함수(시각을 인자로), 마이그레이션에 새 필드 반영 |
| 서버 엔지니어 | 가입 응답 두 모양을 `{confirmed}`로 가름, `DELETE /profile` |
| 클라이언트 엔지니어 | 로그인/가입 분리와 「메일함 확인」 안내, 이름 변경 팝업, 테스트 도시 삭제 버튼 |

**맞물린 자리** — 서버가 가입 응답을 `{confirmed}`로 갈라 넘기고 클라가 미확인이면 로그인시키지 않고 안내만 띄운다. 기획이 정한 비용을 시스템이 새 상수 없이 `RESPEC_GOLD`에 묶고, 화면은 시스템 함수가 낸 실패 사유를 그대로 띄운다.

**검증** — 사용자가 실제 이메일로 가입 → 확인 메일 → 입장까지 확인, 444/444. 이름 변경은 브라우저 수동 확인 전. **결정** — 대시보드 설정에 기대지 않고 코드가 두 경우를 견딘다(B안), 멀티 도시 기각.
**남은 것** — 「Confirm email」 운영 결정, 기본 SMTP 발송 한도, 테스트 삭제 버튼 출시 전 제거, `.env` 확인 중 노출된 DB 비밀번호 교체 여부.
