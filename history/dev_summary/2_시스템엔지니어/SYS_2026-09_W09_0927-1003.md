# 시스템 엔지니어 — W09 · 2026-09-27 ~ 10-03

> **이번 주 요지** — 전투 UI 개편 1단계(엔진)를 끝냈다. WT 동점을 전투 도중 난수가 아니라 **판을 만들 때 뽑는 순번 `UnitState.turnRank`**로 바꿔 전투 규칙 자체가 달라졌고, 화면이 쓸 판정 함수를 `packages/rules/src/commands.ts`(신규)로 엔진에 모았다 — 화면이 규칙을 다시 적지 않게 하기 위해서다.

## 룰 엔진

### 동점 순번 `UnitState.turnRank` (09-27)
- **예전**: WT가 동시에 0이 되는 순간 `grantControl`의 `pick`이 시드 난수로 뽑았다. 배치 화면이 순서를 미리 적을 수 없었다.
- **지금**: `createBattle()`이 **판을 만들 때** 유닛마다 순번(0..n−1 순열)을 한 번 뽑는다. 이것이 **판의 첫 난수 소비**라서 판마다 `rngCursor`가 **인원 − 1만큼 앞서** 시작한다.
- `grantControl()` · 「다음 차례의 적」(`nextEnemiesInTurnOrder`) · 순서 예보가 모두 같은 셈 `byTurnRank`(`state.ts`)를 쓴다.
- 「전투 시작 때」가 아니라 「판을 만들 때」인 이유: 유닛이 생기는 곳이 `createBattle()` 하나이고 배치 사이에 WT가 안 바뀐다. → 결정·교훈 참조.
- 대가: 같은 시드라도 예전과 다른 판이 된다(배포 순간에 진행 중인 판만 영향).

### 화면용 판정 함수 — `packages/rules/src/commands.ts` (신규, 09-27)

| 함수 | 쓰는 자리 |
|---|---|
| `skillStatus` → `none·sealed·used·poor·ready` | 순서 판 표시등 · 배치 목록 · 장수 카드. **카드(`cardStrip.ts`)는 이미 이 함수로 옮겼다** |
| `meditateGain` | 명상 확인창의 N |
| `castEffects` · `castIntent` · `castCandidates` · `canCast` | 조준 — `ControlModal`에 있던 사본을 엔진으로 옮긴 것 |
| `commandsFor` | 명령 6칸 + 고유기술 + 책략별 켜짐. [책략]은 **쓸 수 있는 책략이 있을 때만** 켜진다 |
| `turnForecast` | 순서 판. 「다들 넘긴다」를 가정하고 `endTurn()`과 같은 순서(시간 1 → WT 되돌리기 → 보정 소진)로 센다 |

검증: `packages/rules/test/commands.test.ts`(신규)가 예보를 엔진을 실제로 돌린 순서와 맞춘다. 옛 동점 규칙을 고정하던 회귀 넷을 고쳤다. 상세 → QA 문서.
