# 2. 시스템 엔지니어

## 개요

**게임의 규칙과 성장·경제를 「결정적인 코드」로 만드는 사람.** 이 게임의 심장이다.
같은 시드와 같은 입력이면 언제 어디서 돌려도 같은 결과가 나와야 한다 — 그래서 서버가 판이 끝난 뒤
**다시 돌려 보는 것만으로** 치팅을 잡을 수 있다. 이 성질을 지키는 것이 이 포지션의 첫 번째 책임이다.

출시 전까지는 **서버 일도 이 자리에 붙어 있다.** 서버는 이 사람이 만든 순수 함수를 부르는 껍데기라서,
판정을 아는 사람이 껍데기도 같이 쥐는 편이 자연스럽다. 출시 직전 서버 엔지니어가 갈라져 나간다.

## 역할

| 축 | 하는 일 |
|---|---|
| **룰 엔진** (`packages/rules`) | CTB 스케줄러(대기 시간이 0이 된 유닛이 제어권을 얻는다), 이동·공격·크리티컬 판정, 고유기술·책략 효과의 해석기(Effect DSL), 지형, 아이템, AI의 수, 판 재생 |
| **메타 시스템** (`packages/meta`) | 장수 성장(레벨업·재설계), 부대 편성, 군량 시간 충전, 도시·건물·부상, 전적 집계, 가챠, 계정 저장 형식과 옛 형식 되접기(`migrateProfile`) |
| **데이터 파이프라인** (`packages/data`, `tools/extract_data.py`) | 엑셀을 JSON으로 추출하고 검증한다. 기물 위협 범위를 Python과 TypeScript가 **각자** 다시 계산해 서로 대조한다 |
| (밸런스 도구) | 수천 판 시뮬레이터, 전투력 회귀 도구(`power_fit.ts`) — **숫자는 기획자가 읽고, 도구는 이 사람이 만든다** |

## 지키는 규칙

- 룰 엔진과 meta에서는 `Date.now()`·`Math.random()`을 쓰지 않는다. 시각과 시드는 밖에서 받는다.
- 개별 스킬을 엔진에 하드코딩하지 않는다. 데이터(Effect DSL)로 적고, 데이터로 접히지 않는 것만 `scriptId` 핸들러로 둔다.
- 화면이 미리 보여 주는 숫자(공격 예상, 책략 성공률, 레벨업 증분)도 엔진 함수가 낸다.

## 다른 포지션과의 계약

- **← 게임 디자이너**: 수치는 엑셀에서 온다. 코드에 다시 적지 않는다.
- **→ 서버 엔지니어**: 결정적인 엔진과 순수한 meta 함수를 넘긴다. 서버는 그것을 다시 계산할 뿐 규칙을 따로 갖지 않는다.
- **→ 클라이언트 엔지니어**: 화면이 판정하지 않도록, 화면이 필요한 판단(누를 수 있나, 결과가 어떻게 되나)을 함수로 내준다.

## 이 자리에 필요한 역량

TypeScript, 순수 함수 설계, 결정적 시뮬레이션, 테스트 습관. 간단한 통계(회귀·표준오차)를 도구로 만들 수 있는 정도.
