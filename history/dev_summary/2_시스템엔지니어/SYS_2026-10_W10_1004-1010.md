# 시스템 엔지니어 — W10 · 2026-10-04 ~ 10-10

> **이번 주 요지** — 전투 UI 개편 2~8단계가 화면 일이었지만, 화면이 규칙을 다시 적지 않도록 **판정 질문을 엔진 함수로 하나씩 더 모았다** —
> `Commands.attackOpen`(「공격이라는 행동이 막혀 있지 않다」) · `useItemOpen` · `tacticsRevealed(state, side)`(척후기 판정 셋을 하나로) ·
> 이벤트의 `target?`(온라인에서 적이 겨눈 장수). 판 위 상태 링을 다섯 갈래로 접으며 엔진이 **효과의 출처**(`origin: 'skill'`)를 남기게 했고,
> 추출기의 옛 시각 효과 표 여덟을 `STATUS_FX_RINGS` 하나로 걷었다. 데모 판에 배치 단계 · 상태 배지 · 시전 중 장면을 여는 흉내 통로가 붙었다.

## 룰 엔진

### 화면용 판정 — `Commands.attackOpen` · 이벤트 `target?` (10-06, 4단계)

- **`Commands.attackOpen`** — 기획자 확정 「[공격]은 대상이 없어도 언제나 켜짐」 때문에 생겼다. 「칠 적이 있다」(`attack`)와 「공격이라는 행동이 막혀 있지 않다」는
  **다른 물음**이고, 뒤의 것을 화면이 `turn.acted` · `control.mode`로 다시 적으면 규칙이 새어 나간다. → 결정·교훈 참조
- **`tacticCast` · `uniqueSkillCast` · `itemUsed`에 `target?: UnitId`** — 장수를 겨눌 때만 싣는다(칸을 겨눈 것은 없다). 온라인은 상대의 의도가 안 오고 이벤트만 오므로
  맥락 판의 「적이 겨눈 장수」 카드는 이것밖에 근거가 없다.
- 회귀 2건. 상세 → QA 문서.

### `tacticsRevealed(state, side)` — 「이 진영이 상대 책략을 보는가」 하나로 (10-06, 5단계)

`rules/src/wire.ts`. 전선(`hideEnemyTactics`)과 살펴보기(`InspectPanel`의 `scouted`)가 **각자** `heldEffectOf(u.held).revealTactics`를 세고 있었고,
배치 판의 [책략 확인]이 셋째가 될 참이었다. 하나로 모았다. 켜짐의 뜻은 **「척후기를 들었는가」**이지 「적 책략이 실려 왔는가」가 아니다(기획자 확정 — 뒤의 것은 Lv1 상대 앞에서 꺼진다).

- 회귀 1건(`held.test.ts` — 든 쪽만 · 적이 책략이 없어도 켜짐 · 전선을 지나도 같은 답).

### `useItemOpen` · 조준 반경 (10-09)

- **`useItemOpen`**(`rules/commands.ts`) — [공격]의 `attackOpen`과 같은 결. 대상이 없어도 [아이템]을 열어 「없습니다」를 듣게 한다. **`useItem`이 참이면 언제나 참**(회귀가 고정).
- 명령 흐름의 조준이 엔진의 `withinRadius`(`radius` · `side`)를 받아, 8방향 아이템(탕약 · 폭약)은 판 전체로 물러나지 않고 둘레를 칠한다.
- 확인 — **탕약은 엔진이 자기 자신도 대상으로 받는다**(거리 0). 설명은 「8방향 내 아군 1명」이고 목우유마만 「(자신 포함)」이라 의도가 갈릴 수 있다 — 규칙이라 손대지 않고 기획자 판단으로 넘겼다.

### 효과의 출처 `origin: 'skill'` · 즉시 WT 링 (10-08)

판 위 링을 「고유기술발 / 책략발 × 나쁨 / 좋음」으로 가르게 되자(기획자 확정, 게임 디자이너 문서) **상태 이름으로는 출처를 못 가른다**는 것이 드러났다 —
크리티컬 · 반감 · 지속 피해 · 조종이 책략과 고유기술 **양쪽에서** 온다.

- `applyEffects`가 이유 문자열(`skill:` · `tactic:` · `item:`)을 보고 **거는 순간** 남긴다. 삼고초려의 표식 · 영구 조종(`state.ts`)과 「지정 강제」(`scripts.ts`)는 직접 넣는다.
- **책략 · 아이템발은 키를 안 만든다** — 전선 스냅샷을 늘리지 않으려고. **판정은 안 읽는다**(화면 전용 표지).
- **즉시 WT 링** — 「선공」만 다음 차례까지 링을 물던 것(`hastenWt`)을 `instantWt`(이유 → buff/debuff)로 넓혔다. 일회성 `D`를 걷으면 「함정」 · 「경직」은 판에 아무 흔적이 안 남아서
  미는 쪽(함정 · 경직 · 십면매복 · 장판하뢰)도 같은 규칙에 넣었다(기획자 확인 대기).
- 넘어진 것 — 삼고초려 회귀가 조종 객체를 통째로 비교해 새 `origin`에 걸렸다(두 줄) — 기대값에 넣었다. `status-origin.test.ts` 1건 신설.

## 데이터 파이프라인

### 시각 효과 표를 `STATUS_FX_RINGS` 하나로 (10-08)

- 추출기의 옛 표(`BY_STATUS` · `BY_AURA` · `BY_CONTROL` · `BY_TERRAIN` · `WT_MODIFIER` · `COMBO` · `EXCLUSIVE` · `ONESHOT_*`)를 걷고 `STATUS_FX_RINGS` 하나로.
- 「아무도 안 쓰는 그림이 있으면 막는다」 대조는 갈래를 접은 뒤엔 대부분이 안 쓰여 **세기만** 한다.
- 같은 날 앞서 — 시전 오라 4장(`cast-{S,A,B,E}`)을 받아 굽자 `npm run extract`의 `STATUS_FX_BY_CASTING` 대조가 통과했다.
- `npm run extract`가 생성물 10개를 「바꿨다」 — Windows Python이 CRLF로 쓴 **줄 끝뿐**이었다. 내용이 바뀐 `visualEffects.json` · `build-report.json`만 남기고 `git checkout`으로 되돌렸다.

## 시험용 판 통로 (데모)

검사할 상태에 **도달할 수 없던** 판을 여는 통로들이다(「안 붙은 갈래」의 교훈).

| 통로 | 무엇 | 날 |
|---|---|---|
| `?deploy=1` | `createDemoBattle(…, { deploy: true })`가 `createBattle()`의 배치 단계를 그대로 둔다 — 데모는 기본 배치로 곧장 전투에 들어가 배치 중 위 칸에 닿을 수 없었다 | 10-06 (3단계) |
| `?status=1` | 남군 군주가 「반격」 · 「공포」를 든 채 시작(`?terrain=1`과 같은 결). 상태 배지 검사가 운이 아니라 **언제나** 돈다 | 10-06 (6단계) |
| `?late=N` | `LocalTransport`의 `opponentReadyMs` — 상대가 사람이 [준비완료]한 뒤 N ms 늦게 준비한다. AI 대전으로 못 닿던 배치 대기(`waiting`) | 10-07 (8단계) |
| `?cast=1` | `battle/setup.ts` — 북군을 등급마다 한 명(S · A · B · E · C)으로 세우고 고유기술이 있는 장수 전원을 시전 중으로. 처음엔 북군이 내 차례 전에 발동해 사라져 **북군 WT를 남군 누구보다 뒤로 민다** | 10-08 (3차) |
