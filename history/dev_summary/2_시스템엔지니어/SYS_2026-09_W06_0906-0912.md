# 시스템 엔지니어 — W06 · 2026-09-06 ~ 09-12

> **이번 주 요지** — 룰 엔진에 **고유기술 시전 지연**을 넣었다. 처음에는 곽가 「유언계책」이 쓰던 절대시각 예약(`PendingEffect`)으로 짰다가, WT를 미는 기술과 못 만난다는 것을 알고 **`UnitState.casting` + `grantControl()`**로 옮겨 시전 방해·발동 시점 대상 재선정·시전 중 무산이 한꺼번에 풀렸다. 손권 「수성지주」 3×3은 `scriptId` 핸들러 없이 새 `TargetSpec` `selfArea` 하나로 데이터에 접었다. 메타 쪽에 대장간 제조·지급의 순수 함수 모듈 `forge.ts`를 세웠고, 추출기에 장비 추출(`extract_equipment()`)과 다국어 열·등급별 문장 표를 붙였다.

## 룰 엔진

### 시전 지연 — 발동을 「제어권」에 묶는다 (09-07)

**데이터에서 값만 읽는다.** 정본은 `tools/extract_data.py`의 `SKILL_CAST_DELAY`이고 `uniqueSkills.json`의 `castDelay`로 나온다. 개별 스킬을 엔진에 하드코딩하지 않는다는 기존 규칙 그대로다.

**처음 구현은 `PendingEffect`(절대시각 예약)였다.** 곽가 「유언계책」이 이미 쓰는 기반이라 결정성·리플레이·와이어 스냅샷이 공짜로 따라오는 자연스러운 선택이었다. 그런데 기획이 명시한 시나리오(시전 중 장판하뢰로 WT가 30 → 180)가 성립하지 않았다 — 절대시각 예약은 WT가 밀려도 원래 시각에 그대로 터진다. 발동은 시각이 아니라 「내 차례가 돌아오는 것」에 묶여야 했다(→ 결정·교훈 참조).

그래서 [`UnitState.casting`](../../../packages/rules/src/types.ts) + [`grantControl()`](../../../packages/rules/src/battle.ts)로 바꿨다. 이 하나로 셋이 동시에 풀렸다.
1. **시전 방해** — 시전 중 WT도 보통의 WT라 십면매복(+90)·장판하뢰(+150)가 민다.
2. **발동 시점 대상 재선정** — 장료 「장료지제」가 그 순간 살아 있는 적을 센다.
3. **시전 중 무산** — `damageUnit()`이 필드 하나(`casting`)를 지우면 끝이다.

발동은 `grantControl()`이 제어권을 주기 **직전**에 돈다 — 「효과가 발휘되면서 자기 턴이 돌아온다」가 코드 순서 그대로다. 발동이 판을 끝내면(장료지제가 마지막 적을 칠 때) 제어권을 주지 않고 물러나고, `advanceTime()`의 반복문이 알아서 이어 간다.

곁가지 — 예약 방식으로 짤 때 `applyTick()`이 도는 동안 `state.time`이 아직 옛 시각이라 지속시간이 시전 시점 기준으로 잡혔다(회귀가 191 vs 221로 잡았다). 다른 틱들은 `tick.at`을 직접 써서 이 함정을 피하고 있었다. 제어권 방식으로 바꾸면서 문제 자체가 사라졌다 — `advanceBy()`가 시계를 맞춘 **뒤**에 돌기 때문이다.

그 밖에:
- **WT 보정 충돌**은 구조적으로 닫히지만(지연 대상 보유자는 「신속」·「병귀신속」을 가질 수 없다) `endTurn(forceWt)`는 보정을 안 얹는 쪽으로 적어 뒀다.
- **예약에는 스킬 id만 싣는다** — 지연 대상 13종이 전부 `self`·`allAllies`·`allEnemies`·무지정이라 발동 시점에 `undefined`로 다시 겨눠도 같은 결과가 나온다. 단일 대상 기술을 지연 목록에 넣으면 회귀(「지연 대상 13종은 전부 대상 지정이 없다」)가 먼저 깨져 대상 id를 함께 실어야 한다고 알린다.
- **AI** — [`ai.ts`](../../../packages/rules/src/ai.ts)에 가드 한 줄. 없으면 시전으로 턴이 끝나 `activeUnit`이 null인 채로 공격을 시도해 `apply()`가 던지고 **AI 대전이 통째로 죽는다.** AI는 지연 기술을 시전하면 그 턴을 거기서 접는다.
- 화면 쪽 자세·오라·로그는 클라이언트 문서. 검증(`skills-delay.test.ts` 10건, 지연을 걷어내 8건이 깨지는 것 확인)은 → QA 참조.

### 수성지주 3×3 — 새 `TargetSpec` 하나로 접힌다 (09-10)

「S급이니 `scriptId` 핸들러로 빼자」가 첫 안이었는데, 실제로 필요한 것은 **「시전자 중심 정사각 범위」라는 조준 규약 하나**였다. 데이터로 접히는 것을 엔진에 하드코딩하지 않는다.
```
{ kind: 'selfArea', radius: 1, filter: 'noTerrain' }
```

| 붙은 것 | 자리 |
|---|---|
| `TargetSpec`에 `selfArea` 추가 · `TerrainTile.fort` 추가 | `rules/src/types.ts` |
| `areaTiles()` · `tilesOf`·`resolveUnits`의 `selfArea` 갈래 · `createTerrain`이 조각 정보를 적는다 | `rules/src/effects.ts` |
| 「수성지주」 효과 정의 · 열 언어 설명문 정정(`SKILL_TEXT_FIXES`) | `tools/extract_data.py` |

- **「조준」과 「선결 조건」은 다른 것이다.** 3×3 안에 지형이 있으면 못 쓰게 하는 검사를 처음에 `resolveTacticTarget`의 조준 분기에 얹었는데, `selfArea`는 `aimingSpec()`이 돌려주지 않는 규약이라(고를 것이 없다) 그 위의 `if (!spec) return ok`에서 이미 빠져나가 **검사가 한 번도 안 도는** 형태였다. 조준과 별개로 효과 배열을 훑는 자리를 함수 맨 앞에 따로 뒀다(→ 결정·교훈 참조).
- **조각 정보는 깔 때 적는다.** 「상하좌우가 성지인지 보면 조각을 알 수 있다」는 손권이 둘이면 성채가 붙거나 겹쳐 어느 성의 조각인지 알 수 없고, 진영 색은 애초에 이웃에 안 적혀 있다. `createTerrain`이 `{side, dx, dy}`를 함께 적는다 — 판정에는 한 톨도 안 쓰이고 화면만 읽는다.
- **첫 칸이 중심이다** — `areaTiles()`가 중심을 맨 앞에 놓아, 로그를 한 줄로 접을 때 그 줄이 중심을 말한다.

### `docs/대장간 장비.xlsx`와 `extract_equipment()` (09-07)

**새 정본 엑셀은 시트 셋**이다. 원본을 `삼국지 약식체스.xlsx`에 합치지 않았다 — 읽기 전용이라 장비 한 줄을 고치려고 260명짜리 통을 열게 된다.

| 시트 | 무엇 |
|---|---|
| **대장간** | 번호 · 이름 · 종류 · 해금레벨 · 가격 · 효과 · 이미지 생성 프롬프트 · 해설 |
| 밸런스검토(참고) | 효과 3안의 실측과 결정 이력 |
| 가격산정(참고) | 가격 환산 과정 |

**효과의 정본은 코드의 표다.**
```python
EQUIP_EFFECTS = {
    ("weapon", 1): {"criticalRate": 5},
    ...
    ("armor", 4): {"barrier": 12},
}
```
엑셀의 「효과」 열은 화면 글자이고 엔진이 읽는 것은 이 표다(`TACTIC_EFFECTS`와 같은 자리·같은 이유 — 한국어 문장을 파싱하면 조사 하나에 깨진다). 대신 **둘이 어긋나면 추출이 멈춘다** — 패턴 넷(`크리티컬 확률 \+(\d+)%p` 등)으로 문장에서 숫자를 되읽어 **양방향으로 대조**한다. 표에 있는데 문장에 없어도, 문장에 있는데 표에 없어도 실패다. 부저추신 사고를 장비에서 되풀이하지 않기 위해서다.

검사는 여섯 갈래(효과 문장↔표 · 해금 레벨 범위 · 같은 티어 가격 일치 · 프롬프트에 한글·한자 금지 · 머리글 · 해설 비어 있음)이고 전부 깨 봤다(→ QA 참조). **「5」를 추출기에 적지 않았다** — `buildings.json`의 forge에서 `maxLevel`을 꺼내 넘긴다. 대장간이 6레벨이 되면 검사가 저절로 따라온다.

부수적으로 — 리더(`Workbook`)가 `sharedStrings.xml` 없는 통에서 죽었다. 엑셀이 쓴 통에는 늘 있지만 문자열을 셀 안에 그대로 적는(`inlineStr`) 도구가 만든 통에는 그 항목이 없다. 리더가 이미 `inlineStr` 갈래를 갖고 있었는데 한 번도 안 돌던 길이라 드러나지 않았다. 없으면 빈 표로 두게 고쳤다.

**`@samchess/data`** — `EquipmentData` · `EquipmentEffect` · `EQUIPMENT` · `equipmentById` · `equipmentForForge(level)`를 냈다. 마지막 것은 **누적**이고(Lv3 대장간은 Lv1·Lv2 상품도 판다) **`level`이 0이면 빈 배열**이다 — 화면이 `buildingLevel(profile, 'forge')`를 그대로 넘길 수 있게 여기서 받아낸다. 안 그러면 안 지은 도시에서 Lv1 상품이 보인다. `BuildingData.effect`의 「시장·대장간은 품목 표가 아직 없다」 주석도 고쳤다(이제 시장만 남았다).

### 장비 문구 정정과 다국어 열 (09-09 ~ 09-10)

- **`EQUIP_TEXT_FIXES` / `apply_equip_text_fixes()`** (09-10 화면 다듬기 세션) — 엄심경 문구(「베리어(추가 HP) +3 — 회복되지 않는다」 → 「HP+3 베리어, 회복되지 않음.」)를 엑셀을 안 건드리고 고치는 통로. `SKILL_TEXT_FIXES`와 같은 결로 원본이 갱신되면 스스로 「필요 없어졌다」고 알린다. `npm run extract` 후 `equipment.json`의 해당 `text`만 바뀐 것을 `git diff`로 확인했다.
- **`EQUIP_TEXT_BY_TIER`** — 효과 문장은 품목이 아니라 **등급**이 정한다. 같은 `(종류, 레벨)`이면 15종 어디서나 같으므로 이름별 표에 적으면 같은 짝을 14번 베껴 적어야 하고 한 줄만 빠뜨려도 그 품목만 옛 문구로 남는다. 등급 키(`EQUIP_EFFECTS`와 같은 키)로 9줄을 적었다. 엄심경 정정도 이리로 옮겨 방어구 넷이 한자리에서 보인다. `EQUIP_TEXT_FIXES`는 비워 두되 지우지 않았다 — 한 품목에만 있는 오탈자가 나오면 쓸 자리다. 엑셀은 안 건드렸다 — `EQUIP_EFFECT_PATTERNS` 대조는 `extract_equipment()` 안에서 **정정 전 원본 문장**으로 이미 끝나므로 정규식도 그대로다. `npm run extract`가 등급 아홉이 전부 「규칙대로 적었다」로 찍는다(무기 11종 · 방어구 4종).
- **`EQUIP_TEXT_I18N`** — 효과 문장의 아홉 언어는 엑셀 열이 아니라 코드(등급 키)에 뒀다. **9문장 × 9언어 = 81개**(엑셀이었으면 15행 × 9열 = 135칸). 주석의 용어표도 문구와 함께 고쳤다 — 표만 낡으면 다음 사람이 「Critical rate」로 되돌린다.
- **해설·이름 열** — `해설_{lang}`·`이름_{lang}` 9열씩을 엑셀에 더했다. 쓰기 전에 백업하고, 시트 셋이 그대로인 것과 그림·차트가 없는 것을 확인했고, **행은 이름으로 찾아 채웠다**(순서에 기대면 행 하나가 끼어들 때 조용히 어긋난다). `extract_equipment()`는 열을 **이름으로** 찾는다(자리로 세면 열 하나가 끼어들 때 다른 언어를 읽는다). `EQUIP_HEADERS`(순서 검사)에는 안 넣는다 — 있으면 읽고 없으면 안내만 찍는다. 비어 있으면 **키째로 안 담는다**(빈 문자열을 담으면 `loreI18n?.[lang] ?? lore`의 물러남이 안 걸린다). `loreI18n`·`nameI18n`에 담고, `ko`는 안 담는다(`lore`/`name`이 그 값이다). `EquipmentData`의 `loreI18n?: Partial<Record<StoryLang, string>>`은 09-09에 옵션 필드로 먼저 열어 뒀다.
