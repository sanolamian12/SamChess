### 온라인이 이어 붙을 자리 셋 (08-02 ~ 08-07)
서버가 새로 맡을 것은 **타이머와 전송뿐**이다 — 판정은 이미 엔진에 있고 편성·배치·정찰 화면도 다 있다.

| 자리 | 지금 | 온라인에서 |
|---|---|---|
| `playback.ts`의 `submit()`/`step()` | 로컬 `apply()` 호출 | 서버에 Intent 전송 → 이벤트 수신 |
| `Playback.deadlineMs` | 클라가 만든다 | **서버가 내려 준다** |
| `client/src/meta/storage.ts` | localStorage | **서버 API** |

- `playback.ts`는 「서버가 `BattleEvent[]`를 브로드캐스트하면 클라가 재생하는」 구조라 온라인에서 다시 만들지 않는다.
- 버튼 활성 여부도 조준 후보도 전부 `validate()`에 물어 만들었으므로 판정 주체가 서버로 바뀌어도 화면 로직은 그대로다.
- 대화 문장(`eventText.ts`)은 엔진이 준 `BattleEvent[]`만 읽는다 — 온라인에서 서버가 보내 주는 것이 바로 이 배열이다.
- `waiting` 단계(상대의 `ready`를 기다리는 자리)는 AI가 곧바로 준비를 마쳐 화면에 나타나지 않는다 — 온라인에서 쓰일 자리가 정확히 여기다.
- 넷코드에서 새로 필요한 것은 방 · 연결 · 재접속과, 클라이언트가 로컬로 하는 `apply()` 호출을 서버로 옮기는 일이다.
