# 서버 엔지니어 — W04 · 2026-08-23 ~ 08-29

> **이번 주 요지** — 실사용자가 보고한 회원가입 크래시를 고쳤다: Supabase 대시보드의 「Confirm email」이 켜져 있어 `/auth/v1/signup` 응답 모양이 코드의 가정과 달랐다. `signUp()`이 두 응답 모양을 `{confirmed}`로 가르게 했고 실제 이메일 가입 → 확인 메일 → 로그인까지 사용자가 확인했다. 계정 API에 `DELETE /profile`(테스트용 도시 초기화)과 `GET /ranking`(전체 프로필 스캔 랭킹)이 더해졌다.

## 계정·백엔드

### 회원가입 확인 메일 버그 (08-24)
실사용자가 간판 화면의 「계정 생성」에서 화면이 죽는 것을 스크린샷과 함께 보고했다. 증상은 두 단계였다.

**1단계 — 버그가 아니었다.** 이메일·비밀번호를 비운 채 누르면 `Anonymous sign-ins are disabled` 알림만 떴다. `signUp(email, password)`가 입력값을 그대로 `POST /auth/v1/signup`에 보내는데, 빈 문자열 `{email:"", password:""}`를 Supabase Auth는 **익명 로그인 시도**로 해석하고 이 프로젝트는 익명 로그인이 꺼져 있다(정상 설정). 코드가 에러 메시지를 그대로 화면(`title.error`)에 띄워 Supabase 내부 사정이 노출된 것뿐이다.

**2단계 — 진짜 버그.** 실제 값을 넣자 `Cannot read properties of undefined (reading 'id')`로 죽었다. `packages/client/src/meta/auth.ts`의 `toSession(t)`이 `t.user.id`를 읽는데 `t.user`가 `undefined`였다. `signUp()`은 「확인 메일은 꺼져 있다」(개발 단계 결정, `auth.ts` 머리말 주석) 전제로, 가입 성공 시 로그인과 같은 모양(`{access_token, refresh_token, expires_in, user: {id, email}}`)이 온다고 가정했다. 그런데 실제 Auth 대시보드 설정은 **「Confirm email」이 켜져 있었다.** 이때 `/auth/v1/signup`은 세션 토큰 없이, 유저 필드를 `user`로 감싸지 않고 **응답 최상위에 바로**(`{id, email, email_confirmed_at: null, ...}`, `access_token` 없음) 돌려준다.

**고친 것** — (A) 대시보드에서 「Confirm email」을 끈다 vs (B) 코드가 켜진 경우도 처리한다 중 사용자가 **(B)**를 골랐다(대시보드 설정에 의존하지 않는 쪽이 견고).
- `meta/auth.ts` — `authFetch`(세션 응답을 요구하는 `signIn`/토큰 갱신 전용)와 `rawAuthFetch`(원본 응답을 그대로 돌려주는 저수준 함수)를 갈랐다. `signUp()`은 `rawAuthFetch`로 받아 `access_token`·`user`가 있는지 직접 확인해 `{confirmed: true, session}` 또는 `{confirmed: false}`를 돌려준다 — 크래시 대신 타입으로 두 경우를 구분한다.
- 화면 쪽(`TitleScreen.tsx`의 `runSignIn()`/`runSignUp()` 분리, `confirmSent` 상태, `title.confirmEmail` 문구)은 → 클라이언트 문서.
- 지금 코드는 **어느 쪽 설정이든** 안전하게 동작한다. 확인 메일을 끌지(A안) 켜 둘지는 기획이 아니라 운영 결정이라 확정하지 않았다.
- 교훈(외부 서비스 설정 가정) → 결정·교훈 참조.

### `GET /ranking` (08-27)
- `packages/server-api/src/ranking.ts`(신설) + `GET /ranking` — 로그인 유저면 누구나 조회. `profiles` 테이블을 통째로 스캔(`SCAN_CAP` 자리표시자, 지금 규모용)해 meta의 순수 함수(`cityRankRow`/`squadRankRows`/`officerRankRows`)로 행을 뽑고 정렬·검색·자른다.
- **새 스키마 없음** — 「아이디」 열을 빼기로 해서 `auth.users` 조인도 필요 없어졌다.
- 서버가 필요한 것은 top-5와 검색뿐이다. 「내 랭킹」은 클라이언트가 같은 함수로 직접 계산하므로 서버가 죽어도 보인다.
- 둘째 세션: 장수 랭킹 모드 필터 추가에 맞춰 `queryRanking()`이 `mode` 인자를 그대로 넘기도록 한 줄 고쳤다.

- 확인 메일의 안정적 발송은 Supabase 내장 SMTP에 달려 있다 — 기본 메일 서비스는 시간당 발송 제한이 있어, 계정 생성이 잦아지면 별도 SMTP 연동이 필요할 수 있다.
- 「Confirm email」을 켜 둘지 끌지 운영 결정.
- `GET /ranking`의 전체 스캔(`SCAN_CAP`)은 지금 규모용 자리표시자다.
- `DELETE /profile`과 `[테스트] 도시 삭제`는 출시 전 제거 대상.
- `.env`가 없거나 Supabase 설정이 다른 환경에서 `currentSession()`의 동작은 이번에 새로 보지 않았다.
