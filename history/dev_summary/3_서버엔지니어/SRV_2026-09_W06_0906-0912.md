# 서버 엔지니어 — W06 · 2026-09-06 ~ 09-12

> **이번 주 요지** — 대장간 제조를 **서버 권위 거래**로 배선했다. 금화(클라이언트 소유)를 내고 아이템(서버 소유)을 받는 거래라 폴백하면 금화만 사라지므로, 제조 시작·취소는 `POST /forge/order`·`/forge/cancel`로 서버가 판정하고 못 닿으면 말만 하고 멈춘다. 지급/해제는 총량이 안 늘어나 `PUT`으로 받되, `forgeOwned`의 **키는 서버가, 값은 클라이언트가** 갖도록 경계를 갈랐다. 실제 계정으로 대장간을 처음 돌려 보며 `getProfile()`의 read-modify-write 경주를 발견해 보고만 남겼고, 간판 화면에 Supabase 비밀번호 초기화를 붙였다.

### 화면 전용 QA 오버라이드와 「진짜 계정 심기」의 차이 (09-10)

- **`?forgeLevel=5`** — 레벨 5의 15종 레이아웃을 보려고 `?match=fast`와 같은 결로 만든 화면 전용 오버라이드다. 진짜 `profile`은 안 건드리고 화면 표시(`forgeLevel(debugProfile)`)와 목록(`craftableEquipment(debugProfile)`) 네 자리만 이 값을 쓴다. 제작 시작(`startForgeOrderOnServer`)은 여전히 서버가 실제 프로필로 재검증하므로 **화면만 5로 보이고 주문은 서버가 거절한다.** 「확인이 끝나면 지운다」는 주석이 남아 있다.
- **`npm run seed:forge -- --email <메일>`** — 이쪽은 계정을 **진짜로** 그 상태로 만든다(대장간 레벨·금화를 `saveProfileTrusted()`로 서버에 심는다). 제조·지급이 실제로 돈다. 정식 경로(도시 Lv2 → 자재 → 건설 기회 → 건설)가 전투·장터를 여러 번 돌아야 해서 화면 확인의 앞길이 너무 길다는 것이 만든 이유다. 로컬 개발 전용이고 `.env`의 Supabase 키로 돈다.

### 비밀번호는 우리가 저장하지 않는다 (09-11)

기획자 요청 「로그인에 성공한 아이디와 비밀번호를 자동저장」을 셋으로 갈랐다.

| | 어떻게 |
|---|---|
| **다시 안 적어도 들어간다** | **이미 된다.** 세션(리프레시 토큰)이 `localStorage`에 남아 `App.tsx`의 부팅이 간판 화면을 건너뛴다. 로그아웃하거나 토큰이 죽었을 때만 간판이 뜬다 |
| **이메일 기억** | 새로 했다 — `save(session)`이 성공한 이메일을 `samchess.lastEmail`에 남기고, 입장 팝업이 그 값으로 시작한다. **`signOut()`은 이 값을 안 지운다**(로그아웃은 「이 계정에서 나간다」이지 「이 기기를 남에게 넘긴다」가 아니다) |
| **비밀번호 기억** | **우리가 저장하지 않는다.** 평문으로 `localStorage`에 두면 같은 출처에서 도는 모든 스크립트가 읽는다. 대신 `<form>` + `autocomplete`(`username`·`current-password`)로 **브라우저·OS의 비밀번호 관리자**가 맡게 했다 — 그쪽은 OS 잠금 뒤에 있고 출처까지 검증한다 |

→ 결정·교훈 참조. 폼 처리의 화면 쪽 세부는 클라이언트 문서.

### `POST /forge/order` · `POST /forge/cancel` (09-09)

`profileStore.ts`에 `ForgeAction`(`start`/`cancel`) · `applyForgeAction()`을 `applyCityAction()`과 같은 모양으로 추가했다. `routes.ts`에 `POST /forge/order`(`{equipmentId}`) · `POST /forge/cancel`을 `/city/*`와 완전히 같은 골격(토큰 검증 → 판정 함수 → 400/결과)으로 붙였다. **지급/해제는 새 라우트가 필요 없다** — `PUT /profile`이 위 경계로 그대로 받는다.

### `getProfile()`의 read-modify-write 경주 — 보고만 남겼다 (09-10)

실제 계정 확인 도구(`tools/forge_play.ts`)가 서버 반영을 `getProfile()`로 폴링했더니 **회수가 간헐적으로 서버에 안 남았다.** `PUT`은 `{"dae-gam-do":null}`로 제대로 나갔는데(추적해서 확인) 서버는 계속 `ma-cho`였다. 원인은 `getProfile()`이 **읽으면서 `syncCity()` 결과를 되쓰는** read-modify-write라는 것 — 300ms마다 부르니 그 되쓰기가 마침 날아온 `PUT`을 덮었다. 도구는 행을 날것으로 읽게 고쳐 0.8~1.4초에 안정적으로 남았다.

이번엔 검사 도구가 만든 상황이었지만 **경로 자체는 실제로 그렇다** — 잠금이 없어 동시에 온 `GET`과 `PUT`이 겹치면 `PUT`이 사라질 수 있다(탭 둘, 또는 로드와 저장이 겹치는 순간). 고치려면 조건부 갱신이나 행 잠금이 필요한데 H3d의 계정 권위 설계를 건드리는 일이라 **보고만 남겼다.**

### Supabase pooler DNS가 간헐적으로 죽는다 (09-10)

`aws-0-ap-northeast-1.pooler.supabase.com`이 `EAI_AGAIN`으로 안 풀리는 일이 세션 내내 여러 번 있었다. **`EAI_AGAIN`은 NXDOMAIN이 아니라 「일시적 실패」다.** 한때 「Supabase가 호스트 이름을 바꿨나」 싶어 `.env`를 `aws-1-…`로 고쳤다가(그쪽은 `tenant not found`) 몇 초 뒤 `aws-0`이 멀쩡히 풀리는 것을 보고 되돌렸다. 설정은 그대로가 맞고, 도구가 실패하면 그냥 다시 돌리면 된다. 또 앞 세션이 「이 환경에 Supabase 로그인 정보가 없다」고 남겼지만 **`.env`에 값이 다 들어 있었다.**

### 비밀번호 초기화 — `meta/auth.ts`의 `resetPassword` (09-11)

Supabase의 `/auth/v1/recover`를 그대로 부른다. 주석에 둘을 적어 뒀다.
- **없는 계정에도 200이 온다** — 어느 이메일이 가입돼 있는지 알려 주지 않으려는 Supabase의 의도다. 그래서 화면은 「보냈다」까지만 말할 수 있다.
- **재설정 화면은 아직 우리 앱에 없다** — 메일의 링크는 대시보드의 Site URL로 간다. 앱 안에서 받으려면 `redirectTo`와 복구 토큰 경로를 따로 만들어야 한다.

이메일이 비면 Supabase가 422를 주는데 그 문장이 사용자에게 아무것도 안 알려 줘, **먼저 막고 한 줄로 말한다**(`title.resetNeedEmail`).

### H3b 군량 재검증이 간헐적으로 실패한다 — 안 고쳤다 (09-11)

간판 작업 뒤 `smoke:meta`를 세 번 돌렸는데 판마다 다른 자리에서 H3b 확인이 깨졌다(1판 통과 · 2판 「참가비가 server-api에 안 남았다」 · 3판 「거절 군량이 —」). `waitServerGrain()`이 DB 행을 5초(20×250ms) 폴링하는데, Colyseus 셸이 부르는 `POST /internal/grain`이 그 안에 안 들어오는 것으로 보인다 — **경주이지 이번 변경과는 무관**하다. 이 세션에서는 건드리지 않았다.
