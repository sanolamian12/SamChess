# 3. 서버 엔지니어

## 개요

**서버를 「판정의 주인」으로 세우고, 출시 뒤에는 그것을 운영하는 사람.**
이 게임에는 현금 가챠와 랭킹이 있어 치팅할 이유가 크다. 그래서 클라이언트는 「이렇게 하고 싶다」는
**의도만** 보내고, 결과는 서버가 정한다. 군량·금화·보상처럼 값이 걸린 것은 서버가 다시 계산한다.

> **필요 시점 — 출시 직전부터 상근.** 8~9월의 서버 작업은 8월 셋째 주(대전 서버·계정·서버 권위)에
> 몰렸고, 그 뒤로는 하루짜리 작업이 드문드문 이어졌다. 방 규칙과 경제가 순수 함수(시스템 엔지니어 몫)에
> 있어 서버가 얇게 유지됐기 때문이다. 결제 연동·라이브 운영·장애 대응·치팅 대응이 시작되면
> 상시 업무가 된다. **지금은 자리를 열어 두고, 그동안의 서버 작업을 여기에 쌓는다.**

## 역할

| 축 | 하는 일 |
|---|---|
| **대전 서버·네트워크** (`packages/server`) | Colyseus 대전 방과 대기열. 배치 30초·제어 20초·재접속 유예 60초 같은 방 규칙, 이탈·유휴 처리, 서버에서 클라이언트로 가는 상태 전송(로그를 빼고 이벤트만 붙인다) |
| **계정·백엔드** (`packages/server-api`) | 회원가입·로그인(Supabase), 계정 저장 API, DB 스키마와 마이그레이션, 도시 이름 고유성 같은 DB 제약 |
| **서버 권위·보안** | 참가비·환불·전투 보상·군량 충전을 서버가 다시 계산한다. AI 대전은 판이 끝난 뒤 서버가 재생해 검증하고, 온라인 대전은 서버가 판정한 결과를 그대로 정산한다. 결제 연동 |

## 다루는 것

- `packages/server` — Colyseus 방(`room-logic.ts`, `queue-logic.ts`는 시각을 인자로 받는 순수 로직, `BattleRoom`/`QueueRoom`은 껍데기)
- `packages/server-api` — Fastify + Supabase(Postgres)
- `client/src/meta/storage.ts` 등 — 클라이언트가 서버 API에 붙는 층(저장 순서를 지키는 쓰기 큐 포함)

## 다른 포지션과의 계약

- **← 시스템 엔지니어**: 규칙과 경제 계산은 그쪽 함수를 부른다. 서버가 같은 규칙을 따로 갖지 않는다.
- **→ 클라이언트 엔지니어**: 화면은 `BattleTransport`라는 이음매 하나로 로컬(AI)과 온라인을 똑같이 다룬다.
  서버가 꺼져 있어도 AI 대전은 돈다 — 실패하면 로컬로 물러나는 길을 항상 남긴다.

## 이 자리에 필요한 역량

Node.js, 실시간 게임 서버(Colyseus), Postgres, 인증, 그리고 **「클라이언트를 믿지 않는」 설계 감각**.
라이브 운영(모니터링, 장애 대응)과 결제 연동 경험.
