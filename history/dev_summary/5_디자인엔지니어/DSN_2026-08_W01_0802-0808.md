### 전투 화면 레이아웃 — 1:2 프레임 · `rem` · `--board` (08-04 ~ 08-07)
기획 pptx 20~25쪽 지침(모바일 세로 `1:2` 프레임 · 시스템 대화창 · 하단 패널 4줄 · 고유기술 물음/연출 · 기물 팝업)을 반영했다.
- **크기는 전부 `rem`, 기준값은 프레임 폭이 준다.** `useFrameFit`이 `html { font-size }`를 프레임 폭의 1/26로 정한다. 프레임이 320px(작은 폰)에서 700px(세로 모니터)까지 변하는데 글자만 고정이면 좁은 화면에서 커맨드가 줄바꿈되고 넓은 화면에서는 허전해진다. px를 새로 적지 않는다.
- 체스판 가로 폭만 `--board` 변수로 따로 넘긴다(`rem`은 글자 기준이라 「판의 절반」을 표현할 수 없다).
- **시스템 대화창 줄 눌림** — `#log`는 세로 flex이고 줄이 기본 `flex-shrink: 1`이라 영역이 얇아지면 글자가 잘려 빈 막대처럼 보였다(5v5에서 늘). `.log-line`에 `flex: none`, 넘치는 줄은 `justify-content: flex-end` + `overflow: hidden`으로 위로 밀려 잘린다 — 의도한 「밀려 올라가는」 모습 그대로. → 결정·교훈 참조
- 2차 시점의 판 위 표시: 셀 96×120이 기본 줌에서 30px대로 줄어 5px 바 3줄과 글자 배지가 뭉갠다 — 배지는 점(dot)으로 개수만, 확인은 `npm run shot -- --zoom 2.4`로 한다. 제어 모달은 오른쪽 여백.

### 장수 초상 배경 제거 도구 `tools/remove_char_background.py` (08-07)
시작 시점 `assets/Chars-noback/`에는 손으로 만든 예제 5건(가후 · 간옹 · 감녕 · 감택 · 강유)만 있었고 나머지 255건은 원본 복사본이었다. 끝에 **260장 전부 배경이 제거된 440×540 RGBA**(원본과 파일명 동일)가 됐다. 도구는 신규 287줄, 260장 39초(장당 0.15초).

```
python tools/remove_char_background.py                 # 260장 39초
python tools/remove_char_background.py --dry-run       # 저장 없이 진단만
python tools/remove_char_background.py --only 관우      # 일부만
python tools/remove_char_background.py --only 여포 --seed 192,100 --seed 135,300
```
`assets/`는 `.gitignore`라 커밋 대상은 도구 하나다. 의존성은 이미 깔린 `Pillow` · `numpy` · `scipy`뿐 — 학습 모델(rembg 등, 약 176MB)은 쓰지 않았다. 260장이 같은 생성기에서 나온 같은 구도라 배경의 성질을 직접 쓰는 편이 더 정확하다.

**원본의 성질** — `crop_chars.py`가 3인 합성 이미지에서 잘라낸 결과다. 배경은 밝은 황갈색 양피지 + 갈색 등고선 + 회색 자갈, 발밑에 녹색 풀밭, 위나 아래에 이름 현판이 붙은 컷이 있다. 장수는 픽셀아트이고 항상 어두운 외곽선으로 둘러싸여 있다. 컷마다 배경 색이 달라 배경판 차분은 불가능하다(무작위 6장을 서로 뺐을 때 픽셀의 73~98%가 10 이상 달랐다). 색만으로도 못 가른다:

| | 배경 픽셀 | 장수 픽셀 |
|---|---|---|
| 평균 RGB | R232 G198 B138 | R133 G115 B93 |
| 「양피지 계열」 판정 통과율 | 97~99% | **15~30%** |

장수의 15~30%(피부 · 황갈색 가죽 갑옷)가 배경과 같은 색 계열이라 색은 후보를 좁히는 데만 쓰고 실제 판정은 연결성이 한다.

**알고리즘 다섯 단계**
1. **색상 게이트** — 테두리 4px 띠에서 표본을 뽑아 밝기를 나눈 색도(`rgb / (r+g+b)`)를 2차원 히스토그램에 찍고 허용치만큼 부풀린다. 여기 걸리면서 밝기 110 이상이면 배경 후보. 밝은 바탕(232,198,138)과 어두운 등고선(144,94,35)은 색조가 같아 한 후보로 묶인다. 대표색 하나가 아니라 히스토그램인 이유는 하늘색 · 연녹색 띠가 섞인 컷 때문이다.
2. **연결성** — 후보 중 이미지 테두리에서 인접 픽셀 색차 40 이내로 이어지는 것만 배경. 어두운 외곽선(밝기 110 미만)이 방벽이 된다. 픽셀 BFS가 아니라 가로·세로 이웃쌍 중 「양쪽 다 후보 + 색차 40 이내」인 간선만 만들어 `scipy.sparse.csgraph.connected_components`에 넘긴다(24만 픽셀을 numpy/C 쪽에서 처리).
3. **누수 차단(열림 연산)** — 반지름 3으로 침식해 좁은 통로를 끊고, 테두리에 남은 덩어리만 다시 부풀려 원래 배경과 교집합.
4. **최대 덩어리** — 남은 전경 중 가장 큰 연결 요소만 장수. 이름 현판 · 멀리 떨어진 자갈 · 등고선 조각이 여기서 탈락.
5. **경계 매팅** — 경계 2px를 `p = a·F + (1−a)·B`로 보고 `a`를 최소자승으로 푼다(`B` 가장 가까운 배경 픽셀, `F` 가장 가까운 내부 픽셀 색). 반투명 알파와 원래 색을 같이 복원.

거쳐 간 실패(단일 대표색 → 46장 배경 잔존, 히스토그램 → 8장 얼굴 손실, 정련 패스 → 풀밭 소실, 이진 마스크 → 황갈색 테 1px)와 그 해법은 결정·교훈 문서, 수치 표는 QA 문서. 여포는 깃털 장식과 방천화극이 배경을 완전히 가둬 원리적으로 못 지우므로 `--seed X,Y`(매직완드처럼 그 점 주변 색을 배경 표본에 추가하고 flood 시작점으로도 쓴다)로 처리했고 명령을 docstring에 적었다.

### `tools/build_portraits.py` — `Chars-noback` 우선 · 폴백 보고 · 프리멀티플라이 축소 (08-07)
- `TILE_SOURCES = (Chars-noback, Chars)` 순으로 찾는다. 배경 제거를 안 돌린 신규 장수가 생겨도 빌드가 멈추지 않고, **어느 장수가 원본에서 왔는지 이름을 찍어 알린다** — 조용히 폴백하면 260장 중 1장이 배경을 단 채 서 있어도 눈으로 찾기 어렵다. 현재 260/260이 `Chars-noback`.
- 축소는 `RGBa`(알파를 곱한 형식)를 거친다. 440×540 → 96×120은 4.5배 축소라 투명 픽셀의 RGB가 섞이면 가장자리에 배경색이 번질 수 있다(도구가 만든 255장은 알파 밑이 검정(0,0,0), 손으로 만든 예제 5장은 양피지색(222,181,114)이 남아 있다). 다만 Pillow 12에서는 경유 전후 출력이 바이트 단위로 같았다 — 버전에 딸린 성질이라 남겨 두었다. → 결정·교훈 참조
- 원본이 바뀌었으므로 `npm run portraits -- --force`로 260장을 재생성했다.
- `public/portraits/`에 개명 찌꺼기 `i-gwak.png`가 남아 261장이었던 것을 지웠다. 자동 삭제는 넣지 않았다. → 결정·교훈 참조

## 남은 일
- 원본이 추가되면 `--skip-existing`으로 새 파일만 처리하되, 파라미터는 260장 구도에 맞춘 것이라 구도가 다른 원본(배경 없는 컷, 2인 이상)에는 그대로 안 통한다 — `--dry-run`으로 남은 넓이를 보고 8~55%를 벗어나면 눈으로 확인.
- 장수를 추가하면 `Chars`뿐 아니라 `Chars-noback`에도 넣어야 한다.
- 장수 이름을 바꾸면 `public/portraits/`의 옛 id 파일을 손으로 지운다.
- 여포 `--seed` 좌표는 원본이 갱신되면 다시 잡는다. 갇힌 배경 자동 판별은 원본이 늘어 빈번해지면 다시 본다.
- 타일 뒤에 소속 색을 깔게 되면 반투명으로, 세 판 색 위에서 다시 확인.
- 수묵화(`CharsInBattle`)는 197/260명 — 나머지는 초상화로 대신하는 중.
