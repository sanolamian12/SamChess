## 화풍·UI 비주얼

### 배경 미세 이동 (08-16)
사장님 요청 — **「각각의 사진이 2초나 3초 간격으로 약간씩 움직이는 형태로」.** 간판·도시·궁궐·병영·장터의 배경이 2.6초마다 여덟 자세를 하나씩 짚으며 조금 밀리고 확대된다(한 바퀴 약 21초). 룰 엔진도 그림 파이프라인도 안 건드렸다 — `npm run backgrounds`의 열넉 장과 「어느 그림을 띄울지」의 `backdrop.ts`는 그대로이고, **움직임은 그 뒤에 얹히는 별개의 층**이다.

| 붙은 것 | 파일 |
|---|---|
| 여덟 자세표 + `transform` 계산(순수 함수) | `screens/backdropMotion.ts`(신규) |
| 걸음 세기 — 시계와 「동작 줄이기」를 읽는 유일한 곳 | `screens/useBackdropDrift.ts`(신규) |
| 그림을 `.scr-art` 층으로 분리 | `screens/ScreenChrome.tsx` |
| 층 · 쌓임 순서 · 전환 | `style.css` 「배경 화면」 절 |

정한 것
- **간격 2.6초**(「2초나 3초」의 가운데, `DRIFT_MS` 한 곳).
- **쉬지 않고 흐르지 않고 자세를 짚는다** — 켄 번스는 한 방향으로 계속 흐르는데 지정이 「간격」이라 여덟 자세를 하나씩 선다. `ease-in-out`이라 자세마다 부드럽게 섰다 떠난다.
- **밀리는 거리 최대 1.5%**(700px에서 약 10px) — 「약간씩」의 정의.
- **편성 화면(`.scr-dim`)은 멈춰 둔다** — 거의 불투명한 어둠 아래로 물러나는 자리라 움직여도 안 보인다.
- **「동작 줄이기」(`prefers-reduced-motion`)를 켠 사용자에게는 안 움직인다.**

왜 그렇게 만들었나
- **그림을 화면 div에서 떼어 냈다.** 원래 배경은 `.scr-bg` 자체의 `background-image`였는데(「`<img>`로 깔면 쌓임 순서를 일일이 정해야 한다」), 그 div가 제목 · 기어 · ID칸 · 단추를 다 담고 있어 `transform`을 걸면 글자와 단추가 함께 흔들린다. 예전에 피했던 대가 — 쌓임 순서를 손으로 정한다.
```
.scr-art        (z 0)  움직이는 그림
.scr-bg::before (z 1)  위아래 어둠
.scr-bg > *     (z 2)  제목 · 내용
```
  셋은 함께 봐야 뜻이 통한다 — 하나만 지우면 어둠이 글자를 덮거나 그림이 어둠을 덮는다. `.scr-bg > *`가 `.scr-art`에도 걸리므로 `.scr-bg > .scr-art`로 **구체성으로** 이긴다(규칙 순서를 옮겨도 안 깨지게).
- **확대는 장식이 아니라 안전 여백이다.** 배율 1을 옆으로 밀면 반대쪽에 바탕색 띠가 드러난다. 1.06배로 키워 한쪽 `(1.06−1)/2 = 3%` 여유 안에서만 움직인다. 부등식은 `밀리는 거리(s × x / 100) < 여백((s − 1) / 2)` 하나. `transform: scale(s) translate(x%, y%)`에서 `scale`을 먼저 적어 밀리는 거리도 배율만큼 커지므로, 순서를 뒤집으면 계산이 조용히 어긋난다(테스트가 문자열 순서까지 고정).
- **자세를 난수로 고르지 않는다** — 굴리면 여백을 넘는 자세가 어쩌다 한 번 나오고 재현이 안 된다. 정해진 여덟이면 테스트가 전부 검산한다. `backdropMotion.ts`는 시계도 난수도 모르고, 시계를 읽는 것은 `useBackdropDrift.ts` 하나(그 파일만 React를 안다 — `i18n/index.ts` ↔ `i18n/useLang.ts`와 같은 갈래).
- **걸음 수를 0으로 되돌리지 않는다** — `step`은 계속 느는 정수이고 여덟으로 접는 것은 `driftPose()`. 0으로 되감으면 그 한 번만 이동 거리가 커져 그림이 튄다.
- **머무는 시간 = 옮기는 시간** — `transition-duration`이 `DRIFT_MS`와 같아 한 걸음이 끝나는 순간 다음이 시작된다. 옮기는 시간을 짧게 하면 「움직였다 → 멈췄다」가 반복되어 끊겨 보인다.

손잡이

| 상수 | 지금 | 무엇 |
|---|---|---|
| `DRIFT_MS` | `2600` | 한 자세에 머무는 시간. 줄이면 부산해진다 |
| `DRIFT_ZOOM` | `1.06` | 안전 여백. **자세를 키우면 이것도 함께 올린다** |
| `DRIFT_PATH` | 여덟 자세 | `x`·`y`는 최대 1.5%, `z`는 1.000~1.018 |

`DRIFT_PATH`만 키우고 `DRIFT_ZOOM`을 두면 테스트가 먼저 걸린다. 스모크용으로 걸음 수를 `data-drift`로 내보낸다. 검증 → QA 참조

### 장수 일람 · 상세의 CSS 지뢰 셋 (08-17)
셋 다 CSS라 오류가 안 나고 700px 화면을 봐야 알았다.
- **접두사 안에서도 이름이 겹친다** — `.ofc-head`를 표 머리(`display: grid`)와 상세 머리(`display: flex`)에 함께 써 나중 규칙이 이겼다. `.ofc-thead` / `.ofc-bio`로 갈랐다.
- **기존 규칙이 선택자 하나 더 많아 이겼다** — `.scr .foot { flex-direction: column }`(0,2,0)이 `.ofc-tally { flex-direction: row }`(0,1,0)를 이겨 요약 줄이 「보유 카드」/「0 / 3장」/「레벨업 가능」 세 줄로 쌓였다. `.scr .foot.ofc-tally`로 올렸다(상세의 카드 줄도 같은 자리).
- **팝업이 화면 한가운데가 아니라 내용 맨 아래에 붙었다** — `.scr-bg > * { position: relative; z-index: 2 }` · `.scr-dim > * { position: relative }`가 `.modal-back`의 `absolute`를 덮어 `inset: 0`이 무시되고 흐름대로 붙었다. **환경설정 팝업(`SettingsModal`)도 2026-08-15부터 계속 그랬다.** `.scr-bg > .modal-back, .scr-dim > .modal-back { position: absolute; }`로 팝업을 그 규칙에서 뺐다(한 칸 더 세게).

### 부대 편성 — 부모가 달라 뜻이 바뀐 `.foot` (08-18)
저장 단추를 `<footer className="foot">`으로 뒀더니 **안내문이 세로 한 줄로 짜부라졌다.** `.scr .foot`의 `margin-top: auto`와 배경 화면 `.place-body`의 `margin-top: auto`가 서로를 밀어내 폭이 0에 가까워졌다. `.scr-roster`가 `.foot`을 쓰고 있어 따라 했는데 **`.scr-roster`는 `ScreenChrome`을 안 두르는 화면**이라 전제가 달랐다 — 이름이 겹친 것이 아니라 부모가 달랐던 새 종류(`.panel` · `.ofc-head` · `.city`에 이은 네 번째). 접두사는 처음부터 `.sqd-`로 — `.slot` · `.slots` · `.pieces` · `.piece` · `.pool` · `.card`가 전부 `RosterScreen`이 이미 쓰고 있다.
