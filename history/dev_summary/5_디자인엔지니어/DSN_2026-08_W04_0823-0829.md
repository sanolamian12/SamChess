2. **받아 온 그림 검수** — 사용자가 `assets/icons/`를 채워 왔고 문제 넷을 짚었다: ① `button_back_arrow.png`(라벨 포함판) 글자가 다른 아이콘 프롬프트 낱말과 섞여 「뒤로설정」, ② 확인(checkmark)의 「아이콘만」 버전 누락(6종 × 3벌 중 확인만 2벌), ③ 파일명 공백(`button_back arrow_blank.png` — 나머지는 언더스코어), ④ `create_city.jpg`의 비석에 뜻이 안 통하는 한자 — 이 화면은 입력한 도시 이름을 그림 **위에** 얹으므로 그림에 어떤 글자도 박히면 안 된다. 또 **라벨 포함 / 빈칸 / 아이콘만 세 벌 중 「아이콘만(justicon)」을 정본**으로 정했다 — `.btn`은 아이콘과 라벨을 DOM에서 따로 그리고 `t()`로 다국어를 렌더링하므로, 라벨 포함판은 언어마다 그림을 다시 구워야 한다. 사용자가 반영해 justicon 6종(설정·뒤로·닫기·확인·전투/출정·기록) + 필드 1 + 버튼 3 + 글자 없는 새 배경(`create_city.png`)으로 정리해 왔다.
3. **배선** — `style.css`에 `.scr-title`·`.scr-new` 공용 절. `.field`는 두루마리 프레임 배경 + 먹색 글자(`#3a2c1e`, 다른 화면의 밝은 글자와 반대라 셀렉터를 이 두 화면으로 좁혔다), `.btn.primary`는 옥색 목판, 「계정 생성」(primary가 아닌 `.btn`)은 참나무 목판. `border-image-slice` 값은 실측이 아니라 **눈대중**이다.
- 아이콘 6종·`.btn.ghost`는 이때 화면에 안 붙였다 — 두 화면에 아이콘이 들어갈 빈 버튼이 없었다. `ScreenChrome`의 톱니는 `GearIcon` 주석대로 「에셋 파이프라인에 걸리면 그림 못 받은 사람 화면에서 설정 버튼이 사라진다」는 이유로 의도적으로 인라인 SVG였고, 그 결정을 그때는 뒤집지 않았다.

### `tools/strip_reveal_bg.py` — 개봉 연출 배경 제거 (08-24)
`assets/market/reveal-{s,a,b,e}.jpg`(각 2048×2048에 2×2 변형 4장)만 사용자 도구로 투명 처리가 안 됐다. 결과: 4장 전부 알파가 든 `.png`(원본 `.jpg`와 나란히, 원본은 백업 겸 재처리 입력으로 보존). 도구는 ~140줄, 의존성 `Pillow`·`numpy`·`scipy`, 학습 모델 없음. `assets/`는 git에 없어 커밋 대상은 도구 하나다.

```bash
python tools/strip_reveal_bg.py                        # 기본 4장(s,a,b,e) 전부
python tools/strip_reveal_bg.py reveal-b                # 파일 하나만
```

08-07 장수 초상 260장 배경 제거(양피지 배경 + 색상 히스토그램 + 연결성)와는 소재가 달라(검은 바탕 발광 이펙트) 그 도구를 못 썼다. `is_checker_bg()`가 좌상단 20×20 코너 밝기로 자동 분기한다.

- **검은 캔버스(`s`·`a`·`e`)** — `strip_black_bg()`: additive glow 소재의 표준 추출. `alpha = arr.max(axis=2)`, 그 알파로 **역-예비곱셈**(`fg = arr/alpha*255`)해 합성 시 색이 탁해지지 않게 한다. 배경이 0이라 왜곡이 없다. 한 번에 통과.
- **체커보드 박제 파일(`b`)** — 코너가 순수 검정이 아니라 **회색 72와 108이 30px 격자로 번갈아** 있었다(코너 x=0 ≈ (72.2, 72.4, 72.3), x=30 ≈ (107.5, 107.6, 107.5), (0,0) 정렬). 예전 어떤 도구가 배경을 지운 뒤 **투명도 미리보기(체커보드)를 통째로 JPG로 납작하게 저장**한 결과로 추정된다 — 진짜 알파는 사라지고 무늬만 남았다. 세 번 실패 후 풀렸다:
  1. **30px 타일 평균으로 두 배경 매팅** — 가는 광선(폭 1~3px)이 타일을 가로질러 「타일 안 전경이 같다」 전제가 깨져 누런 얼룩·노이즈.
  2. **픽셀별 정확한 배경값 빼기** — `effective = arr - bg`, `alpha = clip(effective.max(2) / (255 - bg), 0, 1)`. 배경은 완전히 깨끗해졌지만 이펙트 **내용물 안**에 체커가 비쳤다. 분모 `255 - bg`가 타입마다 다르고(183 대 147) 「진짜 색이 채널 최댓값 255로 포화한다」 가정에서만 맞아, 채도가 낮거나 어두운 픽셀에서 같은 진짜 알파에 ~20% 다른 값을 냈다.
  3. **알파만 가우시안 블러**(반경 = 타일 × 1.5) — 알파는 깨끗해졌지만 **색(fg)**에 체커가 남았다. 색 복원식 `fg = bg + effective/alpha`에서 블러된 알파로 뭉개지지 않은 `effective`를 나눠 짝이 안 맞았고, 특히 파란 이펙트의 R 채널은 `effective_R ≈ 0`이라 `fg_R ≈ bg` = 72/108이 그대로 찍혔다.
  4. **최종** — 색은 **원본(raw) 알파**로 복원하고, 남은 체커 편향만 **AM 복조 → 저역통과 → 재변조**로 제거:
     ```python
     signal = fg_channel * checker_sign          # 복조
     bias = gaussian_filter(signal, sigma=tile)  # 30px 주기 성분만 남는다
     fg_channel -= checker_sign * bias           # 재변조 후 빼기
     ```
     격자에 정렬되지 않은 대각선 광선·둥근 꽃잎은 건드리지 않는다. 알파는 가우시안 블러 + 임계값(35/255 미만은 0 — JPEG 링잉 제거).
- 2048px 원본을 4배 확대해야 보이는 ~7% 진폭 잔물결은 실사용 크기에서 안 보여 받아들였다.
- 재사용: 검은 배경 발광 이펙트가 새로 오면 `MARKET_DIR`과 `main()`의 파일 목록만 바꿔 `strip_black_bg()` 경로를 탄다. 체커가 박제된 JPG는 `is_checker_bg()`가 잡지만 **타일 30px·회색 72/108은 이 파일 전용 실측 상수**(`strip_checker_bg()`의 `tile=`·`bg_low=`·`bg_high=` 기본값)라 새 소재면 코너 픽셀을 다시 재야 한다.
