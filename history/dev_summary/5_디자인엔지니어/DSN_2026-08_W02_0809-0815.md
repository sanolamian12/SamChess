기획자 결정에 따라 프레임 110×110(보드 셀 96×120에 세로를 맞춘다), 몸통 높이 칸의 90%, 잔디는 지우고 **코드로 그린 타원 그림자**(`SHADOW_A = 0.45`, 어두운 판 위에서 옅으면 올린다). 결과 실루엣 높이 93~100(110 중) · 발끝 y 98~104 — 원본의 28% 편차가 사라졌다.

**배경 제거에서 밟은 것들**(본문은 결정·교훈):
- **마젠타 테두리** — 기획자가 배경제거해 넘긴 PNG의 RGB에 합성색이 그대로 남아 있었다(알파 1~32 구간 평균 RGB (236,12,233), 마젠타 지수 508; 알파 255는 20). `p = a·F + (1−a)·B`를 풀되 **알파까지 다시 풀어야** 사라진다(색만 걷으면 470 → 216, 알파까지 → 56). 하한 `a ≥ max(G/255, 1−R/255, 1−B/255)`는 파란 투구를 84% 투명으로 깎아 못 쓰고, **이웃의 깨끗한 색을 참값으로** 삼는다.
- **JPG 직접이 낫다** — 같은 장수 8명 비교: JPG 직접 잔여 마젠타 ~100px, PNG 경유 ~30,000px. 도구는 두 갈래를 다 받지만 앞으로는 마젠타 합성본을 그대로 받는다.
- **배경색을 파일마다 다시 뽑는다** — 순수 마젠타가 아닌 것이 있다(이엄 `(212,68,212)`, 주강 `(252,132,252)`). 이엄은 회색 갑옷과 색차가 92뿐이라 피부까지 초록이 됐다 → 속살을 **색과 위치 둘 다로** 판정(배경에서 3px 넘게 떨어지면 속살).
- **정덕이 통째로 사라졌다** — 위·아래 띠가 배경을 가둬 플러드가 못 닿았다(배경 15조각 중 2개만 테두리에 닿음, 배경 77% 생존) → 플러드 씨앗을 **안쪽 16px 띠**에.
- **유엽의 5명이 붙었다** — `BAND_FILL = 0.5`인데 발치에서는 캐릭터만으로 폭의 65%가 찬다 → `0.9`(진짜 띠는 폭의 100%).
- **갇힌 마젠타**(팔과 몸 사이, 무기 아래, 마법진 안쪽) — 기획자가 260장을 넘겨 보며 찾았다. 배경색과 색차 48 이내면 위치를 안 따지고 배경으로 본다(진한 마젠타를 캐릭터에 칠하는 일은 없다는 기획자 확인). 진한 마젠타 픽셀 최대 2467 → 87.
- **축소는 RGBa를 거친다** — 투명 픽셀의 색이 평균에 섞이면 실루엣 가장자리에 배경색이 번진다. Pillow 12는 RGBA로 줄여도 결과가 같지만 버전에 딸린 성질이라 명시했다(2026-08-07 §3-1의 교훈).

### 지형 · 액자 · 지도 · 소리 도구 (08-14)
```
assets/map/지형_*.png     ─ build_terrain.py ─→ public/terrain/{id}.png
assets/map/chessmap.png   ─┐                    public/ui/chessmap.png
assets/map/person.png     ─┴ build_frames.py ─→ public/ui/card-frame.png  (9분할)
                                                public/ui/backdrop.png
assets/Audio/bgm/*.mp3    ─ build_audio.py  ─→ public/bgm/{id}.mp3
```
**도구가 한글 이름을 화면 id로 갈아 끼우는 자리다.** URL에 한글이 남으면 서버·CDN마다 인코딩이 갈리므로 굽는 단계에서 바꾼다. 화면은 `{id}` 규약만, 기획자는 한글 이름만 알면 된다. 표에 없는 그림(`지형_돌`)은 **이름을 찍어 알리고** 건너뛴다. 원본이 리포에 없어도 셋 다 없는 대로 돈다.

이 세션에서 같은 모양의 결정을 세 번 했다 — 에셋이 들어오면 이 셋을 먼저 정한다:

| | 지형 | 화면 | 소리 |
|---|---|---|---|
| **한글 이름 → id 를 잇는 자리** | `build_terrain.py`의 표 | (없음, 한 장씩) | `build_audio.py`의 표 |
| **없으면 어떻게** | 그 지형만 안 그린다 | 예전 어두운 격자로 물러난다 | 조용히 넘어간다 |
| **무엇으로 검증** | 스모크가 좌표로 | 스모크가 좌표로 | 「어느 곡을 틀기로 했나」 |

**`build_frames.py` — 벽보 액자 9분할.** 카드는 3:3이면 세 장, 5:5면 다섯 장이 한 줄이라 칸의 가로세로비가 판마다 다르다. 통째로 늘이면 3:3에서 지붕이 옆으로 퍼지고 5:5에서 홀쭉해진다. CSS `border-image` 9분할이 정확히 그 도구다(귀퉁이 고정, 변만 늘인다 — 지붕 두께·기둥 굵기가 언제나 같다). 자르는 자리가 정해진 비율이어야 해서 굽는 단계에서 아홉 조각을 따로 줄여 맞췄다(잰 값 14.4/21.7/14.7/12.0% → **15/22/15/12%**, 1% 안쪽).
- **처마가 기둥보다 넓다** — 몸통 폭으로 자르면 처마 끝이 잘리고, 처마까지 넣으면 카드 좌우에 산수 배경이 딸려 온다. **지붕 띠만 가로로 20% 눌러** 몸통에 맞췄다(기와 무늬라 안 티 난다).
- **흰 종이(248,247,245)와 크림색 배경(244,239,233)의 차이가 12뿐** — 색으로 지우면 종이가 뚫린다. 「가장자리에서 이어진 것만」 지우자 처마 아래 그늘 틈이 좌우 까치발에 갇혀 카드마다 흰 줄이 남았다. 결론 **「종이가 없는 줄에서만 지운다」**.
- **지도 세기** — 「배경 컬러가 세다」에 반투명 막을 덮는 길은 하이라이트·기물까지 뿌옇게 해 접었다. **배경은 굽는 단계에서 누르고**(채도 −45% · 종이색 +42%), 앞의 것은 화면에서 세운다. 세기는 눈으로 정하는 값이라 손잡이를 명령줄로 뺐다(`--map-desat` · `--map-fade`).

**`build_audio.py`** — 처음엔 「출력이 원본보다 새로우면 건너뛴다」여서 기획자가 3·4번 곡의 **내용을 맞바꿔** 저장했을 때(파일 시각은 그대로) 아무 일도 안 했다. 1:1 복사라 **내용을 그대로 비교**하도록 고쳤고(크기가 다르면 읽어 볼 것도 없다, 17MB 여섯 곡도 눈 깜짝할 사이), 갈아 끼운 곡은 `prep(갈아끼움)`처럼 이름을 찍는다. 그림 도구들(`terrain`·`frames`·`vfx`·`actions`)은 아직 시각으로 판단하므로 원본을 맞바꾸면 `--force`를 붙인다. → 결정·교훈 참조.

### 화면 배경 — `tools/build_backgrounds.py` (08-15)
`npm run backgrounds` → `public/backgrounds/{id}.jpg` 14장(4.2MB, 원본은 `_big.jpg` 넷).

- **띠를 칸마다 잘라 굽는다(CSS로 잘라 쓰지 않는다)** — 칸 수가 원본마다 다르고(3칸·4칸) 화면이 그것까지 알면 「몇 칸짜리인가」가 CSS와 코드 두 곳에 적힌다. 또 밤 그림 하나를 띄우려고 낮·황혼까지 받게 된다(고해상도 원본은 한 장 4MB). 칸 순서 → id 표는 도구 하나뿐(`build_terrain.py`와 같은 결).
- **경계를 그림에서 찾는다** — `openBackground.png`(804px, 3칸)의 진짜 경계는 268·536이 아니라 **266·535**였다. 등분하면 낮 그림 오른쪽에 황혼의 주황 띠가 2px 남는다. 지금은 등분 자리 ±1%에서 색이 가장 크게 튀는 열을 찾아 자르고 옮긴 값을 찍으며, 안쪽 가장자리는 1px 더 깎는다(`cut_points()`).
  ```
  · openBackground: 경계를 그림에서 찾았다 [268, 536] → [266, 535]
  · mainBackground: 경계를 그림에서 찾았다 [300, 600] → [299, 599]
  ```
  `eachBackground.png`는 정확히 등분 자리였다 — 넷 중 하나만 맞았다면 「다 그렇겠지」로 넘어갔을 것이다.
- **고해상도 원본으로 교체** — 처음 PNG는 폭 804~900px라 칸 하나가 225~300px, 프레임은 320~700px라 늘려 깔면 깨졌다. `{이름}_big.jpg`(2062~2912px)를 받아 원본을 **`_big.jpg → _big.png → .png` 순**으로 고르고 어느 것으로 구웠는지 실행마다 찍는다.
- **출력을 JPG로** — 칸 하나가 687×1536이라 PNG면 14장에 25MB 이상(지금 4.2MB). 확장자는 도구와 `screens/backdrop.ts` 두 곳이 함께 바뀌어야 해서, 도구가 **계획에 없는 출력을 지운다** — 안 지우면 PNG·JPG가 섞여 어느 게 살아 있는지 눈으로 못 가른다.

### 전투 화면 리디자인 — 지도 · 벽보 액자 · 산수 배경 (08-14)
- **카드 한 장 = 벽보 한 장** — 카드 줄과 고유기술 줄로 나뉜 두 그리드를 한 칸으로 합쳤다(액자가 둘을 함께 감싸야 한다). 버튼이 카드 아래 한 줄로 늘어서는 모습은 그대로.
- **밝은 바탕이 되자 전제가 뒤집혔다:**

  | | 어두운 판에서 | 지도 위에서 |
  |---|---|---|
  | 좌표 눈금 | 밝은 글자 + **검은 외곽선** | **먹 글자 + 종이색 외곽선** |
  | 진영 구역 | 불투명 | 색조만 (0.13) |
  | 체스판 무늬 | 한 칸 걸러 밝게 | **아예 뺀다** |

  눈금을 그대로 뒀더니 글자는 날아가고 외곽선만 남아 판이 얼룩졌다. 무늬는 지도 위에 격자를 얹는 셈이라 강물과 산이 안 읽혔다. 지도가 없으면 예전 값 그대로다.
- **3:3에서만 카드가 깨졌다** — `.strip-slots`에 `grid-template-rows`가 없어 암시적 줄이 `auto`(내용 높이)가 되었고, 3:3은 카드가 넓어 사진 최소 높이가 커지면서 벽보가 스트립을 넘어 HP·WT·고유기술 줄이 잘렸다. 5:5는 우연히 맞았다. `minmax(0, 1fr)`로 못 박았다. → 결정·교훈 참조.

- 자리 화면 판때기에 `.panel`을 붙였더니 전투 화면의 `position: absolute`와 폭 `--board × 3/8`이 먹어 오른쪽 아래에 좁게 붙었다 → **`.place-panel`**. (`.panel`이 두 번째로 사고를 냈다 — 결정·교훈.)
