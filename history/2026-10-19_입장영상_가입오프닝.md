# 입장 영상 → 입장 하늘 · 가입 오프닝 (2026-10-19)

기획자가 「전에 로그인하면 카메라가 하늘로 올라갔다 내려오며 메인으로 바뀌는 연출을 넣었는데 안 보인다」고 물었다.
찾아보니 **소재만 있고 이은 적이 없었다.** 그 자리에서 입장 영상을 붙이고, 이어서 새 계정용 가입 오프닝을 기획자와 몇 차례 주고받으며 만들었다.
커밋 `5890a02`(main에 푸시).

오후 작업(입장 하늘 · 입장/계정 생성 패널 · 세 단추 통일 · 도시 이름 짓기 다듬기 · 가입 오프닝 다듬기)은 둘째 커밋이다.

**같은 날 오후에 입장 영상을 걷고 「입장 하늘」로 바꿨다** — 기획자가 직접 해 보니 영상의 첫 · 끝 장면이 간판 · 메인 그림과 달라
이질감이 컸다. 아래 2절(영상)은 그 경위로 남기고, 지금 모양은 **8절**이다.

## 1. 「안 보인다」의 정체

- 처음엔 [입장] 뒤의 **입성 로딩**(가마 · 「도시를 불러오는 중」, `EnterLoading`, 10-13)을 말하는 줄 알고 재 봤다 — 실제 앱에서 프레임마다 재니
  1.3~3.2초 동안 정상으로 떴다(Playwright, 시험 계정). 기획자가 말한 것은 그게 아니라 **시간대별 영상**이었다.
- `assets/opening/`에 `입장동영상_1_낮` · `_2_황혼` · `_3_밤`(10초, 720×1280, 9월 11일)이 있었는데 **그것을 부르는 코드가 git 어디에도 없었다** —
  클라이언트 소스 · `public/` · 전체 이력 · stash · 매달린 커밋(`git fsck`)까지 뒤졌다. 세션 기록은 9/22 이후만 남아 그 전 사정은 알 수 없다.
- 프레임을 뽑아 보니 영상은 **간판 그림과 같은 성문 앞 → 하늘(독수리) → 메인 그림과 같은 저잣거리**로 끝난다 — 겹쳐 넘기기에 꼭 맞는 소재였다.

## 2. 입장 영상 — 간판 [입장] → 메인 (오후에 걷었다 — 8절)

- 흐름: [입장] → 입성 로딩(인증 · 프로필 왕복) → **시간대 영상**(`screens/EnterCine.tsx`) → 메인. 시간대는 배경과 같은 `currentBand()`(7~16 낮 · 16~20 황혼 · 나머지 밤).
- **메인은 영상 밑에서 이미 서 있다.** `App.tsx`가 계정을 읽자마자 화면을 메인으로 바꾸고 그 위에 영상을 덮는다 — 영상이 끝나 흐려질 때(0.7초) 비치는 것은
  그림까지 다 받은 메인이고, 영상 끝 장면과 메인 배경이 같은 저잣거리라 이음매가 안 보인다.
- 영상은 **계정을 안 뒤에** 튼다 — 새 계정(도시 이름 짓기로 가는 길)에 성 안 장면을 틀어 놓고 끊을 일이 없다.
- 안 트는 경우: 새 계정 · 끊긴 판으로 곧장 돌아가는 길(AI 판 · 온라인 재접속 표가 있으면) · 저장된 세션으로 새로고침.
- **못 돌면 막지 않는다** — 파일 없음(`error`) · 재생 거부(소리를 끄고 한 번 더) · 4초 동안 시작 안 함이면 곧장 지나간다.
- 소리: 영상 동안 배경음악을 붙들고(`holdBgm`) 끝나면 이어 튼다. 음소거는 같은 스위치(`bgmMuted`). [입장] 클릭이 사용자 조작이라 소리 자동재생이 허락된다.
- [건너뛰기]는 0.9초 뒤에 오른쪽 위에. 영상은 입장 팝업을 여는 순간 **미리 받아**(Blob URL) 로그인 왕복 동안 다 받는다. 포스터(첫 프레임)를 깔아 검은 번쩍임이 없다.
- 앱 틀은 1:2, 영상은 9:16이라 `cover`로 좌우를 약 11% 자른다.

### 낮 · 황혼은 20초 한 파일에서 자른다 (기획자 지정)

- `입장동영상_1_2_낮_황혼.mp4`(20초)에 낮 · 황혼 두 편이 이어 붙어 있다. 장면 전환 검출(`select='gt(scene,0.25)'`)로 **9.833초 = 24fps의 236번째 프레임**을 찾았다.
- 앞 절반은 `_1_낮`과 같은 영상(프레임 차이 평균 1.4/255 — 인코딩 차이)이고, **뒤 절반은 `_2_황혼`과 다른 영상**이다. 그래서 낮 · 황혼 둘 다 20초 파일에서 쓴다.
- 자르기는 **프레임 단위**(`trim=start_frame/end_frame`, 소리는 `atrim`)로 — 시각(`-ss`)으로 자르면 키프레임에 붙어 경계가 밀린다. 경계 앞뒤 다섯 프레임을 찍어 다른 시간대가 안 섞인 것을 봤다.

### 굽기 — `npm run opening` (`tools/build_opening.py`)

- 원본이 10초에 4~7MB라 휴대폰에서 [입장]마다 받기 무겁다. 해상도는 그대로, H.264 CRF 26 + `+faststart`로 줄였다(2.4 · 1.8 · 1.5MB). 포스터 JPG도 함께.
- 다시 구울지는 시각이 아니라 **원본 sha1 + 자르는 프레임**으로 정한다(`public/opening/sources.json`). 원본 폴더나 ffmpeg가 없으면 건너뛴다고 알리고 통과(에셋 방침).
- `public/opening/`은 `.gitignore` — 다른 PC에서는 `npm run opening`을 한 번 돌린다.

## 3. 가입 오프닝 — 새 계정이 도시 이름을 지은 뒤

기획자와 네 번 주고받으며 모양이 정해졌다. 최종:

1. **첫 대사**(석양 위, 한 줄씩 1.3초) — 도시 이름을 지으면 곧장 시작.
   > {ID}는 구국제민(救國濟民), 곧 나라를 구하고 백성을 살리라는 뜻을 받들어 거병하니, / 거점의 이름을 「{도시}」라 하였다. / 그 뜻을 함께할 다섯 인재가 모였나니…
2. 그동안 **다섯 장수가 다가오는 그림 일곱 장**(`opening_2~8`)이 0.5초마다 겹쳐 넘어가 8에서 멈춘다.
3. **판 위 W 대형** — `slot-first` 판(2:1)이 뜨고 처음 받은 다섯이 **한 명씩 「팡」**(D → C → B → A → S, 0.65초 간격, 작게 났다가 1.25배로 부풀고 자리 잡음, 효과음 `battle_collection_open`).
   왼쪽부터 D · B · S · A · C, 위 줄 B · A · 아래 줄 D · S · C. 크기는 C · D 1 · A · B 1.1 · S 1.2배. 그림 밑에 등급 표시 + 이름(궁궐 · 병영과 같은 Song Myung).
4. **둘째 대사**(장수들 그림자 위) — 천하를 통일하고 백성이 안정되는 그날까지! / 도시의 흥망과 이들의 운명이 그대에게 달렸다!
5. **[성 안으로 들어가기]** → 8번 장면 한가운데로 0.7초 파고들며 하얗게 번쩍 → 흰 섬광 속에서 1.45배로 뜬 메인이 줄어들며 자리 잡는다. **입장 영상은 안 튼다**(기획자 확정).

### 만든 방식

- **그림은 배경과 같은 층(`ScreenChrome`의 `artOverlay`)에 겹친다.** 도시 이름 짓기 화면의 배경 `new-city.jpg`가 곧 `opening_1`과 같은 장면이라 2부터 그 위에 얹었다.
  층을 따로 두면 배경만 드리프트로 흔들려 겹치는 순간 그림이 어긋난다. 그림은 png 원본(360×640) 그대로 JPEG로만 바꿨다(기획자 선택 — 영상에서 720p로 다시 뽑는 안은 안 택함).
- **화면이 바뀌는 순간을 넘는 전환은 두 곳에 나눴다.** 파고들기 · 번쩍은 가입 화면(`.ngo-leaving`, `.ngo-flash`), 메인이 줄어드는 쪽은 App(`#frame[data-arrive]`) —
  가입 화면은 그때 이미 내려가 있다. **이음매는 흰색이다** — 앞이 흰색으로 끝나고 뒤가 흰색에서 시작한다.
- W 대형의 크기 기준은 판 안쪽 폭(`container-type` + `cqw`) — C · D가 17cqw. 둘째 대사 · 단추의 아래 칸(`.ngo-foot`)은 처음부터 높이를 잡아 둬, 내용이 들어올 때 판이 밀려 올라가지 않는다.
- `{ID}`는 **로그인 이메일의 @ 앞**(기획자 확정) — 이 게임에 따로 지은 이름이 없다. 한국어 조사는 값에 붙인다 — `josaOf(id, '은는')`에 「은는」을 더했고,
  「(이)라」는 `copulaOf()`를 새로 뒀다(`ui/eventText.ts`). 다른 언어는 조사 자리 없이 그 언어 어순으로.
- 계정은 이름을 지은 순간 이미 서버에 있다 — 오프닝 도중 창을 닫아도 다음 [입장]은 메인으로 간다(오프닝은 다시 안 뜬다).

### 거쳐 간 모양 (버린 것)

- 처음엔 장수 공개를 **장터 1회 뽑기 연출**(`CardRewardReveal` — 효과음 · 섬광 · 카드 · [확인])로 다섯 번 돌렸다 → 기획자가 [확인] 없이 2초로 → 그래도 다섯에 약 21초가 걸렸고,
  기획자가 섬광 없이 판 위 「팡」으로 바꿨다(약 3초). 자동 넘김(`autoMs`)을 위해 고쳤던 `CardRewardReveal`은 원래대로 되돌렸다 — 장터 · 도적떼는 영향 없음.
- 판 그림: `panel_done`(9분할) → `slot-first.png`(세로 그림을 9분할로 2:1에 폄 — **안쪽 구름무늬가 찌그러졌다**) → 기획자가 **2:1로 다시 그린 `slot-first2.jpg`를 통째로** 깐다.

### 굽기

- `npm run opening`이 가입 그림 일곱 장(`public/opening/signup-2~8.jpg`)도 굽는다.
- `npm run ui`(`build_ui.py`)가 `slot-first2.jpg` → `ui/slot-first.png`(폭 1400, 바깥 검정 약 21px를 걷음). 판 비율 2.02 → 2:1 상자에 `100% 100%`.
- `build_ui.py`의 검은 바탕 걷기가 **`.jpg`일 때만** 돌았다 — 확장자만 `.png`이고 바탕이 불투명 검정인 그림(`slot-first.png`)이 검은 테를 두른 채 구워졌다.
  「투명 칸이 하나도 없는 png도 걷는다」(`opaque()`)로 고쳤다. 이 조건에 걸리는 그림은 그것 하나뿐인 것을 확인했다(다른 그림 결과 불변).

## 4. 문구 — 열 언어

- 새 키: `enter.skip`(건너뛰기) · `newgame.say` · `newgame.say2` · `newgame.enter`(성 안으로 들어가기). 줄은 `\n`으로 나누고 화면이 한 줄씩 띄운다.
- 「구국제민」은 한자를 두고 바로 뒤에 뜻을 풀었다(한국어 「곧 나라를 구하고 백성을 살리라는」). 일본어 · 중국어는 그 언어의 한자 표기.
- 다른 언어 문장은 이 세션에서 옮긴 것 — **기획자가 번역을 확인하기로 했다**(몽골어는 특히).
- 줄 끝: 이 저장소의 i18n JSON은 CRLF/LF가 섞여 있다. Edit 도구로 한 줄을 고쳤더니 ko.json **전체**의 줄 끝이 바뀌었다(`--stat` 2,253줄) — HEAD 원본에서 다시
  「이웃 줄의 줄 끝을 따라」 넣었다. Python 텍스트 쓰기도 `NewGameScreen.tsx` · `build_opening.py`를 CRLF로 바꿨다 — LF로 되돌렸다. CLAUDE.md에 이미 적힌 함정 그대로다.

## 7. 교훈

- **소재가 있다고 이어진 것은 아니다.** 기획자는 「붙였는데 안 보인다」로 기억했지만 코드는 한 번도 없었다. 「왜 안 되지」 전에 「부르는 자리가 있나」를 grep · git 이력으로 먼저 본다.
- **Playwright의 Chromium은 H.264를 못 푼다.** 영상이 곧장 `error`로 걷혀 「못 돌면 지나간다」 갈래만 시험된다 — 실제로 보려면 Edge(`channel: 'msedge'`)로 띄운다.
  거꾸로 다른 `*_ux` 도구들이 지금 통과하는 것은 그 우연 덕이다(로그인 뒤 10초 영상이 메인을 덮지 않는다) — CLAUDE.md에 적었다.
- **세로 그림을 9분할로 눕히면 테는 살아도 안쪽 무늬가 찌그러진다.** 9분할은 가운데가 무늬 없는 판일 때만 안전하다 — 무늬가 있으면 목표 비율로 그린 그림을 통째로.
- **「정확히 그 단계」를 기다리는 검사는 앞 단계가 늦으면 지나쳐 버린다.** 그림이 4번일 때를 기다리다 앞의 그림 받기 확인이 늦어 5번으로 넘어간 뒤라 시간 초과가 났다 — 「4 이상」으로.
- **화면이 바뀌는 순간을 가로지르는 전환은 양쪽이 같은 색에서 만나야 한다.** 한 컴포넌트가 다 하려 하면 그 컴포넌트는 이미 내려가 있다.

## 8. 오후 — 영상을 걷고 「입장 하늘」로

### 왜

기획자가 dev 서버로 직접 로그인해 보고: 「영상과 시작 화면(간판), 도착 화면(메인)이 둘 다 많이 달라 메인으로 진입했다는 느낌이 없다.
간판의 다이얼로그 · 단추가 흐려지고 → 하늘(시간대마다 색이 다른)로 올려다봤다가 → 땅으로 내려오면 메인에 안착하는 화면을 원한다.」
나란히 놓고 보니 간판 그림은 성을 멀리서 내려다본 구도에 위아래 무늬 테두리가 있고 영상 첫 장면은 성문 앞 근경이다. 메인 그림과 영상 끝 장면도
같은 장소를 다르게 잡은 그림이다. 생성 영상은 첫 · 끝 장면을 지정해도 다시 그려 양 끝 이음매가 남는다 — 그래서 **화면에 깔린 바로 그 그림을 코드로 움직이는** 안(A)을
골랐다(영상을 다시 만드는 B, 하늘 구간만 영상인 C와 비교해 기획자 확정). 다른 세션이 코드를 고치던 중이라 처음엔 검토만 하고, 하늘 그림 프롬프트를 드렸다.

### 계정 생성을 간판의 따로 난 길로

- 기획자: 입장 패널의 [계정 생성] 자리엔 [취소]를 되살리고, 간판에 [계정 생성]을 두자. [크레딧 보기]를 걷고 [입장]을 그 자리로, 맨 아래 [계정 생성].
- 간판: [언어](참나무) · [입장](옥색) · [계정 생성](금빛 두루마리, hover 빛 번짐) — `data-action` `languageOpen` · `loginOpen` · `signupOpen`.
  `CreditsModal`은 화면이 생기면 다시 부를 자리로 남겼다(지금은 아무도 안 부른다).
- `LoginModal`을 `mode: 'login' | 'signup'` 두 모드로 — 입력칸 · 바쁨 · 오류 · 안내 칸이 같다. 계정 생성은 「계정 생성」 명패 · 빈 이메일(지난 이메일은 이미 있는 계정의 것) ·
  `new-password` · 금빛 [계정 생성](폼 제출) · 붉은 [취소]. 입장은 옥색 [입장] · [비밀번호 초기화] · 붉은 [취소].
  [취소]가 돌아오자 기획자가 구석 X를 걷자고 했다 — 닫기는 [취소]와 바깥 누르기 둘이다.
- [취소](`loginCancel`, 새 문구 `title.cancel` 열 언어)는 간판 팝업의 붉은 [닫기]와 같은 판 · 같은 규칙이고, 테 두께를 옥색 · 금빛과 같은 .35rem 1.05rem으로 맞췄다
  (그 규칙을 쓰는 언어 팝업 [닫기]도 함께).
- `smoke_meta`: 간판 단추 셋 순서 · 계정 생성 팝업(빠진 것 · [입장]이 없음 · 금빛/붉은 그림 · 빈 이메일 · [취소]로 닫힘) · 입장 팝업([계정 생성]이 없음 · 붉은 [취소] · 구석 X).

### 계정 생성의 안내 — 이미 가입한 이메일 · 안내는 팝업으로

- 기획자가 자기 이메일로 [계정 생성]을 눌렀더니 「확인 메일을 보냈다」가 떴다(이미 가입한 계정인데). 실측: 확인 메일이 켜진 Supabase는 **이미 가입한 이메일에도 200**을 주고
  (가입 여부를 숨기려고) 세션 없는 사용자 모양을 돌려주되 **`identities`가 빈 배열**이다 — 새 가입이면 하나 있다. 메일은 안 나간다.
  `signUp()`이 그것을 `{ confirmed: false, exists: true }`로 가르고, 확인 메일이 꺼진 프로젝트의 422 `user_already_exists`도 같은 값으로 모은다
  (`rawAuthFetch`가 던지는 오류에 `code`를 붙였다).
- 계정 생성 팝업의 안내는 [취소] 밑 글줄이 아니라 **팝업 하나 더**(`data-modal="signupNotice"`, 기획자 지정) — 확인 메일([확인] → 그 이메일을 든 입장 팝업) ·
  이미 가입함([입장하러 가기] → 이메일을 든 입장 팝업 · [확인]) · 오류([확인] → 계정 생성 팝업 그대로). 입장 팝업의 안내(재설정 메일 · 오류)는 글줄 그대로다.
  새 문구 `title.notice` · `title.signupExists` · `title.toLogin` · `title.ok`(열 언어). 「이미 가입」 문장은 기획자가 두 줄로 줄였다 —
  「이미 가입한 계정이 있습니다.」 · 빈 줄 · 이메일(처음엔 [입장] · [비밀번호 초기화] 안내까지 넣었는데 [입장하러 가기] 단추가 그 일을 한다).
- `smoke_meta`가 가입 요청을 가로채(진짜로 가입시키면 확인 메일이 나간다) 「이미 가입」 응답을 흉내 내 팝업 → [입장하러 가기] → 이메일이 채워진 입장 팝업을 본다.
- 남은 것: Supabase의 오류 문장(예: 비밀번호 6자 미만)은 영어 그대로 뜬다 — 입장 팝업의 오류도 같다. 번역하려면 `error_code`별 문구가 필요하다.

### 도시 이름 짓기에 들고 날 때는 흰 전환

- 기획자 실기: 도시 이름 짓기 화면은 **노을 한 장뿐**이라, 낮 · 밤에 새 계정으로 들어가면 하늘로 올라갔다 내려왔을 때 시간이 지나 있다.
  그 화면에 들고 날 때는 「지금 화면이 확대되며 흐려지고 → 화면 전체가 흰빛으로 부드럽게 번쩍 → 다음 화면이 떠오름」으로(기획자 지정).
- `App.tsx`의 `whiteCut(swap)` — out .65s(`.scr`가 1.1배로 커지며 흐려지고 `#frame::before` 흰빛이 차오름) → 화면을 바꿈 → in .8s(흰빛이 걷히고
  다음 화면은 .45s로 먼저 떠오른다 — 같은 빠르기로 엇갈리면 가운데서 바탕 어둠이 비쳐 잿빛으로 꺼진다). 흰빛은 `::before`(`::after`는 메인 도착이 쓴다).
- 새 계정인지는 계정을 읽어야 안다. 처음엔 입장 하늘이 `in`(간판 위 것들이 흐려지는 0.7초)에서 도착지를 기다렸다가 하늘로 갈지 흰 전환일지 정했는데,
  기획자가 「[입장] 뒤 3초쯤 멈췄다 움직인다」고 짚었다. 재 보니 인증 약 1초 + 계정 읽기 0.9~4.1초(`server-api` 로그의 `/profile` 처리 시간 — 토큰 확인을 Supabase에
  한 번 더 묻고, 도쿄 리전 DB를 여러 번 오간다). 예전엔 이 기다림이 하늘에 숨어 있었는데 그 순서 바꿈으로 흐려진 간판 위에 드러난 것이다.
- 기획자 안대로 **늘 곧장 하늘로 올라가고**, 새 계정이면(`to: 'cut'`) 하늘에 머문 채(`hold`) 계정 읽기가 끝나는 대로 **하늘 장면에서** 흰 전환으로 도시 이름 짓기에 간다
  (하늘 층 `.sky-enter`도 `#frame[data-flash="out"]`에서 커지며 흐려진다). 기존 계정은 예전 그대로 내려앉는다. [뒤로 가기]도 흰 전환.
- 줄일 거리(안 함): 토큰 확인을 `server-api` 안에서 공개키로 끝내기(요청마다 Supabase 왕복 하나가 빠진다) · `/profile` 안의 DB 왕복 수 재기 · 입장 팝업을 열 때 미리 연결.
  가입 오프닝 끝의 [성 안으로 들어가기](파고들기 · 번쩍 · 메인 줄어듦)는 그대로 — 이미 같은 결이다.
- `enter_ux`가 페이지 안에서 하늘 단계 · 흰 전환 걸음 · 화면을 프레임마다 적어 「새 계정은 up · hold · down이 한 번도 없고 간판 out → 도시 이름 짓기 in」,
  「[뒤로 가기]는 도시 이름 짓기 out → 간판 in」을 본다(정규식의 `|`가 스크립트를 지나며 `|`로 풀려 모든 줄에 걸린 것을 한 번 밟았다).

### 가입 오프닝 다듬기 (기획자 실기 뒤)

1. 그림 넘김 0.5초 → **1초**(겹침 전환도 1초) — 「생각보다 되게 빠르게 걸어온다」. 일곱 장이 약 7초.
2. 첫 대사를 간결하게 네 줄로(열 언어): 「{ID}는」 / 「나라를 구하고 백성을 살리라는 뜻을 받들어,」 / 「「{도시}」에서 거병하였다.」 / 「그 뜻을 함께 할 다섯 인재가 모였나니...」.
   「구국제민(救國濟民)」은 빠졌다. 도시 이름 뒤가 「에서」라 받침 조사(`copulaOf`)는 이제 안 쓴다(함수는 남겼다).
3. 장수가 「팡」 나올 때 캐릭터 한가운데서 **눈이 살짝 부시는 섬광**(`.ngo-member::before` — 흰 원형 빛이 0.55초 동안 커지며 밝았다 사라진다, `screen` 섞기).
   페이지 안에서 `::before`의 불투명도가 0 → 0.95 → 0으로 도는 것을 쟀다(밖에서 찍은 사진은 짧아서 자주 놓친다).
4. 둘째 대사를 붉은 판과 초록 단추의 **한가운데**로 — 무대를 「위 대사 / 빈 간격 / 판 / 가운데 칸 / 단추 칸」으로 갈랐다. 빈 간격과 가운데 칸이 남는 높이를 반씩 나눠 판은 가운데쯤,
   둘째 대사는 판과 단추 사이 정가운데. 단추 칸은 처음부터 높이를 잡아 대사 · 단추가 나타나도 판이 안 움직인다.
5. [성 안으로 들어가기]를 **화면 폭 가득** — 오른쪽 아래 구석의 생성 도구 표시(✦)를 덮는다.

### 로그아웃 확인 문구

- 「로그아웃할까요? 진행 상황은 서버에 저장돼 있어 다시 로그인하면 그대로다.」 → **「로그아웃 할까요?」**만(기획자 지정, `main.logoutConfirm` 열 언어 — 첫 물음만 남겼다).

### 세 두루마리 단추 통일 (게임 전체)

- 기획자: 「`button_primary` · `button_forcedcancel` · `button_alart`는 색만 다르고 모양이 같은 단추다 — 적용된 곳을 다 조사해 모양을 통일해 달라.」
- 재 보니 구운 셋(`btn-primary` · `btn-forcedcancel` 828×225, `btn-alert` 960×270)은 양끝 축이 그림 폭의 11%, 위아래 투명 여백이 높이의 5%로 같다.
- `style.css`에서 세 그림을 쓰는 규칙 34개를 뽑았더니 자르기 값이 여섯 가지였다 — `4% 16%`(옥색 · 붉은 23곳) · `12% 11%`(금빛 둘 + 오늘 고친 옥색 둘) ·
  `9% 11%`(금빛 셋) · `14% 10% 14% 13%`(간판 팝업 붉은 [닫기]) · `0 16%` / `0 11%`(전투 맥락 판 · [항복] 물음). 통째로 까는 둘(랭킹 로딩 · 농지 [도적단 퇴치])은 그대로.
- 전부 `12% 11%`로, 위아래를 안 자르는 전투 단추는 `0 11%` + 옆 두께 `--cx-btn-h × 91.1/225`(옥색 · 붉은)로. [항복] 물음의 붉은 단추는 금빛의 옆 두께를
  물려받고 있어 제 값을 따로 적었다. 테두리 두께(단추 크기)는 자리마다 정한 값이라 그대로 뒀다.
- 확인: 새 계정으로 병영 [출정하기] · 궁궐 [이름 변경] · 장터 · 전투 데모 [턴 가져오기]를 찍어 축 모양이 같은 것을 봤다.

### 검사 — `tools/enter_ux.ts`(옛 `enter_cine_ux.ts`)

- 시간대 셋(가짜 시계)마다: 제 하늘인가 · 단계가 `in → up → hold → down → out`인가 · **하늘에 닿기 전에 밑의 화면이 메인으로 바뀌지 않았는가** ·
  걷힌 뒤 메인 배경이 그 시간대 그림인가 · 새로고침엔 안 서는가. 0.25초마다 프레임 사진을 남겨 이음매를 눈으로 봤다. 영상이 없으니 기본 Chromium으로 돈다.
- 새 계정은 하늘을 지나 도시 이름 짓기로 내려앉는가 → 가입 오프닝 전 과정(오전 그대로).

### 밟은 것 — 오전 커밋이 남긴 구멍

- `popup_ux`가 「메인이 안 뜬다」로 멈췄다. 하늘 때문이 아니라 **오전에 넣은 가입 오프닝** 때문이었다 — 새 도시를 만드는 `*_ux` · `*_play` 도구 12개가
  [시작하기] 뒤 곧장 메인을 기다리는데, 이제는 오프닝(약 14초) 끝의 [성 안으로 들어가기]를 눌러야 메인이다. 오전에 `popup_ux`를 돌린 것은 오프닝을 넣기 **전**이었다.
  12개 모두 [시작하기] 뒤에 「[성 안으로 들어가기]를 누르고 메인이 자리 잡는 1초 연출(`data-arrive`)이 끝나길 기다린다」 두 줄을 더했다 —
  연출 도중에 재면 「로그아웃 확인이 가운데가 아니다(36px)」로 떨어졌다.
- `smoke:meta`도 같은 자리에서 「도시 이름이 반영되지 않았다」로 떨어졌다 — 단추 이름이 달라(`.scr-new .btn.primary`) 위 grep에 안 걸렸다.
  같은 두 줄을 더했고, 「[입장] 300ms 뒤 새 계정 화면이 있는가」도 화면을 기다리게 바꿨다(이제 하늘에 닿은 뒤에야 화면이 바뀐다). 완주 통과.

### 교훈

- **흐름 앞에 단계를 끼워 넣으면 그 흐름을 지나는 검사 도구가 전부 영향을 받는다.** 오프닝을 넣은 커밋에서 `enter_cine_ux` 하나만 고치고 나머지 12개를 안 돌렸다.
  끼워 넣은 단계가 있으면 `grep`으로 그 길(`newgame-form`)을 지나는 도구를 찾아 최소 하나는 돌려 본다.
- **전환의 양 끝은 「같은 그림」이어야 한다 — 「비슷한 그림」은 오히려 어긋남이 도드라진다.** 영상은 장면이 비슷해서 더 이질적이었다.
  출발 · 도착을 화면의 그 그림으로 묶고, 바꿔치기는 아무도 못 보는 자리(하늘 한가운데)에서 한다.

## 9. 컬렉션 구성원 중복 — 엑셀 수정 대기 (코드 변경 없음)

기획자가 컬렉션을 보다가 「안량과 문추」와 「관도대전」의 구성원이 순서만 다르고 같다는 것을 찾았다. 전부 훑으니 **세 쌍**이었다 —
37↔38(안량 · 문추 · 원소 · 관우 · 조조), 55↔75(손권 · 조조), 96↔106(강유 · 제갈량). 구성의 정본은 `docs/컬렉션.xlsx` 「칸」 시트라
**엑셀을 고치는 일은 기획자가 하고**, 여기서는 후보 · 비용 영향 · 고칠 행만 정리했다(엑셀은 읽기 전용, 파이썬으로 다시 쓰면 서식 · 수식이 깨질 수 있다).

| 컬렉션 | 확정 구성 | 근거 | 비용 · 등급 |
|---|---|---|---|
| 23번 여포, 백문루에 묶이다 | 여포 · 진궁 · 후성 · **위속** · 송헌 | 상세 설명에 「후성 · 송헌 · 위속이 진궁을 묶어 바쳤고」 | 28 → 20, 영웅 → **희귀** |
| 37번 안량과 문추 | **안량 · 문추** | 하북의 두 기둥 둘만 | 34 → 12, 전설 → **일반** |
| 55번 책상을 베다 | 손권 · **주유** · **노숙** | 항복론 속에서 노숙이 먼저, 주유가 이어 개전을 주장 | 20 → 30, 희귀 → **영웅** |
| 75번 아들을 낳으려면 손권처럼 | 손권 · 조조 · **유종** | 「유경승의 아들은 개돼지일 뿐」 — 조조가 견준 유표의 아들 | 20 → 22, 희귀 그대로 |
| 106번 아홉 번의 북벌 | 강유 · **요화** | 하후패 · 장익은 게임에 없다. 요화는 북벌에 끝까지 함께했다 | 20 → 14, 희귀 → **일반** |

- 「칸」 시트에서 고칠 곳(아래부터 고치면 행 번호가 안 밀린다): 364행 제갈량 → 요화 · 266행 아래 `75 · 3 · 카드 · 유종 · 1` 넣기 ·
  201행 조조 → 주유 + 그 아래 `55 · 3 · 카드 · 노숙 · 1` 넣기 · 123~125행 지우기 · 78행 조조 → 위속.
- 75번은 조조를 빼고 유종만 넣으면 비용 12로 일반이 돼 효과(손권 통솔+2)가 일반 상한(1)을 넘어 **추출기가 막는다** — 그래서 셋으로 했다.
- 바뀐 효과 다섯은 모두 새 등급의 상한 안이다. 고치면 구성원이 같은 컬렉션은 남지 않는다.
- 엑셀이 오면: `npm run extract` → 다섯 개가 예상대로인지 확인 → 「구성원이 같은 컬렉션이 있으면 추출 실패」 검사를 `extract_data.py`에 넣는다(지금 넣으면 위 세 쌍 때문에 바로 실패한다).
