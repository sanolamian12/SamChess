# 2026-08-15 — 간판 · 도시 · 자리 화면 (pptx 33~36쪽)

> 이 문서는 **왜 그렇게 정했고 어디서 넘어졌는지**를 적는다.
> 현재 상태의 정본은 [`HANDOFF.md`](../HANDOFF.md), 구현 기준은 [`Design/GDD.md`](../Design/GDD.md) §8.1.

## 1. 무엇을 했나

기획자가 pptx **33~36쪽**에 화면 구성을 넣고 `assets/Backgrounds/` 4장을 줬다.
게임 URL로 들어왔을 때의 첫 화면부터 도시, 그 안의 세 자리까지를 붙였다.

```
[간판·로그인] → [메인·도시] ─┬─ 궁궐 → 장수 관리
                              ├─ 병영 → 3:3 · 5:5 → 편성 → 전투
                              └─ 장터 → (아직 없다)
```

**룰 엔진은 건드리지 않았다.** 메타 화면(React)과 그림 파이프라인뿐이다.

| | 붙은 것 | 파일 |
|---|---|---|
| 1 | 간판·로그인 화면 | `screens/TitleScreen.tsx` |
| 2 | 시간대 배경 — 접속 시각으로 낮·황혼·밤 | `screens/backdrop.ts` |
| 3 | 도시 화면 개편 — 배경 위 세 간판 | `screens/MainScreen.tsx` |
| 4 | 궁궐·병영·장터 | `screens/PlaceScreen.tsx` |
| 5 | 환경설정 팝업 (기어) | `screens/SettingsModal.tsx` · `ScreenChrome.tsx` |
| 6 | 다국어 틀 5종 | `i18n/index.ts` · `i18n/useLang.ts` |
| 7 | 그림 파이프라인 | `tools/build_backgrounds.py` (`npm run backgrounds`) |
| 8 | 회귀 9건 · 스모크 경로 갱신 | `client/test/backdrop.test.ts` · `tools/smoke_meta.ts` |

세션 후반에 기획자가 화면을 보고 **배경이 깨진다**고 지적해 고해상도 원본으로
갈아 끼웠다 (§4 「저해상도 원본을 그대로 썼다」).

## 2. 이 세션에서 정해진 것

- **게임 이름은 「만민의 삼국지」다.** 「삼국 약식 체스」는 프로젝트 이름으로만 남는다.
  화면에 뜨는 이름은 `i18n`의 `game.title` **한 곳**이라, 이름이 또 바뀌어도 한 줄이다.
- **다국어는 한국어 기준 + 영어·포르투갈어·일본어·중국어.** 문구는 별도 세션에서 받는다.
- **계정 생성·로그인의 실제 구현도 별도 세션.** 지금 「입장」은 곧바로 들어간다.
- **시간대 셋** — `07~16시` 낮 · `16~20시` 황혼 · `20~다음날 07시` 밤.
- **자리 그림 둘** — 도시 `Lv1~4`는 첫째 그림, `Lv5` 이상은 둘째. 나중에 더 잘게 나눈다.
- **넷째 칸(게시판)은 연결점 미정** — 이름을 `extra`로만 두고 자리를 잡아 뒀다.

## 3. 왜 그렇게 만들었나

### 배경 띠를 칸마다 잘라 굽는다 (CSS로 잘라 쓰지 않는다)

`background-position`으로 한 장에서 잘라 쓸 수도 있었다. 그렇게 하지 않은 이유 둘.

1. **칸 수가 원본마다 다르다** (3칸·4칸). 화면이 그것까지 알면 「몇 칸짜리인가」가
   CSS와 코드 두 곳에 적히고, 원본이 바뀔 때 한쪽만 고치게 된다.
2. 밤 그림 하나를 띄우려고 낮·황혼까지 받게 된다. 고해상도 원본은 한 장이 4MB에 이른다.

**칸 순서를 id로 바꾸는 표는 도구 하나뿐이다** — `build_terrain.py`가 한글 파일명을
`TerrainId`로 바꾸는 자리와 같은 결이다. 화면은 `backgrounds/{id}.jpg`만 안다.

### 시각을 읽는 것과 규칙을 갈랐다

`bandForHour(h)`가 규칙이고, 지금 시각을 넣는 것은 부르는 쪽이다. 전투 재현성과는
상관없지만 — **밤 그림은 밤에 접속해야 보인다.** 경계(7·16·20시)를 확인할 방법이
시각을 밖에서 넣는 것 말고는 없다. 룰 엔진의 `Date.now()` 금지와 같은 결이다.

배경은 **화면이 뜰 때 한 번** 정한다(`useState(currentBand)`). 매 렌더마다 새 `Date`를
만들면 자정에 걸친 판에서 그림이 깜빡이고, 어차피 한 화면에 머무는 동안 바뀔 일이 아니다.

### 번역이 없으면 한국어로 물러난다

`en`~`zh`가 비어 있는 채로 화면이 돌아야 한다. 그동안 **키 이름이 화면에 뜨면 안 되므로**
`t()`가 한국어 → 키 순으로 물러난다. 키를 한국어 표에서 뽑기 때문에(`Record<StringKey, …>`)
없는 키를 쓰면 타입 검사가 먼저 막는다.

라이브러리를 쓰지 않은 것은 이 프로젝트에 번들 단계가 없고 문구가 아직 수십 개라서다.
복수형·날짜 서식이 필요해지면 그때 바꾼다.

### 자리만 잡아 둔 스위치는 잠근다

`ID 기억`·`화면 모드`는 눌리지 않게 두고 왜인지 적었다. 눌리는데 아무 일도 일어나지
않으면 「고장인가」가 남는다. 반대로 아예 빼 두면 붙일 때 배치를 다시 잡게 된다.

**음소거는 환경설정에 넣었다** — HANDOFF에 「단추를 화면 어디에 둘지」가 물음으로
남아 있었고, 기어 팝업이 그 자리로 자연스럽다. `M` 키는 그대로다.

## 4. 밟은 지뢰 ★

### 띠를 등분해 자르면 옆 칸이 딸려 온다

`openBackground.png`는 804px이고 칸이 셋이라 268·536에서 자르면 될 것 같다.
**진짜 경계는 266·535였다.** 등분해 자른 낮 그림 오른쪽에 황혼의 주황 띠가 2px 남았고,
화면에서는 「오른쪽 끝에 이상한 줄이 있네」로만 보였다. 도구는 아무 말도 하지 않았다 —
14장을 다 굽고 「배경 14장」이라고 알렸다.

**스크린샷을 눈으로 보고서야 알았다.** 지금은 등분한 자리 언저리(±1%)에서 색이 가장
크게 튀는 열을 찾아 자르고, 옮겼으면 그 값을 찍는다. 안쪽 가장자리는 1px 더 깎는다.

```
· openBackground: 경계를 그림에서 찾았다 [268, 536] → [266, 535]
· mainBackground: 경계를 그림에서 찾았다 [300, 600] → [299, 599]
```

> `eachBackground.png`는 정확히 등분 자리에 경계가 있었다 — 찾아도 값이 안 바뀐다.
> **넷 중 하나만 맞았다면 「원본이 다 그렇겠지」로 넘어갔을 것이다.**

→ **교훈: 「넉 장을 넉 등분」처럼 당연해 보이는 것이 실제로는 안 맞을 수 있다.
그림 도구는 몇 장을 만들었는지만 알려 주지, 잘 잘랐는지는 알려 주지 않는다.**

### `.panel`은 이미 전투 화면이 쓰고 있었다

자리 화면의 판때기에 `.panel`을 붙였더니 `position: absolute`와 폭 `--board × 3/8`이
그대로 먹어 **오른쪽 아래에 좁게 붙었다.** CSS는 이름이 겹쳐도 오류가 없다 —
타입 검사도 테스트도 통과하고 화면만 이상하다. `.place-panel`로 바꿨다.

> 같은 자리를 예전에도 밟았다 — 「`#control`에 남은 `position: relative`가 `.panel`의
> `absolute`를 덮었다」(2026-08-12). **`.panel`이라는 이름이 두 번째로 사고를 냈다.**

→ **교훈: 전역 CSS에 흔한 이름(`.panel`·`.card`·`.bar`)을 새로 쓰지 않는다.**

### 저해상도 원본을 그대로 썼다 (같은 날 2차)

처음 받은 PNG는 폭이 804~900px이라 **칸 하나가 225~300px**이었다. 프레임이
320~700px이니 그대로 늘려 깔면 깨진다 — 기획자가 화면을 보고 곧바로 지적했고,
같은 그림의 고해상도 `{이름}_big.jpg`(2062~2912px)를 더해 줬다.

작은 스크린샷(480px)으로만 확인한 것이 문제였다. **480px 프레임에서는 300px짜리를
늘려도 눈에 잘 안 띈다** — 700px에서 봐야 드러난다.

→ **교훈: 배경처럼 화면을 꽉 채우는 그림은 프레임이 가장 클 때(700px)로 확인한다.**

바꾸면서 정한 것 둘.

- **원본은 `_big.jpg → _big.png → .png` 순으로 고른다.** 고해상도를 아직 못 받은
  사람은 예전 PNG로 굽고 화면은 그대로 뜬다. 어느 것으로 구웠는지 실행할 때마다 찍는다.
- **출력을 JPG로 바꿨다.** 칸 하나가 687×1536이라 PNG면 열넉 장에 25MB가 넘는다
  (지금 4.2MB). 확장자는 도구와 `screens/backdrop.ts` **두 곳이 함께** 바뀌어야 해서,
  도구가 **계획에 없는 출력을 지우도록** 했다 — 안 지우면 폴더에 PNG와 JPG가 섞이고
  화면은 새 것을 보는데 어느 게 살아 있는지 눈으로 못 가른다.

### 스모크가 옛 길을 그대로 걷고 있었다

첫 화면이 간판으로 바뀌고 `3v3`이 병영으로 들어가자 `smoke:meta`가 통째로 막혔다
(`.scr-new`가 없다 → 실패). 화면 골격을 바꾸면 **스모크의 경로도 함께 고쳐야 한다.**

고치면서 확인 항목을 늘렸다.

- 배경이 **띄우기로 한 그림**인가 (`background-image`의 파일명)
- 그 그림을 **실제로 받아오는가** (`fetch` → 200). 에셋이 없으면 404만 나고 화면은
  바탕색으로 물러나므로, URL만 보면 「붙었다」로 보인다.
- 도시의 세 간판이 **프레임 안에 있고 눌리는가** (`elementFromPoint`).
  그림 위에 %로 얹은 것이라 배치가 어긋나면 화면 밖으로 나간다 —
  「화면에 칠했으면 누를 수 있어야 한다」와 같은 자리다.

## 5. 구조

```
assets/Backgrounds/{이름}_big.jpg  띠 원본 (없으면 .png 로 물러난다)
  ↓
tools/build_backgrounds.py        띠 → 칸별 그림. 칸 순서 → id 의 유일한 자리
  ↓  public/backgrounds/{id}.jpg
screens/backdrop.ts               시각·도시 레벨 → 어느 id 인가 (순수 함수)
  ↓
screens/ScreenChrome.tsx          배경 + 「제목·기어」 헤더 + 환경설정 (배경 화면 넷의 공용 틀)
  ↓
TitleScreen · MainScreen · PlaceScreen
```

`i18n/index.ts`는 React를 모른다(`npm test`가 그대로 실행한다). React와 잇는 자리는
`i18n/useLang.ts` 하나다 — `audio/bgm.ts`가 화면을 모르는 것과 같은 결이다.

## 6. 확인

```
npm run backgrounds → 14/14 (4.2MB, 원본은 _big.jpg 넷)
npm run typecheck   → exit 0
npm test            → 214/214   (배경·다국어 회귀 9건 추가)
npm run smoke:meta  → 통과 — 간판·환경설정·도시 간판 좌표·배경 다섯 자리
npm run smoke:ui    → 통과 (전투 화면은 건드리지 않았다)
```

눈으로도 확인했다 — **프레임 700px**에서 간판·도시·병영·장터·궁궐(Lv1·Lv5)을 찍어
칸 경계에 옆 그림이 딸려 오지 않는지, 글자가 그림 위에서 읽히는지 봤다.
