## 1. 농지 화면 — 현황판 · 가운데 퇴치 판 · 바닥 명령 판

다른 건물(병원·대장간·랭킹 메뉴)과 같은 짜임이다 — 제목 바 밑이 현황판, 바닥이 명령 판.

```
┌ 현황 ─────────────────────────────────┐
│   농지 Lv3        │   시간당 군량 6     │   ← 두 칸
│ 파수꾼 배치 : 2/3 명  가후, 서황         │   ← 현황판에는 이름만
│ 도적단 출현 : 출현 (09:31 후 전투)      │
└──────────────────────────────────────┘
          [ 도적단 퇴치 ]                     ← 도적떼가 기다릴 때만, 화면 가운데
┌ [ 파수꾼 관리 ] ──────────────────────┐   ← 바닥
```

- 「도적단 출현」은 셋으로 접는다(`raidText.ts`의 `raidStateText()` · `RaidTone`) —
  **출현**(붉음: 대기 `09:31 후 전투` · 전투 중) · **약탈**(짙은 회색: 패배·항복, `군량 감소 N`) ·
  **퇴치 완료**(파랑: 승리). 규칙의 결말은 여섯이라 접은 것이고, **무승부는 약탈이 없어**
  「약탈 (군량 감소 0)」이 되지 않게 파랑 「물러감 (약탈 없음)」으로 갈랐다. 남은 시간은
  지정 표기대로 `mm:ss`(메인 단추는 `m:ss` 그대로).
- [도적단 퇴치]는 `assets/icons/button_alart.png`(금빛 두루마리) → `ui/btn-alert.png`.
  `build_ui.py`의 `FRAMES`에 더했다. 판 위아래 `margin: auto`가 현황판과 바닥 판 사이의
  빈 높이를 반씩 나눠 가져 화면 가운데에 선다.
- **바닥 명령 판은 두 걸음(홈 ↔ 파수꾼 관리)이 같은 판·같은 높이의 단추**다(`.frm-cmd`,
  단추 `height: 2.75rem`). 처음엔 [파수꾼 관리]에만 아이콘이 들어 키가 컸고 두 판의 안쪽 여백도
  달라 걸음을 옮길 때마다 판이 들썩였다(기획자 지적). 뒤에 아이콘은 빼달라는 지정으로 뺐다.
  `raid_play.ts`가 두 걸음의 판 위치·판 높이·단추 높이를 재서 같은지 본다.

## 2. 파수꾼 관리 — 부대 편집과 같은 줄, 단추는 토글

세 번 고쳐 여기서 멈췄다.

```
기물    이름        레벨  상태  병기구
[King] [S] 황충     Lv1   건강   —    [해제]
[Rock]  -                             [선택]
```

1. 첫 안(09-21)은 줄마다 두 줄 정보 + [보기][교체][빼기] 세 단추였다.
2. 지정(09-22) — **한 줄**에 기물 · 이름 · 레벨 · 상태(건강/부상) · 병기구, 오른쪽 끝에 단추.
   안내 문구(「농지 Lv1은 King 하나다…」·「부대에 편성된 장수는…」)는 뺐다.
3. 지정 — **[선택]/[해제]는 토글**이다. 빈 자리엔 [선택]만, 찬 자리엔 [해제]만. 다른 장수로
   바꾸려면 [해제] 뒤 [선택]. 이름 칸의 사진은 **등급 배지**로 바꿨다(장수 일람 표의
   `.ofc-row .gr`와 같은 값·같은 색).

- 줄 수 = 농지 레벨(`guardSlots`). 빈 줄의 기물은 King → Rock → Queen → Bishop → Knight
  (부대 편성의 처음 포지션과 같은 차례)에서 아직 안 쓴 것. King 줄은 언제나 맨 위.
- [선택]은 **부대 편집·대장간 지급과 같은 장수 일람 팝업**(`OfficerPickModal`)이다 — 줄을
  누르면 장수 카드(상세)가 뜨고, 체크 → [선택하기]. 파수꾼 줄을 눌러도 같은 카드가 뜬다.
- **부대에 든 장수는 목록에서 빼지 않고 흐리게 못 고른다** — `OfficerListPanel`의 고르기 모드에
  `blocked?: (officer) => string | null`를 더했다(`PickMode`). 부대 편집·대장간은 안 넘기므로
  동작이 그대로다.
- 규칙이 거부하면(King보다 Rock을 먼저 등) **팝업을 닫고** 이유를 줄 밑에 띄운다 — 팝업이
  그 자리를 가려서다. 빈 자리에서 다른 자리의 파수꾼을 고르면 그 장수가 **옮겨 온다**. 그래서
  이미 King인 장수를 빈 Rock 자리로 고르면 King이 비어 거부된다(규칙대로).
- 쓰지 않게 된 문구 15개(옛 고르기 팝업·안내문)는 10개 언어 파일에서 지웠다.

## 3. 방어전 결과 화면

어두운 기본 결과 화면이던 것을 농지와 같은 틀로 — 농지 배경 · 청동 명패 「도적떼 방어전」 ·
현황판(판정 문구를 색으로, `남은 도적 : N 명` · `약탈당한 군량 : N/없음`) · 이겼을 때만 보상 판
([군량][재료] 두 칸 + **장터 뽑기와 같은 등급 액자**의 카드) · 바닥 [농지로]/[메인으로].
나가는 문이 둘이라 뒤로 화살표는 없다. `data-screen="raidResult"`는 판 전체를 감싼
`.rrs-frame`에 둔다 — `ScreenChrome`이 데이터 속성을 안 받는다.

이긴 화면은 스크립트로 도적떼를 실제로 이겨야 나와서, **가짜 승리 계정으로 실제 컴포넌트를
그리는 임시 Vite 페이지**(`_preview.tmp.html`)로 찍어 봤다(지웠다). 로그인·서버 없이 결과
화면만 보는 데 쓸 만하다.

## 4. 도적떼 알림 · 메인의 [전투하기]

```
도적 규모 :      1부대 (도적 2명)
아군 :           허저, 능통
항복 시 피해 :   군량 8 약탈
        남은 시간 0:30
[ 항복 ]        ← button_forcedcancel.png (붉은 판)
[ 전투 준비 ]   ← button_alart.png (금빛 두루마리)
[ 지금 전투 ]   ← button_primary.png (옥색 판) — 파수꾼이 없으면 [파수꾼 배치]
```

- 항복 시 피해는 **서버가 항복을 정산할 때 부르는 `raidLoot()` 그대로**다(화면이 다시 적지 않는다).
- 마감 1분 전 알림도 같은 본문·같은 단추 셋이다(예전엔 [지금 전투]·[항복] 둘). 「약탈당했다」
  팝업의 [확인]도 옥색 판.
- 세 판 모두 9분할이고 높이를 못 박았다. 붉은 판과 옥색 판은 같은 상자로 구운 짝이라
  (`FRAME_CROP_LIKE`) 9분할 값도 같다. 판이 좁아 「1부대 (도적 / 2명)」로 접혀 팝업을 넓혔다.
- 메인의 [전투하기 m:ss]는 **도시 이름과 한 줄, 오른쪽 끝**에 금빛 두루마리로 크게. 이름이
  길면 이름 쪽이 말줄임이다. 전투가 걸려 있으면 같은 자리가 붉은 판의 [항복].
- 예전 본문 문장 4개(`raid.alert.body` 등)는 지웠다.

## 5. 버그 둘

### 방어전 위에 「도적떼 출몰!」이 늦게 떴다

[지금 전투]를 누르면 「이미 전투가 시작됐다」고 하고 안 닫혔다. **시작 요청이 두 번 나갔다** —
첫 요청이 판을 열었고, 둘째가 `raid.started`로 거부됐는데 그 실패 처리가 **이미 넘어간 방어전
위에** 알림을 열었다. 새로 만든 농지 [도적단 퇴치]에 두 번 누르기 막이가 없었다(더블클릭이
유력). 고친 것:

- `fightRaid()`를 **ref로 한 번만** 보낸다(`raidBusy` state는 다음 렌더에야 단추를 막는다) ·
  농지 단추도 요청 중에 막는다(`fightBusy`).
- 실패가 도착했을 때 **지금 화면이 판 안이면 알림을 안 연다** — 클로저의 `screen`은 누른
  순간의 값이라 `screenRef`로 묻는다.
- 알림은 `NO_ALERT` 화면에서 **아예 그리지 않고**, 그 화면에 들어가면 남은 알림을 거둔다.
  (예전엔 `NO_ALERT`가 「띄울지」를 정하는 effect만 막고, 이미 켜진 알림의 **그리기**는 안 막았다.)

### 1대1이면 초상화 한 장이 카드 줄을 다 채웠다

카드 줄이 인원으로 폭을 나눴다(`repeat(--cols, 1fr)`). 이제 **칸은 언제나 다섯 자리 폭**이고
실제 인원만큼 가운데에 놓는다(`.strip-slots`). 3v3 대전의 카드도 5v5와 같은 크기로 좁아졌다.

## 6. 다국어

- 농지 화면 · 파수꾼 · 도적떼 알림 · 결과 화면 문구 72개 + 파수꾼 규칙의 거부 이유
  (`reason.raid.*`) 14개 + 결과 화면이 쓰는 보상 칸(`result.*`) 5개 = **91개를 8개 언어**로
  채웠다(영어는 농지 쪽이 이미 있어 `result.*` 5개만). 언어마다 에이전트 하나씩 나눠 맡겼고,
  **각 언어 파일에 이미 있는 용어를 먼저 읽게** 했다.
- 합치기 전에 스크립트로 본 것 — 자리표시자(`{n}` 등)가 한국어와 같은가 · 빠진 키 ·
  한글이 남았나. 몽골어·스페인어·일본어로 농지 화면을 400px에서 찍어 넘침을 봤다.
- 스페인어·포르투갈어(BR·PT)는 파일이 레벨을 `Nv`로 적어(병원 `Hospital Nv3`) 농지도 `Nv`로.
  「재료」는 장터가 파는 건축 자재와 같은 것이라 각 언어의 장터 단어를 따랐다.
- 알림 본문 여섯 줄(규모·아군·피해)은 뒤에 따로 직접 번역해 넣었다.
- ⚠ 영어의 `result.*`는 이번 5개만 있어, **일반 대전 결과 화면**을 영어로 보면 보상 칸만 영어다.
- 원본에 원래 있던 흠(이번에 안 건드림) — 포르투갈어 일부(병원·도시)의 악센트 누락, 이탈리아어의
  「장수」 용어 혼용(generale/ufficiali). 원어민 검수 때 볼 것.

## 7. 확인하면서 배운 것

- **줄마다 제 그리드인 표에서 한 칸이라도 `auto`면 열이 어긋난다.** 파수꾼 관리의 단추 칸을
  `auto`로 두었더니, 단추가 없는 **머리줄만** 이름 칸이 넓어져 레벨·상태·병기구 제목이 밀렸다.
  부대 현황(`.sqv-row`)이 칸을 전부 못 박는 이유가 이것이다 — 머리줄은 내용이 다르니까.
- **첫 스크린샷에서 그림이 없다고 곧장 CSS를 의심하지 않는다.** 스페인어 화면에서 칩 단추의
  옥색 판이 안 보여 계산 스타일을 재 보니 멀쩡했다 — 그림이 아직 안 받아진 순간에 찍었을 뿐이다.
  잠깐 기다려 다시 찍으면 떴다.
- **스모크가 로그인에서 멈추면 코드보다 바깥을 먼저 잰다.** 로그인은 200인데 계정 GET이 안 와
  멈췄고, DB 한 번 묻는 데 **12.8초**가 걸렸다(Supabase 쪽 일시 지연 — 곧 2~4초로 돌아왔다).
  코드는 그대로 둔 채 다시 돌려 완주했다.
- **테스트가 고른 장수가 이미 다른 자리에 서 있을 수 있다.** 장수 일람의 「첫 줄」을 Rock에 세우면
  그 장수가 이미 King이라 옮겨 오며 King이 비었다 — 규칙은 맞게 거부했고 테스트가 틀렸다.
