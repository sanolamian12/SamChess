# 2026-09-02 — 장수 이름 다국어화 (랭킹 패널 등 명단 전 화면 연결)

> 이 문서는 **한 대화 세션의 기록**이다. 프로젝트의 현재 상태와 규칙은
> [`HANDOFF.md`](../HANDOFF.md)와 [`Design/GDD.md`](../Design/GDD.md)가 정본이며,
> 여기는 "무엇을 왜 그렇게 정했는가"와 "어디서 넘어졌는가"를 남긴다.

## 왜 이 작업인가

사용자가 메인 화면 → 랭킹 화면 → 장수 랭킹에서 장수 정보 패널을 띄워 보니
(스크린샷: 몽골어 UI에서 「장포」 카드) **인물 열전(서사)은 이미 번역되어
보이는데 장수 이름만 한국어 그대로** 나오고 있었다. `courtesyName`/`story`는
[2026-08-27 세션](2026-08-27_랭킹화면_장수카드_인물서사연결.md)에서 이미
`sam_people.csv`의 열 언어 열을 연결해 뒀는데, 정작 **이름 자체**(`name_{lang}`
열)는 같은 CSV에 처음부터 있었음에도 한 번도 배선되지 않았던 것 — 그 CSV를
쓰면 장수 이름도 언어별로 낼 수 있으니 적용해 달라는 요청이었다. 범위는 그
패널 하나가 아니라 **장수 명단을 띄우는 모든 곳**.

## 한 일

### 1. 데이터 배선 — `courtesyName`/`story`와 같은 패턴을 이름에도

- `tools/extract_data.py`의 `extract_bios()`/`attach_bios()`가 `sam_people.csv`의
  `courtesy_{lang}`·`bio_{lang}`을 읽던 것과 나란히 `name_{lang}` 열도 읽어
  `nameI18n`으로 붙이게 확장했다. `name_ko`는 담지 않는다 —
  `OfficerData.name`이 이미 그 값이고(id·Map 키로 쓰는 기준 언어), 두 자리에
  같은 값을 따로 관리하지 않기 위해서다.
- `packages/data/src/index.ts`의 `OfficerData`에
  `nameI18n?: Partial<Record<StoryLang, string>>` 필드 추가. `name: string`은
  그대로 두어 `officerByName`·`officerById` 같은 조회 키, id 생성
  (`romanize(name)`) 등 기존 배선을 하나도 안 건드렸다.
- `npm run extract` 재실행 → `[열전] 260/260명 연결(열 언어)` 로그 그대로,
  장포(張苞) 기준 실측: `nameI18n: { en: "Zhang Bao", ja: "張苞", zh_Hant: "張苞",
  zh_Hans: "张苞", mn: "Чжан Бао", ... }` 정상 생성 확인.

### 2. 화면에서 고르는 자리 — `pickOfficerName`

- `packages/client/src/i18n/story.ts`에 `pickStory()`와 같은 규약으로
  `pickOfficerName(officer)` 추가 — `nameI18n?.[currentLang()] ?? officer.name`
  (한국어로 물러난다). `courtesyName`/`story`와 다르게 **빈 문자열로 물러날
  자리가 없어야 해서**(이름은 카드 제목·목록 어디서든 항상 떠야 한다) 별도
  함수로 뒀다.
- 화면 쪽 상당수가 `@samchess/meta`의 행 타입(`OfficerRankRow`,
  `SquadMemberRow` 등)을 쓰는데, 이 타입들은 `OfficerData`를 그대로 들고
  있지 않고 **`officer: OfficerId` + 그때 뽑아 둔 평평한 `name: string`**만
  갖고 있었다(meta는 언어를 모른다는 기존 원칙 그대로). 그래서
  `pickOfficerNameById(id, fallback)`도 함께 추가해 — 화면이
  `officerById.get(row.officer)`로 다시 찾아 `pickOfficerName`을 걸고, id가
  안 걸리면(있을 수 없지만) 원래의 평평한 이름으로 물러난다. `packages/meta`
  자체는 손대지 않았다 — "meta는 순수 함수, 언어는 클라이언트만 안다"는
  원칙을 유지하기 위해서다.

### 3. 적용 범위 — 명단을 띄우는 모든 곳

첫 라운드는 서브에이전트에게 위임해 `packages/client/src` 전체에서
"OfficerData 유래 `.name` 표시" 후보를 찾아 `pickOfficerName`으로 바꾸게
했다(스킬·책략·부대 이름 등 **officer가 아닌 `.name`**은 건드리지 말라고
명시). 결과를 받은 뒤 직접 diff를 훑어 검증·정리했다:

- **전투 화면**: `ui/cardStrip.ts`(유닛 카드), `ui/hud.ts`(상단 현재 차례),
  `ui/controlModal.ts`(커맨드 패널 5곳 — 대상 이름, 스킬 캐스터 툴팁,
  패널 헤더, 고유기술 프롬프트, "상대가 ⟨X⟩를 제어 중"), `ui/statusChips.ts`
  (제어 배지·오라 소유자), `ui/inspectPanel.ts`(초상화 alt·이름 줄),
  `ui/eventText.ts`(전투 로그 문장), `battle/BattleScene.ts`(고유기술 시전
  배너의 캐스터 이름 — `SkillFx.play()`가 실제로 화면에 찍는 문자열임을
  확인하고 반영).
- **메타 화면**: `OfficerRankingScreen.tsx`(문제의 그 랭킹 패널 — 목록 행·
  카드 제목 둘 다), `OfficerListScreen.tsx`, `OfficerDetailScreen.tsx`,
  `LevelUpScreen.tsx`, `RecordsScreen.tsx`, `ResultScreen.tsx`,
  `MarketScreen.tsx`, `MatchScreen.tsx`(대전 상대 명단),
  `SquadEditScreen.tsx`·`SquadDeployScreen.tsx`(편성/배치 중 장수 이름),
  `SquadListScreen.tsx`·`SquadRankingScreen.tsx`(부대원 명단).
- **일부러 안 건드린 것**: `squad.name`(부대 이름), `skill.name`/`def.name`
  (고유기술·책략 이름), `screen.name`(화면 전환용 내부 enum),
  `battle/visualEffect.ts`의 `officerName()`(주석상 로그·디버그 전용, 실제
  화면 호출 없음 확인) — 전부 officer 이름이 아니거나 사용자에게 안 보이는
  자리라 그대로 뒀다.

### 4. 정리 — 헬퍼 도입 뒤 남은 중복 제거

서브에이전트가 낸 1차 결과는 `@samchess/meta` 행 타입을 쓰는 5개 파일
(`OfficerListScreen`·`OfficerRankingScreen`·`SquadEditScreen`·
`SquadRankingScreen`)에서 매번
`(() => { const o = officerById.get(row.officer); return o ? pickOfficerName(o) : row.name; })()`
같은 즉시실행함수(IIFE)를 반복하고 있었다. 위 §2의 `pickOfficerNameById`를
이때 추가해 이 반복을 한 줄 호출로 정리하고, 그 결과 더는 안 쓰이게 된
`officerById`/`pickOfficerName` import를 파일별로 확인해 걷어냈다
(`MatchScreen.tsx`·`SortieScreen.tsx`·`SquadListScreen.tsx`도 같은 패턴이라
함께 정리).

## 이번 범위 밖 (다시 볼 자리)

- **브라우저에서 실제로 언어를 바꿔 가며 화면을 눈으로 확인하지 않았다** —
  `npm run typecheck`/`npm test`는 통과했지만 이 프로젝트의 원칙("UI 변경은
  브라우저에서 먼저 켜 본다")대로 실제 화면 검증은 아직이다. 다음 세션에서
  `?seat=` 없이 그냥 켜서 언어 설정을 바꿔 가며 랭킹·전투·부대 화면을 훑어
  보는 게 좋다.
- **`assets/Languages/sam_people.csv`에 없는 장수**(있다면)는 `nameI18n`이
  안 붙어 한국어로 물러난다 — 지금은 260/260 전원 연결이라 공백이 없지만,
  다음에 장수가 늘면 `npm run extract` 로그의 `[열전]` 줄로 바로 확인된다
  (2026-08-31 세션이 남긴 것과 같은 패턴).
- **커밋 전** — 이번 세션 변경분(`tools/extract_data.py`·
  `packages/data/src/index.ts`·`packages/data/generated/officers.json`·
  `packages/client/src/i18n/story.ts` 및 위에 나열한 20여 개 화면/UI 파일)은
  아직 커밋하지 않았다. `git status --short`로 확인 가능.

## 새 대화로 이어갈 때

- 장수 이름 다국어화는 **데이터·타입·화면 배선 기준으로 완결**됐다 —
  `pickOfficerName`/`pickOfficerNameById` 두 헬퍼가 유일한 진입점이고, 새
  화면에서 장수 이름을 띄울 땐 이 둘 중 하나만 부르면 된다(`officer.name`을
  직접 찍지 않는다).
- 아직 커밋 전이니, 다음 세션(또는 이번 세션 후속)에서 사용자가 원하면
  커밋하고, 그 전에 브라우저로 실제 언어 전환을 한 번 확인하는 걸 권한다.
