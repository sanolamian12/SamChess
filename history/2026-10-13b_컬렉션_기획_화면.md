# 컬렉션 — 기획 117개 · 엑셀 · 목록과 두루마리 화면 (2026-10-13 b)

같은 날 앞 세션(`2026-10-13_입성로딩_방어전결과두루마리_대자보.md` §7)이 넘긴 **컬렉션**을 기획부터 화면까지 이었다.
기획자와 문답으로 규칙을 정하고, 100 → 150개 후보를 뽑아 기획자가 **117개**를 골랐고, 엑셀 · 라벨 그림 의뢰서 ·
상세 설명을 만든 뒤, 기획자가 받은 그림 61장으로 **목록 · 두루마리 · 칸 등록**까지 붙였다. 전투 · 도시 효과와 순위는 다음 세션이다.

## 1. 확정 규칙 (기획자)

| | 규칙 |
|---|---|
| 항목 | 타이틀 · 한자 · 달성 조건 · 설명 · 상세 설명 · 점수 · 효과 |
| 칸 | 조건 하나가 칸 하나 — 카드 칸은 장수 카드, 병기 칸은 대장간 병기, 아이템 칸은 시장 아이템 |
| 등록 | **칸마다 하나씩 · 부분 등록 가능 · 되돌릴 수 없다**. 「등록하시겠습니까?」 |
| 장수 카드 | **여분이 1장이라도 있으면** 등록 · 여분만 쓴다(본체는 안 빠진다). **한 컬렉션에 같은 장수 카드는 1장뿐**(3차) |
| 완성 | 모든 칸이 차야 점수 · 효과. 부분 등록은 아무것도 없다 |
| 효과 | 무력 · 지력 · 통솔 · HP · MP · AT · 고유기술 SP · 진영 SP · 도시 운영. **크기는 작게, 같은 장수×같은 능력치는 한 컬렉션에서만** |
| 도시 효과 | 넣는다 · **금화는 건드리지 않는다** |
| 대장간 | 종류당 상한 = 만든 수 − 컬렉션에 넣은 수 |
| 공개 | **처음부터 117개를 다 보여 준다**(이 세션 마지막에 확정). 「점점 나타나는」 느낌은 달성조건순 정렬(+ 장차 「새로 채울 수 있음」 표시)이 낸다 |
| 상세 화면 | 고유기술과 같은 **두루마리**, 흰 종이에 글, 라벨 그림은 종이 하단에 **워터마크처럼** |

## 2. 목록이 만들어진 길

1. 100개 초안(시대 8장 + 열전) — 「같은 장수×같은 능력치 중복 0」을 스크립트로 검사하며 짰다.
2. 150개로 확장 — 열전 94~100 제외, 덜어 냈던 17개 복원 + 새 사건 40개(「계륵」 포함).
3. 기획자가 **117개**를 고름 → **카드는 모두 1장**으로. 비용 폭이 4~68로 좁아져 등급 경계를 다시 잡고
   (일반 <15 · 희귀 15~27 · 영웅 28~41 · 전설 42~59 · 천하 60+, 점수 50/100/200/300/500, 만점 17,950),
   SP −1 · 진영 SP를 단 것은 **이야기에 실제로 선 인물 · 물건을 더해** 전설로 올렸다(예: 헌제의 동귀에 이각 · 곽사 · 순욱).
   더할 사람이 없는 셋(영웅론 · 고육지책 · 고평릉)은 능력치로 내렸다. 능력치 상한: 등급별 1/2/2/3/3, 조건이 걸리면 +1, HP 2 · MP 1 천장.
4. 고증 — 「십승십패론」은 곽가(『부자』, 순욱은 따로 사승론), 「서서의 어머니」의 정욱 · 가짜 편지는 연의에만,
   「既生瑜 何生亮」을 64번 설명에 원문으로. 상세 설명 117개(59~108자)를 쓰고 사실관계 다섯 곳을 바로잡았다.

## 4. 밟은 것

- **되접기가 새 필드를 버렸다** — `migrateProfile()`은 아는 필드만 담아, 서버가 읽는 순간 `collection`이 사라졌다. 단위 테스트는 되접기를
  안 지나 못 잡았고 `collection_ux.ts`가 잡았다. `readCollection` + 「JSON 왕복 후에도 남는가」 테스트를 달고 CLAUDE.md에 규칙으로 적었다.
- **보관함 장수의 「여분」** — 보관함 장수는 본체가 `cards` 한 장이라 그것까지 내면 장수가 사라진다. `spareCards()`가 한 장을 뺀다.
- **상태 갱신 함수 안에서 부모 상태를 바꾸면** React가 「렌더 중 다른 컴포넌트 갱신」을 경고한다 — 두루마리 칸 번호를 ref로 셌다.
- **떠 있는 계정 서버는 옛 코드다** — 새 경로를 시험하려고 8797에 따로 띄우고 브라우저 요청만 돌렸다(`API_PORT`). 기획자의 8787은 그대로.
- `smoke_meta`의 「[컬렉션 보기]는 꺼져 있다」 고정을 「켜져 있고 들어갔다 돌아온다」로 바꿨다.
- 셸 heredoc이 긴 한글 스크립트를 자르는 일이 잦았다 — 파일로 써서 돌렸다.

## 6. 아직 안 된 것 (다음 세션들)

1. **전투 효과** — 완성한 컬렉션의 능력치 · 고유기술 SP · 진영 SP를 판에 싣는다. `toRosterEntries()`가 장수마다 평평하게 싣고(`RosterEntry`에
   보너스 칸), 조건(함께 참전 · 적진에)은 `createBattle`이 판 시작 때 한 번 판정. **판 시작 시각 이전에 완성된 것만**(태학 `doneAt`과 같은 함정 —
   서버 재생 · 온라인 정산이 같은 값을 써야 한다). 진영 SP +1은 여럿 켜져도 +1. 전투력(`battlePower`)에는 안 넣는다.
2. **배지** — 상태이상 배지와 자리를 나눠 초상화 가장자리 · 이름 칸 주변에. ① 기술 변형(SP 6 → 5, 숫자는 엔진이 낸다) ② 발동 효과(시작 연출 + 장수 팝업). 상대에게도 보인다.
3. **도시 효과** — 군량 충전 · 최대 군량 · 제조 · 치료 · 연구 시간 · 도적떼 약탈률 · 응전 시간. 각 계산 함수가 완성한 컬렉션의 합을 읽게.
4. **서버 순위** — `/ranking/mine`에 컬렉션 순위 한 칸, 대자보 · 상단 패널의 「—위」를 채운다. 점수는 `collectionPoints()`.
5. **다국어** — 문구 키 39개 아홉 언어 · 타이틀 · 한자는 그대로 · 설명 · 상세 설명 · 효과 글(엑셀에 언어 열을 붙이는 장비 해설과 같은 결).
6. **라벨 그림 56장** — 받으면 `npm run collections`.
7. (선택) 목록에 「새로 채울 수 있음」 표시 · 컬렉션 id를 타이틀과 떼기(엑셀 id 열) · 제목 글꼴에 없는 한자(兔).
