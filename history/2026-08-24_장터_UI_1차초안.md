## 왜 이 작업인가

트랙 9(상점/가챠)는 "상점 UI는 기획자가 별도로 준비하기로 했다"는 전제로
경제 로직·그림만 먼저 굳혀 뒀다. 이번 세션 시작 시점에 사용자가 카드 프레임
6종(`frame-{s,a,b,c,d,e}.png`)을 추가로 받아 두고, "지금까지 확보된 그림만으로
UI를 한 번 만들어 보고, 그걸 보면서 고쳐 나가자"고 방향을 바꿨다 — 정식
목업을 기다리지 않고 **동작하는 초안을 먼저 만들어 피드백을 받는 쪽**을
택한 것이다. 그래서 이번 결과물은 "임시 목업"이 아니라 실제로 골드가 빠지고
카드가 지급되는 화면이다 — 이 저장소가 지금까지 다른 화면도 전부 그렇게
만들어 왔다(정적 시안 없이 바로 붙여서 확인).

## 설계에서 새로 정한 것 (이번 세션에서 나온 판단)

- **골드 차감·카드 지급은 화면이 아니라 `buyGacha()`가 한다.** 「화면이
  판정하지 않는다」는 이 저장소 전체의 원칙을 상점에도 그대로 적용했다 —
  `MarketScreen`은 `canAffordGacha()`로 버튼을 잠그고, 눌리면 `buyGacha()`를
  부를 뿐이다. 최종 골드 검증도 화면이 아니라 그 함수 안에서 다시 한다
  (버튼이 잠겨 있어도 호출 경로가 하나 더 있으면 그쪽에서 다시 확인해야
  한다는 뜻 — 전투 UI가 `validate()`를 다시 묻는 것과 같은 결).
- **장터를 별도 최상위 화면으로 뗐다.** 병영(`Barracks`)처럼 `PlaceScreen`
  안에 통째로 접어 넣는 방법도 있었지만, 장터는 재화 바·모달·구매 흐름이
  있어 궁궐(`CityScreen`이 별도 화면인 것)과 같은 무게라고 판단했다 — 내용이
  단추 두어 개뿐인 병영과는 다르다.
- **10연은 개봉 연출을 건너뛴다.** 단발처럼 카드 열 장을 순서대로 연출하면
  한 번 뽑는 데 너무 오래 걸린다 — 결과를 바로 격자로 편다. **이건 확정이
  아니라 사용자 피드백을 받을 1순위 항목으로 코드 주석에도 남겼다**(스킵 사유가
  아니라 "다시 볼 자리"라는 뜻).
- **카드 정리·재설계·금화팩은 화면에 자리는 두되 전부 잠갔다.** 셋 다 값을
  차감하는 실제 규칙이 없다 — 카드 정리는 `economy.json`에 교환 비율(`recycle`)만
  있고 그걸 계정에 반영하는 meta 함수가 없고, 재설계는 이미 `LevelUpScreen`에
  있는 기능을 장터에 새로 만들면 같은 기능이 두 곳에서 어긋날 위험이 있고,
  금화팩은 결제 수단이 아직 안 정해졌다(HANDOFF §7). **잠그면서 왜 잠겼는지
  화면에 적었다** — 「눌리는데 아무 일도 없으면 「고장인가」가 남는다」(CLAUDE.md)를
  다시 반복하지 않기 위해서다.
- **재설계 가격(`market.respec.sub`)은 숫자를 옮겨 적지 않고 `RESPEC_GOLD`를
  그대로 불렀다.** 처음 초안에는 `{ gold: 10 }`을 하드코딩했다가, 리뷰 중
  "기획 수치를 GDD·코드에 옮겨 적지 않는다"는 이 저장소의 반복된 원칙을
  스스로 어긴 걸 알아차려 바로 고쳤다(§4.3·§5·가챠 슬롯 수가 겪은 것과 같은
  종류의 실수를 또 만들 뻔했다) — `packages/meta`의 상수를 참조하는 값은
  전부 그 출처를 그대로 부르게 다시 확인했다.

## 코드를 쓰며 확인한 것 · 검증

- **`npm run market`으로 프레임 6장을 실제로 구운 뒤, 브라우저에서 직접
  써 봤다.** 로그인 없이 화면을 확인할 방법이 없어서(Supabase 이메일
  로그인이 정본이라 계정 생성 없이는 장터까지 못 간다), **세션 동안만**
  `App.tsx`의 초기 상태를 가짜 프로필(`createProfile()` + 금화 250)로
  바꿔 띄우고 Playwright로 스크린샷을 찍은 뒤 **원래대로 되돌렸다** — 커밋에는
  전혀 남지 않는다. 단발 뽑기(개봉 연출 → 액자 카드)와 10연 뽑기(격자
  10장, S·A·E 등급이 섞여 나왔다) 둘 다 실제로 골드가 깎이고 카드가
  들어가는 것까지 확인했다.
- **`npm run extract && npm run typecheck && npm test`** — 444/444
  통과(가챠 구매 회귀 3건 포함, 기존 441건 무회귀).
- **밟은 것 — 비밀번호가 터미널 출력에 그대로 찍혔다.** `.env`를 확인하려고
  `grep -v "KEY\|SECRET\|PASSWORD"`로 민감한 줄을 걸렀는데, `SUPABASE_DB_URL=...`
  줄은 그 세 낱말 중 어느 것도 포함하지 않아 **걸러지지 않고 비밀번호가
  섞인 연결 문자열이 그대로 출력됐다.** 필터가 값이 아니라 **줄에 그 낱말이
  있는지**만 보기 때문에, 변수 이름이 필터 목록에 없으면 그냥 새어 나간다.
  사용자에게 바로 알렸고 필요하면 DB 비밀번호를 새로 돌리라고 안내했다.
  → **교훈: 민감한 파일을 훑을 때 "위험해 보이는 낱말을 걸러내는" 방식은
  변수 이름 목록이 불완전하면 조용히 뚫린다.** `.env` 같은 파일은 애초에
  통째로 출력하지 말고, 필요한 키 하나만 정확히 짚어 읽어야 한다(`grep -v`로
  나머지를 가리는 대신 `grep "특정키="` 하나만 찾는 방향이 더 안전했다).

## 이번 범위 밖

- **카드 정리(recycle) 실제 반영** — `economy.json`의 교환 비율을 계정에
  적용하는 meta 함수가 없다. 만들 때 기획자와 교환 규칙(카드 10장 → 재료
  몇 개, 등급별 점수를 어떻게 쓸지)을 다시 확인해야 한다.
- **결제 연동** — 금화팩 3종은 가격만 있고 살 수 없다. 모의 vs 실 PG가
  아직 결정 안 됐다(HANDOFF §7).
- **다국어** — `market.*` 키는 한국어만 채웠다. 나머지 화면과 같은 상태다.
- **카드 액자 안 초상화 위치(`%` 값)의 정밀도** — S·E 프레임으로만 눈으로
  맞췄다. A·B·C·D 프레임은 테두리 두께가 조금씩 달라 다시 봐야 할 수 있다.

## 새 대화로 이어갈 때

- 사용자가 실제로 화면을 보고 피드백을 준 뒤 고치는 단계다 — 이 문서는
  "1차 초안이 이렇게 동작했다"까지만 기록한다. 피드백 반영은 다음 히스토리
  문서로 남긴다.
- `MarketScreen.tsx`·`gacha.ts`의 다시 볼 자리는 주석에 이미 표시해 뒀다
  (10연 애니메이션 생략, 카드 액자 크롭 좌표).
