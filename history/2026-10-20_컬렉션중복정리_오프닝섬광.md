## 1. 컬렉션 구성원 중복 — 엑셀을 직접 고쳐 정리 (커밋 `32365e7`)

기획자가 「안량과 문추」와 「관도대전」의 구성원이 순서만 다르고 같다는 것을 찾았다. 전부 훑으니 세 쌍이었다
(37↔38 · 55↔75 · 96↔106). 어제 후보 · 비용 영향을 정리했고, 오늘 기획자가 엑셀을 직접 고치라고 해서 고쳤다
(이 저장소에서 `docs/*.xlsx`는 읽기 전용이 원칙 — 이번만 기획자 지시).

| 컬렉션 | 구성 | 비용 · 등급 |
|---|---|---|
| 23 여포, 백문루에 묶이다 | 여포 · 진궁 · 후성 · **위속** · 송헌 | 20 · 희귀 100 |
| 37 안량과 문추 | **안량 · 문추** | 12 · 일반 50 |
| 55 책상을 베다 | 손권 · **주유** · **노숙** | 30 · 영웅 200 |
| 75 아들을 낳으려면 손권처럼 | 손권 · 조조 · **유종** | 22 · 희귀 100 |
| 106 아홉 번의 북벌 | 강유 · **요화** | 14 · 일반 50 |

- **어떻게 고쳤나** — 행을 끼우고 지우면(openpyxl은 수식 속 행 번호를 안 옮긴다) 아래 수식이 전부 어긋난다. 그래서 「칸」 시트 A~F 값을
  새 목록으로 위에서부터 다시 쓰고, G~I 수식은 행 번호에 맞춰 다시 적었다. 쓰기 전에 404행의 수식이 모두 같은 꼴인지 확인했고(다르면 멈춘다),
  F열(등급)은 `officers.json`에서 채웠다. 서식 · 데이터 검증(종류 목록)은 셀에 그대로 남는다.
- **확인** — 백업과 대조해 바뀐 칸이 정확히 여덟(23-4 · 37-3~5 · 55-2~3 · 75-3 · 106-2), 나머지 다섯 시트는 같다. 수식 칸의 계산해 둔 값은
  지워지지만 추출기는 A~E만 읽고 비용 · 등급을 다시 잰다(엑셀은 열 때 다시 계산한다). `npm run extract` 결과가 표와 같고 바뀐 생성물은 `collections.json` 하나.
- **다시 안 생기게** — `extract_data.py`에 「구성원(종류 · 대상 · 수)이 같은 컬렉션이 둘 이상이면 추출 실패」. 고치기 전 엑셀로 돌리면 세 쌍을 모두 잡고 종료 코드 1이다.
- **밟은 것** — `docs/컬렉션.xlsx`를 「git 밖」으로 잘못 알았다. `git ls-files`가 한글 경로를 이스케이프해 `grep 컬렉션`에 안 걸린 것이다 — 실제로는 추적되는 파일이다.
  또 검사가 「안 문다」고 착각할 뻔했다 — 추출기를 직접 돌린 출력이 콘솔 인코딩(cp949)으로 깨져 `grep`에 안 걸렸고, 두 실행의 출력이 섞여 「통과」만 보였다.
  **검사가 무는지는 종료 코드로 본다.**

## 2. 가입 오프닝 — 장수 등장 섬광을 그림으로

어제 장수가 판 위에 「팡」 나올 때 흰 원형 빛(CSS 그라데이션)을 넣었는데, 기획자가 원하는 번쩍임을 그림으로 줬다(`assets/icons/blink.jpg` — 검은 바탕에 빛줄기가
사방으로 뻗는 별빛, 2752×1536).

- **굽기** — `npm run ui`(`build_ui.py`의 `GLOWS`)가 **밝기 = 투명도**인 PNG(`ui/glow-blink.png`, 폭 640, 285KB)로 굽는다. 알파 = RGB 최댓값,
  색 = 원래 색 ÷ 알파. 검정을 걷는 판때기 방식(`knock_out_black`)은 빛줄기의 옅은 끝을 자르거나 회색 테를 남기고, `mix-blend-mode: screen`은
  애니메이션이 만든 쌓임 맥락 안에서 바탕이 비어 **검은 네모가 그대로 남는다**. 붉은 판 위에 얹어 검은 테가 없는 것을 확인했다.
- **세 겹** (기획자와 두 번 주고받아 정했다)
  1. **터지는 별빛**(`.ngo-member::before`) — 그림 상자(17cqw × 등급 배율) 한가운데, 상자의 **5배** 폭(처음 3.2배 → 「더 크게」). 0.07초에 확 터져
     살짝 돌며 0.6초에 사그라진다.
  2. **화면 전체 번쩍**(`.ngo-pop-flash`) — 장수가 나올 때마다 흰빛 최대 32%, 0.38초. 열쇠를 장수 수로 둬 다섯 번 모두 새로 돈다.
  3. **뒤에 남아 도는 별빛**(`.ngo-member::after`) — 사그라질 무렵 떠올라 **캐릭터 뒤에서**(`z-index: -1` — 장수 상자의 쌓임 맥락 안이라 그림 · 이름 뒤)
     2.4배 폭, 밝기 60%로 남는다. 14초에 한 바퀴 돌고 2.6초 주기로 0.82 ↔ 1.08배를 오간다. 회전(`rotate`)과 크기(`scale`)는 다른 속성이라 두 애니메이션이 겹쳐 돈다.
     처음엔 네모 상자에 그림을 180%로 깔았는데 빛줄기 끝이 상자에 잘려 직선 경계가 함께 돌 뻔했다 — 그림 비율(640:357) 그대로 통째로 깐다.
- 그림은 오프닝을 시작할 때 미리 받는다(첫 장수부터 그림이 비지 않게). 움직임 줄이기 설정이면 터지는 별빛 · 화면 번쩍은 빼고 뒤 별빛은 멈춘 채 둔다.
- **확인** — 실제 화면에서 S급이 나오는 순간과 1.3초 간격 두 장을 찍었다. `getComputedStyle(…, '::after')`로 뒤 별빛이 돌고(106°) 커지는 중(1.06배)인 것을 쟀다.
  짧게 스치는 연출은 밖에서 찍은 사진이 자주 놓친다 — 페이지 안에서 잰 값으로 확인한다.

## 3. 그 밖에

- 지난 세션이 끝나며 dev 서버 · 계정 서버가 내려가 있어 다시 띄웠다(기획자가 화면으로 확인).
- 다른 PC에서는 `npm run ui`(섬광 그림) · `npm run backgrounds`(입장 하늘) · `npm run opening`(가입 그림)을 한 번 돌려야 그림이 나온다.

## 4. 남은 것

- 뒤에 남는 별빛의 밝기 · 회전 빠르기 · 화면 번쩍 세기는 기획자가 화면으로 보고 조절할 수 있다(숫자만 바꾸면 된다).
- 어제 문서 10절의 남은 것 그대로 — 로그인 속도(계정 읽기 0.9~4.1초를 하늘에 숨겼을 뿐), 번역 확인, Supabase 오류 문장 번역,
  세 단추 통일 중 눈으로 안 본 화면들, 시험 계정 `opening-look@samchess.test`.

## 5. 교훈

- **빛 그림은 「밝기 = 투명도」로 굽는다.** 검은 바탕 빛을 검정 걷기로 다루면 옅은 끝이 잘리고, 섞기 모드로 다루면 쌓임 맥락 안에서 검은 네모가 남는다.
- **돌리는 그림은 상자에 잘리지 않게 깐다.** 정사각 상자에 넓은 그림을 넘치게 깔면 잘린 직선 경계가 함께 돈다.
- **엑셀을 프로그램으로 고칠 때는 행을 끼우지 말고 값을 다시 쓴다** — 수식 속 행 번호가 따라오지 않는다. 고친 뒤에는 「바뀐 칸이 의도한 것뿐인가」를 백업과 대조한다.
- **검사가 무는지는 출력 글자가 아니라 종료 코드로 본다** — 콘솔 인코딩 하나로 실패 글자가 안 보일 수 있다.
