## 0. 진도 파악 — HANDOFF가 9/4에 멈춰 있었다

HANDOFF는 「진행 상태의 정본」인데, 맨 위 **「새 대화를 여는 프롬프트」가 9/4 기준**으로 남아 있었다 —
「트랙 11 진행 중 · `smoke:meta`가 막혀 있다 · `npm test` 498/1 fail」. 그 사이 9/14~9/27의 일은 전부 history에만
있었고, §7의 「다음 세션은 여기서 고른다」 표는 **끝난 일 다섯을 아직 후보로** 들고 있었다.
진도를 다시 짚으려면 history 30여 개와 git log를 맞대 봐야 했다.

## 1. HANDOFF에서 고친 것

- **「새 대화를 여는 프롬프트」를 다시 썼다** — 읽는 순서(HANDOFF → 최근 history → 이어 할 트랙의 입구 → GDD),
  지금 기대값(`npm test` 801/0 · 스모크 넷 완주), 브랜치 방식, 다음 세션 블록(전투 UI 3단계).
  밀려 있는 것 목록을 §7 후보 표와 맞췄다.
- **§7 후보 표** — 끝난 것에 줄을 긋고 끝난 날과 근거 파일을 적었다:
  11g(10/6) · `useItem`(9/23) · 초기화 아이템 판매(9/24) · 도적떼 마무리(9/22 다국어, vfx는 10/6에 구울 것 없음) ·
  `smoke:meta` 막힘(9/14 풀림, 10/6 완주) · 9b 장터 피드백(9/24 재구성으로 갈음).
  새로 넣은 것: **전투 UI 개편 3단계**(진행 중인 트랙) · **전면 상세 화면 셋 정리**(기획자에게).
- **§7 로드맵 트리** — 트랙 11 ✅ · 9b ✅(갈음) · 10 리스킨 ✅(메타 화면 끝, 전투 화면은 개편 트랙).
- **§2 표** — 도시 확장 줄 ✅.
- **§6 현재 상태** — `npm test` 801/801 · `smoke:ui`(세 칸 무대) · `smoke:meta` 완주와 새 절 둘 · `smoke:raid` 줄 추가.

## 2. 확인만 하고 고치지 않은 것

- `npm run vfx` — 9/21 기록의 「`vfx:cast-*` 콘솔 오류, 다시 굽기」를 돌려 보니 **구울 것이 0장**이었고
  `smoke:ui`(콘솔 오류가 있으면 실패)도 오류 0으로 통과했다. 후보에서 지웠다.
- `smoke:raid`가 스크린샷 아홉 장을 저장소 맨 위(`.`)에 찍는다(`SHOTS` 기본값). 이번엔 손으로 치웠다 —
  프롬프트의 기대값 줄에 적어 뒀다. `.gitignore`에 넣을지는 다음에.
