## 2. 기획자가 내린 결정

### 순서를 바꾼다 — 오프라인 풀 사이클을 먼저

넷코드가 감싸야 할 단계(배치·매칭 대기·정찰)의 **화면이 없는 상태로 서버를 만들면**
나중에 편성·배치 화면을 붙이며 프로토콜을 다시 손대게 된다. 편성 규칙도 서버가 반드시
검증해야 하는 대상이라 오프라인에서 굳혀 두는 편이 낫다. 잃는 것은 없었다 —
`playback.ts`와 `RulesEngine` 계약은 그대로고, Colyseus 설계안도 그대로 유효하다.

### 미결 항목 셋을 한꺼번에 확정 — GDD §12에서 「미해결」이 사라졌다

| 항목 | 결정 | 근거 |
|---|---|---|
| **1:1 대전의 기물** (#8) | **영구 삭제.** 3:3 / 5:5만 | 원문 「1:1은 군주전」은 King 하나로만 두는 뜻인데, 그러면 **기물 조합이라는 이 게임의 정체성이 통째로 빠지고 편성할 것도 없어진다** |
| **레벨업 실패 시 카드** (#6) | **실패를 없앤다 — 전 레벨 100%** | 난이도는 필요 카드 수로만 조절. 확률형 아이템 공시 의무 대상에서도 빠진다 |
| **AI 대전의 보상** (#11) | **군량만. 카드는 없다** | 봇 파밍으로 수집이 굴러가지 않게 |

> **AI 보상 결정의 대가** — 오프라인만으로는 카드가 늘지 않아 **성장(E)을 시험할 수 없다.**
> 게임 규칙은 정한 대로 두고 장수 관리 화면에 **개발용 카드 지급**을 따로 뒀다.
> 규칙이 아니라 시험용 문이라는 것을 화면에도 적어 뒀고, 온라인·상점이 붙으면 지운다.

기술 스택 결정(HANDOFF §3) 그대로. 전투는 Phaser로 두고 그 위를 React가 감싼다.

## 3. 밟은 지뢰 ★ 다시 밟지 말 것

### 3-1. 시스템 대화창의 글자가 사라진다 — 기획자가 플레이 중 발견

상자는 그려지는데 **글자만 없는** 상태가 났다. `#log`는 세로 flex 컨테이너이고
줄들이 기본값 `flex-shrink: 1`이라, 대화 영역이 필요한 높이보다 얇아지면 **줄이 눌려
글자가 잘려 나간다.** 상자는 그대로 남아서 "빈 막대"처럼 보인다.

**5v5에서 늘 났다.** 고유기술 줄이 10개라 HUD가 두꺼워지고 그만큼 대화 영역이 얇아진다.
3v3은 자리가 남아 멀쩡했다 — **"가끔 안 보인다"의 정체가 이것**이었다.

```
                 수정 전      수정 후   (줄 높이 / 필요 높이)
900×760          15.5 / 19    21.4 / 19
390×844          16.1 / 20    21.9 / 20
1440×900         21.2 / 23    24.9 / 23
```

→ `.log-line`에 `flex: none`. 넘치는 줄은 위로 밀려 잘린다 — `justify-content: flex-end` +
`overflow: hidden`이라 **원래 의도한 「밀려 올라가는」 모습 그대로**다.
`smoke:ui`가 대화 영역을 일부러 20px로 좁혀 놓고 이 성질을 지킨다.

> **교훈:** 화면이 "비어 보이는" 버그는 데이터가 아니라 **레이아웃이 원인일 수 있다.**
> 여기서도 `debugLogLines()`에는 줄이 다 들어 있었다.

### 3-2. `charges`가 붙은 상태를 그 행동이 소모하지 않았다 — 기획자가 플레이 중 발견

여포 「인중여포 마중적토」의 자유이동이 **1회로 끝나지 않고 `time 290` 내내 됐다.**
데이터에는 처음부터 `charges: 1`이 적혀 있었는데 **이동이 그 횟수를 깎지 않았다.**
`time 290`은 원래 오라에만 걸리는 지속시간이다.

```
"인중여포 마중적토": [
  { status: "freeMove",         charges: 1 },        ← 여기가 안 깎이고 있었다
  { status: "auraOutgoingHalf", duration: 290, magnitude: 2 } ]
```

→ **기물 마스크 밖으로 갔을 때만** 깎는다. 원래도 갈 수 있던 한 칸을 움직였다고
「맵 어디든 한 번」이 날아가면 함정이 된다. 감녕 「백기겁위영」은 `duration` 지속형이라
`charges`가 없고, `consumeCharge`가 그런 상태는 건드리지 않으므로 영향이 없다.

> 다른 `charges` 스킬도 훑었다 — 「증폭」·「반감」은 `resolveAttack`에서 정상 소모되고
> 「구벌중원」은 `charges`를 상한으로 쓰는 다른 용법이다. **미소모로 남은 건 이 하나뿐**이었다.

### 3-3. 오라는 영향받는 쪽에 흔적이 없다

"내 공격력이 왜 절반이지?"에 화면이 답할 방법이 없었다. 오라는 시전자에게만 표식을 두고
피해 계산 때 거리를 다시 재는 구조라(GDD §12 A1) **당하는 쪽의 `statuses`는 비어 있다.**

→ 엔진에 `aurasOn(state, unitId)`를 두고 화면이 그것을 묻는다.
**판정(`auraApplies`)도 같은 함수를 쓴다** — 둘이 갈리면 "표시에 없는데 실제로는 걸리는"
어긋남이 난다. 배지는 「◎ 여포 2칸」처럼 **오라를 켠 장수 이름**으로 적고,
설명문은 **당하는 쪽 기준**으로 다시 썼다(`STATUS_META`의 문구는 시전자 기준이다).

### 3-4. 캔버스가 더 이상 화면 전체가 아니다

1:2 프레임을 넣으면서 캔버스가 가운데의 정사각 칸이 됐는데, 스모크의 격자→픽셀 변환이
**캔버스 좌상단을 더하지 않아** 클릭이 엉뚱한 칸으로 갔다.
`getBoundingClientRect()`를 더해야 한다.

### 3-5. 연출 중에는 갱신이 멈추므로 물음창이 뒤에 남는다

고유기술을 쏘면 연출이 2초간 판을 덮고 그동안 `refresh`가 돌지 않는다. "다음 갱신 때
사라지겠지"가 통하지 않는 구간이라 **쏘는 순간 직접 걷어야** 한다(`dismissPrompt`).

### 3-6. 그 밖에

- **`StrictMode`를 쓸 수 없다.** 개발 모드에서 effect를 두 번 실행하는데 그게 Phaser를
  띄우는 일이라 캔버스가 둘 생기고 첫 번째가 유령으로 남는다.
- **커밋 메시지에 PowerShell here-string 문법을 Bash로 보냈다** — `@'…'@`가 그대로 들어가
  제목이 `@`가 됐다. amend로 정리한 뒤 푸시했다.
- 배치 중에 내 기물을 누르면 정보 팝업이 떠 **판 한가운데를 덮었다.** 배치는 놓는 단계,
  정찰은 보는 단계로 갈랐다.

## 4. 구조에서 기억할 것

### 계정 규칙도 화면이 판단하지 않는다 ★

`packages/meta`를 **`packages/rules`와 같은 자리에** 세웠다. 룰 엔진이 전투의 권위이듯
여기는 계정의 권위다. 순수 함수만 두고 I/O·`Date.now()`·`Math.random()`을 쓰지 않는다.

- 화면은 "보유하지 않은 장수를 편성했다"를 스스로 판단하지 않고 `validateRoster()`에 묻는다 —
  전투 UI가 `validate()`에 묻는 것과 같은 계약이다.
- **엔진이 최종 권위다.** `validateRoster`를 통과한 편성은 `createBattle`도 받아들여야 하고,
  그것을 테스트로 고정했다(「편성 검증을 통과하면 룰 엔진도 받아들인다」).

### 저장은 한 곳뿐이다

`client/src/meta/storage.ts`. **온라인이 붙으면 이 파일만 서버 API가 된다** — 화면은 그대로다.
`playback.ts`를 둔 것과 같은 결이다.

### 시계를 쥔 자리를 하나로 몰았다

엔진은 시계를 갖지 않는다. 절대시간은 전투가 시작해야 흐르고 **배치 30초·정찰 30초는
실시간**이라 재는 주체가 따로 있어야 한다. 지금은 `Playback.deadlineMs` 하나가 그 자리이고,
**온라인에서는 서버가 이 값을 내려 준다** — 읽는 쪽(패널의 남은 시간)은 그때도 그대로다.
`BattleState.controlStartedAtMs`를 서버가 주입하기로 한 것과 같다.

### 대화 문장은 엔진이 준 이벤트만 읽는다

`eventText.ts`는 `BattleEvent[]`를 문장으로 푼다. 화면이 상태를 뒤져 무슨 일이 있었는지
추측하지 않는다 — **온라인에서 서버가 보내 주는 것이 바로 이 배열**이라, 판정 주체가
서버로 바뀌어도 이 층은 그대로 쓰인다.

> 한 이벤트가 한 줄이 되지는 않는다. 「책략 시전」은 성패와 효과가 **뒤따르는 이벤트에**
> 들어 있어서, 시전 이벤트를 만나면 그 뒤를 훑어 한 줄로 합친다.

### 크기는 전부 `rem`, 기준값은 프레임 폭이 준다

`useFrameFit`이 `html { font-size }`를 프레임 폭의 1/26로 정한다. 프레임이 320px(작은 폰)에서
700px(세로 모니터)까지 변하는데 글자만 고정이면 좁은 화면에서 커맨드가 줄바꿈되고 넓은
화면에서는 허전해진다. **px를 새로 적지 말 것.**
체스판 가로 폭만 `--board` 변수로 따로 넘긴다(`rem`은 글자 기준이라 "판의 절반"을 표현할 수 없다).

### 상태이상의 이름·분류·설명은 `STATUS_META` 하나가 출처다

이번에 `desc`를 같은 표에 넣었다. 화면이 설명문을 따로 적어 두면 상태가 늘었을 때 조용히 어긋난다.

### `deploy` 의도는 전원의 자리를 한 번에 받는다

한 명만 옮겨도 나머지의 현재 위치까지 함께 보내야 검증을 통과한다 —
**부분 배치라는 개념이 룰에 없다.**

### `waiting` 단계는 화면에 나타나지 않는다

AI는 곧바로 준비를 마치므로 「매칭 대기 최대 1분」(GDD §3.9)이 지나갈 일이 없다.
**온라인에서 상대의 `ready`를 기다리는 자리가 정확히 여기다.**

## 5. 검증 방법

층이 하나 늘어 여섯이 됐다.

| 층 | 도구 | 이번에 추가된 것 |
|---|---|---|
| 데이터 정합성 | `npm run extract` | 연출 이미지 대조를 **경고 → 빌드 실패**로 (화면이 쓰기 시작했다) |
| 순수 로직 | `npm test` (134건) | **메타 17건** + 오라·자유이동 4건 |
| 밸런스 | `npm run balance -- 5000` | — |
| 전투 화면 | `npm run smoke:ui` (22항목) | 대화창 · 전체 기록 · 연출과 판 정지 · 배지 설명 · **대화 줄 눌림** |
| **메타 연동** ★신설 | `npm run smoke:meta` | 계정→편성→배치→정찰→전투→군량→레벨업→저장 |
| 눈으로 | `npm run shot` | — |

**`smoke:meta`가 이 세션의 값어치를 증명한 층이다.** 규칙도 맞고 전투도 도는데
**화면이 그 둘을 잇지 못하는** 종류를 잡는다 — 편성이 엔진에 안 넘어가거나, 저장이
안 되거나, 결과가 계정에 반영되지 않는 것.

### 회귀 검사가 실제로 잡는지 확인했다

대화 줄 눌림 검사를 넣은 뒤 **수정을 잠깐 되돌려** 실패하는 것까지 봤다.

```
✗ 대화 영역이 좁아지자 4줄이 눌려 글자가 사라졌다 — .log-line에 flex:none이 빠졌다
```

> 테스트를 새로 쓸 때는 **한 번은 실패시켜 봐야** 한다. 통과만 확인하면
> "아무것도 검사하지 않는 테스트"를 통과로 착각한다.

### 화면 확인용 통로

- `?demo=1` — 계정·편성을 건너뛰고 데모 편성으로 한 판. `smoke:ui`·`shot`이 이 길을 쓴다
- `F` 키 — 확대해서 헤맬 때 판 전체로 되돌린다
- 장수 관리의 **개발용 카드 지급** — 성장 흐름 시험용(게임 규칙 아님)

| `assets/CharsInBattle/*.jpg` **77장** | `public/battle/{장수id}.jpg` 200² | 하단 패널·정보 팝업의 수묵화 |
| `assets/SpecialSkills/*.jpg` 40장 | `public/skills/{기술id}.jpg` 폭 720 | 고유기술 발동 연출 배너 |

**수묵화는 260명 중 77명만 있다.** 없는 장수는 보드 타일과 같은 초상화로 대신하고,
그것마저 없으면 자리를 비운다(`ui/art.ts`의 `setOfficerArt`). 그림이 없다고 화면이
무너지지 않는다 — 「없으면 건너뛰기」 방침 그대로다.
`X`로 시작하는 파일(`X동소.jpg`)은 기획자가 걸러 둔 것이라 빌드에서 건너뛴다.

### 작업 방식에서 확인된 것

- **기획자가 직접 플레이해서 잡아준 버그가 둘이었다** (대화창 눌림 · 인중여포 자유이동).
  둘 다 스크린샷이나 단위 테스트로는 안 드러나는 종류다 —
  **화면 작업 뒤에는 실제 플레이 확인을 요청할 것.**
- **미결 항목을 모아서 한 번에 물으니 한 번에 정리됐다.** 1:1·레벨업·AI 보상 셋을
  선택지와 파급을 함께 보여 주고 물었다.
- **순서를 바꾸자는 판단이 옳았다.** 넷코드를 먼저 했다면 배치·정찰 화면을 붙이며
  프로토콜을 다시 손댔을 것이다.
