# 2026-09-16 부대 편성 정책 — 부대는 장수의 「소속」, 레벨 하향 폐지

2026-08-18(트랙 E, [부대편성_배치프리셋](2026-08-18_부대편성_배치프리셋.md))에 정한
**「부대의 레벨은 상한이지 스냅샷이 아니다」**를 기획자 결정으로 뒤집었다. UI 손질은
이 정책 변경 뒤에 따로 요청이 온다 — 이번 세션은 **규칙과 그 규칙이 강제하는 최소한의
화면 변경**까지다.

## 1. 왜 뒤집었나

옛 규칙은 `Squad.picks[].level`로 부대마다 장수의 레벨을 1 ~ 보유 레벨로 낮출 수 있었다.
낮춘 레벨의 능력치·책략은 성장 스택을 `slice`로 잘라 꺼냈다. 목적은 **전투력을 낮춰 다양한
상대와 매칭되기**였다.

반대쪽에서 문제가 생긴다 — **장수가 레벨업을 해도 부대에는 옛 눈금이 남는다.**

- 부대마다 레벨을 손으로 올려 줘야 하는 번거로움
- 레벨업이 반영이 안 된 줄 알고 **버그로 착각**하는 경우

그래서 부대 편성은 「편성할 때 찍는 스냅샷」이 아니라 **「장수가 어떤 부대에 소속되어 있다」**는
관계로 바꿨다. 한 장수가 둘 이상의 부대에 소속될 수 있다(이건 예전에도 가능했다).

## 2. 새 규칙

| | 규칙 |
|---|---|
| **부대가 저장하는 것** | `RosterPick = {piece, officer}` 둘뿐이다. 레벨이 없다 |
| **전투에 서는 레벨** | 언제나 **장수의 지금 보유 레벨** |
| **레벨·능력·책략이 바뀌는 자리** | **궁궐의 레벨업·둔갑천서뿐.** 바뀌면 그 장수가 속한 모든 부대에 곧바로 반영된다 |
| **병영(편성 화면)의 레벨** | 고르지 않는다 — `Lv N`을 읽기 전용으로 보여 준다 |
| **「일부러 약하게 나가기」** | **궁궐로 옮겨 갔다**(기획자 확정, 아래 3절) |

## 3. 약한 상대를 만나려면 — 둔갑천서로 되감고 카드를 남긴다

부대 화면의 하향 눈금 대신 기획자가 정한 길이다.

1. 둔갑천서(재설계)로 장수를 **Lv1로 되감는다** — 레벨업에 쓴 카드가 전부 돌아온다
   (`cardsSpentOn()`이 정확히 누적 필요분을 돌려준다, GDD §4.3)
2. 돌려받은 카드를 **전부 쓰지 않고 일부만** 써서 원하는 레벨까지만 올린다
3. 그 상태로 출전한다. 남긴 카드로 언제든 다시 올릴 수 있다

옛 눈금과 다른 점 셋:

- **장수 단위다** — 그 장수가 속한 부대 전부가 함께 낮아진다(부대별로 가를 수 없다)
- **비용이 있다** — 둔갑천서 값
- **다시 올릴 때 능력·책략을 새로 고른다** — 옛 눈금은 같은 스택을 잘랐을 뿐이라 빌드가
  그대로였다. 이쪽은 되감기라 빌드가 바뀔 수 있다

이 길은 **이미 있는 절차 그대로**라 코드 변경이 없다(재설계 = 되감기 + 정상 레벨업,
CLAUDE.md 「재설계는 되감기다」). **부대 화면에 레벨 조절을 되살리는 것으로 풀지 않는다** —
CLAUDE.md에 적었다.

## 4. 코드

### meta

| 파일 | 변경 |
|---|---|
| `types.ts` | `RosterPick.level?` 삭제 · 주석을 「소속」 규칙으로 |
| `roster.ts` | `pickLevel()` 삭제 · `toRosterEntries()`가 `inst.level`과 성장 스택 전체를 편다 |
| `squads.ts` | 레벨 범위 검증 삭제(`validateSquad`는 `validateRoster`를 그대로 돌려준다) · `normalizePick()`이 **기물·장수 외의 키를 떨어뜨린다** · `SquadMember.maxLevel` 삭제 |
| `profile.ts` | ★ `growthUpTo()` 삭제 · `statPicksOf`/`tacticsOf`/`statsOf`의 **`cap` 인자 삭제** |
| `ranking.ts` | `statsOf(inst, inst.level)` → `statsOf(inst)` |
| `match.ts` | AI 상대는 계정이 없어 `RosterPick`을 지나지 않고 `RosterEntry`로 곧장 편다 |
| `migrate.ts` | `readSquads()`가 옛 `level`을 **버리고 부대는 살린다** |

**`cap`까지 없앤 이유** — 레벨 하향만 쓰던 인자다. 남겨 두면 누군가 「부대마다 레벨이 다르다」를
다시 조용히 끼워 넣을 자리가 된다. 기능이 사라지면 그 기능을 위한 손잡이도 함께 치운다.

**버전을 안 올린 이유** — 옛 `level`은 되접을 뜻이 없고 읽지 않으면 그만이다. 부대가 죽는
것이 아니라 눈금만 사라진다(「버전은 뜻이 바뀔 때만 올린다」 — 여기는 값을 **버리는** 쪽이라
되접기 절차가 필요 없다).

**보안 쪽 부수 효과** — 서버의 AI 대전 재생 검증(`server-api/src/aiBattle.ts`)이 클라이언트가
보낸 `picks`로 `toRosterEntries()`를 부른다. 이제 거기에 `level`이 섞여 와도 **읽지 않으므로**
레벨을 자칭할 길 자체가 없다(예전에도 보유 레벨 위로는 못 올렸지만 아래로는 적을 수 있었다).

### client

- `SquadEditScreen.tsx` — 자리 카드의 레벨 눈금 단추(`.sqd-levels`/`.sqd-lv`)를 걷고
  읽기 전용 `<span className="sqd-lvnow" data-field="level">Lv{N}</span>`으로. `setLevel`·`onLevel` 삭제
- `style.css` — 어두운 판·양피지 리스킨 양쪽의 눈금 규칙을 지우고 `.sqd-lvnow` 하나로
- `squad.levelNote` 열 언어 — 「캐릭터별 최대 레벨에서 1 사이로 조절 가능」 →
  「레벨은 궁궐에서 키운 장수의 지금 레벨 그대로 따라간다」. 궁궐 이름은 각 언어의
  `place.palace` 번역에 맞췄다(중국어는 「宫阙/宮闕」, 처음엔 「宫殿」으로 적었다가 고쳤다)

## 5. 검사

### 회귀 (`npm test` 586/587)

걷어 낸 것 — `growth.test.ts` §4 「slice로 자른 Lv5가 진짜 Lv5와 같다」(번호는 다른 문서가
가리켜 비워 두었다) · `squads.test.ts` §5 「하향한 Lv5」 세 건 · 「레벨을 하향한 부대」.

새로 넣은 것 (`squads.test.ts`):

1. **한 장수가 3v3·5v5 두 부대에 소속되고, 부대를 한 줄도 안 고친 채 궁궐에서만 Lv6으로
   키우면 두 부대 모두** 표시 레벨·능력치·엔진 레벨이 6이고 전투력이 오른다
2. 전투에 실리는 능력 선택·책략이 장수의 성장 스택 그대로다
3. **편성에 `level`이 섞여 와도 읽지 않고 저장하지 않는다** — `normalizePick()`을
   `({ ...pick })`로 되돌리면 **이 검사가 실패하는 것을 확인했다**
4. 옛 부대의 `level`은 부대를 살린 채 버리고, 표시 레벨은 옛 눈금(1)이 아니라 보유 레벨(5)이다

실패 1건은 이번 작업 전부터 있던 것 — `data.test.ts`의 「추출 빌드」가 쓰는 곳 없는 시각효과
그림 `B_specialstatus.png`·`B_specialstatus_cutguide.png`를 알린다. 이번 변경과 무관하다.

### 스모크 (`smoke:meta` 완주)

편성 화면 절을 「눈금 칸 수 = 보유 레벨」에서 **「레벨 단추가 0개이고 표시가 보유 레벨과 같다」**로
바꿨다. 옛 눈금 단추가 되살아나면 잡는다.

⚠ **스모크의 새 계정은 장수가 전부 Lv1이라 「보유 레벨과 같은가」는 기본값과 같은 값을 보는
검사다** — 반영 자체는 회귀 1번이 키운 장수로 고정한다. 스모크 주석에 그렇게 적었다.
