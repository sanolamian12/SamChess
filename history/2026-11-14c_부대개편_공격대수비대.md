# 부대 개편 — 모드마다 공격대 하나 · 수비대 하나 (2026-11-14)

설계 · 손댈 자리: [`Design/부대개편_공격대수비대.md`](../Design/부대개편_공격대수비대.md) (§5-정이 이번 세션의 기획자 답).

## 기획자 답 (§5)

| 물음 | 답 |
|---|---|
| 「아이디」는 무엇인가 | **도시 이름**. 이메일 앞부분은 남에게 보이지 않는다 |
| 같은 장수가 공격대 · 수비대에 함께 서나 | **선다** — 「소속이지 스냅샷이 아니다」 그대로 |
| 옛 계정 접기 | 수비대 = 옛 수비군. 공격대 = 나머지 중 **가장 최근에 싸운** 부대 → 없으면 **전투력 최고** → 없으면 **수비대 복사**. 나머지와 그 전적은 버린다 |
| 칸 | 꼬마 명단 · 기물 · 전투력(수비대는 수비군 표지). 빈 칸 「+ 편성하기」. 채운 칸 → 부대 현황, 빈 칸 → 곧장 부대원 편집. [부대 삭제] → [부대 비우기] |
| 부대 랭킹 · 전적 | **남긴다** — 칸마다 쌓고, 줄은 「도시 이름 · 3vs3 공격대」 |
| 첫 편성 안내 | **공격대 먼저**. 수비대는 따로 채운다. 출정 조건은 그대로 「두 모드의 수비대」 |
| 수비군 설정 화면 | **따로 한다** — 이번에는 제목 · 확인창 문구만 |

## 구조

- **부대 id = 칸 id**(`atk-3v3` · `def-3v3` · `atk-5v5` · `def-5v5`, `squads.ts`의 `SQUAD_SLOTS`), `Squad.role`. 빈 칸은 배열에 없다.
  `Squad.name` · `squadSeq` · `PlayerProfile.garrison` · `squadCap` · `canAddSquad` · `validateSquadName` · `SQUAD_NAME_MAX` · `setGarrison`이 없어졌다.
  `removeSquad` → `clearSquad`. 새 함수 `squadAt` · `attackSquadOf` · `slotOf` · `squadSlot` · `squadLabelKo`.
  `Squad[]`로 둔 것은 읽는 자리(`squadsOf` · `squadRow` · 전투력 · 배치)를 그대로 쓰려는 것 — 「하나뿐」은 칸 id가 지킨다(되접기 · `addSquad`).
- **저장 형식 v8**(뜻이 바뀌었다). v7 이하는 `readSquads()`가 접는다 — 옛 부대 id · 이름 → 칸 id 짝(`moved`)으로 **도는 AI 대전의 `squadId`**와
  **이력의 `mySquad`**도 고친다(버려진 부대의 이력 줄은 옛 이름 그대로). v8은 칸 id가 아닌 부대를 버리고, 역할은 저장 값이 아니라 id에서 낸다.
- **수비군 = 수비대 칸**(`garrisonOf`). 공격대로 물러나지 않는다 — 수비대가 비거나 장수가 빠지면 출정이 잠긴다.
- **남에게 보이는 부대 이름 = 도시 이름** — `GarrisonSnapshot.squadName`(`defenses.squad_name`) · `warSquadView` · `warEnlist` · 대기열 enlist.
  공성전 목록은 표의 열 대신 계정의 도시 이름을 싣는다(계정이 다시 써질 때까지 옛 부대 이름이 남아 있을 수 있어서).
- **내 이력의 `mySquad` = 칸 id** — 부대 전적을 그 칸에 센다(`rewards.ts`가 이름 대신 id로 찾는다). 온라인 판은 enlist에 `squadId`를 새로 실어
  `BattleRoom`이 정산에 넘긴다(선전포고 방은 서버가 선전포고에 적힌 칸을 싣는다). 화면은 `squadText()`로 「3vs3 공격대」.
- **선전포고** — 거는 쪽은 **공격대**, 받는 쪽은 **수비대**(제 성을 지키는 판). 서버가 칸을 본다(`war.badSquad`). 응전 팝업은 고르지 않는다.

## 화면

- **편성 부대 목록**(`SquadListScreen`) — 2 × 2 정사각 칸(`.sqg-*`). 부대 수 · 정렬 · 쪽 넘김 · [새 편성] · [수비군 지정]을 걷었다.
  몽골어 「Довтолгооны отряд」가 한 줄에서 잘려 **이름표를 아이콘 아래 제 줄로** 내리고 접히게 했다(`squad_ux`의 넘침 검사가 잡았다).
- **부대 현황** — 제목은 「공격대 (3vs3)」, [수비군으로 지정] 없음, 수비대에만 [수비군 설정], [부대 비우기](수비대면 「출정이 잠긴다」 한 줄).
- **새 편성 이름 화면(`SquadNameScreen`) 삭제** — 빈 칸을 누르면 곧장 부대원 편집.
- **출정하기** — 그 구성의 공격대 한 줄이 체크된 채 선다. 비었으면 [공격대 편성하기] → 그 칸의 부대원 편집.
- 병영 현황판 「부대 n / 4」 · 최근 부대 셋은 칸 이름표 · 랭킹 · 부대 랭킹 · 공성전 · 수비군 설정 · 대전 이력 · 결과 화면이 이름 대신 칸 이름표.
- 문구 — 새 4키(`squad.role.*` · `squads.fill` · `squads.delete.garrison`) · 고친 13키 × 열 언어, 안 쓰게 된 22키를 지웠다(지운 뒤 `typecheck` 통과 = 정말 안 쓰는 키).
  한국어 안내 대사(`guide.squads.intro.*` · `squadView.garrison` · `barracks.sortieOpen.4` · `garrison.done`)를 새 구조로.
- **첫 편성 안내** — 3v3 공격대 칸이 빛나고(`firstSquadPending` = 3v3 공격대가 비었다), 부대원 · 배치 미션은 그대로. 공격대 현황에는 수비군 안내가
  안 서고, 3v3 수비대를 채우면 그 현황에서 `squadView.garrison` → 수비군 설정 미션. ⚠ **공격대를 채운 뒤 「이제 수비대를 채우라」는 안내는 없다** —
  병영의 [출정하기] 잠김 이유(「3대3 수비대를 채워야 출정할 수 있다」)가 대신 말한다. 안내 갱신은 기획자가 따로 요청하기로 한 몫이다.

## 서버 · 관리자

- `server-api` — `war.ts`(칸 검사 · `WarEnlist.squadId`) · `siege.ts`(부대 이름 = 도시 이름) · `ranking.ts`(검색은 도시 이름만) · `admin/battles.ts`.
- 대전 서버 — `Enlist.squadId?`(없으면 부대 전적을 안 센다), `BattleRoom`이 `mySquad`로 넘긴다.
- DB 스키마는 그대로다(`defenses.squad_name`에 도시 이름이 들어간다). `db:migrate` 할 일 없음.
- 관리자 — `AdminPlayStatus.garrisons[].picked`를 걷었다(이름은 「3v3 수비대」). 화면: 진행 상태 · 계정 상세 부대 표(「칸」 열 · n/4). 인수인계서 §2 · §3.

## 검사

- `npm test` 1480 pass · `typecheck` · `typecheck:admin` 통과. meta에 칸 · 되접기(v7 → v8 접기 넷 · 도는 AI 대전 · 이력 줄) · 수비대 = 수비군 회귀.
- 완주 — `look:firstSquad`(새 흐름) · `squad_ux`(한국어 · 몽골어 — 칸 넷 · 넘침 · 현황 · 편집 · 배치 · 빈 칸 채우기) · `smoke:account` ·
  `smoke:siege-ux` · `smoke:policy-ux`(새 책략 알림에 「3vs3 수비대」) · `smoke:war-ux`(응전 팝업 = 수비대, 양쪽 이력).
- `smoke:meta` — 부대 구간을 칸 흐름으로 다시 썼다. 다섯 번 돌려 **부대 · 출전 · 매칭 · 전투 · 결과 · 전적까지 66개 통과**, 그 뒤 도시 증축
  조건(「전투 승리가 모자란다 — 0/1」, 앞 커밋 dd1c937의 누적 승리 조건)에서 떨어진다 — 이번 개편과 무관해 손대지 않았다.
  도중에 앞 커밋이 남긴 검사 둘을 고쳤다: 「판 전 명단 ≤ 8」(출정 필수 튜토리얼 다섯 → `5 + SORTIE_TUTORIALS.length`) ·
  「일람 줄 수 = 장수 수」(장수가 열을 넘어 둘째 쪽으로 — 첫 쪽만 센다, 되접기 검사 둘도). 부대원 고르기는 고정 대기 대신 줄이 찰 때까지 기다린다.
- 도구 시드(`icons_look` · `landscape_tour` · `squad_ux` · `smoke_account` · `battles_ux`)를 칸 id로 — **옛 `sq1` id로 심으면 v8 되접기가 조용히 버린다.**
  `war_ux` · `garrison_policy_ux` 선택자와 칸 규칙도 맞췄다.
- 곁가지 — `smoke_meta`의 「판 전 명단 ≤ 8」은 앞 커밋(dd1c937)이 출정 필수 튜토리얼을 다섯으로 늘리며 이미 깨져 있었다 → 상한을 `5 + SORTIE_TUTORIALS.length`로.
