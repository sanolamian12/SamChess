# smoke:meta 「Target crashed」 — 크래시가 아니라 도구의 10분 제한 (2026-10-20)

`npm run smoke:meta`가 main에서 매번 도시 증축 구간(`tools/smoke_meta.ts` 2490줄 근처)에서
`page.click: Target crashed`로 떨어졌다. `[data-action="doneOk"]`를 기다리는 동안, 그러니까 증축 완료 팝업
(`[data-modal="upgradeDone"]`)이 떠 있는 동안이었다. 같은 날 네 번 같은 자리였고, 결과 두루마리 변경 이전 커밋(`12a0da6`)도 같았다.
이 때문에 증축 뒤의 검사 수십 건이 한동안 한 번도 돌지 않았다.

## 결론

**게임 버그가 아니었다.** `smoke:meta`는 한 번 도는 데 **약 12분(실측 699초)**이 걸리는데, Claude Code의 Bash 도구는
포그라운드 명령을 **600초에서 끊는다.** Windows에서 프로세스 트리를 죽이면 Chromium이 node보다 먼저 꺼지고, Playwright가
그것을 `Target crashed`로 남긴다. 10분이 되는 지점이 마침 증축 완료 팝업이라 「팝업이 탭을 죽인다」로 보였다.

## 판 과정

의심 후보(팝업의 그림 · 9분할 · 소리, 긴 실행의 메모리 누적, 헤드리스 GPU · 미디어 경로)를 하나씩 지웠다.

| 시험 | 결과 |
|---|---|
| 완료 팝업 마크업만 dev 페이지에 주입 | 안 죽음 |
| 시험 계정으로 증축만 실제 흐름으로(메인 → 궁궐 → 도시 관리 → 증축) | 안 죽음 |
| 「시계가 뒤로 간」 `grainAt = 지금 + 5시간` 상태로 증축 | 안 죽음 |
| 스모크가 죽기 직전 심는 계정(`reload()` 4번째, 보관함 카드 5장 → `syncCity()`가 풀로 올림)을 그대로 새 브라우저에 | 안 죽음 |
| 고유기술 [발동 영상 보기](SkillFx · 성우 · 효과음) 뒤 새로고침 반복 | 안 죽음 |
| 한 렌더러에서 새로고침 60번 | 안 죽음 |
| 실행 중 메모리(CDP `Performance.getMetrics` 5초 · 0.2초, OS 프로세스 0.5초) | JS 힙 ~28MB, 렌더러 ~200~250MB로 **내내 평평** |
| 풀 Chromium(`channel: 'chromium'`) + 크래시 덤프 폴더 | 같은 구간에서 죽고 **덤프 없음** |

결정적 단서는 **죽는 자리가 내가 건 `timeout`을 따라 움직였다**는 것이다.

- 크래시가 난 실행은 전부 `exit=124`(타임아웃)였다.
- 브라우저를 띄우고 죽기까지가 매번 약 9분 17~20초(560초 타임아웃)였다.
- 480초를 준 실행은 더 앞(2299줄 `reenter`)에서 죽었다.
- 590초를 준 실행은 보고된 자리(완료 팝업)에서 죽었다.
- 덤프가 안 남은 것도 맞아떨어진다. 밖에서 죽인 프로세스는 크래시가 아니다.

**확인:** 원본 스모크를 타임아웃 없이 백그라운드로 돌려 `메타 연동 스모크 통과`로 **끝까지 완주**했다(exit 0, 699초, ✓ 74줄).
증축 뒤 처음 돈 검사(증축 Lv2 · 건물 관리 · 병원 부상 카드 등)에서 새 실패는 없었다.

## 바꾼 것

- 게임 코드 · 스모크 검사는 그대로다. 고칠 것은 실행 방법이었다.
- `CLAUDE.md` 명령 목록에 `smoke:meta`(약 12분, 10분 제한이 있는 도구에서는 백그라운드로)를 넣었다.
- `CLAUDE.md` 규칙에 「스모크의 Target crashed는 먼저 실행 시간을 의심한다」를 넣었다.
- 커밋 `6ac0a7f`. `fix/smoke-meta-crash`에서 main에 ff 머지했다.

## 교훈

- **크래시가 늘 「시작 후 같은 시각」에 나면 크래시가 아니라 끊긴 것이다.** 「같은 자리에서 네 번」은 같은 원인을 뜻했지만,
  그 원인이 그 자리의 코드라는 뜻은 아니었다.
- 진단용으로 건 타임아웃이 증상을 다시 만들어 한동안 「재현됐다」로 읽혔다. **재현 실험의 종료 코드(124)부터 본다.**

## 알고 남긴 것

- **결과 화면 카드 공개 간헐 실패.** 진단 중 한 번, 결말 장을 넘기는 클릭(`.brs-stage`)을 카드 공개 연출(`[data-modal="burst"]`)이
  가로막아 30초 타임아웃으로 떨어졌다(1510줄 근처). 브라우저 로그를 자세히 켜(`DEBUG=pw:browser`) 느려진 실행에서만 나왔고
  깨끗한 실행에서는 안 나왔다. 오늘 들어온 결과 두루마리 변경(`38d3614`)과 닿은 자리라, 다시 나오면 그때 판다.
- **스모크 자체가 12분이다.** 앞으로도 늘면 백그라운드로 돌려도 기다림이 길다. 줄이려면 고정 대기(`waitForTimeout`)를
  실제 단계 대기로 바꾸는 쪽이 먼저다(이번에는 손대지 않았다).
