## 2. 왜 「점수」가 아니라 「승률 눈금」인가

44쪽이 원한 것은 예쁜 숫자가 아니라 **「이 값이 가까우면 대전이 성립한다」는 눈금**이다.
그러면 형태가 저절로 정해진다.

```
power(팀) = Σ 유닛별 기여
winChance = 1 / (1 + exp(−(내 전투력 − 상대) / POWER_SCALE))
```

이 꼴이라서 공짜로 따라온 것 셋.

- **매칭 구간**을 「±몇 점」이 아니라 **「예상 승률 45~55%」**로 정의할 수 있다
- **「동일 전투력이면 어느 쪽이 이겨도 같다」**가 `gap = 0`의 대칭성으로 정의상 성립한다
- 나중에 눈금을 다시 스케일해도 **승률로 적어 둔 규칙은 뜻이 안 바뀐다**

`POWER_SCALE = 100`은 로짓 1단위를 100점으로 부르기로 한 것뿐이다. 그래서
**「격차 100 = 승률 73%」 하나만 외우면** 나머지가 따라온다.

### 등급이 아니라 능력치로 잰다

44쪽은 「클래스 조합」이라고 적었지만 등급이 승률을 만드는 게 아니다. 만드는 것은
**무력(크리티컬)·지력(환술)·통솔(WT)·고유기술**이고 등급은 그 요약이다. 등급으로 접으면

- 같은 S급인데 센 장수와 약한 장수가 같은 값이 되고
- **레벨이 들어갈 자리가 없다** — 44쪽이 함께 요구한 「레벨 1~9」가 사라진다

등급 조합 표는 이 식에서 **파생해서** 찍어 준다. 실제로 개별 장수의 전투력은 등급을
가로질러 겹치는데(B급 최약 164 < C급 중앙값 254), 이건 오류가 아니라 **의도한 결과**다 —
테스트가 그 성질을 따로 고정한다.

## 3. 기획자와 갈린 자리 — 설계안에서 뒤집힌 것

설계안을 먼저 보여 주고 코멘트를 받았다. 넷 중 셋이 뒤집혔다.

| 내 제안 | 기획자 결정 | 이유 |
|---|---|---|
| 카드 보상 상한을 **A**로 열자 | **B로 막는다** | **악성 유저끼리 짜고 큰 이변을 만들어 한 계정에 몰아줄 수 있다.** 나는 「매칭이 전투력으로 붙으니 샌드백은 자멸한다」고 봤는데, 담합은 매칭을 우회한다 |
| 예상 승률로 **카드 등급을 나누자** | **나누지 않는다.** 대신 **전적·랭킹에 기록**해 명예로 | 보상이 걸리면 상한이 곧 파밍 목표가 된다. 기록만이면 담합해도 잃을 게 없다 |
| 기물을 **넣자** (실재하는 효과다) | **뺀다** | 전투력에 넣으면 **사람이 그 숫자를 보고 기물을 고르거나 배제한다.** 기물 선택은 전술이지 강함의 표시가 아니다 |
| 42쪽 「000 점」이 **세 자리 힌트**다 | **아무 뜻 없는 예시다** | 두 자리든 다섯 자리든 상관없다 → 자릿수가 아니라 **눈금의 뜻**에 맞추게 됐다 |

**모드별 계수만 내 예상과 기획자 예상이 같았고**(「갈릴 것 같다」), 실측이 그걸 확인했다.

## 4. 실측

```
npm run power -- 20000 --calib 5000        모드당 2만 판 · 총 488초
```

### 표본을 balance.ts와 다르게 뽑아야 했다 ★

작업계획은 「`tools/balance.ts`를 확장」이라고 적었는데 **형제 도구로 갈랐다.** 이유 둘.

1. `npm run balance`의 Lv1 기본 출력은 HANDOFF §7 기준선(S 66.4 / A 59.4 / …)과 **글자
   단위로 비교되는 자산**이다. 그 파일에서 표본 추출을 갈아 끼우면 기준선이 조용히 흔들린다.
2. **표본 요구가 근본적으로 다르다.** balance는 양쪽에 같은 레벨·같은 능력 정책을 준다 —
   그러면 `hp`·`mp`·`at`이 레벨과 **완전히 공선**이라 셋의 가중치를 분리할 수 없고,
   두 팀의 특징 차이도 좁다. 회귀에는 **유닛마다 등급·레벨·능력 선택을 독립으로 굴린**
   표본이 필요하다.

E급(헌제)은 표본에서 뺐다 — 등급 균등 추출인데 장수가 하나뿐이라 슬롯의 1/5을 단일
이상치가 차지한다. 산출식은 능력치 기반이라 헌제에게도 그대로 적용된다.

### 모형이 맞는지 확인한 방법

**적합에 쓰지 않은 새 시드 5천 판**으로 보정 검사를 했다. 예측 승률 11개 구간이 전부
실제와 **±3%p 이내**였다. 여기에 Δ등급점수 × Δ평균레벨 표가 두 방향 모두 어긋난 칸 없이
단조다(3v3, 왼쪽 위 0.0% → 오른쪽 아래 97.1%). 「전투력이 높은 편성이 유의미하게
이기는가」의 직접 증거다.

### 모드별 계수가 갈렸다 — 44쪽이 맞았다

3v3 계수가 5v5의 **1.65~1.75배**다(차이의 z 4.6~17.7). `5/3 ≈ 1.67`이다 —
**한 명이 셋 중 하나일 때가 다섯 중 하나일 때보다 판을 더 크게 좌우한다.**

그 부작용이 하나 나왔다. **계수가 작아진 만큼 인원이 늘어 상쇄되어 두 모드의 값 범위가
겹친다**(3v3 209~1304 · 5v5 253~1302). 42쪽 목업의 `33`/`55`를 「5v5가 더 크다」로 읽었던
것이 성립하지 않는다. 나란히 놓으면 비교하고 싶어지는 숫자인데 **비교하면 안 되는 값**이라
`battlePower()`가 인원 불일치에 예외를 던지게 뒀다.

## 5. 밟은 지뢰 ★

### 5-1. 기물 지시변수 다섯이 완전 공선이었다

첫 실행에서 기물 계수의 **표준오차가 6435**로 찍혔다. 계수 자체는 `+0.08`, `−0.20`처럼
그럴듯해서 **오차를 안 찍었으면 그대로 믿었을 것**이다.

원인: 각 진영이 `King + (유닛수−1)`개를 가지므로 **다섯 지시변수의 합이 항상 상수**다.
차분을 만들면 합이 0이 되어 다섯 열이 완전히 겹친다. 기준 기물 하나(Pawn)를 빼면
나머지는 「Pawn 대신 이걸 넣으면 승률이 얼마나 달라지나」로 읽힌다.

> **교훈: 공선은 값이 아니라 오차에 나온다.** 도구가 표준오차와 z를 항상 함께 찍는 이유다.

### 5-2. 표본에 없는 값으로 외삽했다

고유기술을 `보유(0/1)` + `SP 코스트`로 뒀다. 표본의 코스트는 **B 4 / A 5 / S 6뿐**인데
**헌제만 7**이고 E급은 표본에서 뺐으니 7은 관측된 적이 없다. 기울기를 외삽하니
**실측 최약체인 헌제(승률 35.8%, 최하)가 D급보다 세게** 나왔다.

둘은 거의 공선이기도 해서 계수가 서로를 밀어냈다(보유 −52.6, 코스트 +14.3).
그렇다고 `보유(0/1)`만 남기면 **S급 고유기술과 B급 고유기술이 같은 값**이 되는데,
코스트를 뺀 대가가 logLik 101이었다 — 그 차이는 실재한다.

**등급 더미 셋**(`skillB`·`skillA`·`skillS`)으로 바꿔 둘 다 풀었다. 관측된 세 등급을
각각 재고 외삽이 없다. 헌제(E급 기술)는 셋 다 0이 되어 고유기술 몫을 못 받는데,
**그게 실측과 맞다.**

> **교훈: 회귀는 관측 범위 밖에서 조용히 틀린다.**

### 5-3. 테스트가 내 가정을 두 번 깼다 (모형이 아니라)

- **「5v5 > 3v3」** — 42쪽을 읽고 당연하다고 여겨 테스트로 박았는데 실측은 겹쳤다(§4).
  테스트를 사실 쪽으로 고쳤다.
- **「D+D+D < C+C+C < … < S+S+S」** — 가나다 이웃 세 명으로 표본을 잡았더니 C가 B를
  이겼다. 등급 **중앙값**으로는 정확히 단조인데(216 < 254 < 279 < 315 < 350) **개별
  장수는 등급을 가로질러 겹친다.** 테스트를 중앙값 기준으로 바꾸고, 겹침 자체를
  **별도 테스트로 고정**했다 — 그게 「등급이 아니라 능력치로 잰다」의 증거이기 때문이다.

## 6. 구조로 보장한 것

**단조성.** E의 「레벨 하향」이 성립하려면 `power(Lv5) < power(Lv7)`이 언제나 참이어야 한다.
그런데 `mp`는 가중치가 0 근처로 나올 것이 예고돼 있었다(Lv9 `mp` 몰빵이 Lv1과 소수점까지
같았던 실측). 음수가 나오면 **레벨을 내렸는데 전투력이 오른다.**

그래서 날계수를 두 번 손본다. 둘 다 **버리는 쪽으로만** 움직여 실측을 부풀리지 않는다.

- `|z| < 2`면 0 — 표본이 「모른다」고 답한 항을 식에 남기지 않는다 (5v5의 B급 기술이 걸렸다)
- 성장분(hp·mp·at)은 하한 0

테스트가 **모든 장수 × 모든 레벨 × 세 가지 몰빵**에서 단조를 확인한다.
