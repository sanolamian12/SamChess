# 2026-09-10 — 손권 「수성지주」: 성지 1칸 → 자신 중심 3×3 성채

> **여기는 「그때 왜 그렇게 정했고 어디서 넘어졌는가」다.** 지금의 사양은
> [`Design/GDD.md`](../Design/GDD.md) §3.8·§3.10, 효과 정의는
> [`tools/extract_data.py`](../tools/extract_data.py)의 `TACTIC_EFFECTS`에 있다.

## 1. 무엇을 왜 바꿨나

기획자 요청: 「수성지주」를 상향한다. 손권이 **선 칸을 중심으로 3×3** 아홉 칸에
성채를 세우고, 그 아홉 칸 어디에 서도 회복한다.

**바뀐 것이 넓이만은 아니다** — 그전에는 **맵 어느 칸이든** 고를 수 있었다
(`{kind: 'tile'}`, 조준이 있었다). 요청은 「손권이 서 있을 곳이 센터」였으므로
**조준이 사라졌다.** 넓어지는 대신 자리를 못 고른다 — 순수 상향이 아니라 성격이
바뀐 것이라 여기 적어 둔다.

| | 전 | 후 |
|---|---|---|
| 넓이 | 1칸 | 3×3 (판 밖은 잘림) |
| 조준 | 맵 아무 칸 | 없음 — 언제나 시전자가 선 칸이 중심 |
| 막히는 조건 | 그 칸에 지형이 있으면 | **3×3 안에** 지형이 하나라도 있으면 |
| 그림 | 성채 한 장 | 조각 아홉 — 가운데 성 · 성벽 넷 · 모서리 넷 |

## 2. 구현

### 엔진 — 새 `TargetSpec` 하나로 접힌다

「S급이니 `scriptId` 핸들러로 빼자」가 첫 안이었는데, 실제로 필요한 것은
**「시전자 중심 정사각 범위」라는 조준 규약 하나**였다. 데이터로 접히는 것을
엔진에 하드코딩하지 않는다(CLAUDE.md).

```
{ kind: 'selfArea', radius: 1, filter: 'noTerrain' }
```

| 붙은 것 | 자리 |
|---|---|
| `TargetSpec`에 `selfArea` 추가 · `TerrainTile.fort` 추가 | [`rules/src/types.ts`](../packages/rules/src/types.ts) |
| `areaTiles()` · `tilesOf`·`resolveUnits`의 `selfArea` 갈래 · `createTerrain`이 조각 정보를 적는다 | [`rules/src/effects.ts`](../packages/rules/src/effects.ts) |
| 「수성지주」 효과 정의 · 열 언어 설명문 정정(`SKILL_TEXT_FIXES`) | [`tools/extract_data.py`](../tools/extract_data.py) |
| 성채 조각 열넷을 굽는다 | [`tools/build_terrain.py`](../tools/build_terrain.py) |
| 조각 이름·진영 색·홑칸 폴백 | [`client/src/battle/terrain.ts`](../packages/client/src/battle/terrain.ts) |
| 성채 조각만 칸을 꽉 채운다 · `debugTerrainTiles`가 텍스처 대신 지형 id를 본다 | [`client/src/battle/BattleScene.ts`](../packages/client/src/battle/BattleScene.ts) |
| 이어진 지형 사건을 한 줄로 접는다 | [`client/src/ui/eventText.ts`](../packages/client/src/ui/eventText.ts) |
| `?terrain=1`이 성채 3×3도 놓는다 | [`client/src/battle/setup.ts`](../packages/client/src/battle/setup.ts) |

### 넘어질 뻔한 자리 넷

**① 「조준」과 「선결 조건」은 다른 것이다.** 3×3 안에 불이 있으면 못 쓰게 하는
검사를 처음에 `resolveTacticTarget`의 조준 분기에 얹었는데, `selfArea`는
`aimingSpec()`이 **돌려주지 않는 규약**이라(고를 것이 없다) 그 위의
`if (!spec) return ok`에서 이미 빠져나간다 — **검사가 한 번도 안 도는** 형태였다.
HANDOFF §5의 「안 도는 갈래」를 규약 이름만 바꿔 다시 만들 뻔했다. 조준과 별개로
효과 배열을 훑는 자리를 함수 맨 앞에 따로 뒀다.

**② 모양을 이웃으로 되짚으면 안 된다.** 「성지 칸의 상하좌우가 성지인지 보면
조각을 알 수 있다」가 처음 생각이었는데, ⑴ 손권이 둘이면 성채가 붙거나 겹쳐
어느 성의 조각인지 알 수 없고, ⑵ **진영 색은 애초에 이웃에 안 적혀 있다.**
깔 때 `{side, dx, dy}`를 함께 적는 쪽으로 갔다 — 판정에는 한 톨도 안 쓰이고
화면만 읽는다.

**③ 기준 방위는 「그림에서 잰다」.** 조각을 어느 칸에 놓을지는 말로 주고받으면
시계·반시계에서 어긋난다. 모서리 원본의 알파를 사분면으로 나누니 **왼쪽 위가
정확히 0픽셀**이고 아래·오른쪽 변이 꽉 차 있었다 — 성벽이 아래·오른쪽 바깥을
두르는 조각이라 **우하단**의 것이다. 여기서 좌하단으로 잡으면 아래 두 모서리가
서로 바뀌는데, **아홉 칸은 다 그려져서** 「빠진 것은 없는데 성벽이 안 이어지는」
그림이 된다. 표기는 기획자가 말하는 대로 **시계 방향**으로 통일했다 —
성벽 `우 0 · 하 90 · 좌 180 · 상 270`, 모서리 `우하 0 · 좌하 90 · 좌상 180 · 우상 270`.

**④ 회전은 화면이 아니라 도구가 한다.** 칸이 **96×120(정사각이 아니다)**이라
스프라이트를 돌린 채 크기를 잡으면 가로·세로가 뒤바뀌어 **성벽 두께가 방위마다
달라진다.** `build_terrain.py`가 90°씩 미리 돌려 열넷을 굽고, 화면은 어느
조각이든 「칸에 꽉 채워라」 하나만 안다.

### 조각을 자르지 않는다

다른 지형 그림은 알파 경계상자로 잘라 정사각으로 채운 뒤 128px로 줄인다. 성채는
**그러면 안 된다** — 조각들이 서로 맞물려야 하는데 성벽 원본은 캔버스 오른쪽에,
모서리 원본은 왼쪽 위에 치우쳐 있다. 기획자가 같은 234² 캔버스 위에 **자리까지
맞춰** 그린 것이라 캔버스째 쓴다. 기준 방위(성벽=동쪽, 모서리=남동쪽)는 위 ③처럼
그림에서 재고, 기획자가 준 배치도와 조립해 한 번 더 대조했다.

**성채 조각만 칸을 꽉 채운다.** 다른 지형은 88px로 격자선을 남기는데(몇 칸짜리인지
읽혀야 한다), 성벽이 이웃 칸과 이어지지 않으면 **아홉 조각으로 흩어져 보인다.**
정사각 원본이 세로로 1.25배 늘어나는 것은 감수했다.

## 3. 정한 것

- **판 밖은 잘린다** — 구석의 손권은 4칸만 짓지만 **쓸 수는 있다.** 막으면 화면에
  이유가 안 뜬다(되돌릴 수 있는 것은 조용히, 없는 것은 말한다).
- **화계뿐 아니라 수계·다른 성지도 3×3 안에 있으면 막는다.** 기획자는 불만
  말했지만 지형 셋이 완전 배타라는 규약(2026-09-01)이 이미 있고, 1칸이던 시절
  「이미 지형이 있다」로 막던 것이 그대로 9칸이 된 것뿐이다.
- **말풍선은 한 줄로 접는다** — 그대로 두면 「…에 성지가 생겼다」가 아홉 줄
  쏟아져 그 앞의 시전 한 줄을 대화창 밖으로 민다. 첫 칸이 중심이라
  `areaTiles()`가 중심을 맨 앞에 놓는다.
- **조각 정보가 없는 성지는 옛 그림 한 장으로 뜬다** — 개발용 통로가 놓는 홑칸과
  이 상향 이전에 저장된 판이 그 갈래다.

### 곁가지로 고친 것

GDD §3.8 지형표가 화계·성지의 정산 주기를 **「1일마다」**로 적고 있었다. 엔진은
`FORMULA.terrainPeriod = 90`, 즉 **0.9일**이다 — 스킬 설명문(엑셀 → 열 언어)은
처음부터 0.9일이라 **화면은 멀쩡했고 GDD만 낡아 있었다.** 「기획 수치의 정본은
엑셀이다」가 또 한 번 맞았다(CLAUDE.md의 §4.3·§5 표 사고와 같은 종류).

- `npm run terrain` — 성채 조각 14장
- `npm run typecheck` · `npm test` — 548 pass / 1 fail(**이 세션과 무관한**
  에셋 경고 누적: 연출 이미지 1건 · 시각효과 2건, 손대기 전부터 있던 것)
- `npm run smoke:ui` — **끝까지 완주.** 지형 검사가 12칸(기존 3 + 성채 9)을
  엔진과 화면 양쪽에서 대조한다
- 실제 화면 — `?terrain=1`로 판에 깔린 3×3을 확대해 눈으로 확인했다(남군·북군 둘 다).
  회귀는 「아홉 칸이 생겼는가」만 알고 **「성벽이 바깥을 향하는가」는 모른다** —
  그래서 개발용 통로에 성채를 놓아 눈으로 볼 자리를 남겼다.
