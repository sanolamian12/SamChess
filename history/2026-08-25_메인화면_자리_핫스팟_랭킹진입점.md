## 왜 이 작업인가

사용자가 "메인 페이지의 디자인을 손보려고 한다"며, 먼저 오프닝·환경설정·도시
생성 화면에서 쓰인 폰트와 다국어 지원을 메인 화면에도 적용해 달라고 요청하며
시작됐다. 그 뒤 실제 화면을 보면서 "자리 버튼을 그림 속 건물 실루엣으로
바꿔 달라" → (적용해 보니) "실루엣은 필요 없다, 모바일엔 호버가 없으니 이름표를
늘 띄워 달라" → 자리 위치를 다섯 차례에 걸쳐 미세 조정 → "도시 관리 > 도시
전적 보기 화면을 메인에 자리 하나로 더 꺼내 랭킹으로 쓰자" → 그 화면의 배경도
전용 그림으로 갈아 달라, 순서로 범위가 늘었다. 전형적인 스크린샷 기반 반복
피드백 세션이다.

## 한 일 — 크게 다섯

### 1. 메인 화면에 Song Myung 폰트 + 다국어 적용

`TitleScreen`·`NewGameScreen`(`.scr-title`·`.scr-new`)에만 걸려 있던 Song Myung
고풍 폰트를 `.scr-main`에도 걸었다(`style.css`). 의도적으로 「간판·도시 생성
두 화면만」이라고 적혀 있던 주석을 "메인 도시 화면이 합류했다"로 고쳤다 — 화풍
리스킨이 이제 온보딩 화면을 넘어 도시 화면까지 이어지는 첫 걸음이라는 뜻이다.

`MainScreen.tsx`는 이미 `t()`로 대부분 다국어였지만, `window.confirm()` 다이얼로그
둘(로그아웃 확인·도시 삭제 확인)과 `[테스트] 도시 삭제` 버튼 글자가 한국어
하드코딩으로 남아 있었다. `main.logoutConfirm`·`main.deleteCity`·
`main.deleteCityConfirm` 키를 새로 추가했고, 이 참에 **`main.*`·`place.*` 키가
비한국어 9개 언어 파일에 아예 없던 것**(간판·환경설정·도시생성 키만 채워져
있었다)도 전부 채웠다.

### 2. 자리 버튼 — 실루엣 → 늘 보이는 이름표 + 네모, 두 번 뒤집었다

**1차**: 반투명 네모 버튼 셋을, 배경 그림(`main-day.jpg`, 685×1536)에서 손으로
딴 SVG 다각형으로 바꿨다. 평소엔 안 보이다가 마우스를 올리면 노란 테두리로
윤곽이 떠오르는 방식 — `궁궐`은 성문 누각+성벽, `병영`은 천막 셋, `장터`는
아래쪽 오른쪽 지붕 서너 채만 골라 땄다.

핫스팟은 `ScreenChrome`에 새로 낸 `artOverlay` prop으로 들어간다 — 배경 그림이
`backdropMotion.ts`의 드리프트로 몇 초마다 아주 조금씩 밀리는데, 핫스팟이
`children`(안 흔들리는 층)에 있으면 그림만 움직이고 다각형은 제자리에 남아
어긋난다. `artOverlay`는 그림과 같은 `.scr-art` 안에 들어가 같은 `transform`을
받아 항상 붙어 다닌다. SVG `viewBox`를 그림의 실제 픽셀 크기로, `preserveAspectRatio`를
`xMidYMid slice`로 두면 배경의 `background-size: cover; center`와 **정확히 같은
규칙으로 잘린다** — 화면 크기가 달라도 좌표를 다시 셀 필요가 없다. 이 값은
이번 리디자인 내내 그대로 쓰였다.

**2차 (사용자가 뒤집었다)**: 실제로 적용해 보고 나서 "모바일엔 호버가 없으니
실루엣을 정확히 딸 필요가 없다, 이름표를 호버와 상관없이 늘 띄워 달라"는
피드백을 받았다. 이름표가 늘 보이면 클릭 영역이 정확한 건물 윤곽일 이유도
같이 없어진다 — 어차피 눈에 보이는 글자가 「여기다」를 말해 주므로, 손가락으로
짚기엔 다각형보다 네모가 더 관대하다. 그래서 손으로 딴 다각형(`points`)을
걷어내고 단순한 `rect`로 바꿨다. 노란 테두리 강조는 **데스크톱 사용자를 위한
덤으로만** 남겼다 — 이름표를 같이 켤 필요가 없어지니 자바스크립트 상태(호버
추적)도 함께 사라지고 순수 CSS `:hover`/`:focus-visible`만 남았다.

**진짜 버그 하나** — 자리를 비워 두려고 남긴 빈 `<div className="city-map" />`가
`.scr-bg > *` 규칙으로 `z-index: 2`(내용 층)에 떠서, `z-index: 0`인 그림 층 안의
핫스팟 클릭을 통째로 가로챘다. Playwright의 `hover()`가 "`.city-map` intercepts
pointer events"로 정확히 짚어 줘서 잡았다 — `pointer-events: none` 한 줄로 고쳤다.

### 3. 자리 위치 — 여섯 차례 미세 조정

스크린샷을 주고받으며 다섯 번(궁궐 세 번·장터 두 번·랭킹 두 번, 정확히는
아래 표) 좌표를 고쳤다. 병영은 처음부터 맞아 한 번도 안 건드렸다.

### 4. 「랭킹」 진입점 — 새 화면이 아니라 이미 있던 화면을 재사용

`CityRecordsScreen`(도시 전적 보기)은 원래 궁궐 → 도시 관리 → 도시 전적, 세 번
눌러야 닿았다. 화면 자체는 안 건드리고 메인 화면에 자리를 하나 더 내
`onRanking`으로 바로 부르게 했다 — 병영 바로 아래, 그림 속 작은 민가와 좌판
상인이 보이는 자리에 병영과 **같은 너비·가로 위치**로 두라는 요청이었다.

두 갈래에서 들어오므로 "뒤로"가 어디로 가야 하는지 갈린다. `App.tsx`의
`Screen` 유니온에 `cityRecords`의 `from: 'city' | 'main'`을 추가해 해결했다 —
궁궐 쪽에서 왔으면 도시 관리로, 메인에서 왔으면 메인으로. **뒤로 버튼의
글자 자체도** 갈렸다는 것을 스크린샷으로 확인하고서야 알아챘다 — 처음엔 두
경로 다 "← 도시 관리로"로 고정 문구였는데, 메인에서 들어온 경우 실제로는
도시로 돌아가면서 글자만 "도시 관리로"라고 거짓말하고 있었다. `from`에 따라
`city.records.back`/`place.back` 둘 중 하나를 고르는 것으로 고쳤다.

### 5. 랭킹 화면 전용 배경 — 넷째 칸에 이름을 붙였다

`tools/build_backgrounds.py`는 `eachBackground(2)_big.jpg` 띠를 4칸으로 잘라
`place-{1,2}-{palace,barracks,market,extra}.jpg`로 구웠는데, 넷째 칸(`extra`)은
2026-08-15에 "기획자가 연결점을 나중에 알려주겠다"며 자리만 잡아 둔 것이었다.
이번에 사용자가 "그 넷째 칸이 랭킹이다"라고 확정해 줘서 `PLACES` 튜플의
`extra`를 `ranking`으로 바꾸고 다시 구웠다 — 실제로는 **게시판(방문 붙이는
곳) 그림**이었다. 도시 전적/랭킹 화면과 잘 맞는 소재였다.

`backdrop.ts`에 `rankingBackdrop(cityLevel)`을 새로 냈다 — `placeBackdrop`/
`PlaceId`에 안 넣은 이유는, 궁궐·병영·장터는 `PlaceScreen`(갈래 화면) 하나가
공유하는 자리지만 랭킹은 `CityRecordsScreen`으로 곧장 가기 때문이다. `PLACES`
배열(메인 화면이 궁궐·병영·장터를 순회하는 그 배열)에 넣으면 존재하지 않는
`PlaceScreen`으로 이어야 하는 문제가 생긴다.

**진짜 버그 하나 더** — `npm run backgrounds`를 다시 돌리자 `new-city.jpg`가
사라졌다. `build_backgrounds.py`의 "계획에 없는 출력은 지운다" 정리 로직이
**같은 출력 폴더(`public/backgrounds/`)를 쓰는 다른 도구**(`build_ui.py`가
`assets/icons/create_city.png`에서 굽는 새벽 배경)의 산출물까지 "내가 모르는
파일"로 보고 지운 것이다. `npm run ui`를 다시 돌려 복구했다 — **근본 원인은
안 고쳤다**(아래 「범위 밖」 참조).

## 이번 범위 밖 (다시 볼 자리)

- **`build_backgrounds.py`의 스테일 정리 로직이 다른 도구의 산출물을 지우는
  문제를 고치지 않았다** — `public/backgrounds/`를 이 스크립트와 `build_ui.py`
  둘이 같이 쓰는데, 이 스크립트는 자기 `STRIPS` 표에 없는 파일을 전부 "묵은
  것"으로 보고 지운다. `npm run backgrounds`를 단독으로 돌릴 때마다
  `new-city.jpg`가 사라지고, `npm run ui`를 다시 돌려야 돌아온다. 두 도구가
  아예 다른 폴더를 쓰게 가르거나, 서로의 산출물 이름을 아는 예외 목록을 두는
  식으로 고쳐야 하는데 이번 세션 범위는 아니었다.
- **`backdrop.test.ts`의 게임 제목·언어 목록 기대값이 여전히 낡았다** —
  "만민의 삼국지" → "만인의 삼국지", 5개 언어 → 10개 언어로 갱신이 안 됐다.
  전날(2026-08-25 첫 세션) 이미 발견하고 "이번 세션이 만든 문제는 아니라
  손대지 않았다"고 남긴 것을 이번에도 그대로 뒀다.
- **메인 화면 자리 이름표를 10개 언어 전부 눈으로 확인하지는 않았다** — 한국어·
  영어·중국어 간체 셋만 스크린샷으로 봤다. 포르투갈어·몽골어처럼 긴 번역이
  두 줄로 접히는 문제가 환경설정 팝업에서 나온 적이 있어(전날 세션), 메인
  화면 이름표도 같은 문제가 날 수 있다 — `useFitText` 같은 훅이 필요할 수
  있다.
- **자리 좌표(`CITY_HOTSPOTS`)는 `main-day.jpg` 하나만 보고 잡았다** — 황혼·밤
  그림도 같은 구도로 보이긴 했지만(스크린샷에서 확인), 픽셀 단위로 대조하진
  않았다. 그림이 갈리면(예: 재작업) 다시 잡아야 한다.

- 메인 화면 자리 배치는 사용자가 만족한 상태로 세션을 마쳤다 — 추가 피드백이
  없으면 이 화면은 당분간 안 건드려도 된다.
- 다음 걸음 후보: ① 메인 화면 이름표의 나머지 7개 언어 눈검사, ②
  `build_backgrounds.py`/`build_ui.py`의 출력 폴더 공유 문제, ③ 궁궐·병영·장터
  화면 자체(아직 화풍 리스킨 전)의 폰트·다국어 적용 — 전날 세션이 "다음은
  궁궐·병영·장터의 화풍 리스킨이나 나머지 화면 다국어 채우기"라고 남긴 것과
  같은 줄기다.
