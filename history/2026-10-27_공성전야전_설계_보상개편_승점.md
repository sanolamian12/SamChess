# 대전 방식 재검토 — 공성전 · 야전 설계, 보상 네 줄, 승점 (2026-10-27)

기획자가 「병영 [출정하기]의 실시간 1:1 매칭은 출시 초기에 사람이 드물고, 붐비면 트래픽 · 서버 안정성이 걱정이라는
시니어 피드백을 받았다. Clash of Clans · Guns Up처럼 방어는 미리 세워 두고 공격이 찾아가는 방식은 어떤가」로 꺼냈다.
검토 · 제안 → 기획자 의견 → 다시 제안을 네 번 오갔고, 이 세션에서는 **설계를 GDD에 적고 보상 · 승점만 구현**했다.
공성전 자체(수비군 · 도시 목록 · 선전포고)는 아직 없다 — GDD §8.8의 단계 1부터다.

## 검토 — 왜 비동기가 이 저장소에 싸게 붙나

AI 대전이 이미 「서버가 시드를 뽑아 상대를 굳히고 · 시작 순간 명단 · 배치를 굳히고 · 수를 덧붙이고 · 재생해 한 번만
정산」이다(`aiBattle.ts`, 2026-10-15). 엔진이 결정적이라 상대를 AI가 움직여도 재생 검증이 선다. 공성전은 그 경로에서
**`makeAiOpponent()`가 지어내던 상대를 다른 플레이어의 수비군 스냅샷으로 바꾸는 일**이다. 판마다 방을 붙들지 않으니
부하는 HTTP 몇 번 + 재생 한 번이다. 함께 짚은 위험 — 방어 AI 품질이 방어의 재미 전부다 · 정산이 방어자 계정 행을
잡으면 인기 수비군에 잠금이 몰린다(→ 덧붙이기 전용 `defense_log`) · 수마다 계정 jsonb 행을 다시 쓰는 덧붙이기가 오히려
주 부하가 될 수 있다(묶어 보내기는 단계 뒤쪽).

## 확정한 것 (기획자)

| 물음 | 결정 |
|---|---|
| 대체인가 | **둘 다** — 상대가 접속해 있으면 **야전**(선전포고 → 회신 → 수락, 실시간), 아니면 **공성전**(수비군을 AI가) |
| 이름 | 농지 = **보초병**(출전 · 수비군 불가), 성 = **수비군**(출전 가능) |
| 출정 조건 | 튜토리얼 + 3v3 · 5v5 부대 각 1개 이상(+ 수비군). 튜토리얼 끝에 곧바로 이끈다 |
| 목록 | 도시 레벨로 묶고 그 안에서 수비군 전투력 순 · 상위 도전 제한 없음 · 도시 점수는 표시만 · 접속 / 미접속 탭(받아온 시각 기준) |
| 선전포고 | 30초 응답 · 바쁜 상대 · 스팸 방지 · 수락 뒤는 지금의 `BattleRoom` |
| 방어자 | 약탈 없음 · 보상 없음 · 히스토리와 방어 승률만 · 랭킹에 안 넣음 |
| 야전 | 공격 · 방어가 아니라 두 세력 — 양쪽 다 참가비 · 양쪽 다 보상 |
| 방어 AI 방침 UI | 더 고민 — 스냅샷에 `policy` 칸만 |
| 「약한 상대」의 잣대 | **전투력** (도시 점수는 활동량이라 오래 한 사람이 거꾸로 깎인다고 설명) |
| 보상 | 아래 네 줄 — 기획자가 통째로 새로 정했다 · 군량은 모드와 무관 · 도적떼 승리 = 약한 상대에게 승 |
| 랭킹 | 기획자 원안 「이길 때 (상대 전투력 − 내 전투력)을 더한다」 → 대등한 승리 0 · 약한 상대 음수 · 복권 · 모드 섞임을 짚고 **100 × (1 − 예상 승률)**로 확정 |

```
                 카드 ①                         카드 ②     자재  군량
센 상대에게 승   보유 전원 + 새 B·C              D 전원      1     2
약한 상대에게 승 보유 B 이하 + 새 C              D 전원      —     1
센 상대에게 무·패 보유 B 이하 + D 전원           —           —     1
약한 상대에게 무·패 보유 C 이하 + D 전원         —           —     —
센 상대 = 상대 전투력 ≥ 내 전투력 − MATCH_BAND(20)
```

## 구현

- **데이터** — `extract_data.py`의 `ECONOMY.battleRewards`를 네 줄(`strongWin` · `weakWin` · `strongLose` · `weakLose`)로.
  한 줄 = 카드 칸 목록(칸마다 `ownedGrades` + `newGrades`에서 한 장) + 자재 + 군량. 옛 `win` · `lose` · `raidWin` · `bonusGrades`(C·D 덤)는 없다.
- **meta** `rewards.ts` — `REWARD_TABLE`은 표를 읽기만 한다. 경계는 `rewardTier()` 하나(공성전 화면의 「보상이 줄어듭니다」도 이것을 부른다),
  줄은 `rewardKey()`(무승부 = 패배 줄). `grantBattleRewards(profile, key, seed)` — 도적떼가 `'weakWin'`으로 부른다.
  승점은 `winPoints()` — 정산이 `bumpTally(…, points)`로 계정 · 부대 · 출전 장수 칸에 같은 값을 쌓는다.
  `RecordTally.points` 신설(되접기는 없으면 0), `ranking.ts`의 `battleScore()`는 그 칸을 읽는다.
- **무승부 택1 폐지** — 결과 화면의 고르기(`ResultScreen` · `ResultScroll`의 `holdAt` · `overlay` · CSS), 클라이언트 `meta/battleResult.ts`,
  서버 `/battle/draw-result`, meta `clearAiBattle()`, AI 정산 · `BattleRoom`의 무승부 갈래가 전부 없어졌다. 무승부도 AI 재생 · `BattleRoom`이
  직접 정산한다 — **클라이언트 값을 믿던 마지막 경로**(`picks` · `kills` · `power` · `fallen`)가 함께 사라졌다.
- **문구** — 「총점」 → 「승점」과 그 설명(열 언어), 택1 문구 4키 삭제. 몽골어 열 이름은 넓은 키릴이라 「Оноо」로 짧게.
- **GDD** — §6.4 새 표 · §7 승점 · **§8.8 공성전 · 야전(새 절, 미구현)** · §5.11 도적떼 보상 · §12 결정 이력과 미해결(승점 담합 · 방어 AI 방침 UI).
