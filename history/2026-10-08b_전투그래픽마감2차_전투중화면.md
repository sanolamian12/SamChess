## 2. 한 것

### 2-1. CSS 네 가지 (`56ae477`)

- **「자동 포커싱 OFF」** — 반투명(`opacity .45`) 회색 글자가 밝은 종이 지도 위에서 사라졌다. 짙은 바탕(`#0b0d10cc`) · 밝은 글자(`#d6d9de`)로.
  「판을 가리지 않는다」는 크기(한 줄 · 작은 글자)로 지킨다.
- **게임 정보 「남은 시간」** — 흐린 꼬리표 한 줄이 진영 두 줄과 같은 칸 모양이 됐다. 꼬리표 `#c3c8cf` · 값은 금색.
- **맥락 판 책략 목록** — 한 열이라 넷째 줄부터 [취소] 위에서 잘려 스크롤했다(Lv9 = 8종). **두 열**(`.cx-list-tactics`, `contextPanel.ts`) +
  줄 높이 축소로 8종이 4줄에 든다. 아이템 목록은 한 줄뿐이라 그대로다.
- **순서 판 얼굴 띠** — 전투 중에만(`#frame.battle:not([data-stage="prep"])`) `mask-image`로 양옆을 다시 녹인다. 칸(56×36)이 그림(2:1, 필요 72)보다
  좁아 `object-fit: cover`가 구워 둔 좌우 흐림을 잘라 네모 경계가 보였던 것(1차 3-7). 배치 화면(54×27)은 그대로 맞으므로 손대지 않았다.
- **게임 정보 판때기** — 전투 중엔 순서 판 그림을 같은 9분할 값(`125 66 68 66`)으로 입는다.

### 2-2. JPG 검은 바탕 걷기 — `build_ui.py` (`567484f`)

- `FRAMES`에 `panel_battle_command` → `panel-battle-command.png`, `button_battle_command` → `btn-battle-command.png`.
- 새 `FRAME_BLACK_BG` — 이 둘은 `.png`가 없으면 `.jpg`를 찾고, JPG일 때만 **`knock_out_black()`**을 거친다. 다시 받을 때 투명 PNG로 오면 저절로 빠진다.
- `knock_out_black()` — RGB 최댓값 < 28(`BLACK_BG_LEVEL`, JPEG 잡음이 바탕에 10~20으로 깔린다)인 덩어리 중 **캔버스 가장자리에 닿은 것**만 걷는다.
  판 쪽을 닫고(`binary_closing`) 구멍을 메운(`binary_fill_holes`) **바깥 윤곽 밖만** 투명하게, 경계 1px은 알파 반. `scipy.ndimage`는
  `remove_char_background.py`가 이미 쓰는 의존이고 함수 안에서만 import한다.

### 2-3. 판때기 · 명령 단추 · 시전 오라 (`f0864a5`)

- **명령 판 · 맥락 판** — `panel-battle-command.png`(960×962). 슬라이스 **왼쪽 위 108 · 오른쪽 아래 130**(오른쪽 아래 귀퉁이쇠가 더 크게 그려졌다 —

  명령 판 제목은 배치 때의 고유기술 패널처럼 크림색 + 그림자.
- **명령 단추 여섯** — `btn-battle-command.png`(960×528) 한 장, 9분할 `100`. 꺼짐 = `grayscale(1) brightness(.55)`, 고른 것 = 금빛 글자 + `brightness(1.3)` +

## 3. 넘어진 곳

### 3-1. 「가장자리에 닿은 검정」을 다 걷으면 판 안에 줄이 뚫린다

첫 굽기를 분홍 바탕에 올려 보니 **테와 판 사이의 검은 홈**이 통째로 빠져 판 안쪽에 분홍 줄이 그어졌다. 홈이 몇 px 틈으로 바깥 검정과 이어져 있었다.
단추도 같았다. 판 쪽 마스크를 닫고 구멍을 메워 **바깥 윤곽**을 만든 뒤 그 밖만 걷자 깨끗해졌다. **투명 처리는 반드시 대비되는 바탕 위에 올려 본다** —
짙은 판 위에서는 검은 줄이 그냥 홈처럼 보여 못 알아챈다.

### 3-2. 있는 그림을 빌려 입혀 보니 「테 두께」가 문제였다

새 그림을 받기 전에 페이지에 CSS만 주입해(코드 변경 없음) 고유기술 판때기를 아래 칸에 입혀 봤다. 화풍은 맞는데 **테가 두꺼워** 책략 이름이 「공…」으로 잘리고
목록이 6종만 보였다 — 프롬프트에 「테 6% · 귀퉁이 장식은 귀퉁이 안에서 끝나게」를 적은 근거다. 새 그림을 입힌 뒤에도 처음 값(1.3rem)으로는 책략 넷째 줄 ·
장수 카드 숫자가 다시 깨져 한 번 더 얇게 했다. **아래 칸은 내용이 빽빽해서 테 한 단계가 곧 한 줄이다.**

### 3-3. 판때기가 폭을 먹자 숫자가 쪼개졌다 — `overflow-wrap: anywhere`

「무 36」이 「3 / 6」 두 줄이 됐다. `#ctx-flow`에 걸린 `overflow-wrap: anywhere`(한글 끝 음절이 혼자 떨어지는 것을 막으려던 것)가 좁아진 칸에서 **숫자 사이**를 끊었다.
숫자 칸에 `white-space: nowrap`. 남색 상자 시절엔 폭이 넉넉해 한 번도 안 드러났다.

### 3-4. 스모크가 3px을 잡았다 — 내가 고른 판과 스모크가 고른 판은 다르다

`gfx_look`(seed 3, 곽가)에서는 장수 카드가 딱 맞았는데 `smoke:ui`가 「맥락 판의 장수 정보가 칸을 3px 넘친다」로 멈췄다. 초상을 25% → 22%로 줄여 통과.
**눈으로 맞춘 한 장면은 상한 근처의 다른 장면을 보장하지 않는다** — 이 검사(`scrollHeight − clientHeight`)를 1차에 넣어 둔 덕에 잡혔다.

### 3-5. 시전 오라를 화면으로 보는 통로가 없다

데모 인자에 「시전 중」 장면이 없다. 이번엔 Playwright로 `__battle.scene.state.units`에 `casting`을 걸어 찍었다(커밋 안 함, 일회용).
보라(S) · 파랑(B)은 또렷이 돌고 두 프레임이 달라 애니메이션도 확인했다. **노랑(E)은 밝은 종이 지도 위에서 흐리다.** 빨강(A)은 데모 편성(seed 3, 5v5)에 A급이 없어 못 봤다.
C · D급은 고유기술이 없어 링이 안 뜬다(`FX.byCasting`에 없다 — 정상).

### 3-6. `npm run extract`가 생성물 10개를 「바꿨다」 — 줄 끝뿐

Windows Python이 CRLF로 썼고 내용은 같았다(`git diff`가 줄 끝 경고만 냈다). `git checkout -- packages/data/generated`로 되돌렸다.

## 5. 남은 것

- **비켜 선 장수 팝업과 시스템 메시지(왼쪽 위)의 겹침** — 이번 장면에선 팝업이 오른쪽에 떠 재현 못 했다. 판 오른쪽 끝 장수를 눌러 `data-pos="left"`를 만들어 봐야 한다.
- **고른 명령 단추가 덜 갈린다** — 옛 초록 테 대신 금빛 글자 + 밝기뿐이다. 기획자 화면 확인 대기.
- **노랑(E) 시전 오라가 밝은 지도 위에서 흐리다** — 진한 노랑 · 그림자 중 고를 것. 빨강(A)은 화면으로 아직 못 봤다.
- **시전 장면을 찍는 통로** — 데모 인자(`&cast=1` 같은)나 `gfx_look`의 장면 하나로 두면 다음부터 손으로 상태를 안 바꿔도 된다.
- 명령 판 · 맥락 판 **안쪽의 줄 · 칸**(책략 줄 · 진영 칸 · [취소] · 장수 카드 칩)은 아직 남색 상자다 — 나무 판 위에서 그대로 둘지 기획자 판단.
- 1차에서 넘어온 것: 매칭 화면 「전투준비 · 다시 찾기」 문구가 한국어 파일에만 있다 · `gfx_look`의 「상대 차례」 장면이 [대기] 확인 단계를 못 넘긴다.
