# 2026-10-21c — 관리자 역할 나누기(관리자 / CS) 설계

본체 세션이 설계하고 기획자가 정했다. **구현은 관리자 세션이 맡는다** — 닿는 곳이 `server-api/src/admin/*` · `tools/admin_role.ts` ·
`tools/smoke_admin.ts` · `meta/src/admin.ts`이고, 공용 파일은 `sql/schema.sql` 한 줄(아래 ④)뿐이다. 본체는 머지 전에 검토한다.

## 지금

- 역할은 `app_metadata.role === 'admin'` 하나. 관리자 API 17개 경로를 전부 쓴다.
- 판정은 `server-api/src/admin/auth.ts`의 `verifyAdmin()` 한 곳 — 매 요청 Supabase에서 다시 읽어 역할을 거두면 바로 막힌다. MFA(aal2 + 인증된 TOTP)도 여기서.
- 역할을 주는 길은 `tools/admin_role.ts`뿐(서비스 키).

## 기획 결정 (2026-10-21 기획자)

| 하는 일 | admin | cs |
|---|---|---|
| 보기 — 대시보드 · 추이 · 유저 검색 · 계정 상세 · 게임 데이터 · 우편 목록 · 받을 수 있는 계정 수 | ✓ | ✓ |
| 감사 로그 보기 | ✓ | ✓ **전부** (문의에 답하려면 누가 무엇을 했는지 알아야 한다) |
| 멈춘 상태 정리 — AI 대전 · 도적떼 · 태학 · 부상 · 판 도중 아이템(돌려주기 포함) | ✓ | ✓ |
| 지급(조정 중 주는 쪽) | ✓ | ✓ **CS 상한 안에서** |
| 회수(조정 중 거두는 쪽 — 음수 · `equipmentRevoke`) | ✓ | ✗ |
| 한 사람 우편 | ✓ | ✓ 보상은 **CS 상한 안에서** |
| 전체 우편 · 우편 회수 | ✓ | ✗ |
| 계정 정지 | ✓ | ✓ **7일 이하만**(영구 ✗) |
| 정지 해제 | ✓ | ✗ |
| 역할 주기 · MFA 지우기 | 도구만 | 도구만 |

**CS 상한** — 한 번 상한은 관리자(`ADJUST_LIMITS`)의 **1/10**, 그리고 **하루(KST) 합계 상한**을 함께 둔다(기획자 확정).

| 종류 | 관리자 한 번 | CS 한 번 | CS 하루 합계(한 번 × 5) |
|---|---|---|---|
| 금화 | 100,000 | 10,000 | 50,000 |
| 군량 | 100,000 | 10,000 | 50,000 |
| 건축 자재 | 10,000 | 1,000 | 5,000 |
| 장수 카드 | 100 | 10 | 50 |
| 시장 아이템 | 99 | 9 | 45 |
| 병기 | 10 | 1 | 5 |

하루 합계가 필요한 까닭: 한 번 상한만 두면 같은 지급을 열 번 반복해 넘긴다 — 우편의 「같은 보상 두 줄」(`6b1951e`)과 같은 구멍이다.
**지급과 우편 보상은 같은 하루 합계를 나눠 쓴다**(길이 둘이라고 두 배가 되면 안 된다). 하루 × 5는 출발값이고 표 하나에서 바꾼다.

## 설계

### ① 역할 → 권한 표 하나 (`meta/src/admin.ts`, 순수)

```ts
export const ADMIN_ROLES = ['admin', 'cs'] as const;
export type AdminRole = typeof ADMIN_ROLES[number];
export type AdminPermission =
  | 'view' | 'resolve' | 'grant' | 'revoke' | 'mail.one' | 'mail.all' | 'mail.revoke' | 'ban' | 'unban';
export const ROLE_PERMISSIONS: Record<AdminRole, readonly AdminPermission[]>;
export const CS_LIMITS;          // 위 표의 「CS 한 번」 — ADJUST_LIMITS에서 파생(÷10, 최소 1). 숫자를 두 번 적지 않는다
export const CS_DAILY_FACTOR = 5;
```

- 판정 함수도 여기 — `csCheck(adjOrRewards, usedToday)`가 「한 번 상한 · 하루 합계」를 보고 사람 말을 돌려준다. **회귀가 이 표와 셈을 고정한다.**
- 「조정 하나가 지급인가 회수인가」도 여기서 가른다(`delta > 0`이면 지급, 음수 · `equipmentRevoke`면 회수).

### ② 판정 자리는 그대로 하나 (`admin/auth.ts` · `routes.ts`)

- `verifyAdmin()`이 `role`을 함께 돌려준다 — `app_metadata.role`이 `ADMIN_ROLES`에 없으면 지금처럼 `forbidden`. MFA는 CS도 똑같이 요구한다.
- `requireAdmin(req, reply, perm)` — 경로마다 필요한 권한을 적는다. 권한이 없으면 **403 `{ error: 'role_forbidden', need: perm }`**(역할 자체가 없는
  `forbidden`과 가른다 — 화면이 「이 일은 관리자에게」를 말할 수 있게).
- **조정 경로는 본문을 보고 나서 권한을 정한다** — 같은 `POST /admin/users/:uid/adjust`가 지급이면 `grant`, 회수면 `revoke`.
  정지도 같다 — `days`가 `null`(영구)이거나 7 초과면 CS는 `role_forbidden`.

### ③ 하루 합계 — 감사 로그에서 센다

- CS가 지급 · 한 사람 우편을 할 때, 그 트랜잭션 안에서 **오늘(KST) 그 CS가 남긴 감사 로그**의 주는 양을 종류별로 더한다
  (`adjust.*`의 양수, `mail.send`의 `rewards`). 따로 세는 표를 두지 않는다 — 감사 로그가 이미 정본이다.
- **동시에 두 요청이 들어와 둘 다 통과하는 것을 막는다** — 세기 전에 `pg_advisory_xact_lock(hashtext(admin_uid))`로 그 CS의 요청을 줄 세운다.
- 넘으면 **403 `{ error: 'cs_limit', kind, limit, used }`** — 화면이 「오늘 남은 양」을 보여 줄 수 있게.
- KST 하루는 meta에 이미 있는 셈(`raidDay`와 같은 날짜 경계)을 쓴다 — 날짜 경계를 두 벌 적지 않는다.

### ④ 감사 로그에 역할 (`sql/schema.sql` — 공용 파일, 본체에 미리 알린다)

```sql
alter table admin_audit_log add column if not exists admin_role text not null default 'admin';
```

- 누가 **어떤 자격으로** 했는지 남긴다. 옛 줄은 전부 관리자였으므로 기본값 `'admin'`이 맞다. 감사 로그 화면 · 거르기에 역할을 더한다.

### ⑤ 화면 · 도구

- `/admin/me`가 `role`과 권한 목록을 준다 — 화면은 그것으로 단추를 감추거나 잠근다. **막는 것은 언제나 서버다**(감춘 단추를 우회해 불러도 403).
- CS 화면의 지급 · 우편 양식은 「한 번 상한 · 오늘 남은 양」을 보여 준다.
- `npm run admin:role -- <이메일> --role cs` · `--role admin` · `--revoke`. `--list`는 역할 · MFA를 함께.

### ⑥ 검사

- 회귀(`meta/test/adminRoles.test.ts`) — 권한 표 · 지급과 회수 가르기 · CS 한 번 상한 · 하루 합계(지급 + 우편을 함께) · 정지 일수.
  **상한 근처에 실제로 닿는 입력**(정확히 상한 · 상한 + 1)으로 잰다(「상한을 재는 검사는 그 상한에 닿았는지부터」).
- `smoke:admin` — CS 시험 계정(MFA 등록)으로: 보기 200 · 회수 · 전체 우편 · 우편 회수 · 해제 · 영구 정지 · 8일 정지는 `role_forbidden` ·
  한 번 상한 + 1은 `cs_limit` · 상한 안의 지급을 다섯 번 → 여섯 번째는 하루 합계로 `cs_limit` · 감사 로그에 `admin_role = 'cs'` ·
  역할을 `cs → admin`으로 바꾸면 다음 요청부터 바로 풀린다.

## 순서

1. 관리자 세션이 ④ 스키마 한 줄을 본체에 알리고 시작한다(본체가 `db:migrate`로 개발 DB에 적용해도 된다 — `if not exists`).
2. ① 표와 셈 + 회귀 → ② 판정 → ③ 하루 합계 → ⑤ 화면 · 도구 → ⑥ 스모크.
3. 머지 전에 본체가 검토한다 — 특히 **조정 경로가 본문을 보고 권한을 정하는가**, **하루 합계를 잠근 채 세는가**, **우편과 지급이 같은 합계를 쓰는가**.

## 따로 남은 것 — 운영 DB에서의 스모크

`smoke:admin`은 전체 공지를 실제로 보냈다가 회수 · 삭제한다(실계정에 몇 초 보인다). 배포를 정할 때 함께 정한다 — 운영 DB에서는 안 돌리거나,
전체 우편 단계를 시험 계정 대상 우편으로 바꾸는 갈래를 둔다.
